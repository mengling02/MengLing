# 电力系统弹性(Resilience)

## 一句话

系统被打了之后，**还能不能保住关键负荷、能多快恢复** —— 它衡量的是"挨打之后的表现"，而不是"能不能不挨打"。

## 为什么重要

安全研究里有一个必须承认的现实：**没有绝对防得住**。攻击者总会有一次成功，尤其是面对[[高级持续性威胁(APT)]]。所以除了"防住"（prevention），还需要一套指标回答另一个问题：**如果没防住，后果有多严重、恢复有多快？**

这就是弹性（resilience）要回答的。它和两个相邻概念必须分清楚：

| 概念 | 针对什么 | 关心什么 |
|---|---|---|
| **可靠性（Reliability）** | 随机故障（设备老化、天气、误操作） | 长期统计意义上的"够不够用" |
| **安全性（Security）** | 恶意攻击 | "会不会被打穿" |
| **弹性（Resilience）** | 任何扰动，尤其是低概率高影响事件 | "被打之后能不能扛住、多久恢复" |

弹性之所以在电网安全里地位特殊，是因为**电网的失效代价具有不可替代性**：医院、通信、供水都依赖它，停电的社会成本远超直接经济损失。所以电网的安全目标从来不是"零故障"，而是"**关键负荷不停、其余尽快恢复**"。

它也是本库里大量论文的**共同落脚点**：论文 082 讲微电网的抗 DoS 弹性控制，论文 056 讲异常检测后的惩罚式缓解，论文 087 讲用预测性能量管理缓解负荷篡改 —— 它们的方法不同，但评价标准都是"系统在攻击下保住了多少功能"。

## 核心要点

| 维度 | 要点 | 说明 |
|---|---|---|
| 四个阶段 | 预防（Prevent） | 减少被攻破的可能（IDS、加密、隔离） |
| | 吸收（Absorb） | 被攻破时限制影响范围，不让它扩散 |
| | 适应（Adapt） | 系统自动重构、降级运行，保住关键功能 |
| | 恢复（Recover） | 快速回到正常状态，且不引入新风险 |
| 三个能力要素 | 鲁棒性（Robustness） | 抗扰动的固有强度 |
| | 资源性（Resourcefulness） | 可调动的备用手段（储能、备用线路、可中断负荷） |
| | 快速恢复（Rapid Recovery） | 恢复速度 |
| 电网特有的弹性资源 | 微电网与孤岛运行 | 主网故障时保住本地关键负荷（见[[微电网安全]]） |
| | 分布式能源与储能 | 提供就地支撑（见[[逆变器与电力电子安全]]） |
| | 需求响应 | 用负荷侧灵活性换取平衡（见[[电力需求响应]]） |
| | 数字孪生与预案演练 | 提前推演、快速决策（见[[数字孪生]]） |
| 量化难点 | 事件稀疏 | 大规模攻击样本极少，难以统计 |
| | 指标不统一 | 不同文献的弹性定义与指标差异较大 |
| | 攻击 vs 故障 | 攻击者会主动规避防御，统计模型不适用 |

## 关键公式

弹性最经典的量化方式是**弹性三角（resilience triangle）**，用性能曲线的"损失面积"来度量：

$$R=\frac{1}{T}\int_{0}^{T}\frac{Q(t)}{Q_{0}}\,dt$$

- $T$：考察时间窗口（从扰动发生到观察结束）
- $Q(t)$：时刻 $t$ 的系统性能，通常取"被供给的负荷比例"或"关键负荷保有率"
- $Q_0$：扰动前的正常性能水平（基准值）
- $R$：弹性指标，取值范围大致在 $[0,1]$，越接近 1 越好

**白话**：把性能曲线画出来，正常时是一条在 $Q_0$ 的水平线；被打之后它会**掉下去、维持一段、再爬回来**，中间围出的那块"凹下去的面积"就是损失。$R$ 就是"整段时间内平均保住了多少性能"。

**为什么这个公式重要**：它把"弹性"从形容词变成了一个可以比较的数。两台不同的防御方案，可以比较"同样的攻击下谁的凹口更浅、更窄"。这也解释了为什么论文里常见的对比维度是**性能跌落深度（多严重）**和**恢复时间（多久）**，而不是"有没有被攻破"。

（注：弹性量化指标在文献中形式多样，上式是最常见的一种；也有文献拆成"吸收能力 + 恢复速度"两个独立指标。）

## 用网安的话说（小电解读）

弹性在网安里有一个非常贴近的对应物：**从"防入侵"转向"假设失陷"（assume breach）+ 业务连续性/灾难恢复（BCP/DR）**。

- **≈ 蓝队的"纵深防御 + 遏制 + 恢复"闭环**。你熟悉的 IR（事件响应）四阶段（准备、检测、遏制、恢复）在这里被映射成"预防、吸收、适应、恢复"。**弹性就是给安全体系加上"恢复能力"这个维度**。
- **≈ MTTR / 爆炸半径（blast radius）的量化**。IT 里你关心"平均恢复时间"和"影响范围"；电网里同样关心，只是度量对象从"服务可用性"换成了"**负荷供给能力**"。公式里的 $Q(t)$ 就是电网版的"可用性曲线"。
- **≈ 抗 DoS 的服务降级设计**。DoS 打不死一个设计良好的系统（有缓存、有降级、有限流），电网的弹性也一样：**不是让攻击无效，而是让攻击的后果可控**。

相同点：都强调"遏制比预防更现实"、都用量化指标（MTTR、可用性）来度量、都需要预案和演练。
不同点，也是电网场景的本质特殊性：

1. **电网有物理守恒约束**。IT 系统可以通过限流、排队、降级来"拖延"，因为请求可以等待；**电网里功率必须实时平衡，不能"排队"**。发多少、用多少必须瞬间相等，否则频率就变。这让电网的弹性设计空间比 IT 小得多 —— 你不能说"这个负荷稍后再供"。
2. **恢复不是"重启服务"**。IT 里恢复往往是一键重启或切流量；电网里恢复意味着**重新同步、重新并网、逐步带负荷**，每一步都有物理风险（合闸冲击、非同步并网）。所以电网的"恢复过程本身"就是一个脆弱窗口。
3. **攻击者会瞄准恢复过程**。这是弹性研究里最值得注意的一点：既然恢复期最脆弱，那么**针对恢复过程的攻击**（比如在恢复时再来一次 DoS）就是最优策略。IT 里的"二次攻击"（如勒索软件加密备份）是同一个思路。

电网场景的特殊之处：
1. **弹性的层次性**。设备级、馈线级、微电网级、区域级、系统级 —— 不同层级的弹性目标不同，指标也不通用。
2. **与物理稳定性耦合**。弹性不只是"供电与否"的问题，还包括"系统还稳定吗"（见[[电力系统稳定性]]）。低惯量的新型电力系统（见[[逆变器与电力电子安全]]）弹性天然更差，因为它"扛不住扰动"。
3. **人的因素占比高**。电网的很多弹性来自调度员的经验和预案，所以"弹性"评价里常包含决策速度。这也是[[数字孪生]]、LLM 辅助调度（见[[大语言模型(LLM)]]）这类工作想改善的东西。

切入建议：弹性是一个**天然的"评价框架"**。对你来说最实用的用法是：**不要只报检测率，还要报"检测失败时系统保住了多少性能"**。把论文的结论从"我的检测器 AUC 多少"升级到"在检测延迟 X 的情况下，$R$ 提升了多少" —— 这种表述在电网安全论文里更受欢迎，也更能体现你理解了电网的关切。
