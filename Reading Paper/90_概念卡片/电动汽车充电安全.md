# 电动汽车充电安全

## 一句话

电动车充电桩是"电网的插座 + 联网的设备"，它同时连着电网、车辆和后台云平台 —— **三个信任域的交汇点，就是攻击者的天堂**。

## 为什么重要

EV 充电基础设施（EVSE，Electric Vehicle Supply Equipment）在电网安全里地位特殊，因为它是一个**罕见的"三栖"设备**：

- **朝电网**：它是一个可控负荷（而且功率很大），充电功率的集体波动会直接影响配电网的负荷曲线和电压。
- **朝车辆**：它通过充电枪和车辆 BMS 交互，涉及电池安全、充电协议。
- **朝云端**：它必须联网与运营商的充电管理系统（CSMS）通信，接受远程启停、计费、固件升级。

这三条链路中任何一条被攻破，后果都可能外溢：**改计费是经济问题，改充电功率是电网问题，改 BMS 交互是车辆安全问题**。而充电桩通常部署在无人值守的公共停车场、安装分散、更新困难、还可能由第三方运营商维护 —— 这基本就是"安全的完美反面"。

对电网的意义在于：EV 是未来最大的**灵活负荷**（也是[[虚拟电厂]]、[[电力需求响应]]的核心资源）。谁能控制充电桩，谁就能在物理层面制造负荷冲击。这使得 EV 充电安全从"IT 问题"升级成了"电网稳定问题"。

## 核心要点

| 维度 | 要点 | 说明 |
|---|---|---|
| 三个信任域 | 电网侧 | 充电功率影响配电网，可被聚合操控 |
| | 车辆侧 | 与 BMS/整车交互，涉及电池与安全 |
| | 云平台侧 | 与运营商后台通信，涉及身份、计费、固件 |
| 关键协议 | OCPP | 充电桩与后台管理系统（CSMS）之间的通信协议，基于 WebSocket + JSON，用于启停、状态上报、计费 |
| | 充电控制协议 | 桩与车之间的握手与功率协商 |
| | 上层电网协议 | 如 IEC 61850 / DNP3 / Modbus 等，见[[Modbus协议安全]] |
| 主要攻击面 | 报文篡改 | 改充电功率、改身份、改计费记录 |
| | 状态切换攻击 | 在充电状态机之间强行跳跃，制造电气冲击 |
| | 固件与供应链 | 恶意固件、第三方组件后门 |
| | 认证与计费欺诈 | 伪造身份白嫖充电、伪造交易 |
| | 隐私泄露 | 充电时间/地点轨迹暴露行程与居住地（见[[成员推理攻击]]） |
| 防御思路 | 端到端认证与消息完整性 | 桩-云-车三段的双向认证 |
| | 状态机形式化校验 | 用协议状态机约束合法迁移 |
| | 物理侧监控 | 电压/电流异常检测，兜住协议层失守 |

## 关键公式

这个概念以定性描述为主，没有单一的核心公式。它的技术要点可以用一组**协议状态机约束**来刻画：

- 充电过程是一个有限状态机（如：空闲 → 插枪 → 握手 → 充电中 → 停止 → 拔枪），**每一次状态迁移都应有前置条件**（插枪到位、认证通过、绝缘检测通过）。
- 攻击的核心手法之一就是**绕过前置条件直接触发迁移**（这正是 ChargeX 那类状态切换攻击的思路）：攻击者不必伪造全部报文，只要让状态机跳到一个"物理上不该出现"的状态，就可能造成电弧、过流、通信中断或计费异常。
- 因此防御的等价表述是：**任何状态迁移都必须能通过"前置条件 + 物理量一致性"双重校验**。

## 用网安的话说（小电解读）

从网安视角看，充电桩是一个**典型的 IoT + 云平台架构**，你熟悉的那套问题在这里全部重现，而且还多了物理后果：

- **OCPP 之于充电桩 ≈ MQTT/私有 API 之于 IoT 设备**。都是长连接 + JSON/轻量消息，都存在"设备身份弱、消息无完整性保护、固件升级通道可被劫持"的老问题。你做过的 IoT 渗透思路几乎可以平移。
- **状态切换攻击 ≈ 协议状态机攻击**。这跟 TCP 状态机攻击、SIP/SS7 状态绕过是同一类问题：不伪造数据内容，只把协议推进到不该在的状态。你熟悉的"协议 fuzzing + 状态覆盖"正好是这个方向的研究方法。
- **充电桩集群 ≈ 大型僵尸网络**。几千个桩同时被控并执行恶意充电计划，效果等价于一次**针对配电网的协同 DoS**。这跟[[拒绝服务攻击(DoS)]]的思路一致，只是"拒绝"的对象从服务器变成了电网。

相同点：攻击面（固件、通信、认证、计费）和 IT 几乎一模一样，方法论可完全复用。
不同点：**后果会物理化**。在 IT 里改一个字段最多是数据错误；在这里改一个充电功率值，可能是配电变压器过载或者电池热失控。**而且攻击可以"延迟引爆"** —— 恶意固件可以今天装好、下周才在特定条件触发。

电网场景的特殊之处：
1. **分散部署、无人值守、第三方运维** —— 攻击者物理接近桩的机会非常多（USB 口、调试口、本地 Wi-Fi）。
2. **隐私与电网数据的双重价值** —— 充电记录既能反推个人行踪，也能反推配电网的负荷结构。
3. **跨行业标准碎片化** —— 桩厂商、车企、运营商、电网各管一段，安全责任边界模糊，这本身就是结构性的漏洞。

切入建议：这是整个库里**最适合你上手的方向**之一。协议安全分析 + 状态机 fuzzing 是你的主场，而"EV 充电对配电网的物理影响"可以慢慢补。
