# 电力需求响应（Demand Response, DR）

## 一句话

**不是"多发电"，而是"让用户少用电"** —— 通过价格信号或激励，引导用户在高峰时段主动削减负荷，从而平衡供需。

## 为什么重要

传统思路：负荷涨了 → 建电厂。但电厂建设贵、周期长、还污染。
需求响应思路：**把"用户侧"也变成可调度的资源**。

在"新型电力系统"里（高比例新能源），供需波动更大，**需求响应几乎是必选项**。

## 三种主要形式

| 形式 | 机制 | 例子 |
|---|---|---|
| **价格型** | 电价随时间变化，用户自行响应 | 分时电价、实时电价 |
| **激励型** | 签约承诺削减，给补偿 | 直接负荷控制、可中断负荷 |
| **市场化** | 需求响应资源参与电力市场竞价 | 辅助服务市场 |

## 与新能源的关系

光伏、风电出力不稳定 → 需要**灵活性资源**来平衡。
需求响应就是最便宜的灵活性来源之一：
- 中午光伏大发 → 电价低 → 鼓励用户多用电（充电、制氢）
- 傍晚光伏退出 → 电价高 → 用户削减负荷

## 关键公式

价格弹性（刻画"电价变一点，用电量变多少"）：

$$\varepsilon = \frac{\Delta q / q}{\Delta p / p}$$

- $q$：用户用电量（负荷需求）；$\Delta q$：用电量的变化量
- $p$：电价；$\Delta p$：电价的变化量
- $\varepsilon < 0$：电价上升则用电量下降；绝对值越大，说明用户对价格越敏感

白话：**"电价涨 1%，用电量会降百分之几"**——弹性越大，价格型需求响应的可调潜力越大，它是分时电价与实时电价方案设计的基本参数。

自弹性与交叉弹性（多时段之间的相互影响）：

$$\varepsilon_{ij} = \frac{\partial q_i / q_i}{\partial p_j / p_j}$$

- $i, j$：时段编号
- $i = j$ 时为**自弹性**：当前时段电价对本时段用电量的影响，通常为负
- $i \neq j$ 时为**交叉弹性**：$j$ 时段电价对 $i$ 时段用电量的影响，通常为正，代表用户把用电挪到便宜时段

白话：**用户不只会"少用"，还会"挪着用"**——交叉弹性正是"负荷转移"这件事的数学表达，也是需求响应建模中不能省略的部分。

需求响应量（实际削减了多少）：

$$\Delta L = L_{\text{base}} - L_{\text{actual}}$$

- $L_{\text{base}}$：基线负荷，即假设没有需求响应时的负荷，通常由历史数据估算
- $L_{\text{actual}}$：响应后的实际负荷
- $\Delta L$：削减量，也是激励型需求响应的结算依据

白话：**"基线减实际"就是用户声称削减的电量**——而基线本身是估算出来的，所以这里天然存在博弈与欺诈空间（伪造削减量骗取补偿），这正是需求响应场景特有的安全问题。

## 用网安的话说（小电解读）

- **需求响应 ≈ 一个由十万个用户侧设备组成的"分布式执行器集群"**，动作由价格信号统一驱动。**你在网安里最想要的那个"批量控制一千台肉鸡"的能力，在这里是系统自带的功能**。
- **价格信号 ≈ 一条被广播执行的"策略指令"**，篡改它等于拿到了整个集群的写入权限。
- **激励型结算 ≈ 一个基于"自报数据"的补偿机制**，而基线负荷是估算出来的——这天然是虚假申报的博弈场，和你熟的刷奖励同类。

### 相同点
通信安全、身份认证、指令完整性保护、采集链路可信，技术栈和你在 IoT/SCADA 上做的没区别。数据隐私推断也和你熟的用户画像推断同源。

### 不同点 / 难点
1. **这里的"执行器"后果是电网级的**。IT 里操纵一万台肉鸡发垃圾流量，危害止于网络层；需求响应里同时控制一万台可控负荷启停，**危害是直接在电网里制造功率振荡**，可能演变成频率事件（见[[电力系统稳定性]]）。
2. **基线负荷不可验证**。你怎么证明一个用户"本来会用这么多电"？这个数只存在于估算模型里。所以"伪造削减量骗补偿"**无法靠事后审计排除**，只能靠异常检测。
3. **响应是自愿且行为不定的**：用户会按舒适度做次优反应，攻击扰动会被人为随机性掩盖。

### 电网场景的特殊之处
1. **DR 本身是为新能源波动服务的灵活性资源**。但一个可被攻击的 DR 系统意味着**你手里那个平抑波动的工具，可能被反过来用作制造波动的武器**。
2. **市场化机制引入了新的攻击动机**：DR 参与辅助服务竞价，攻击还可以**操纵价格获利**。
3. **聚合商是单点故障**：分散资源通过聚合商接入市场（见[[虚拟电厂]]），平台被打下就可控制海量负荷。

### 切入建议

**"虚假削减申报检测"最接地气**：建立诚实用户与欺诈用户的基线负荷博弈模型，再做统计学习检测。更前沿的题是**"面向需求响应的负荷操纵攻击建模"**：把可控负荷当分布式执行器，求制造负荷振荡的策略。
