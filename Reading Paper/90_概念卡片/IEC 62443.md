# IEC 62443

## 一句话

工控系统（IACS）网络安全的国际标准族，用**区域（Zone）+ 管道（Conduit）**给系统分块、再用**安全等级（SL）**给每块定强度要求。

## 为什么重要

前面那些卡片讲的都是"攻击怎么做、怎么防"，IEC 62443 回答的是另一个问题：**一个工控系统"应该做到什么程度才算安全"，以及"怎么证明你做到了"**。

对做研究的人来说，它的价值有三层：

1. **它提供了标准术语和分类框架**。当你要描述"这个变电站的安全边界应该怎么划"，用 Zone/Conduit 说话，审稿人和工程师都能听懂。
2. **它定义了安全等级（SL），给出了"强度"的刻度**。这让"安全需求"从形容词变成了可量化的目标 —— 你要防的是"无意的误操作"还是"掌握复杂手段的高资源攻击者"？答案不同，方案完全不同。
3. **它是合规基线**。工控产品要进电力行业，通常绕不开它；写论文时引用它，等于把你的工作锚定在产业界认可的需求上。

需要区分三个常被混淆的标准体系：
- **IEC 62443**：通用的工控系统（IACS）网络安全标准族，覆盖面最广。
- **IEC 62351**：电力系统通信安全标准，是[[IEC 61850]]等电力协议的"安全配套"，解决的是"这些电力协议怎么加认证和加密"。
- **NERC CIP**：北美电力行业的强制性合规要求（不同体系，不在本库重点）。

在本库里，[[电力监控系统安全防护体系]]是中国的电力行业防护要求（"安全分区、网络专用、横向隔离、纵向认证"），而 IEC 62443 是国际通用的工控标准 —— 两者思路可对照阅读。

## 核心要点

| 维度 | 概念 | 说明 |
|---|---|---|
| 标准族结构 | 通用（General） | 术语、概念、模型等基础内容 |
| | 政策与流程（Policies & Procedures） | 面向资产管理方，规定安全管理制度与流程 |
| | 系统（System） | 面向系统集成，规定系统级安全要求与安全等级 |
| | 组件（Component） | 面向产品厂商，规定组件级技术要求 |
| 两个核心机制 | 区域 Zone | 把具有相同安全需求的资产划成一组，形成信任边界 |
| | 管道 Conduit | 定义区域之间允许的通信通道及其安全要求 |
| 安全等级 SL | SL 1 | 防"偶然的、无意的"违规（防误操作） |
| | SL 2 | 防"使用简单手段、资源有限"的故意攻击者 |
| | SL 3 | 防"使用复杂手段、资源较充足"的攻击者 |
| | SL 4 | 防"掌握高级手段、资源充足"的对抗性攻击者 |
| 基础要求 FR | 识别与鉴别 | 确认"你是谁" |
| | 使用控制 | 确认"你能干什么"（授权与最小权限） |
| | 系统完整性 | 防未授权篡改，保证数据与系统可信 |
| | 数据保密性 | 防未授权读取（加密） |
| | 受限数据流 | 限制数据只在规定路径与区域内流动 |
| | 事件响应 | 安全事件能被及时发现与处理 |
| | 资源可用性 | 保证系统在攻击下仍能提供服务 |
| 与电网的关系 | 映射到电力场景 | 变电站、调度中心、新能源场站都可按 Zone/Conduit 划分 |
| | 与 IEC 62351 配合 | 62443 定"要求与等级"，62351 定"电力协议怎么实现" |

（注：上述 FR 与 SL 的表述为通用概述，具体条文与编号请以标准原文为准。）

## 关键公式

这个概念以定性描述为主，没有单一的核心公式。它最有用的量化表达是**风险的一般化定义**，工控安全的风险评估通常沿用它：

$$R=f(T,\ V,\ C)$$

- $R$：Risk，风险 —— 需要被降低的量
- $T$：Threat，威胁 —— 谁会来打、有多大能力（这正对应 SL 里的"攻击者能力"分级）
- $V$：Vulnerability，脆弱性 —— 系统本身有多少可被利用的缺口
- $C$：Consequence，后果 —— 被打中的代价（电网里可能是停电、设备损毁、人身安全）

**白话**：安全投入应该跟着风险走，而风险由"威胁能力 × 脆弱性 × 后果"决定。IEC 62443 的两个核心机制正是在**降低 $V$**（Zone 缩小爆炸半径、Conduit 收紧通信路径）和**对抗 $T$**（用 SL 分级去匹配攻击者能力）。至于 $C$，电网场景下通常远大于 IT 场景，这也是为什么电力行业的安全要求普遍更严。

## 用网安的话说（小电解读）

IEC 62443 在网安语境里相当于**"工控版的等保 + ISO 27001 + 安全架构设计规范"三合一**：

- **Zone/Conduit ≈ 网络分段 + 防火墙策略 + 微隔离**。这跟你在 IT 里做的 VLAN 划分、DMZ、零信任微隔离在目标上完全一致 —— 只是它明确要求"**分区依据是安全需求，而不是组织结构**"。这一点很多人会做错：按部门划 VLAN 是运维方便，按安全需求划 Zone 才是安全设计。
- **SL 1–4 ≈ 安全等级/等保级别**。思路是"不同资产配不同强度的防护"，避免一刀切。你可以把它理解成"给每块资产定一个攻击者能力假设"，然后验证防护手段能否对抗该级别 —— 这和你做威胁建模时定义攻击者模型（attacker model）是一回事，只是它把它标准化了。
- **七项基础要求 ≈ 安全控制项清单**。识别鉴别、访问控制、完整性、保密性、数据流限制、事件响应、可用性 —— 这套清单和 ISO 27001 的控制域、NIST 的控制族高度重合，只是措辞面向工控。
- **受限数据流 ≈ 出向流量白名单**。工控网络里这条特别重要：正常情况下一台 RTU 不该主动往外连，所以"数据只能沿规定路径走"是极强的检测规则（见[[入侵检测系统(IDS)]]）。

相同点：分段、最小权限、纵深防御、身份认证、事件响应 —— 与 IT 安全完全同构。
不同点：**可用性优先于保密性**。IT 里数据泄露是头等大事，工控里"系统不能停"往往压倒一切。这导致很多 IT 的最佳实践在工控里不能直接用（比如"频繁强制改密码"会逼运维把密码写在便签上；"打补丁优先"在不能停机的系统上行不通）。**"安全措施不能破坏可用性"是工控安全的铁律**，也是 62443 反复强调的地方。

电网场景的特殊之处：
1. **区域划分要跟着物理拓扑走**。IT 分区看业务，电网分区要看电气边界和通信路径（变电站内部、站间、站到调度中心），跨区通信的代价和风险都更高。
2. **合规驱动强**。电力行业的安全要求通常是"必须做"，不是"建议做"，所以 62443 在这里更像是设计输入而不是参考文献。
3. **生命周期极长**。设备二十年不换是常态，标准里对"补丁管理、退役、遗留系统"的要求因此格外实际。

切入建议：如果你要做偏工程/落地的工作，用 IEC 62443 的 Zone/Conduit 框架去分析一个真实的变电站或新能源场站通信架构，指出分区不合理之处并给出改进方案 —— 这是很容易做出成果、也很容易被电网侧认可的题目。
