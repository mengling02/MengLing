# Modbus协议安全

## 一句话

1979 年为 PLC 通信设计的协议，今天还在大量电网设备上跑 —— **它设计时根本没有考虑安全：没有认证、没有加密、没有权限，谁连上谁就能读写。**

## 为什么重要

Modbus 是工控协议里的"活化石"：诞生于 1979 年，原本跑在串口上，后来被搬到了以太网上（Modbus TCP）。它简单、轻量、好实现，所以成了事实标准 —— 大量 PLC、RTU、智能电表、逆变器、充电桩都在用它。

**它的安全问题不是"实现有 bug"，而是"设计里没有安全这个概念"。** 这一点非常重要：

- 没有身份认证 —— 任何能连上端口的客户端都是合法主站。
- 没有访问控制 —— 一个读请求和一个写请求在协议里没有权限差别。
- 没有加密和完整性保护 —— 明文传输，中间人可以随意改。
- 没有会话概念 —— 无法区分"同一个主站"和"另一个攻击者"。

所以在工控安全里，Modbus 常被当作"**协议层攻击的教科书样本**"：它让你能清楚地看到"一个没有安全设计的协议长什么样"，以及"工业场景为什么容忍它"（历史包袱、设备寿命长、实时性优先、改造代价高）。

它也是[[入侵检测系统(IDS)]]在工控场景最经典的应用对象 —— 因为协议本身没法保护自己，只能靠旁路检测来兜。

## 核心要点

| 维度 | 要点 | 说明 |
|---|---|---|
| 变体 | Modbus RTU | 串口（RS-485/RS-232）传输，二进制帧，带 CRC |
| | Modbus ASCII | 串口传输，可读字符形式，效率低 |
| | Modbus TCP | 以太网传输，通常用 502 端口，无 CRC（靠 TCP 保证传输正确） |
| 通信模型 | 主从（Master/Slave） | 主站轮询，从站应答；从站之间不通信 |
| | 单播/广播 | 广播写请求没有应答，攻击者最爱用（无回执可查） |
| 帧结构（Modbus TCP） | 事务标识符 | 用于匹配请求与应答 |
| | 协议标识符 | 标识这是 Modbus 协议 |
| | 长度字段 | 后续字节数 |
| | 单元标识符 | 目标从站地址 |
| | 功能码 + 数据 | 要执行的操作及其参数 |
| 功能码（典型） | 读类 | 读线圈、读离散输入、读保持寄存器、读输入寄存器 |
| | 写类 | 写单个线圈/寄存器、写多个线圈/寄存器 |
| 安全缺陷 | 无认证、无加密、无授权粒度 | 协议层面的结构性缺失，不是实现缺陷 |
| | 功能码滥用 | 用写功能码直接改设定值、改输出 |
| | 重放与篡改 | 明文无完整性保护，改一个字节就改了一个物理量 |
| 防护思路 | 网络隔离与分段 | 见[[IEC 62443]]的 Zone/Conduit |
| | 深度包检测/协议白名单 | 只允许合法功能码与合法地址范围 |
| | 行为基线检测 | 检测异常轮询频率、异常写操作、非法主站 |
| | 协议加固 | Modbus/TCP Security 等带 TLS 的扩展、串口认证网关 |

## 关键公式

这个概念以定性描述为主，没有单一的核心公式。它的技术要点可以用一条**检测规则**来概括 —— 工控 IDS 里最有效的一类规则就是"功能码 + 地址范围"白名单：

$$\text{Alert}\iff \Big(\text{func}\notin \mathcal{F}_{allow}\Big)\ \vee\ \Big(\text{addr}\notin \mathcal{A}_{allow}\Big)\ \vee\ \Big(\text{src}\notin \mathcal{S}_{allow}\Big)$$

- $\text{func}$：报文的功能码（读还是写、写哪个对象）
- $\mathcal{F}_{allow}$：该链路在正常工况下允许出现的功能码集合
- $\text{addr}$：访问的寄存器/线圈地址
- $\mathcal{A}_{allow}$：该主站在正常工况下允许访问的地址范围
- $\text{src}$：请求来源（IP、端口、串口设备标识）
- $\mathcal{S}_{allow}$：被授权的合法主站集合

**白话**：Modbus 协议本身给不出任何安全保证，所以安全只能靠"**外围约定 + 监控**"：正常情况下，谁在什么时候、用什么功能码、访问哪段地址，都是高度固定的。任何偏离这条基线的地方都值得报警 —— 这就是为什么 Modbus 场景下基于规则的 IDS 依然非常有效。

## 用网安的话说（小电解读）

Modbus 对你来说应该是最没有门槛的一个概念：**它就是一个没有任何安全设计的自定义应用层协议**，类比成"裸的 TCP + 私有二进制格式"最贴切。

- **没有认证 ≈ Telnet/FTP 匿名登录**。你不需要"攻破"任何东西，连上就能操作。渗透测试里的第一件事"扫端口、看服务"，在 Modbus 场景就是扫 502 端口 —— 而且**几乎不会有任何登录界面拦你**。
- **功能码 ≈ RPC 方法名 / HTTP 的动词**。读类功能码相当于 GET，写类相当于 PUT/POST。区别是：Modbus 里**没有任何东西区分"这个客户端有没有资格 PUT"**。所以一个 Modbus 写请求，等于一个不需要 token 的 POST。
- **主从轮询 ≈ 定时轮询的客户端**。这个特性带来一个非常实用的检测思路：**轮询是有节律的**。攻击者的工具很难完美复刻主站的时序特征（间隔、功能码顺序、地址扫描顺序），所以"节律异常"是很强的检测信号。这和用"请求时序指纹"做恶意客户端识别是一回事。
- **明文无完整性 ≈ 无签名报文**。改一个字节就把"目标功率 50"变成"目标功率 5000"，没有 HMAC 能发现。

相同点：协议层攻击的思路（伪造、重放、篡改、扫描、DoS）与 IT 完全一致，工具链也可以直接复用（Wireshark 有完整的 Modbus 解析器）。
不同点，也是最关键的：

1. **后果是物理的**。在 IT 里改一个 POST 参数，最多是数据出错；在这里改一个寄存器，可能是阀门开度、断路器位置、逆变器功率。**"写操作"在工控协议里的危险等级远高于 IT**。
2. **可用性绝对优先**。所以不能随便上加密（会增加延迟、增加计算、可能影响实时性），也不能随便加认证（老设备不支持）。这是"明知不安全还得用"的现实约束。
3. **协议没有"用户"概念**。IT 协议有账号、有角色；Modbus 只有"从站地址"和"功能码"。所以任何基于"用户身份"的检测方案在 Modbus 上根本不适用，只能基于"设备行为"。

电网场景的特殊之处：
1. **Modbus 常出现在"最后一公里"** —— 逆变器、电表、充电桩、辅助设备这类边缘环节。这些设备算力弱、更新难、物理可达，是攻击者最容易下手的入口。
2. **它常和更"高级"的协议共存**。变电站内部可能用[[IEC 61850]]，而场站层和辅助系统还在用 Modbus —— 这种"新旧混合"本身就是攻击者的跳板（从一个弱协议跳进强协议域）。
3. **论文 099 那类工作很有价值**：用真实 Modbus/TCP 数据集做异常检测算法的横向评测。因为 Modbus 流量简单、标签清楚，它是**练习工控异常检测的最佳靶场**。

切入建议：这是全库里最适合"快速出成果"的方向。你已经会协议分析和流量分析，缺的只是"电力场景的物理含义"。具体做法：拿一个公开的 Modbus 数据集，把你的 IDS 方法跑一遍，然后重点解释"哪些告警对应物理上的什么异常" —— 这个解释就是电网安全论文和普通 IDS 论文的分水岭。
