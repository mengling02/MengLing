# 对抗样本攻击（Adversarial Attack）

## 一句话

**给输入加一点点人眼/人耳察觉不到的扰动，就能让 AI 模型给出完全错误的输出**。
当电网开始用 AI 做负荷预测、入侵检测、状态估计时，这个威胁就变成了**物理世界的事故**。

## 在电网里的三种形态

### 1. 对抗样本（Evasion，逃逸攻击）

在**推理阶段**扰动输入，让模型判断错误：

- 让[[入侵检测系统(IDS)]]把一个真实的攻击流量判为正常 → **漏报**
- 让[[电力负荷预测]]模型输出错误的峰值 → 调度做出错误决策 → 见 [[20_Research/Papers/L4-AI与电网安全/Exploiting_Vulnerabilities_of_Load_Forecasting_Through_Adversarial_Attacks|032]]

**经典方法**（你熟悉）：
- **FGSM**：$x' = x + \epsilon \cdot \text{sign}(\nabla_x L)$，一步梯度
- **PGD**：多步迭代，更强
- **C&W**：优化最小扰动

### 2. 数据投毒（Poisoning，污染攻击）

在**训练阶段**污染数据，让模型学到错误的模式（如植入后门 backdoor）：
- 在历史量测数据里植入特定模式 → 训练出的 FDIA 检测器对该模式"视而不见"

### 3. 模型窃取 / 成员推断

- 通过查询 API 反推模型结构或训练数据

## 为什么电网场景更危险

| IT 场景 | 电网场景 |
|---|---|
| 误判 → 一个请求被放行 | 误判 → **保护装置拒动/误动，设备烧毁** |
| 扰动是像素 | 扰动是**物理量**（电压、功率），必须满足物理约束 |
| 可随时重训 | 模型部署在**嵌入式装置**里，更新困难 |

**关键约束**：电网的对抗扰动不是随便加的 —— 它必须**通过物理可行性检验**（不能出现负功率、不能违反 KCL/KVL）。这让攻击构造更难，但也更"高级"。

## 关键公式

FGSM（单步梯度攻击）：

$$x' = x + \epsilon \cdot \mathrm{sign}\!\left(\nabla_x J(x, y)\right)$$

- $x$：原始输入；$x'$：构造出的对抗样本
- $y$：真实标签；$J(\cdot)$：模型的损失函数
- $\nabla_x J(x,y)$：损失对输入的梯度，指示"往哪个方向改输入最能抬高损失"
- $\epsilon$：扰动预算，约束为 $\|x' - x\|_\infty \le \epsilon$
- $\mathrm{sign}(\cdot)$：只保留梯度方向，使扰动在无穷范数约束下最"划算"

白话：**沿着让模型最难受的方向走一小步**。因为只走一步，所以快，但也容易被对抗训练等防御削弱。

PGD（多步迭代，攻击强度更高）：

$$x^{t+1} = \Pi_{\mathcal{S}}\!\left(x^{t} + \alpha \cdot \mathrm{sign}\!\left(\nabla_x J(x^{t}, y)\right)\right)$$

- $t$：迭代步数；$\alpha$：每步步长
- $\mathcal{S} = \{x'' : \|x'' - x\|_\infty \le \epsilon\}$：允许的扰动集合，即以原样本为中心、半径为 $\epsilon$ 的无穷范数球
- $\Pi_{\mathcal{S}}(\cdot)$：投影算子，每步之后把结果拉回扰动集合内

白话：**把 FGSM 的一步走成多步、每步都重新算梯度、并且不许越界**——它至今仍是评测对抗鲁棒性最常用的强攻击基线。

需要记住的电网特殊性：这里的 $x'$ 不是像素而是电压、功率等物理量，因此扰动还必须额外满足物理可行性约束（非负、KCL/KVL 一致、潮流可解等），这既提高了攻击构造门槛，也让攻击更"高级"。

## 用网安的话说（小电解读）

- **对抗样本 ≈ 针对 AI 判决逻辑的"绕过技术"**。你在 Web 里绕过 WAF、在 AV 里做免杀，思维完全一样：找决策边界的缝隙。区别是要绕的判决器可能是[[入侵检测系统(IDS)]]或[[电力负荷预测]]模型。
- **投毒 ≈ 供应链投毒/训练集污染**：不是骗过模型，而是训练阶段让它"学歪"，做得好会让检测器对某类攻击永久性视而不见。
- **模型窃取/成员推断 ≈ 黑盒指纹识别**：从响应差异反推内部实现。

### 相同点
FGSM/PGD/C&W 可以直接搬，梯度怎么算、扰动预算 $\epsilon$ 怎么定、对抗训练怎么加，几乎不用改。防御端的输入净化、模型集成、随机化、异常输入检测也是现成武器库。

### 不同点 / 难点
1. **扰动必须物理可行**。像素改一点没人看得出来；量测值改一点可能违反 KCL/KVL、让潮流无解，攻击当场暴露。攻击构造从无约束优化变成带物理约束的优化——反过来，这也是天然的隐蔽性来源，见[[虚假数据注入攻击(FDIA)]]。
2. **误判的后果是设备烧毁或停电**，不是放行一个请求。电网误判会驱动保护装置拒动/误动，所以鲁棒性要求不是准确率数字而是安全约束。
3. **模型跑在嵌入式装置里，更新极难**。"发现漏洞→打补丁"这个你习以为常的闭环，在电网里几乎不存在。

### 电网场景的特殊之处
1. **对抗鲁棒性和物理可检测性会互相打架**：隐蔽的扰动物理上往往更难生效，物理后果强的攻击又容易被状态估计识破。这个权衡缺少系统性研究。
2. **很多电网 AI 既是预测器又是安全组件**，攻击它同时削弱了防御能力，这在 IT 里少见。

### 切入建议
最稳的题是**面向电网 AI 组件的对抗鲁棒性评测与加固框架**，比如"带物理可行性约束的扰动构造 + 面向 FDIA 检测器的鲁棒性评估"。你出攻击算法与评测方法，电网侧只需 IEEE 标准算例加潮流校验，不必碰真实工控环境（见[[工控安全测试床与数据集]]）。
