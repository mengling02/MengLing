# SCADA 系统

## 一句话

SCADA 是**工业控制系统的"大脑 + 神经系统"**：采集现场数据（Supervisory），再下发控制指令（Control）。电网调度中心就是最大的 SCADA。

## 为什么重要

你未来要做的入侵检测、异常检测、FDIA 检测，**绝大多数都发生在 SCADA 的数据流上**。
不理解 SCADA 的架构，就看不懂那些论文里的"RTU""主站""轮询""遥测遥信"在说什么。

## 核心要点（小白版）

SCADA 四大件：

| 组件 | 作用 | 类比 |
|---|---|---|
| **现场设备层** | 传感器、执行器、断路器 | 手脚 |
| **RTU / PLC** | 采集数据、执行指令 | 脊髓反射 |
| **通信网络** | 把数据送回主站 | 神经 |
| **主站 / HMI** | 人机界面、数据库、调度决策 | 大脑 |

电网里最常见的四类数据：

- **遥测（Telemetry, YC/analog）**：连续量，如电压、电流、功率 → 喂给[[状态估计]]
- **遥信（Status, YX/digital）**：开关状态，0/1
- **遥控（Control, YK）**：下发断路器分合指令 ← **最危险的攻击目标**
- **遥调（Adjust, YT）**：调整发电机出力设定值

## 关键公式

这个概念以架构/标准/定性描述为主，没有单一的核心公式。理解它的要点在于：

- **四层结构**：现场设备层（传感器、执行器、断路器）→ 控制层（RTU/PLC）→ 通信层 → 主站/HMI 层，数据自下而上汇聚、指令自上而下下发。
- **数据语义四件套**：遥测（模拟量）、遥信（开关量）为上行；遥控（分合指令）、遥调（设定值）为下行。下行通道是攻击的最终目标，上行通道是检测的数据来源。
- **运行模式**：主站周期轮询（polling）从站，或从站主动变化上送；数据带时标，主站侧做时序对齐后才送入[[状态估计]]。
- **实时性约束**：从量测到控制指令的闭环时延被严格限制，这直接决定了可用安全机制的预算——认证、加密与深度检测都要在这个延迟与算力额度内完成。

## 用网安的话说（小电解读）

- **≈ 一套超长生命周期的工业控制系统**："采集端 + 控制端 + 通信 + 集中控制台"，ICS 靶场里见过的都对应得上。
- **≈ "明文协议 + 无认证"的极端案例**：Modbus/DNP3/IEC 61850 ≈ "裸奔的 TCP"，谁在链路上谁就能读、能改、能发指令。

### 相同点

1. **攻击链完全复用你的经验**：拿下 IT 办公网 → 横向移动到 OT → 拿下 HMI/工程师站 → 发遥控指令，这就是乌克兰事件的路径，每一步都对得上。
2. **协议逆向是同一门手艺**：工控协议字段比 HTTP 还简单，[[Modbus协议安全]] 那类工作本质就是"抓包 + 猜语义 + 造畸形帧"。
3. **检测侧也能复用**：[[入侵检测系统(IDS)]] 在工控里的落点就是主站与 RTU 间流量，你的异常检测方法仍有效。

### 不同点 / 难点

1. **实时性锁死了安全机制**。IT 里挂个 IDS 最多加毫秒级延迟；SCADA 的量测到控制闭环有严格时延预算，**加密和检测必须在毫秒与低算力额度内完成**。
2. **设备打不了补丁、也换不掉**。生命周期 15–25 年，老 RTU/PLC 跑着停产固件，**"升级修复"工程上常不成立**，只能走旁路监测。
3. **协议改不了，只能加外套**。工控改协议等于全网换设备，**不现实**，只能做不侵入协议的旁路或网关。

### 电网场景的特殊之处

1. **上行与下行的价值不对称**。遥测/遥信是检测的数据来源，遥控是攻击目标：**防守方盯上行，攻击方盯下行**。
2. **语义极其稳定，异常容易暴露**。一台 RTU 常年只做那几件事，越界即强信号 —— 这是 [[电力系统异常检测]] 在工控比 IT 更好做的原因。
3. **指令下发即物理动作**。遥控没有"确认"和"撤销"，所以 [[虚假数据注入攻击(FDIA)]] 这类针对量测的攻击格外重要。

**切入建议**：做**"旁路、不改协议、满足时延"的检测** —— 在主站侧对遥测/遥信流做时序建模，证明开销落在时延预算内。两条硬约束（不改协议、不拖慢）天然把问题收窄，适合第一篇论文，数据可走 [[工控安全测试床与数据集]]。但真实抓包很难拿，**数据集本身就可能是贡献**，也容易被质疑，最好提前想好回答。
