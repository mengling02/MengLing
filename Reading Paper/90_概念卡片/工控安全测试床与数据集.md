# 工控安全测试床与数据集

## 一句话

**没有测试床和数据集，电网安全研究寸步难行** —— 你不能拿真电网做实验，所以必须在仿真环境里复现攻击、验证检测。

## 为什么这对你最重要

你研一要找选题、做实验、发论文。**第一件要解决的事就是：数据从哪来、实验在哪跑。**
这个领域有一条铁律：**好的数据集/测试床，本身就是一篇高被引论文。**

## 三类资源

### 1. 电力系统仿真（物理层）

| 工具 | 特点 |
|---|---|
| **MATPOWER / PYPOWER** | MATLAB/Python 潮流与最优潮流，最常用 |
| **pandapower / pandapipes** | Python 生态，易上手 |
| **GridLAB-D** | 配电网仿真 |
| **OpenDSS** | 配电网，工业界常用 |
| **Andes / ANDES** | 动态仿真 + 强化学习环境（`andes_gym`） |
| **PowerGridworld / Gym-ANM** | 专为 RL 设计的电网环境 |

### 2. 通信/攻防联合仿真（信息层 + 物理层）

| 工具 | 特点 |
|---|---|
| **Mininet / NS-3** | 网络仿真 |
| **OMNeT++** | 通信协议仿真 |
| **GridLAB-D + ns-3 联合** | 经典 co-simulation 方案 |
| **EPICTWIN / PowerCyber** | 电力数字孪生 + 攻防测试 |
| **RTDS / OPAL-RT** | 实时数字仿真（贵，但最接近真实） |

### 3. 公开数据集（做 ML 检测的关键）

| 数据集 | 内容 |
|---|---|
| **Mississippi State / ORNL** | 电力系统网络攻击数据集 |
| **Texas A&M (TAMU) 智能电网数据集** | FDIA、继电器攻击等，ML 检测常用 |
| **SWaT / WADI** | 水处理工控系统，入侵检测基准（iTrust） |
| **Modbus/DNP3 抓包数据集** | 工业协议流量 |
| **IEEE 14/30/57/118/300 节点** | 标准测试系统（几乎所有电力论文都用） |

> 注意：**IEEE 14/118 节点系统不是数据集，是标准测试网络拓扑**。几乎所有 [[虚假数据注入攻击(FDIA)]] 论文都在它上面做仿真。

## 关键公式

这个概念以架构/标准/定性描述为主，没有单一的核心公式。理解它的要点在于：

- **物理层仿真**：用潮流与最优潮流求解器（MATPOWER、pandapower、GridLAB-D、OpenDSS）或动态仿真器（ANDES、RTDS/OPAL-RT）复现电网的物理响应，它是"攻击是否造成物理后果"这一判据的唯一来源。
- **信息层仿真与联合仿真**：用网络仿真器（Mininet、NS-3、OMNeT++）复现通信与协议行为；只有把信息层与物理层对接起来（co-simulation，如 GridLAB-D + ns-3），才能刻画"跨域传播"。
- **攻防注入与数据采集**：在测试床上实现量测篡改、协议伪造、重放等攻击并同步采集带标签数据，这是数据集的主要生成方式。
- **评测基准三要素**：统一的网络拓扑（IEEE 14/30/57/118/300 节点）、统一的攻击场景定义、统一的指标口径，三者齐备才谈得上公平比较——当前的最大痛点正是"缺乏统一基准"。

完整实验链条可以概括为：仿真环境 → 攻击注入 → 数据采集 → 检测算法训练与评测 → 回到仿真中验证物理后果。

## 用网安的话说（小电解读）

- **物理层仿真 ≈ 一个"有状态的目标靶机"**。你在 CTF 里打的是 Web 服务，这里打的是电网模型：你注入的每条恶意量测，MATPOWER/pandapower 会算出它在物理世界里究竟引发了什么。
- **信息层仿真 ≈ Mininet/NS-3 那套你熟的东西**，协议、抓包、重放、中间人基本可以复用。
- **联合仿真（co-simulation）≈ 把靶机和真实业务后端接起来**：只有两层对接，才能看到"一个伪造报文导致某条线路过载"的跨域链条。

### 相同点
数据采集、标签生成、特征工程、类别不平衡处理、检测模型训练与评估——这条流水线和你在 IT 流量检测上做的几乎一样，检测方法可以直接上手。

### 不同点 / 难点
1. **真实攻击样本极度稀缺，且不能"造"**。IT 里有扫描器流量、有百万级标注；电网里攻击样本远不到 1%，因为你没法为了造数据去攻击真电网。这直接决定了很多 SOTA 检测方法在电网数据上训不起来。
2. **误报代价不对称**。电网里一次误报可能触发不必要的运维动作，所以必须讨论误报率的工程含义，不能只报 AUC/F1。
3. **仿真与真实的差距是根本性的**。仿真里的"攻击"是脚本注入的，真实攻击者的分布与隐蔽手段都不同，跨环境迁移性差。

### 电网场景的特殊之处
1. **IEEE 14/118 节点系统是标准网络拓扑，不是数据集**。它提供的是物理场景，攻击数据要你自己在[[潮流计算]]之上生成。几乎所有[[虚假数据注入攻击(FDIA)]]论文都在它上面仿真，这既统一了口径，也让"只在 IEEE 118 上验证"成为常见批评点。
2. **缺少统一评测基准是最大痛点**：各家拓扑、攻击强度、指标口径都不同，检测率无法公平比较。

### 切入建议
这是你**最低风险、最高确定性**的起步方向。可行题目：一是"跨数据集泛化性评测"，把在一个数据集上训好的检测器拿到另一个上测，量化性能损失；二是"带物理一致性校验的攻击数据生成"，把物理可行性做成数据集标签。两者都对得上工业 AI 与安全实验室的定位：你出评测方法论，电网物理交给仿真器。
