# IEC 61850

## 一句话

**变电站内部的"通信宪法"**。它规定了智能变电站里保护装置、测控装置、交换机之间怎么说话 —— 而且是**明文广播、无认证、无加密**地说话。

## 为什么它重要

- 智能变电站是电网的**关键节点**，IEC 61850 就是它的神经。
- 它把"物理设备"抽象成**面向对象的逻辑节点**（如 `XCBR` 断路器、`PTOC` 过流保护），使不同厂商设备可以互操作。
- 安全研究者爱它，是因为它的几个报文类型**天生高危**。

## 三种关键报文（记住这三行就够）

| 报文 | 全称 | 用途 | 危险点 |
|---|---|---|---|
| **MMS** | Manufacturing Message Specification | 客户端/服务器读写数据、报告 | 用于配置和监视，可被篡改 |
| **GOOSE** | Generic Object Oriented Substation Event | **跳闸、联锁等快速事件**（要求 < 4 ms） | **伪造 GOOSE 报文可直接让断路器误跳闸** |
| **SV** | Sampled Values | 电子式互感器采样值（每周期 80/256 点） | 伪造采样值 → 保护装置"看到"错误的电流电压 |

**为什么快就是危险**：为了满足毫秒级实时性，GOOSE/SV 跑在以太网二层，直接广播，**没有握手、没有认证、没有加密**。任何人插进这个网段，都能发一条"跳闸"指令。

## 关键公式

这个概念以架构/标准/定性描述为主，没有单一的核心公式。理解它的要点在于：

- **三层结构**：站控层（MMS 客户端/服务器，负责配置与监视）→ 间隔层（保护、测控装置，逻辑节点所在处）→ 过程层（电子式互感器 SV 采样、智能终端 GOOSE 跳闸）。
- **信息模型**：把物理设备抽象为面向对象的逻辑节点（如 `XCBR` 断路器、`PTOC` 过流保护），数据按"逻辑设备 / 逻辑节点 / 数据对象 / 数据属性"分层组织，并配合 SCL 配置描述语言实现不同厂商设备的互操作。
- **报文映射决定安全属性**：MMS 走 TCP/IP，可承载配置与慢速监视；GOOSE 与 SV 直接映射到以太网二层，组播广播、周期性重发，用"放弃握手"换取毫秒级确定性时延。
- **结构性缺口与加固路径**：实时性优先的设计使报文层没有认证与加密，加固需依赖 IEC 62351 系列在报文层补认证；但受老设备算力与改造成本限制，实际部署率低，于是"在 IEC 61850 网络上做轻量级异常检测"成为现实的替代路线。

## 用网安的话说（小电解读）

- IEC 61850 ≈ **一个没有鉴权的工业级 Modbus**：报文在二层裸奔，谁接进网段谁就能说话（对比[[Modbus协议安全]]）。
- GOOSE/SV ≈ **明文组播上的关键控制指令**。相当于内网里有一条不加密不认证的组播通道，谁都发一条就能让设备动作 —— 它买的是**确定性时延**，代价是丢掉全部安全属性。
- IEC 62351 ≈ **给这套协议补认证的安全扩展包**，但受老设备算力限制，部署率低。

### 相同点

1. **攻击面模型一致**：能接入网络即获得伪造/篡改/重放能力。可用性攻击最要命 —— 伪造一条 GOOSE 跳闸报文即可停电，逻辑同[[拒绝服务攻击(DoS)]]，只是**触发路径从"打满带宽"变成"发一条合法报文"**。
2. **检测思路可复用**：协议特征规则、时序行为基线，你在[[入侵检测系统(IDS)]]里的积累可直接用。

### 不同点 / 难点

1. **"快"与安全是结构性冲突，不是工程疏忽**。GOOSE 要求毫秒级，握手与加解密会打破时延保证，**"上 TLS 就行"在过程层根本走不通**。这正是研究价值所在。
2. **报文没有"异常语法"可抓**。GOOSE/SV 格式极简单、字段极固定，格式层面几乎没有检测空间，必须转向时序规律与物理一致性。
3. **一次误判就是物理事故**。IT 里误封流量无感，这里误判可能导致保护拒动或误动，**误报率目标比 IT 严格得多**。

### 电网场景的特殊之处

1. **三层结构把攻击面切开了**：站控层 MMS 走 TCP/IP（可篡改配置），间隔层与过程层 GOOSE/SV 走二层（直接控断路器），**攻击不同层后果差一个量级**。
2. **逻辑节点抽象给了语义抓手**：`XCBR`、`PTOC` 这些对象名带语义，可做"本该 PTOC 发的东西为何由别处发来"这类检测。
3. **加固两条路都不完美**：靠 IEC 62351 补认证（受硬件限制），或在网络上做轻量级异常检测（不改协议、代价小）。**后者更适合做研究。**

切入建议：**"在 IEC 61850 网络上做轻量级异常检测"是清晰且有空间的题**，尤其 GOOSE 侧。可做的组合：用 SCL 配置反推正常的逻辑节点交互关系，建"谁可以和谁说话"的关系基线再做时序检测 —— 本质是把[[零信任架构]]的"行为基线 + 持续验证"搬到过程层。注意真实变电站报文极难获取，测试床是硬门槛。
