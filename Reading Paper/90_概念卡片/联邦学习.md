# 联邦学习（Federated Learning）

## 一句话

**数据不动，模型动**：各方在本地训练模型，只上传模型参数（梯度），由中心聚合。既保护数据隐私，又能联合建模。

## 为什么电网需要它

电网数据的三个特点，天然适合联邦学习：

1. **数据高度分散**：各省电力公司、各变电站、各用户电表，数据不可能集中
2. **隐私与合规**：用户用电数据涉及隐私，受《个人信息保护法》约束
3. **数据孤岛**：不同主体（发电、输电、配电、售电）不愿意共享原始数据

→ 想要训练一个跨区域的[[入侵检测系统(IDS)]]或[[虚假数据注入攻击(FDIA)]]检测器，联邦学习几乎是唯一可行路径。

## 基本流程

1. 服务器下发全局模型给 $N$ 个客户端
2. 各客户端用**本地数据**训练，得到梯度 $\nabla_i$
3. 上传梯度（不是数据！）
4. 服务器聚合（最经典的是 **FedAvg**）：

$$w_{t+1} = \sum_{i=1}^{N} \frac{n_i}{n} w_{t+1}^{(i)}$$

5. 重复直到收敛

## 但它自己也不安全（重点！）

| 攻击 | 原理 | 后果 |
|---|---|---|
| **投毒攻击（Poisoning）** | 恶意客户端上传带毒的梯度 | 全局模型被污染 |
| **梯度泄露（Gradient Leakage）** | 从梯度反推出原始训练数据 | 隐私保护失效 |
| **拜占庭攻击** | 部分客户端任意作恶 | 聚合结果偏离 |
| **推理攻击（Inference）** | 判断某条数据是否在训练集中 | 成员推断 |
| **搭便车（Free-rider）** | 不上传真实梯度，白嫖全局模型 | 影响收敛 |

**这构成一个漂亮的选题结构**：用联邦学习保护电网隐私 ⟷ 联邦学习自身被攻击 ⟷ 怎么防。

## 关键公式

联邦学习的全局目标（各客户端只用自己的本地数据）：

$$\min_{\theta}\; F(\theta) = \sum_{k=1}^{K} \frac{n_k}{n}\, F_k(\theta), \qquad F_k(\theta) = \frac{1}{n_k}\sum_{i \in \mathcal{D}_k} \ell(\theta; x_i, y_i)$$

- $K$：参与方（客户端）数量
- $\mathcal{D}_k$：第 $k$ 个客户端的本地数据集，$n_k = |\mathcal{D}_k|$，$n = \sum_{k=1}^{K} n_k$
- $F_k(\theta)$：第 $k$ 个客户端上的本地经验损失
- $\ell(\cdot)$：单样本损失函数；$\theta$：模型参数

白话：**大家想共同训练一个模型，但谁的数据都不许出门**，于是把全局损失拆成"各家本地损失按数据量加权平均"。

FedAvg 的聚合规则（最经典的实现）：

$$\theta_{t+1} = \sum_{k=1}^{K} \frac{n_k}{n}\,\theta_{t+1}^{(k)}$$

- $\theta_{t+1}^{(k)}$：第 $k$ 个客户端在本地多轮训练后得到的参数
- $\frac{n_k}{n}$：聚合权重，按本地样本量加权
- $\theta_{t+1}$：服务器聚合出的新一轮全局模型

白话：**服务器只做"按数据量加权平均"，从不接触原始数据**。也正因为聚合这一步完全依赖上传的参数，投毒、拜占庭与梯度泄露攻击都从这里切入。

## 用网安的话说（小电解读）

- **≈ 分布式训练 + 隐私计算的组合，但有个关键反转**：它**不是为了安全而设计的机制，而是为了合规而设计的工程妥协**——"数据不出本地"首先解决法律与商业问题，安全只是副产品。摆正这点才不会高估它。
- **≈ 一个"只传中间态"的分布式协议**：参数服务器那套骨架你熟，只是它额外强调数据主权。

### 相同点

1. **分布式系统的老问题全部适用**：节点异构、通信瓶颈、掉线、时钟不同步。FL 的通信压缩、异步聚合，思路和分布式训练优化几乎一样。
2. **"不可信输入"的思维可直接复用**：服务器假设参与方不可信，**威胁建模方法完全通用**。
3. **隐私技术共通**：安全聚合 ↔ 安全多方计算，[[差分隐私]] ↔ 加噪去标识化。

### 不同点 / 难点

1. **"不上传原始数据"≠"不泄露信息"**。梯度含大量原始数据信息，反演可还原训练样本，**"传输量小"和"信息量小"是两回事**。注意：这张卡只讲 FL 是什么、为什么在电网成立；具体攻防见本库 [[联邦学习攻击与防御]]。
2. **Non-IID 是电网 FL 的核心障碍**。IT 里各用户图片分布还算接近；电网里不同台区、季节、用户类型的负荷曲线差异极大。**非独立同分布会拖慢收敛，并让"异常检测式防御"失效**——诚实方本来就差异大，恶意更新藏在正常差异里。
3. **参与方算力极度不均**。可能是变电站服务器，也可能是极受限的智能电表，**端侧训练与通信轮次要按"最弱节点"设计**，这排除很多重密码学方案。
4. **通信成本可能影响生产业务**。电网通信网与生产业务共用带宽，**FL 的开销可能挤占生产流量**——这个约束在 IT 云环境里不存在。

### 电网场景的特殊之处

1. **合规动机强于技术动机**。用电数据受《个人信息保护法》约束，各主体又不愿共享原始数据，**FL 是被合规推着走的技术**。于是更看重**可审计、可解释、可合规**，而不是刷精度。
2. **数据孤岛按企业边界切**，跨主体联邦几乎必然跨信任域，FL 必须与安全聚合、认证、审计捆绑。
3. **有些场景数据不敏感但共享成本极高**，如跨区域[[电力负荷预测]]、跨变电站的 [[入侵检测系统(IDS)]] 训练——**FL 的价值不只是隐私，还有"避免数据搬运"**。

**切入建议**：最稳的起点是**面向电网时序数据的 FL 基线与失效分析**——把本库已有的 FDIA 检测、负荷预测任务做成 FL 版本，测量"Non-IID 严重到什么程度 FL 就训不动"。这题出硬结果，不依赖新算法。再往上做**轻量级联邦适配**（针对智能电表算力受限设计低开销训练与压缩），以及**精度–隐私噪声–通信轮次–异构程度**的四变量权衡。这与你的"工业 AI 与安全"很契合，因为电网 FL 的瓶颈恰是**工业数据的分布特殊性**。可参考 [[Federated_Learning_for_Smart_Grid_A_Survey_on_Applications_and_Potential_Vulnerabilities|028 智能电网联邦学习：应用与潜在脆弱性综述]]。
