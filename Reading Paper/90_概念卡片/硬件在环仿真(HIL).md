# 硬件在环仿真(HIL)

## 一句话

把**真实硬件**（保护继电器、PLC、RTU、逆变器控制器）接到**实时仿真器**上，仿真器以真实的时间速度跑电网模型，让硬件以为自己在真实电网里工作。

## 为什么重要

电网安全研究有一个根本矛盾：**你不能拿真实电网做攻击实验**（停机损失巨大、物理风险不可接受），但**纯软件仿真又不够真**（抓不到固件缺陷、协议实现的怪癖、时序抖动、硬件时序行为）。

HIL 就是这个矛盾的解：仿真器负责"电网物理"，真实硬件负责"控制器/通信/协议"，两者闭环互联。这样一来：

- 攻击者面对的是**真实的设备固件和协议栈**，不是模拟器 —— 攻击能不能成功、能不能复现，结论才算数。
- 实验可以**反复重放**，攻击脚本能一键重跑，这跟 IT 靶场一样。
- **物理后果可以被观测**：你能看到保护误动、频率跌落，而不只是日志里的一行报错。

它和[[数字孪生]]是一对：孪生强调"用实时数据同步真实系统"，HIL 强调"用真实硬件闭合仿真回路"。现实中两者高度重叠，一个好用的安全测试床往往**既是数字孪生也是 HIL**。

## 核心要点

| 维度 | 要点 | 说明 |
|---|---|---|
| 三大组成 | 实时仿真器 | 以实时步长求解电网模型（电磁暂态/机电暂态） |
| | 待测硬件（DUT） | 保护继电器、PLC、RTU、IED、逆变器控制器、充电桩控制器 |
| | 接口层 | 模拟量/数字量 I/O、通信协议接口（Modbus、DNP3、IEC 61850 等） |
| "实时"的含义 | 仿真步长 ≤ 真实时间步 | 仿真算完一个步长所花的时间必须小于该步长代表的真实时间，否则闭环失效 |
| | 硬实时 vs 软实时 | 硬实时不允许超时抖动，软实时可容忍少量延迟 |
| 常见变体 | CHIL（控制器在环） | 被测的是控制器 |
| | PHIL（功率在环） | 通过功率放大器接入真实功率级设备，最接近真实但代价最高 |
| | 纯 HIL | 只接信号级硬件，最常用 |
| 在安全研究中的用途 | 攻击复现 | 真实协议栈上的攻击效果验证 |
| | 防御验证 | 检测算法在真实时序下的性能 |
| | 数据集采集 | 采集带标签的真实流量与物理量（见[[工控安全测试床与数据集]]） |
| 主要难点 | 成本 | 实时仿真器与 I/O 板卡价格高 |
| | 建模工作量大 | 电网模型、通信模型都要自己搭 |
| | 保真度验证 | 怎么证明你的测试床"足够像真的" |

## 关键公式

这个概念以定性描述为主，没有单一的核心公式。它唯一必须满足的硬性约束是**实时性约束**：

$$\Delta t_{compute}\ \le\ \Delta t_{sim}$$

- $\Delta t_{sim}$：仿真模型的一个步长所代表的**真实时间**（例如 50 μs、1 ms）
- $\Delta t_{compute}$：仿真器实际求解这一个步长所消耗的**墙钟时间**

**白话**：仿真的每一小步，都必须在"这一步代表的真实时间"内算完。如果算得比真实时间还慢，仿真就会落后于真实世界，闭环里的硬件就会收到"过期"的信号 —— 实验结论立刻失效。这也是为什么 HIL 对模型简化和算力都很敏感。

（附带一提：$\Delta t_{sim}$ 的选取取决于你要观察的现象 —— 看电磁暂态要微秒级，看机电暂态毫秒级就够。）

## 用网安的话说（小电解读）

HIL 在网安里没有直接对应物，但它的**方法论**你非常熟悉：**它就是工控领域的网络靶场 + 真实设备在环**。

- **≈ 网络靶场 + 真实设备**。你在 IT 靶场里用过真实的路由器、防火墙做实验，那就是"设备在环"；HIL 只是把"设备"换成了保护继电器和 PLC，把"网络拓扑仿真"换成了"电网物理仿真"。
- **≈ 硬件渗透测试台**。你做 IoT/固件安全时，会把真实设备摆在桌上、接上调试口、抓串口流量 —— HIL 的思路完全一样，只是多了一层"仿真器在实时喂它物理信号"。
- **≈ 可复现的恶意软件分析环境**。HIL 的杀手级价值是**可重放**：同一段攻击流量可以在同一台真实继电器上跑一百遍，每次结果一致。这在真实电网里是不可能的。

相同点：真实设备、可复现、可观测、可批量跑实验。
不同点（也是最本质的一点）：**HIL 有物理闭环**。IT 靶场里你发一个包，收到响应就结束了；HIL 里你发一个包，硬件动作 → 影响仿真电网 → 电网状态变化 → 又产生新的信号喂回硬件。**攻击效果会被物理过程持续放大或衰减**，这是纯 IT 靶场永远不会有的现象。这意味着"攻击脚本的时序"在 HIL 里变得极其重要 —— 同一攻击早发 100 ms 可能完全失效。

电网场景的特殊之处：
1. **代价门槛高**。实时仿真器和 I/O 板卡都是钱，所以这个方向对实验室硬件条件有要求。
2. **保真度是学术诚信问题**。用过度简化的模型得出的"攻击有效"结论，在真实系统里可能完全不成立。所以论文里必须交代模型来源和简化假设。
3. **安全边界要额外注意**。HIL 台架里接的是真实设备，攻击实验可能真的把硬件打坏（尤其是 PHIL 带功率的），台架本身也需要保护。

切入建议：HIL 是**做实验的能力**，不是研究题目本身。对你来说最实际的用法是：如果你的实验室有实时仿真器，就把"**在 HIL 台架上复现一篇 FDIA/DoS 论文的攻击**"当作第一个练手项目 —— 复现过程中你一定会发现论文没写的细节（时序、噪声、协议实现差异），这些恰恰是新论文的切入点。
