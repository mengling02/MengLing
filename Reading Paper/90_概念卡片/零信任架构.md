# 零信任架构

## 一句话

**永不信任，始终验证**：不再假设"进了内网就是自己人"，每一次访问都要重新确认身份、设备和权限。

## 为什么重要

传统电力工控安全的核心思路是**强边界**：把系统划成安全区、用专用网络、用物理隔离装置挡住跨区流量。中国电力行业的[[电力监控系统安全防护体系]]把这条思路总结得很清楚 —— **安全分区、网络专用、横向隔离、纵向认证**。

这套体系非常有效，但它有一个隐含前提：**边界之内是可信的**。而这恰恰是它最大的软肋：

- **运维笔记本一插，边界就没了**。现场调试、临时接入、移动介质，是工控事故最常见的入口。
- **供应链投毒绕过所有边界**。恶意固件/组件是"从内部合法进入"的（见[[IEC 62443]]提到的物料清单管理、[[数据投毒攻击]]）。
- **内部人员与横向移动**。一旦一个低权限节点被打下（比如一台没有隔离的辅助终端），横向移动在"内网可信"的环境里几乎畅通无阻。
- **新形态打破了物理边界**。分布式能源、充电桩、[[虚拟电厂]]的资源散布在千家万户，根本没有"围墙"可画。

零信任不是要取代分区隔离，而是回答"**边界被穿透之后怎么办**"。它的三个核心原则直接对应上面四个问题：**身份为中心（不看你在哪，看你是谁）、最小权限（每次只给够用的权限）、持续验证（权限不是一次授予终身有效）**。

在本库的语境里，零信任是**防御侧的顶层设计框架**，它把很多分散的技术（认证、加密、微隔离、行为检测）串成一条逻辑链。理解它，你就有了一个"这些防御手段各自解决什么问题"的坐标系。

## 核心要点

| 维度 | 要点 | 说明 |
|---|---|---|
| 核心原则 | 永不信任，始终验证 | 不存在"可信网络"，只有"已验证的访问" |
| | 身份为中心 | 判断依据是身份与设备状态，而不是 IP 段或网络位置 |
| | 最小权限 | 只授予完成当前任务所需的最小权限，最好是一次性、临时的 |
| | 假定已被入侵 | 默认系统内已有攻击者，按此设计检测与遏制 |
| | 微隔离 | 把信任边界切细到工作负载/设备级 |
| 架构组件 | 策略决策点（PDP） | 负责算"这次访问该不该放行" |
| | 策略执行点（PEP） | 负责真正拦住或放行流量 |
| | 策略引擎 / 信任引擎 | 结合身份、设备状态、行为、上下文计算信任分 |
| | 身份与设备目录 | 身份、凭证、设备资产的权威来源 |
| 关键能力 | 持续评估 | 访问过程中持续重估信任，条件变化即撤销 |
| | 动态授权 | 权限随上下文（时间、位置、设备健康度）变化 |
| | 全程加密与完整性 | 假设链路不可信，端到端保护 |
| 在电网里怎么用 | 运维接入场景 | 远程运维、第三方维护、移动终端接入 —— 收益最直接 |
| | 分布式资源接入 | 光伏、储能、充电桩、[[微电网安全]]的成员认证 |
| | 站内东西向流量 | 站内设备之间的访问控制与微隔离 |
| | 与既有体系结合 | 分区隔离保"纵深"，零信任保"边界内也不轻信" |

（注：零信任的具体技术组件与成熟度模型有多个业界框架版本，此处只给通用的逻辑结构。）

## 关键公式

这个概念以定性描述为主，没有单一的核心公式。它的技术要点可以用一条**访问决策**的逻辑式概括：

$$\text{Allow}\iff \underbrace{\text{Identity}}_{\text{你是谁}}\ \wedge\ \underbrace{\text{Device\ Health}}_{\text{你的设备可信吗}}\ \wedge\ \underbrace{\text{Context}}_{\text{时间/位置/行为正常吗}}\ \wedge\ \underbrace{\text{Policy}}_{\text{策略允许这个操作吗}}$$

- **Identity**：经过强认证的主体身份（人 / 服务 / 设备）
- **Device Health**：设备是否合规（补丁、固件版本、是否被篡改、是否在册）
- **Context**：请求发生的上下文 —— 时间、来源、行为是否符合该主体的历史基线
- **Policy**：策略引擎根据最小权限原则给出的授权判断

**白话**：传统访问控制只问"你在不在内网"（一个条件）；零信任要求**四个条件同时成立**才放行，而且这些条件是**每次请求都重新算**的。任何一个条件变化（比如设备突然开始扫描端口、运维人员半夜从异地登录），权限立刻可以收回。

在电网里，这四条的权重和 IT 场景不同：**Device Health 和 Context 的权重更高**，因为工控设备的"行为基线"极其稳定 —— 一台 RTU 二十年如一日地做同一件事，任何行为偏差都是强信号。

## 用网安的话说（小电解读）

零信任就是你熟的那套东西的**系统化表述**，你的知识可以直接复用，但要理解它在工控里的"变形"：

- **≈ 微隔离 + 最小权限 + 持续认证**。你在 IT 里做的 SDP、IAM、条件访问（conditional access）、UEBA，全都是零信任的组件。差别只是零信任把它们组织成了一个统一的架构原则。
- **≈ "假设已被入侵"的威胁模型**。这跟你做渗透测试时的思路一致：不要问"攻击者能不能进来"，而要问"他进来之后能走多远"。零信任的所有设计都是为了**压缩横向移动的空间**。
- **≈ 从"网络边界"到"身份边界"的范式转移**。这一点最关键：传统的"内网/外网"二元划分在云、移动办公、IoT 时代已经失效，零信任的答案是**用身份重新画边界**。

相同点：身份认证、最小权限、加密、日志审计、持续监控 —— 与 IT 完全一致。
不同点，也是工控/电网场景的难点：

1. **可用性压倒一切**。IT 里"每次访问都验证"最多增加几十毫秒；工控里这几十毫秒可能让保护动作超时。**所以电网的零信任必须做分级：关键控制回路不能承受额外的认证开销，只能在非实时层面实施**。这是电网落地零信任最核心的工程约束。
2. **设备能力参差**。老 RTU、老电表根本跑不了现代认证协议，也没有可信执行环境。所以"设备身份"在电网里往往要靠**外部代理或物理特征**（比如电池指纹那类思路）来建立，而不是靠设备自证。
3. **"设备"比"人"更重要**。IT 零信任以人为中心；电网里绝大多数流量是设备对设备（RTU 上报、控制器协商），**没有"用户"这个主体**。所以电网零信任的重心是**设备身份 + 行为基线**，而不是账号体系。

电网场景的特殊之处：
1. **分区隔离与零信任不是二选一**。中国的电力监控系统防护体系（安全分区、网络专用、横向隔离、纵向认证）提供的是**纵深防御的外层**；零信任补的是**内层**。两者叠加才完整。
2. **分布式资源让边界彻底消失**。当电网的组成单元散布在用户侧（见[[虚拟电厂]]、[[电动汽车充电安全]]），你根本无法为它们画一个物理边界，**这时零信任几乎是唯一可行的安全模型**。
3. **行为基线极其稳定，检测信噪比高**。这是电网做零信任的**优势**：IT 环境里用户行为千变万化，很难建模；工控环境里"RTU 只做那几件事"，异常检测的信噪比高得多。

切入建议：这个方向非常适合你，而且**选题空间大**：可以做"零信任在电力工控场景的适配性分析"（指出哪些 IT 假设在电网不成立），也可以做具体的"设备行为基线建模 + 持续验证机制"。关键是别只讲概念，要落到"电网的哪条约束让 IT 零信任方案不能用" —— 这种"冲突点"分析最容易出论文。
