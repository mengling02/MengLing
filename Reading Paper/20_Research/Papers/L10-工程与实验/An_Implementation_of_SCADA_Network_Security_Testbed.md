# 102 | 一个 SCADA 网络安全测试床的实现

> [!abstract] 一句话
> 用**纯软件仿真**搭了一个 Modbus 水箱系统测试床，配套攻击和防御工具包，而且**能"诱捕黑客并采集他们的活动数据"**——这就是工控蜜罐的思路。

## 为什么读它

这是 L10 专题的最后一篇，也是**最轻量的一篇**：**不需要任何真实硬件，纯软件仿真**。

把它和 091 LICSTER 对照着看，能看清一个关键的分野：

| | LICSTER（091） | 本文（102） |
|---|---|---|
| 实现方式 | 低成本真实硬件 + 真实物理过程 | **纯软件仿真（software emulation）** |
| 成本 | 约 500 欧元 | 接近零（只需一台电脑） |
| 物理真实性 | 高（有真实物理过程） | 低（物理过程是模拟的） |
| 上手速度 | 需要采购、搭建 | 立刻能跑 |

**这篇论文最值得注意的点是最后一句**：它**不只是"造一个靶场"，还要"诱捕攻击者并采集他们的活动数据"**。这意味着它同时具备**测试床**和**蜜罐（honeypot）**两种属性。

> **蜜罐是你熟悉的概念**：一个故意暴露的、看起来有漏洞的系统，用来吸引攻击者、记录他们的行为、提取攻击特征。**工控蜜罐（ICS honeypot）是当前的热门方向**——因为真实工控系统的攻击样本太少了，蜜罐是获取真实攻击数据的少数途径之一。

另外，这篇论文有一个产业背景值得注意：**"Motivated by on-going collaborations with Fortinet Corp., a security company"**——研究动机来自与安全公司 Fortinet 的合作。**这说明工控测试床是工业界真实需求，不只是学术玩具。**

## 这篇论文在讲什么（白话版）

### 背景：工业网络的安全问题，需要用软件来复现

论文的第一句话定调：**"The security of industrial network has become an increasing concern in industry infrastructure operation."**——工业网络的安全已经成为工业基础设施运营中越来越受关注的问题。

论文还交代了它的来源：这个项目**受到与安全公司 Fortinet Corp. 持续合作的推动（Motivated by on-going collaborations with Fortinet Corp., a security company）**。

**它的实现路线很明确：用软件仿真（by software emulation）来搭一个 SCADA 网络安全研究测试床。**

**"软件仿真"意味着什么**：整个测试床（包括控制器、被控过程、通信）都跑在软件里，**不需要任何真实的 PLC 或传感器**。好处是**零硬件成本、立刻可用、可以随意克隆**；代价是**物理过程是假的**——攻击一个仿真的水箱，水位不会真的变化。

### 内容一：SCADA 与 Modbus 协议回顾

论文首先做了基础回顾：

- **SCADA 的概念**（报告里做了 review）；
- **Modbus 协议的概念**。

**这是这篇论文对你最"友好"的地方**：它是一份**技术报告（report）**，**面向的读者可能是不熟悉工控的人**，所以把基础概念讲了一遍。**对电网知识为零的你来说，这类"带基础回顾"的论文是最容易读的入口。**

### 内容二：不止 Modbus——其他工业协议的漏洞研究

论文明确说：**"Besides Modbus, vulnerabilities about several other industrial protocols are also studied for this project."**

即：**除了 Modbus，本项目还研究了几种其他工业协议的漏洞。**

**摘要中没有说明具体是哪些协议**（不要臆造）。从工控领域的常见范围推断，可能包括 DNP3、IEC 61850、PROFINET、EtherNet/IP 等，**但这是推测，摘要中没有依据。**

**这一点本身很有价值**：它说明**工业协议的漏洞研究是一个系统性的工作**——不是"Modbus 有问题"，而是"这类为可靠性和实时性设计、当年没考虑安全的协议，普遍有问题"。

### 内容三：Modbus 水箱系统测试床

论文的核心产出是：

> **"In this report, a typical tank system following Modbus protocol is built as a testbed."**

**一个遵循 Modbus 协议的典型水箱系统（tank system）**，被搭建为测试床。

> **为什么工控安全测试床总爱用"水箱"**：因为水箱是**最经典的工业控制教学案例**——它有明确的物理量（液位）、有控制目标（保持液位在某个范围）、有执行机构（进水阀、出水阀、水泵）、有反馈（液位传感器）。**结构简单但完整，足以演示所有核心概念。** 这也是 092 那篇论文同样选水箱的原因。

**摘要中没有给出的关键信息**（不要臆造）：
- 用了什么仿真软件或框架（摘要未给出）
- 水箱的具体参数（容积、控制逻辑，摘要未给出）
- 测试床的网络拓扑（摘要未给出）
- 是否开源（摘要未提及）

### 内容四：攻击与防御工具包

论文引入了**攻击工具包和防御工具包（Both attack and defense toolkits）**，用来**模拟 Modbus 网络的攻击与防护（emulate the attack and protection of the Modbus network）**。

**这个设计很实用**：它不只是"环境"，还配了"工具"。
- **攻击工具包**：让研究者能快速复现已知攻击（比如伪造 Modbus 写命令、重放、DoS）；
- **防御工具包**：让研究者能快速验证防护措施（比如规则过滤、异常检测）。

**用你熟悉的话说**：这相当于靶场里**同时提供 Metasploit 的模块和 Snort 的规则集**——**能打也能防，才能做对照实验。**

### 内容五：诱捕攻击者并采集活动数据（蜜罐能力）

这是论文最有意思的一条：

> **"The emulation platform is also capable of entrapping hackers and gathering their activity data."**

即：**这个仿真平台还能诱捕黑客（entrap hackers）并采集他们的活动数据（gathering their activity data）。**

**这就是工控蜜罐（ICS Honeypot）的定义**。

**为什么这条很重要**：

1. **真实攻击数据极度稀缺**——这是整个工控安全领域的核心瓶颈（你在 099 那篇里已经看到"因为数据是合成的所以能做监督学习"这句话背后的无奈）；
2. **蜜罐是获取真实攻击数据的少数途径之一**——因为攻击者会真的来打；
3. **蜜罐的难点在于"像不像真的"**——如果太假，攻击者一眼识破（工控协议有指纹特征，很容易识别出仿真环境），就不会留下有价值的行为数据。**这个"高交互蜜罐保真度"问题是当前的研究热点。**

**摘要中没有说明**：蜜罐是如何暴露给攻击者的（是部署在公网还是仅内部）、如何采集数据、采集了哪些数据。这些都需要读原文。

### 结论

论文证明了：**用纯软件仿真可以搭建一个具备"环境 + 攻击工具 + 防御工具 + 攻击者诱捕"完整能力的 SCADA 安全测试床。**

## 用网安的话说（小电解读）

**这篇论文 ≈ "用软件搭的工控靶场 + 工控蜜罐"**。它对你来说几乎是零门槛，因为它的技术栈就是纯软件。

**几个直接对接点**：

1. **"攻击工具包 + 防御工具包"这个组合，是靶场设计的正确姿势。**
   只有攻击工具 → 你只能做渗透演练；只有防御工具 → 你没东西可防。**两者配套，才能做"红蓝对抗"和"检测算法评测"**。
   **对你有直接价值**：如果你要搭靶场做 IDS 研究，**必须同时准备好"攻击流量生成器"和"防御/检测模块"**，才能做完整的对照实验。

2. **"诱捕攻击者并采集活动数据"= 工控蜜罐，这是数据来源的破局点。**
   回忆你在 099 那篇看到的问题：**真实攻击样本稀缺**。三条解法：
   - **合成数据**（099 的做法）→ 快，但不真实；
   - **测试床注入攻击**（092、094 的做法）→ 可控，但攻击模式是预设的；
   - **蜜罐诱捕**（102 的做法）→ **最真实，但不可控、样本量小、有法律和伦理边界**。
   **这三条路都有空间，而蜜罐是唯一能拿到"真实攻击者行为"的途径。**

3. **蜜罐的核心矛盾是"保真度 vs 可观测性"。**
   - 做得越像真的 → 攻击者越愿意深入 → 数据越有价值；
   - 但越像真的 → 被攻陷的风险越高 → 可能成为跳板。
   **"高交互工控蜜罐的安全隔离设计"**是一个很好的工程选题。

4. **工业协议的漏洞是"系统性"的，不是偶然的。**
   Modbus、DNP3 这些协议诞生于**"网络是可信的"这个假设之上**——它们追求实时性和可靠性，**根本没设计认证机制**。这不是"某个实现有 bug"，而是**设计层面的安全缺失**。
   **这个认知对你很重要**：意味着**基于协议语义的检测（097 的路线）会有长期价值**，因为协议本身的缺陷不会因为打补丁而消失。

**可迁移的选题**：

1. **工控蜜罐的保真度评估与改进**——怎么判断一个蜜罐"够不够真"？（对接 096 的靶场保真度问题）
2. **蜜罐数据的攻击行为建模**——从诱捕数据中提取攻击者的行为模式（攻击链、工具指纹、时序特征）；
3. **软件仿真测试床的物理真实性评估**——纯软件仿真缺了真实物理过程，这对检测算法评测有什么影响？（和 091 的硬件测试床做对照）
4. **工业协议漏洞的系统性分析**——横向对比 Modbus、DNP3、IEC 61850 的安全设计缺失，形成分类学（taxonomy）。

## 局限性

- **纯软件仿真，缺少真实物理过程**：这是它最大的局限。攻击一个仿真的水箱，**无法反映真实的物理后果**（比如阀门真的卡死、水泵真的过载）。**对比 091 LICSTER 的"real-world physical process"卖点，这是明确的短板。**
- **摘要信息极度稀疏**：没有说明用了什么仿真框架、支持哪些协议、攻击工具包包含什么、是否开源。**仅凭摘要完全无法复现。**
- **单作者技术报告，非同行评审论文**：**质量保证弱于正式发表论文**，结论的可靠性需要打折。
- **没有实验数据**：摘要未给出任何攻击成功率、检测率、蜜罐捕获数据量。**"capable of entrapping hackers" 是能力声明，不是实验结果。**
- **蜜罐的伦理与法律问题未讨论**：诱捕攻击者涉及**法律边界**（在某些司法辖区，"entrapment"有严格定义）、**责任风险**（蜜罐被攻陷后成为攻击跳板）。论文摘要完全未涉及。
- **2017 年的工作**，工控蜜罐领域此后发展迅速（如 Conpot、SNAP7 蜜罐等成熟方案），**这篇的技术方案可能已被超越**。

## 原文摘要

> The security of industrial network has become an increasing concern in industry infrastructure operation. Motivated by on-going collaborations with Fortinet Corp., a security company, this project implements a testbed for supervisory control and data acquisition (SCADA) network security research by software emulation. Concepts about SCADA and Modbus protocol are reviewed in the report. Besides Modbus, vulnerabilities about several other industrial protocols are also studied for this project. In this report, a typical tank system following Modbus protocol is built as a testbed. Both attack and defense toolkits are introduced to emulate the attack and protection of the Modbus network. The emulation platform is also capable of entrapping hackers and gathering their activity data.
