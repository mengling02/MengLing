# 076 | 面向住宅短期负荷预测的隐私保护联邦学习

> [!abstract] 一句话
> 用大规模真实住宅负荷数据做仿真，验证了"联邦学习 + 差分隐私 + 安全聚合"这套组合拳可以同时拿到高预测精度和接近完全的隐私——而且连模型本身都保护住了。

## 为什么读它

- **这是本专题里"三件套最完整"的一篇**：联邦学习（不传数据）+ 差分隐私（传的东西加噪）+ 安全聚合（加噪的过程也不被看）。**三种技术各管一段，论文把它们的组合效果测了出来。**
- **它是本专题里最"工程"的一篇**：用的是**大规模住宅负荷数据**（不是玩具数据集），而且是**仿真实验**——意味着你可以复现、可以改参数、可以做对比。**这是最适合作为你第一个动手项目的论文。**
- **它提出并验证了一个很实用的结论**：隐私保护和预测精度**不一定是对立的**，用对了组合可以"两个都要"。这与你可能有的"加 DP 就要掉精度"的直觉形成对照——**它给出了那个权衡的边界在哪。**
- **它和 065 直接对话**：065 说"共享梯度会泄露数据"，076 说"加上 DP 和安全聚合就不泄了"——**攻防两面凑齐了。**
- **它和 067 形成对比**：067 讲"DP 在电力场景会被合谋击穿"，076 用"安全聚合"从另一个角度加固。**两篇一起读，你能看到 DP 在电力场景的两种失败模式和两种补强思路。**
- 建议读法：重点看它**怎么设计对比实验**（不同 FL 模型 × 不同隐私技术），这个实验矩阵的设计方法你可以直接照搬。

## 这篇论文在讲什么（白话版）

### 背景：为什么住宅负荷预测重要，又为什么难

论文的出发点是一个**新能源时代的结构性变化**：

> **随着间歇性发电（intermittent power generation）比例升高、用电需求模式越来越动态化（dynamic demand patterns），对住宅负荷（residential loads）的准确预测变得至关重要。**

**先解释这两个背景概念：**

- **间歇性发电**：风电、光伏这类新能源的出力**看天吃饭**——风大就多、云遮就少，不像火电水电那样想发多少就发多少。**发电侧变得不可控了，那么"需求侧"就必须更可预测**，否则供需无法平衡。
- **动态需求模式**：随着电动汽车、热泵、分布式储能的普及，居民用电不再是"白天少、晚上多"的简单规律，而是变得更加波动、更难预测。

**智能电表（smart meters）在这里扮演关键角色**：它们提供**细粒度的负荷数据**，是做预测的理想素材。

**但问题来了：这些数据涉及隐私。** 论文明确说：**由于数据隐私要求，用智能电表数据做负荷预测是困难的（challenging due to data privacy requirements）。**

**为什么难？** 因为前面 067 已经讲清楚了：**细粒度的用电数据可以直接推断用户的生活习惯**——家里有没有人、几点睡觉、用不用大功率电器、是不是长期空置。所以数据不能随便集中。

### 方法：三种技术的组合

论文研究的核心问题是：

> **如何通过"联邦学习 + 隐私保护技术"的组合，来同时满足"预测要准"和"隐私要保"这两个要求？**

论文具体考察的组合是：

| 技术 | 作用 | 保护的是什么 |
|---|---|---|
| **联邦学习（Federated Learning, FL）** | 各方不共享原始数据，只共享模型更新 | **原始负荷数据**不出本地 |
| **差分隐私（Differential Privacy, DP）** | 在上传的信息里加入校准过的噪声 | **上传的更新**不能被反推出原始数据 |
| **安全聚合（Secure Aggregation）** | 让聚合服务器只能看到"总和"，看不到任何单个客户端的更新 | **聚合过程中的个体更新** |

**三者是层层递进的，你可以这样理解**：

```
第 1 层（FL）：数据不出本地           → 但上传的梯度可能泄露数据（065 说的就是这个）
第 2 层（DP）：上传的东西加噪声       → 但服务器还是能看到每个客户端的加噪更新
第 3 层（安全聚合）：服务器连单个更新都看不到，只能看到总和
```

> **这是一个"纵深防御"（Defense in Depth）的经典设计**——不指望任何单一机制提供完全保护，而是用多层机制叠加，让攻击者必须同时突破所有层。

### 实验设计：一个完整的对比矩阵

论文的实验方法是：

> **采用大规模住宅负荷数据集（a large set of residential load data），仿真不同的联邦学习模型和不同的隐私保护技术，如何影响"性能"和"隐私"。**

**这个实验矩阵的设计思路值得你学习**：

- **自变量 1**：不同的联邦学习模型（具体是哪些，摘要未说明）；
- **自变量 2**：不同的隐私保护技术（DP 的配置、是否用安全聚合等）；
- **因变量 1**：预测性能（精度）；
- **因变量 2**：隐私程度。

**通过扫描这个矩阵，论文就能画出一条"隐私—精度"的权衡曲线**——而不是只报一个孤立的实验结果。**这是评估隐私保护方法的正确姿势，你在做类似实验时应该照搬。**

### 结论：两个"都要"是可以实现的

论文的核心结论（摘要原文的表述）：

> **把联邦学习和隐私保护技术结合起来，可以同时获得高预测精度和接近完全的隐私（secure both high forecasting accuracy and near-complete privacy）。**

具体地说：

> **这种组合使得在保证"处理后的负荷数据"和"预测模型"两者隐私的前提下，仍然可以实现高水平的信息共享。**

**注意这里有两个保护对象，很容易被忽略：**

1. **负荷数据（load data）的隐私**——用户不想让人知道自己的用电行为；
2. **预测模型（forecasting models）的隐私**——模型本身也是资产，可能泄露训练数据的分布，或者被竞争对手窃取。

**第 2 点特别值得注意**：通常我们讨论隐私保护时只想到"数据"，而这篇论文明确把**模型**也列为需要保护的对象。这是一个更完整的威胁视角。

### 挑战

论文最后**识别并讨论了**把 FL、DP 和安全聚合用于住宅短期负荷预测时的**挑战**（challenges）。

> **摘要未说明这些挑战具体是什么**，只说"identify and discuss"。要了解具体内容需要查原文。不过结合本专题其他论文，可以推测至少包括：DP 带来的精度损失、安全聚合的通信与计算开销、参与方数量变化时的隐私预算分配、以及非独立同分布（non-IID）数据下的收敛问题。**这些是推测，不是摘要原文，请注意区分。**

## 关键公式（小白版）

论文摘要没有给出公式。理解这篇论文，需要掌握**差分隐私的拉普拉斯机制**和**安全聚合的核心约束**（以下都是领域通用形式，不是摘要原文）：

**（1）差分隐私（与 067 相同的形式）**

$$\mathcal{M}(D) \;=\; f(D) \;+\; \mathrm{Lap}\!\left(\frac{\Delta f}{\varepsilon}\right)$$

符号解释：

- $D$ —— 本地数据（这里的居民用电数据）。
- $f(D)$ —— 要发布的统计量（这里是模型更新）。
- $\mathrm{Lap}(b)$ —— 拉普拉斯噪声，尺度为 $b$。
- $\Delta f$ —— **敏感度**：改变一个用户的数据，最多让 $f(D)$ 变化多少。
- $\varepsilon$ —— **隐私预算**。

**一句话白话**：**隐私预算 ε 越小 → 噪声越大 → 越私密，但模型越差。** 论文做的实验本质上就是在扫这条曲线，找"精度还够用"的那个 ε 位置。

**（2）安全聚合（Secure Aggregation）的核心约束**

$$\text{Server sees: }\ \sum_{i=1}^{n} u_i \qquad \text{Server does NOT see: }\ u_i \ \text{for any } i$$

符号解释：

- $u_i$ —— 第 $i$ 个客户端上传的更新（加了 DP 噪声之后）。
- $\sum_{i=1}^{n} u_i$ —— 所有更新的总和（服务器**只能**看到这个）。
- $u_i$ —— 任何单个客户端的更新（服务器**看不到**）。

**这个约束在说什么**：

> **服务器只能看到"总和"，看不到"每一项"。**

**为什么这很重要？** 因为联邦学习的聚合只需要总和（FedAvg 就是加权平均）。**既然只需要总和，那么"看不到每一项"完全不损失功能**——这就是安全聚合的精妙之处：**用密码学/掩码技术把"个体信息"隐藏起来，但保留"聚合结果"。**

**（3）为什么 DP 和安全聚合要一起用？**

两者防的攻击**完全不同**：

| | 差分隐私 | 安全聚合 |
|---|---|---|
| 防的是谁 | **任何拿到聚合结果的人**（包括最终发布的模型） | **聚合服务器本身** |
| 防的是"从结果反推个体" | 是（噪声破坏可反推性） | 否（服务器看到的是精确总和，只是看不到个体项） |
| 防的是"服务器偷看个体" | 否 | 是 |

> **一句话**：**DP 防"结果反推"，安全聚合防"服务器偷看"。两个一起用，才形成完整的防护。** 这也是论文强调"组合"的原因。

## 用网安的话说（小电解读）

**这篇论文是"纵深防御"思想在隐私保护上的标准实现，你应该把它当作一个工程模板。**

**对照表**：

| 你熟悉的 | 这篇论文里的 |
|---|---|
| 传输加密（TLS） | 安全聚合（服务器看不到个体更新） |
| 数据脱敏 / 加噪 | 差分隐私（ε 控制脱敏强度） |
| 纵深防御（Defense in Depth） | FL + DP + 安全聚合 三层叠加 |
| 成员推理攻击（MIA） | DP 要防的核心攻击之一 |
| 数据最小化原则 | FL 让数据不出本地 |

**三个关键洞察：**

**第一，"安全聚合"这个机制你其实很熟——它是"加密求和"。**

安全聚合的实现方式通常有两种：**基于掩码的（客户端两两协商随机掩码，掩码在求和时相消）** 和 **基于同态加密的（见 066 的 Paillier）**。前者更快，后者更通用。

> **这正好和 066 形成对照**：066 用 Paillier 加密做聚合（精确、无损、但慢），076 用的是"DP + 安全聚合"的组合（有噪声、但更便宜）。**两条技术路线，一个要精度、一个要效率，你要根据场景选。**

**第二，"隐私"有两个层面，这篇论文都覆盖了——这是它比一般论文完整的地方。**

- **数据隐私**：不能从模型反推出用户用电行为（防 065 的梯度泄露、防成员推理）。
- **模型隐私**：模型本身也是资产，不能被窃取或反推。

**为什么"模型隐私"值得单独说？** 因为**模型可能泄露训练数据的分布信息**。一个在特定小区数据上训练的负荷预测模型，它的参数里编码了这个小区居民的生活模式。**攻击者拿到模型，就能推断这个小区的情况**——这在竞争场景（比如两家售电公司）里是实打实的商业机密泄露。

**第三，这篇论文的结论"精度和隐私可以兼得"需要仔细看条件。**

论文说可以"secure both high forecasting accuracy and near-complete privacy"。这个结论成立的前提是：

- **任务本身有足够多的数据**——住宅负荷预测是一个"规律性强、冗余度高"的任务（大家都在晚上用电、都开空调），所以加一点噪声不会毁掉可预测性。
- **不是所有任务都这么"抗噪"**。**如果任务本身信号很弱（比如异常检测要发现极其罕见的攻击），加 DP 噪声可能直接淹没信号。** 这一点论文没有讨论，但对你的选题非常重要。

> **这个洞察很关键**：**隐私保护在"预测类任务"（信号强、冗余高）里代价小，在"检测类任务"（信号弱、长尾）里代价大。** 如果你要做电力场景的隐私保护检测，**必须先测清楚"加了 DP 之后，检测性能掉多少"**——这是一个明确且重要的研究问题。

**攻击面在哪**：**模型更新**。联邦学习协议规定客户端要上传更新，而这个更新是数据的函数（065 已证明可反推）。DP 和安全聚合分别从"内容"和"可见性"两个角度加固这条通道。

**如果要迁移到你的研究**：

1. **DP 对电力"检测类任务"的影响评估**——预测类任务已经有人做了（就是这篇），但**检测类任务（FDIA 检测、异常检测）在 DP 下的性能衰减**几乎没人系统研究过。**这是一个明确、重要、可执行的选题。**
2. **隐私保护的代价量化**——论文说"high accuracy + near-complete privacy"，但**没有给出具体的精度损失数字**。你可以做一组更细粒度的实验：扫 ε 从 0.1 到 10，画"ε vs 预测误差"曲线，给出工程可用的 ε 建议值。**这种"给出实用参数"的工作非常有引用价值。**
3. **安全聚合的开销评估**——安全聚合需要额外的通信轮次和计算，在电力边缘设备上是否可行？论文没有给性能数字，你可以补。
4. **复现与扩展**——论文用的是"a large set of residential load data"，**数据集来源需要查原文**。如果能拿到公开数据，复现成本很低，适合作为你的第一个实验项目。

## 局限性

- **摘要未给出任何具体数值**：没有预测误差指标（MAE/RMSE/MAPE）、没有 ε 的取值、没有安全聚合的开销、没有数据集名称和规模。**"高精度"和"接近完全的隐私"都是定性表述，无法量化引用。**
- **"near-complete privacy"这个说法缺少定义**：用什么指标衡量隐私？是 ε 的值？还是做了具体的隐私攻击实验（如成员推理）来验证？摘要没有说明。**没有攻击实验的"隐私保护"主张，可信度是要打折的。**
- **没有考虑恶意参与方**：论文假设参与方都是诚实的，只防"服务器偷看"。**如果参与方本身是恶意的（投毒、后门），这套组合完全无法防御**——DP 噪声对后门无效（后门是有结构的信号，不是随机扰动），安全聚合也挡不住投毒（投毒更新会被正常聚合进去）。**这是本文与 069/070 之间的空白。**
- **实验是仿真而非真实部署**：论文说"simulate"，意味着没有考虑真实智能电表的通信约束、设备算力、故障重传等工程问题。
- **"挑战"部分的具体内容摘要未说明**：论文说"identify and discuss challenges"，但摘要没列出是什么，无法判断讨论的深度。
- **住宅负荷预测的结论未必能推广**：居民用电规律性强、数据冗余度高，所以"抗噪"。**工业负荷、新能源出力预测这些任务是否也抗噪，需要单独验证。**
- 论文是 2021 年的工作，此后联邦学习 + 安全聚合的工程实现（如 Google 的跨设备联邦学习、工业界的隐私计算平台）已有大量进展，本文的仿真结论需要结合新工具重新验证。

## 原文摘要

> With high levels of intermittent power generation and dynamic demand patterns, accurate forecasts for residential loads have become essential. Smart meters can play an important role when making these forecasts as they provide detailed load data. However, using smart meter data for load forecasting is challenging due to data privacy requirements. This paper investigates how these requirements can be addressed through a combination of federated learning and privacy preserving techniques such as differential privacy and secure aggregation. For our analysis, we employ a large set of residential load data and simulate how different federated learning models and privacy preserving techniques affect performance and privacy. Our simulations reveal that combining federated learning and privacy preserving techniques can secure both high forecasting accuracy and near-complete privacy. Specifically, we find that such combinations enable a high level of information sharing while ensuring privacy of both the processed load data and forecasting models. Moreover, we identify and discuss challenges of applying federated learning, differential privacy and secure aggregation for residential short-term load forecasting.
