## 今日主推

### `2607.05993` Bit2Watt：用 GPU 工作负载跨越"计算—电力"边界的网络物理漏洞

**Zhouhao Ji, Kaikai Pan（通讯）, Wenyuan Xu** — 浙江大学 USSLab
arXiv v1 2026-07-07 · **IACR TCHES / CHES 2026 录用** · cs.CR（+cs.AR, cs.DC）· 28 页 / 19 图 / 5 表 · NSFC 62571474 / 62201501 / U25B20188

#### 深度解读摘要

**它做了什么。** 论文提出并验证了一条此前没人认真走过的因果链：**合法的计算调度指令，可以穿过电力电子接口，把电网推到不稳定。**

具体是两步：

**第一步（信息域）：怎么造出 kHz 的功率波动。** 两种手法，都只用用户态能力：

- **SWMA**（合成工作负载调制）：自写 CUDA kernel，内含 active/passive 两种执行模式，用 `cudaMallocManaged` 分配的统一内存标志做控制通道，CPU 侧轮询改写。**RTX 4090 上做到 6,000 Hz / 248 W**。
- **LTMA**（LLM 训练调制）：不写额外 kernel，**把调制逻辑嵌进 PyTorch/DeepSpeed 训练管线**——改超参、插辅助算子，让高/低负载相位交替。频率低（3,000 Hz）但幅度大（**355 W**），而且**在信息层与正常训练噪声不可区分**。

**第二步（物理域）：为什么这点波动能掀翻系统。** 用阻抗法建三元件模型（主网 Thévenin + DER 受控电流源 + GPU 集群 CPL），抓住两个放大器：

- **GPU 集群的负增量电阻（NIR）**：$Z_l \approx -V_l^2/P_l$。电压跌 → CPL 加电流 → $Z_g$ 压降更大 → 电压更低。正反馈，等于往系统里**注入负阻尼**。
- **DER 输出阻抗的谐振峰**：逆变器无物理惯性，$Z_{der}(s)$ 完全由控制动态塑形，在特定频率有峰——论文叫 "out-of-band vulnerability"。

两者用 Middlebrook 判据合起来：$|T_m| = |Z_g/Z_{dl}| < 1$，$Z_{dl} = Z_l \parallel Z_{der}$。**DER 渗透率一升，相位裕度从 ~60° 掉到 ~10°，NIR 再吃掉剩下的。**

**它测到了什么。** 三级硬件验证，一环不缺：

1. **GPU 功耗**：NI DAQ 采 +12 V 供电，六代 GPU 的频率-幅度表（1500→6000 Hz，103→248 W）。
2. **集群 CPL**：**约 100 张卡、3 个机架**，在配电箱处测。10 次试验（5 降 5 升，225↔195 V）。结果：**电压变化 >10%，功率只变 1%**（误差 0.0151，σ 0.0123）。**这是"数据中心 = 恒功率负荷"最直接的现场证据。**
3. **DER 阻抗**：扰动注入法扫 1 Hz–10 kHz，Bode 图上谐振峰清清楚楚。
4. **8 kW 样机**：`GPU→SPS→PDU→UPS→PCC` 全链，光伏供 40%。
5. **广域仿真**：9241 节点欧洲输电网，13 级级联、1,238 条线路、失负荷 ~81%。

**主结果**（1 MW 系统，90% DER，1000 GPU）：THD **46.80%**（IEC 61000-3-12 限值 13%）；阻尼比 **0.46 → −0.27**；电压偏移 22.31%。**但注意：即使 DER 只有 10%，THD 也有 19.60%——仍然超标 50%。** 这说明"高 DER"只是放大器，不是必要条件。

#### 为什么值得读

**理由一：它把"攻击面"这个概念往前推了一格。**

过去的网络物理攻击分类学，是按"攻陷了什么"来分的：攻陷量测（FDIA）、攻陷通信（中间人）、攻陷设备（固件/僵尸网络）、攻陷物理（电磁注入）。

Bit2Watt 提出了第四类：**什么都没攻陷，只是"正常使用"。**

这一格的推进有实际后果——**它让所有基于"边界"的防御同时失效**。IDS 看流量，是合法的；容器安全看进程，是合法的；云审计看 API 调用，是付费客户在正常下单。**防御方不是没看到，是看到了也没理由拦。**

**理由二：它给出了一个可以立刻借用的分析工具——$\Gamma_s(f)$。**

论文把"数据中心的供电链"当成一个**滤波器**来刻画，逐级实测谱增量的变化：

$$\Delta_s(f) := M_s^{atk}(f) - M_s^{base}(f),\qquad \Gamma_s(f) := \Delta_s(f) - \Delta_{s-1}(f)$$

$\Gamma_s(f)>0$ 表示该级放大，$<0$ 表示衰减。**这等于给整条链算了一个"扰动传递函数"，而且是在真实硬件上逐级测的。**

这个工具是**双向可用**的：红队用它选频，蓝队用它选监测点。而且它可以直接推广——任何"算力 → 电网"的耦合，都可以用这个框架去量化"扰动在哪一级被吸收、在哪一级被放大"。

**理由三：它诚实地暴露了一个"物理侧反直觉"的现象。**

三级 THD 的实测结果是：**SPS 8.91%→5.08%（降），PDU 8.17%→5.55%（降），UPS 25.31%→50.76%（翻倍）。**

下游变干净、上游变脏。原因是：SPS 的 DC 母线电容吸收了大量高频，但 **UPS 的级联反馈环被打进限流模式**，把能量"存"进 DC 母线电压（纹波 0.45%→2.82%），再反过来扭曲输入电流。

> **一句话：UPS 不是滤波器，是频率搬移器。**

这个机理，和公众号《14.7 Hz 振荡溯源》描述的工程现象是同一件事的两面——那篇讲的是"UPS 引发持续振荡"，这篇讲的是"**外部工作负载如何把 UPS 推进那个状态**"。

#### 核心创新（五条）

1. **把"合法算力"确立为一类新攻击面**——什么都没攻陷，只是正常使用。**这是概念层贡献，也是最难被反驳的一条。**
2. **把"功率调制带宽"变成可测量的攻击能力指标**——六代 GPU 的频率-幅度-可控性三维表。**战略含义：攻击能力随 GPU 代际单调增长（1500→6000 Hz，103→248 W），这个漏洞会随时间自动变严重，攻击者不需要做任何改进。**
3. **$\Gamma_s(f)$ 逐级谱传播分析**——把供电链当滤波器，双向可用。
4. **Watt2Bit 闭环**——电网的反弹会打回计算：谐波 → ESR 上升（集肤/邻近效应）→ 附加发热 **+17.8%** → 保护跳闸（电流翻倍约 2 s）→ GPU 断服。另加一条 EMI 外泄通道（FSK，2 kHz/200 Hz，10 ms/bit，>99% 准确率）。
5. **三级硬件验证的完整性**——GPU 功耗 → 集群 CPL → DER 阻抗 → 样机 → 广域仿真，五环全有实测或仿真支撑。**这在网络物理安全论文里相当罕见。**

#### ★ 但请把摘要和图 11 放在一起看

这是我读完最想提醒的一件事。

**摘要卖的是"6,000 Hz"。物理侧兑现的是"200–700 Hz"。**

图 11(a) 的合成曲线写得很清楚：**在 300–500 Hz 达到 +18 dB 峰值，到 6–10 kHz 掉到 −45 dB。**

45 dB 是幅度上的 **1/178**。也就是说，"能调出 6 kHz"这个能力，**在到达电网之前几乎被完全吸收**。真正打进去的是 UPS 重塑出来的几百赫兹。

而更麻烦的是**第二个矛盾：6 kHz 与"1000 卡相干叠加"在时间同步上互斥。**

6 kHz 的周期只有 **167 μs**。论文自己的 jitter 分析说：2 kHz 下 $\sigma_\tau = 100\ \mu s$ 时幅度掉 20%。用相位扩散模型粗算（我的推导，非论文结论），相干叠加幅度按 $e^{-2\pi^2 f^2 \sigma_\tau^2}$ 衰减：

| $f$ | $\sigma_\tau$ | 幅度保留 |
|---|---|---|
| 2 kHz | 100 μs | ~45% |
| 6 kHz | 100 μs | **~0.08%** |
| 6 kHz | 10 μs | ~93% |

**要在 6 kHz 上让 1000 张卡相干叠加，需要全集群对齐精度 $\lesssim 10\ \mu s$。** PTP 在网卡层能到 1 μs，但 **CUDA kernel 启动 + 驱动排队 + 容器调度**的抖动通常是几十 μs 到 ms。

> **结论：在公有云上，6 kHz 与 1000 卡相干叠加基本不可能同时成立。**
> 这不是"论文错了"，而是**论文没把这个权衡摆到台面上**——而它恰恰是最该被摆上台面的东西，因为"频率"和"聚合规模"是一对互斥的资源，**这本身就是一个可发表的定量结论**（见下面选题 B）。

#### 另外三处需要留意的地方

- **阻尼比是黑箱**。全文最关键的数字（0.46 → −0.27），论文**没有交代怎么算出来的**：是 Jacobian 主导特征值？是 Prony 辨识？还是从 $T_m$ 反推？这是可复现性的最大缺口。
- **正文数值与图 9(c) 矛盾**。摘要写 −0.27、图 9(c) 也是 −0.27，但正文 5.1 节写成"drops from 0.46 to **0.27**"——**丢了负号**，而"正的 0.27"不可能同时是 "unstable regime"。另外正文说"80% DER 下约 800 张卡之后阻尼变负"，但图 9(c) 的 80% 行在 800 处是 **0.11**，到 1000 才 **−0.14**——**阈值说错了 200 张卡**。

## 关联追踪论文

### 一号关联（必读）`2610.22572` DC-TORQ：把"振荡"落到"轴会断"

**Yingyi Tang, Bin Wang, Junbo Zhao, Qiang Zhang, Pradip Vijayan, Xiaochuan Luo, Tongxin Zheng** — 2026-10-15 · eess.SY 单分类

**为什么重要**：这是本期**唯一一篇有系统运行方署名的论文**（Luo 与 Zheng 来自 ISO-NE）。它回答的问题比 Bit2Watt 更"电网"：

> 数据中心的周期性功率需求会注入强迫振荡。当振荡的频率分量接近**汽轮发电机组的扭振模态**时，会激励出持续的轴系扭矩振荡，幅值可能超过**允许的循环扭矩限值**。

**方法**：不靠 EMT 反复仿真（那要在激励频率 × 负荷位置上做二维扫描，计算量爆炸），而是建"发电机—网络"详细模型，**推导从"数据中心功率扰动"到"各轴段扭矩"的闭式传递函数**。核心是必须计入**数据中心、输电网、发电机之间的频率相关网络耦合**——这正是纯机械扭振分析漏掉的东西。

然后把"允许的轴扭矩幅值"反解成**频率相关的数据中心功率振荡限值**，给出并网母线的**定量筛选判据**。IEEE 基准模型验证，IEEE 39-bus 应用。

**和 Bit2Watt 的关系**：Bit2Watt 停在"阻尼比变负、系统失稳"。DC-TORQ 往前推了一步——**"失稳"之前，轴已经在被疲劳损伤了"**。而且它给出的"频率相关功率限值"，正是 Bit2Watt 缺的那块拼图：**Bit2Watt 说"能造多大振荡"，DC-TORQ 说"允许多大振荡"。两者相除，就是安全裕度。**

**延伸**：`2605.01173`（汽轮机疲劳寿命的频域方法，给出"三步流程"把疲劳约束转成运行限制）、`2607.14412`（水轮机轴疲劳）。**三篇合起来是"轴系疲劳"这条新线的全部家底，值得一次读完。**

### 二号关联（强烈推荐）`2610.22972` 转换器感知的计算灵活性协调

**Ruolan Cui, Ruizhang Yang, Chenxi Hu, Franxis Yunhe Hou** — 2026-10-16 · eess.SY 单分类 · 249 KB

**一句话**：**"计算灵活性不会自动转化为电气可实现的功率灵活性。"**

这句话是整个"算电协同"研究方向最需要的一盆冷水。论文指出：忽略变换器与网络运行限值，会导致**变换器过载、保护跳闸、供电与算力服务同时中断**。

**方法三段**：

1. **任务级 MILP**：保留同步训练配置与完成时限；用 **Minkowski 和聚合 + Shapley–Folkman 凸化**得到线性化的推理池表示，**不需要单元级二值变量**，并给出"相对松弛间隙随池规模反比下降"的条件界；

3. **混合整数模型**：协调工作负载、光伏、储能、购电。

**结论**：电气限值会**重塑调度与新能源消纳**；在研究条件下，**固定训练无法在电压限值内支撑完整推理服务**，而协调调度能做到"推理缺口可忽略"，且通过原始 AC 模型校验。

## 选题出口

读完本期两篇（Bit2Watt + DC-TORQ），我认为有五个可做的方向，按"出成果速度"排序：

### A（最快，纯方法论）把"不可检测"改写为"混叠可检测"

**论点**：1–6 kHz 调制在 ≤1 kHz 采样下**必然混叠**，混叠会产生一个**确定性的低频鬼影**（频率 $= |f_{att} - k f_s|$）。只要知道采样率 $f_s$，就能从鬼影反推 $f_{att}$。

**为什么能做**：Bit2Watt 的 Table 4 已经把六种监测工具的采样率列全了，图 14(b) 也给了基线（LTMA 18.05%、SWMA 40.93%）。**你只需要证明"正确的信号处理视角能把这两个数字显著推高"**——不需要新硬件，不需要新台架。

**工作量**：自己复现一个 GPU 功率调制（单卡即可）+ 降采样到 1 kHz + 谱分析。**三周内能出初稿。**

**风险**：可能被质疑"你的数据不是真实数据中心的"。对策：用 MIT Supercloud 公开数据集做真实轨迹验证。

### B（理论清晰，实现量小）形式化"频率—同步—规模"三元可行域

**论点**：给出"要在频率 $f$ 上造成 $A$ 的扰动，需要 $N$ 张卡、时间同步精度 $\sigma_\tau$"的约束曲面，把 Bit2Watt 的 6 kHz 主张变成一条**可检验的边界**。

**核心公式**（我在笔记里已经推了一半）：相干叠加幅度 $\propto e^{-2\pi^2 f^2 \sigma_\tau^2}$，于是可行性要求 $N \cdot A_0(f) \cdot e^{-2\pi^2 f^2 \sigma_\tau^2} \ge A_{req}$。

**为什么值钱**：**这是对 Bit2Watt 最直接、最有价值的补全**，而且它把"高频"这个卖点变成一个**可量化的边界**——结论可能是"6 kHz 只在单机架内可行"，那本身就是个有用的结论。

**工作量**：纯理论 + 少量数值验证。**一个月。**

### C（最有护城河）物理层逆问题：从 UPS 输入电流反推 GPU 侧调制参数

**论点**：Bit2Watt 给了正向的 $\Gamma_s(f)$（GPU → 电网）。**反过来做**：只观测 UPS 输入电流，能否反演出"GPU 侧在什么频率、什么幅度、多少张卡在调制"？

**为什么难、为什么值钱**：这是个**病态逆问题**（多频叠加 + 非线性限流 + 三级变换），但**正因为病态才有做头**。而且它天然用上"物理 + 信息"双视角——纯 ML 的人做不了，因为不懂 $\Gamma_s$ 的物理结构；纯电力的人做不了，因为不熟悉逆问题与正则化。

**攻防两侧都用得上**：红队用它评估暴露度，蓝队用它做取证。**这是我认为最可能形成"只有我能做"优势的入口。**

**工作量**：需要台架（8 kW 级别即可）。**三个月。**

### D（最"电网"）区分"自激"与"他激"的 UPS 振荡

**问题**：UPS 引发的持续振荡，到底是**设备控制失稳**（工程问题），还是**外部负载恶意激励**（安全问题）？两者在 PMU 上的签名有何差异？

**为什么现在能做**：`2608.06521`（UPS 弱网 PLL-free VM-DPC）给了"自激"的机理，Bit2Watt 给了"他激"的机理，**两篇合起来正好是一个"二选一"的判别问题**。而公众号《14.7 Hz 振荡溯源》说明这个现象在工程上**真实存在**。

**学术界目前零篇。** 但周期最长，需要 PMU 数据或高保真 EMT 模型。

### E（最省力，适合第一篇）把 $\Gamma_s(f)$ 做成"并网频谱准入"指标

**论点**：类比谐波国标（IEEE 519 / IEC 61000-3-12）的思路，提出"数据中心并网的**调制频谱限值**"——给定接入点，规定在哪些频段允许多大幅度的功率调制。

**为什么省力**：用 Bit2Watt 的模型 + DC-TORQ 的闭式传递函数，**就能算出这条曲线，不需要新实验**。

**为什么有价值**：这是一个"标准提案型"贡献，落地路径清晰（可以直接投 IEEE 的标准类期刊，或作为 TPWRS 的 letter）。**和 DC-TORQ 的"筛选判据"是同一个思路的两种表述，注意别撞车。**

> **优先级建议：A、E 最快出成果（适合第一篇）；C 最有护城河；B 理论最干净；D 最"电网"但周期最长。**
