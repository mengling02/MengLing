## Day 15 · 09:00 —— SCADA 系统全景：数据采集与监控的核心架构

> **一句话**：SCADA 是电力系统的"中枢神经系统"——**采集数据、监控状态、下发指令**。你在乌克兰停电事件里看到的"攻击者像调度员一样点鼠标"，点的就是 SCADA。

### 一、SCADA 是什么

**SCADA = Supervisory Control And Data Acquisition**（数据采集与监视控制）。它做四件事：

| 功能 | 说明 |
|---|---|
| **数据采集** | 从 RTU/PLC/IED 收集遥测数据 |
| **监视** | 在人机界面（HMI）展示实时状态 |
| **控制** | 下发遥控指令（开/合断路器） |
| **告警** | 异常时通知操作员 |

### 二、SCADA 的经典架构

```
┌──────────────────── 调度中心（主站）────────────────────┐
│  [HMI 人机界面]  [历史数据库]  [应用服务器]           │
│         ↑              ↑              ↑               │
│         └──────── [SCADA 服务器] ──────┘               │
└────────────────────────┬──────────────────────────────┘
                         │ 通信网络（专网/光纤）
          ┌──────────────┼──────────────┐
          │              │              │
     [变电站A]      [变电站B]      [变电站C]
      [RTU/网关]     [RTU/网关]     [RTU/网关]
          │              │              │
     [IED/保护]     [IED/保护]     [IED/保护]
          │              │              │
      [断路器/变压器等一次设备]
```

**四层结构**：主站层 → 通信层 → 子站层 → 过程层

### 三、四遥功能

SCADA 的核心是"四遥"：

| 功能 | 方向 | 例子 |
|---|---|---|
| **遥测 (YC)** | 上行 | 电压、电流、功率 |
| **遥信 (YX)** | 上行 | 断路器位置、告警状态 |
| **遥控 (YK)** | 下行 | 分/合断路器 |
| **遥调 (YT)** | 下行 | 调节变压器分接头、机组出力 |

**注意"下行"命令**——这是攻击者最想要的权限。**能在 SCADA 里下发遥控命令，就等于能控制整个电网。**

### 四、SCADA 的安全弱点（为什么它这么脆弱）

| 弱点 | 原因 |
|---|---|
| **设计无安全考虑** | 早期 SCADA 运行在**物理隔离**的专网，厂商假设"不会有人攻击" |
| **协议无认证** | Modbus、DNP3 早期版本**没有身份验证和加密** |
| **生命周期长** | 一套 SCADA 用 15-25 年，系统陈旧、补丁困难 |
| **可用性优先** | 停机维护成本极高，所以不敢打补丁 |
| **扁平网络** | 内部通信往往不分区，横向移动容易 |

**核心矛盾**：**SCADA 为"可靠性"设计，而不是为"安全性"设计。**

### 五、和电网安全研究的关系

**SCADA 是电网攻击的核心目标**，研究切入点：

| 研究方向 | 说明 |
|---|---|
| **SCADA 流量异常检测** | 工控协议有强周期性，异常容易检测（**入侵检测对口！**） |
| **HMI 操作行为分析** | 操作员行为有规律，异常操作可识别（UEBA 思路） |
| **主站-子站通信安全** | 纵向加密、认证机制 |
| **SCADA 蜜罐** | 部署诱捕系统，研究攻击者行为 |

**特别提示**：**工控协议流量的"规律性"是最大的检测优势**。与 IT 网络流量不同，SCADA 通信高度周期性（每 100ms / 1s 轮询一次），这个规律让**基于时序的异常检测**（LSTM、自编码器）非常有效。**这是你实验室入侵检测方向最容易落地的场景。**

## Day 15 · 14:00 —— 电力"三区四层"安全架构：安全 I/II/III 区与生产控制大区

> **一句话**：中国电力行业用**"安全分区、网络专用、横向隔离、纵向加密"**十六字方针构建防护体系。这是理解中国电力安全的理论基石，也是行政规章的硬性要求。

### 一、电力监控系统的分区

根据 **《电力监控系统安全防护规定》（国家发改委 14 号令）**，电力系统划分为：

```
┌─────────────────────────────────────────────────────┐
│              管理信息大区（信息外网/内网）            │
│  办公自动化、企业管理系统、对外网站                   │
└──────────────────────┬──────────────────────────────┘
                       │ 电力专用横向单向隔离装置
                       │ （单向！只能生产大区→管理大区）
┌──────────────────────┴──────────────────────────────┐
│              生产控制大区                             │
│  ┌──────────────┐  ┌──────────────┐  ┌───────────┐ │
│  │  安全 I 区    │  │  安全 II 区   │  │ 安全 III 区│ │
│  │ 实时控制      │  │ 非控制业务    │  │ 生产管理   │ │
│  │ SCADA/AGC    │  │ 水情/气象     │  │ 电量计量   │ │
│  │ 保护/稳控     │  │ 保护信息子站  │  │ 统计报表   │ │
│  └──────────────┘  └──────────────┘  └───────────┘ │
│         ↑ 逻辑隔离          ↑ 逻辑隔离                │
└──────────────────────────────────────────────────────┘
```

### 二、安全 I/II/III 区的区别

| 区 | 业务 | 实时性要求 | 安全等级 |
|---|---|---|---|
| **安全 I 区** | 实时监控、AGC、保护、稳控 | **毫秒~秒级** | 最高 |
| **安全 II 区** | 非控制类生产业务 | 分钟级 | 高 |
| **安全 III 区** | 生产管理、电量计量 | 小时级 | 中 |

**关键约束**：**安全 I 区严禁任何外部连接**，包括无线、拨号、互联网。

### 三、三道防线

| 防线 | 手段 | 保护对象 |
|---|---|---|
| **横向隔离** | 电力专用单向隔离装置 | 生产控制大区 ← 管理信息大区 |
| **纵向加密** | 纵向加密认证装置 | 主站 ← → 子站通信 |
| **边界防护** | 防火墙、入侵检测 | 各区间边界 |

**"横向隔离"最值得注意**：它是一个**物理上的单向装置**——数据只能从生产控制大区流向管理信息大区，不能反向。**这是通过"物理不可逆性"来实现的安全，比软件防火墙强得多。**

### 四、和电网安全研究的关系

**这套架构有明确的研究机会**：

| 研究方向 | 说明 |
|---|---|
| **隔离装置能否被绕过** | 单向装置的原理是"物理单向"，但数据流中的**隐蔽信道**是研究热点 |
| **隐蔽信道（Covert Channel）** | 通过时间、编码等方式在单向链路上传信息 |
| **I/II 区的逻辑隔离强度** | 逻辑隔离比物理隔离弱，是攻击的"软肋" |
| **合规性自动化检测** | AI 自动检查系统是否符合 14 号令要求 |

**特别推荐"隐蔽信道"**：单向隔离装置理论上"物理上无法反向传输"，但研究发现，**通过调制数据的发送时机（时间隐蔽信道）或利用数据的某些位（存储隐蔽信道），信息仍可逆向传输**。这是一个**理论深刻、实验可行、且直接服务国家需求**的选题。

## Day 16 · 09:00 —— EMS / DMS / 调度自动化系统分工

> **一句话**：SCADA 是"眼睛和手"，**EMS 是"大脑"**。搞清 EMS/DMS/SCADA 的分工，你就理解了电力系统调度的组织逻辑。

### 一、三大系统的分工

| 系统 | 全称 | 管什么 | 层级 |
|---|---|---|---|
| **SCADA** | 数据采集与监控 | 数据采集 + 遥控 | 基础层 |
| **EMS** | 能量管理系统 | **输电网**的调度决策 | 省级/区域调度 |
| **DMS** | 配电管理系统 | **配电网**的调度管理 | 地市/县级调度 |

```
        ┌─────────── EMS（输电网大脑）───────────┐
        │  状态估计、潮流计算、AGC、经济调度、    │
        │  安全分析、调度员潮流                   │
        └───────────────┬─────────────────────────┘
                        │ 基于
                    [SCADA 数据平台]
                        │ 基于
        ┌───────────────┴─────────────────────────┐
        │        DMS（配电网大脑）                 │
        │  负荷管理、故障隔离、无功优化、GIS 集成   │
        └─────────────────────────────────────────┘
```

### 二、EMS 的核心功能

| 功能 | 说明 | 安全意义 |
|---|---|---|
| **状态估计 (SE)** | 从量测推算全网状态 | **FDIA 的直接目标** |
| **调度员潮流 (PF)** | "假设"分析 | 输入被污染则结论错误 |
| **最优潮流 (OPF)** | 优化发电出力 | 被操纵则经济损失 |
| **AGC** | 自动发电控制 | **可被攻击导致功率振荡** |
| **安全分析 (CA)** | N-1 校验 | 可被欺骗 |
| **经济调度 (ED)** | 成本最优 | 可被操纵牟利 |

**EMS 的每一个功能，都是一个潜在的攻击面。**

### 三、调度体制：四级调度

```
国调（国家电力调度控制中心）
  ↓
网调（区域电网调度）
  ↓
省调（省级调度）
  ↓
地调（地区调度）/ 县调
```

**各层级之间有明确的数据交换**（上送遥测、下达指令），这些**层间接口就是攻击路径**。

### 四、和电网安全研究的关系

**EMS 是"决策大脑"，攻击它等于攻击电网的判断力**：

| 攻击对象 | 后果 | 研究价值 |
|---|---|---|
| **状态估计** | 调度员看到错误的全网状态 | **极高（FDIA 核心）** |
| **AGC** | 发电功率异常振荡 | 高 |
| **经济调度** | 经济损失、机组错误启停 | 中 |
| **安全分析** | N-1 校验失效 | 高 |
| **调度员潮流** | 影响人工决策 | 中 |

**一个值得注意的"高价值低门槛"选题**：

**"EMS 历史数据投毒"** —— EMS 大量使用历史数据做预测和趋势分析。攻击者如果**长期、缓慢地注入偏差较小的虚假历史数据**，可以让预测模型"学错"，在关键时刻给出错误建议。**这种"慢攻击"极其隐蔽，且非常适合用 AI 异常检测方法（时序分析）来发现。**

## Day 16 · 14:00 —— RTU / PLC / IED：现场终端设备家族

> **一句话**：**RTU、PLC、IED 是变电站里的"末梢神经"**——它们直接连接一次设备，采集数据、执行命令。**攻击者攻破它们，就等于把手伸到了电网的物理层。**

### 一、三者对比

| 设备 | 全称 | 主要用途 | 编程方式 |
|---|---|---|---|
| **RTU** | 远程终端单元 | 采集现场数据、上传主站 | 厂商专用 |
| **PLC** | 可编程逻辑控制器 | 逻辑控制（工业通用） | IEC 61131-3 |
| **IED** | 智能电子设备 | 保护、测控、计量 | IEC 61850 配置 |

**实际中三者界限越来越模糊**——现代 IED 常集成 PLC 功能，RTU 也支持 IEC 61850。

### 二、IED：变电站的主角

**IED（Intelligent Electronic Device）** 是数字化变电站的核心，包括：

| 类型 | 功能 |
|---|---|
| **保护 IED** | 继电保护 |
| **测控 IED** | 测量与控制 |
| **合并单元 (MU)** | 采集 CT/PT 信号，输出 SV 报文 |
| **智能终端 (ST)** | 执行断路器操作，收发 GOOSE |

**合并单元和智能终端是 IEC 61850 过程层的核心**——它们引入了"数字化采样"和"网络化跳闸"，效率提升，但**安全风险也随之引入**。

### 三、安全弱点

| 弱点 | 说明 |
|---|---|
| **固件老旧** | 设备生命周期 15-20 年，固件很少更新 |
| **默认口令** | 大量设备使用出厂默认密码 |
| **无认证协议** | Modbus/DNP3 早期版本无认证 |
| **物理可达** | 变电站往往地理上分散，物理防护薄弱 |
| **调试接口** | JTAG、串口、USB 调试口常未禁用 |
| **供应链风险** | 固件可能被植入后门 |

**"默认口令"是最现实的威胁**：Shodan（网络空间搜索引擎）上可以搜到大量暴露在互联网的工控设备，很多用默认口令就能登录。

### 四、和电网安全研究的关系

**这是"程序逆向"和"入侵检测"两个方向的交汇点**：

| 选题 | 方法 | 对接方向 |
|---|---|---|
| **IED 固件逆向与漏洞挖掘** | IDA/Ghidra、Fuzzing | **程序逆向** |
| **IEC 61850 协议模糊测试** | 协议 Fuzzing | 程序逆向 + 入侵检测 |
| **IED 流量异常检测** | 深度学习时序模型 | **入侵检测** |
| **工控蜜罐诱捕** | 模拟 IED 服务 | 入侵检测 |
| **固件供应链分析** | 二进制相似性检测 | 程序逆向 |

**特别推荐"IEC 61850 协议模糊测试"**：这是工控安全领域**经典且仍然有效**的研究方法。IEC 61850 报文种类多、字段复杂，很多实现存在解析漏洞。**用 AFL/Boofuzz 等工具对协议实现做 Fuzzing，找到漏洞 → 分析危害 → 提出修复，这就是一篇完整的安全论文。**

## Day 17 · 09:00 —— Modbus 协议：最简单也最脆弱的工控协议

> **一句话**：Modbus 是工控界的"普通话"——**简单到极致，也脆弱到极致**。它没有任何认证和加密，**只要网络可达，就能读写任何寄存器**。

### 一、Modbus 的结构

Modbus 是**主从（Master-Slave）**架构：

```
[主站 Master] ──请求──→ [从站 Slave 1, 地址 1]
              ──请求──→ [从站 Slave 2, 地址 2]
              ←─响应──  [从站 1]
```

**每个请求包含**：

| 字段 | 长度 | 说明 |
|---|---|---|
| 事务标识 | 2 字节 | 匹配请求/响应（TCP 版） |
| 协议标识 | 2 字节 | 固定 0 |
| 长度 | 2 字节 | 后续字节数 |
| **单元标识** | 1 字节 | 从站地址 |
| **功能码** | 1 字节 | 操作类型 |
| **数据** | n 字节 | 寄存器地址 + 数量/值 |

### 二、常用功能码

| 功能码 | 操作 | 危险度 |
|---|---|---|
| 0x01 | 读线圈（读开关状态） | 低 |
| 0x02 | 读离散输入 | 低 |
| **0x03** | 读保持寄存器 | 低 |
| **0x04** | 读输入寄存器 | 低 |
| **0x05** | 写单个线圈 | **高（改开关状态）** |
| **0x06** | 写单个寄存器 | **高（改设定值）** |
| **0x10** | 写多个寄存器 | **高（批量篡改）** |

**攻击者要做的就是发送 0x05/0x06/0x10 报文。**

### 三、Modbus 的安全缺陷（致命）

| 缺陷 | 后果 |
|---|---|
| **无认证** | 任何能发包的人都能操作 |
| **无加密** | 明文传输，可监听可篡改 |
| **无完整性校验** | 改一个字节神不知鬼不觉 |
| **无审计** | 谁操作的完全不知道 |
| **地址空间暴力可达** | 遍历所有寄存器只需几秒 |

**一个真实的攻击示例**（教学用途）：
```python
# 概念演示：修改从站 1 的保持寄存器 40001 的值为 9999
# 实际使用 pymodbus 需要指向真实设备
from pymodbus.client import ModbusTcpClient
client = ModbusTcpClient('192.168.1.10', port=502)
client.write_register(0, 9999, unit=1)   # ← 无任何认证
```

**就这一行代码，就能篡改一个工业现场的关键参数。**

### 四、Modbus 在电力中的地位

Modbus 在电力系统中主要用于：
- **配电自动化**（部分老旧系统）
- **辅助系统**（环境监测、消防）
- **新能源场站**（部分逆变器、电表）
- **楼宇/厂用电**

**注意**：主干输电监控已经更多用 **IEC 61850 / DNP3 / IEC 104**，但 Modbus 在**配电和新能源**领域仍然广泛存在。

### 五、和电网安全研究的关系

**Modbus 是"入侵检测"最容易上手的场景**：

| 选题 | 说明 |
|---|---|
| **Modbus 异常指令检测** | 检测非法功能码/非法地址访问 |
| **写操作频率异常检测** | 正常写操作很少，突然大量写 = 异常 |
| **Modbus 蜜罐** | 模拟从站，诱捕攻击者 |
| **协议白名单** | 只允许合法的主从+功能码组合 |

**为什么适合入门**：
1. **协议简单**，容易解析（你自己就能写解析器）
2. **流量规律性强**，异常容易构造
3. **公开数据集多**（很多工控安全数据集都含 Modbus）
4. **实验环境影响小**：可以用软件模拟，不需要真实设备

**推荐第一个实验**：用 `pymodbus` 在本地搭建一个 Modbus 从站 + 主站，用 Wireshark 抓包，然后写脚本注入异常写指令，再用简单的机器学习分类器检测。**一个下午就能跑通。**

## Day 17 · 14:00 —— DNP3 协议：电力远动通信的主力

> **一句话**：DNP3 是电力系统**远动通信**的主力协议，功能比 Modbus 强大得多，也**比 Modbus 更早考虑了安全性**（虽然早期版本仍不安全）。

### 一、DNP3 的定位

**DNP3 = Distributed Network Protocol version 3**，主要用于：
- **配电自动化 (DA)**
- **SCADA 主站 ↔ RTU/变电站**通信
- **水/气/油等公用事业**（与电力同源）

**与 Modbus 的关键差异**：

| 维度 | Modbus | DNP3 |
|---|---|---|
| 架构 | 简单主从 | 主从 + **支持主动上报** |
| 数据类型 | 4 类寄存器 | **丰富（模拟量、状态、时间戳、事件）** |
| 时间戳 | 无 | **有（重要！事件顺序记录）** |
| 安全 | 无 | **有安全认证（v2 起 Secure Authentication）** |
| 复杂度 | 极低 | 中高 |

### 二、DNP3 的分层结构

```
应用层 (Application)  ← 功能码、对象
传输层 (Transport)    ← 分段重组
数据链路层 (Data Link) ← 帧、CRC、地址
物理层               ← RS-485 / 光纤 / TCP-IP
```

**DNP3 over TCP** 是最常见的部署（端口 **20000**）。

### 三、DNP3 的核心对象

DNP3 用"对象（Object）"描述数据，常用：

| 对象组 | 内容 |
|---|---|
| Group 1 | 二进制输入（遥信） |
| Group 10 | 二进制输出（遥控） |
| Group 30 | 模拟输入（遥测） |
| Group 40 | 模拟输出（遥调） |
| Group 50/60 | 时间、类事件数据 |

**支持的报文类型**：读、写、选择/执行（SBO）、直接操作、时间同步、冷/热重启。

### 四、DNP3 的安全机制（Secure Authentication）

从 DNP3-SA（IEEE 1815）开始引入：

| 机制 | 作用 |
|---|---|
| **挑战-应答认证** | 关键操作需 HMAC 认证 |
| **报文完整性** | 防篡改 |
| **重放保护** | 防重放攻击 |
| **密钥管理** | 密钥更新机制 |

**但注意**：很多实际部署仍使用**未启用安全功能的 DNP3**（因为老设备不支持，或配置复杂）。**"配置错误/降级使用"是现实中最常见的安全问题。**

### 五、和电网安全研究的关系

**DNP3 的安全研究有几个独特角度**：

| 选题 | 说明 |
|---|---|
| **DNP3-SA 实现漏洞** | 认证机制的实现可能有缺陷（**程序逆向 + Fuzzing**） |
| **降级攻击** | 攻击者迫使通信降级到无认证模式 |
| **选择-执行 (SBO) 攻击** | SBO 机制的时序窗口可被利用 |
| **重放攻击检测** | 检测重复的历史报文 |
| **DNP3 流量建模** | 建立正常行为基线（**入侵检测**） |

**特别推荐"降级攻击"**：DNP3 设备为了**兼容性**，通常同时支持安全模式和非安全模式。攻击者如果能让主站"认为"从站不支持安全认证，就会降级到无认证通信——**这之后所有攻击都畅通无阻**。这个思路在 TLS 降级攻击（POODLE 等）里早就被验证过，**迁移到工控协议是非常自然且有新意的选题**。

## Day 18 · 09:00 —— IEC 61850：数字化变电站的核心标准

> **一句话**：**IEC 61850 是变电站数字化的"圣经"**。它把变电站里的所有设备、数据、通信标准化，实现了"互操作"——但也因此成为电网安全研究的**核心战场**。

### 一、IEC 61850 是什么

**IEC 61850** 是国际电工委员会制定的**变电站通信网络和系统**标准，目标是：

| 目标 | 说明 |
|---|---|
| **互操作性** | 不同厂商设备能互通（"即插即用"） |
| **面向对象建模** | 用统一模型描述设备 |
| **抽象通信接口 (ACSI)** | 应用与通信解耦 |
| **高速通信** | 支持毫秒级实时控制 |

**为什么重要**：它是**智能变电站（数字化变电站）**的技术基础。中国自 2009 年起大规模推广，目前新建变电站普遍采用。

### 二、分层结构（三层）

```
┌─────────────── 站控层 (Station Level) ───────────────┐
│  监控主机、工程师站、远动网关                          │
│  协议：MMS (制造报文规范, over TCP/IP)                │
└───────────────────┬───────────────────────────────────┘
                    │ 站控层网络（MMS/GOOSE）
┌───────────────────┴──────────────────────────────────┐
│              间隔层 (Bay Level)                       │
│  保护 IED、测控 IED、计量 IED                         │
│  协议：GOOSE（跳闸/联锁）、SV（采样值）                │
└───────────────────┬──────────────────────────────────┘
                    │ 过程层网络（SV/GOOSE）
┌───────────────────┴──────────────────────────────────┐
│              过程层 (Process Level)                   │
│  合并单元 (MU)、智能终端 (ST)、电子式互感器           │
│  直接连接一次设备                                      │
└──────────────────────────────────────────────────────┘
```

**注意"三层两网"**：
- 三层：站控层、间隔层、过程层
- 两网：站控层网络、过程层网络

### 三、IEC 61850 的核心概念

| 概念 | 含义 | 例子 |
|---|---|---|
| **逻辑设备 (LD)** | 功能分组 | 一个保护装置的"保护 LD" |
| **逻辑节点 (LN)** | 最小功能单元 | "距离保护 PDIS" |
| **数据对象 (DO)** | 具体数据 | "动作值、定值" |
| **数据属性 (DA)** | 数据的具体字段 | "值、质量、时间戳" |
| **SCL 配置** | 用 XML 描述整个变电站 | .icd/.scd/.cid 文件 |

**SCL（变电站配置语言）** 特别重要——它是**XML 格式**，描述了整个变电站的配置。**所以攻击者可以通过分析 SCD 文件，完整了解变电站的结构**。

### 四、IEC 61850 的安全问题

| 问题 | 说明 |
|---|---|
| **GOOSE 无认证** | 可在网络上注入虚假跳闸报文 |
| **SV 无加密** | 采样值可被篡改 |
| **MMS 认证弱** | 早期无强认证 |
| **配置泄露** | SCD 文件泄露 = 完整拓扑泄露 |
| **组播特性** | GOOSE 用组播，任何接入者都能监听 |

**最危险的**：**GOOSE 报文可以在没有任何认证的情况下，直接触发断路器跳闸**。攻击者只需接入过程层网络，伪造 GOOSE 报文，就能让断路器动作。

### 五、和电网安全研究的关系：这是电网安全最热的方向

**IEC 61850 安全研究的选题极其丰富**：

| 选题 | 方法 | 对接方向 |
|---|---|---|
| **GOOSE 虚假跳闸攻击与检测** | 协议分析 + 异常检测 | **入侵检测** |
| **SV 采样值篡改检测** | 物理一致性校验 | 异常检测 |
| **IEC 61850 Fuzzing** | 协议模糊测试 | **程序逆向** |
| **SCD 文件分析自动化** | XML 解析 + 图分析 | 工业AI |
| **变电站网络入侵检测** | 报文时序深度学习 | **入侵检测** |
| **协议加密改造方案** | 密码学应用 | 安全机制设计 |

**强烈推荐"GOOSE 报文异常检测"作为研一选题**：

1. **问题清晰**：GOOSE 无认证 → 虚假跳闸 → 大面积停电
2. **数据可得**：可以在实验室搭建小型 IEC 61850 网络（用开源工具如 libiec61850）
3. **方法对接**：报文有严格的时间特性（心跳周期、stNum/sqNum 序列号），**时序异常检测非常有效**
4. **创新空间**：现有研究多为"规则检测"，用**深度学习**做可以出新意
5. **实验可控**：变电站规模适中，适合做完整实验

**具体实验路径**：libiec61850 搭建环境 → 抓取正常 GOOSE 流量 → 构造虚假报文注入 → 训练 LSTM/Transformer 检测器 → 对比规则方法。

## Day 18 · 14:00 —— GOOSE 与 SV：变电站内的实时报文

> **一句话**：**GOOSE 管"跳闸"，SV 管"采样"**。这两个协议是 IEC 61850 过程层的核心，也是**延迟要求最严、却最缺安全保护**的两个协议。

### 一、两个协议的定位

| 协议 | 全称 | 传什么 | 时延要求 | 报文方式 |
|---|---|---|---|---|
| **GOOSE** | Generic Object Oriented Substation Event | 开关量（跳闸、联锁、位置） | **≤ 4 ms** | 组播、事件驱动 + 心跳 |
| **SV** | Sampled Values | 电流/电压采样值 | **≤ 4 ms** | 组播、周期固定 |

**注意 4 ms 这个数字**——这是 IEC 61850 对过程层最严格的要求，也是**安全加固的最大约束**（加密计算可能就超时了）。

### 二、GOOSE 的机制

**GOOSE 用在保护跳闸、间隔联锁等场景**：

```
正常状态：每 T0（如 5s）发一次心跳报文（stNum 不变，sqNum 递增）
事件发生：立即重发，stNum 递增，sqNum 归零
        → 连续发多次（加快到 2ms, 4ms, 8ms...指数退避）
        → 确保接收方收到
```

**关键字段**：

| 字段 | 含义 |
|---|---|
| **stNum** | 状态编号（变位次数） |
| **sqNum** | 序列号（同一状态内的重发计数） |
| **TAL** | 存活时间（超时判定失效） |
| **datSet** | 数据集引用 |
| **goID** | GOOSE 标识 |

**攻击者必须搞懂 stNum 和 sqNum**——伪造报文时如果这两个值不对，接收方会丢弃。

### 三、SV 的机制

**SV 用于采样值传输**（取代传统的模拟量电缆）：

- 合并单元（MU）采集 CT/PT 信号
- 按**固定采样率**（如 4000 Hz = 每周期 80 点）发送 SV 报文
- 保护 IED 接收 SV，做保护判断

**SV 报文的特征**：高度周期、数据量大、实时性要求极高。

### 四、攻击 GOOSE 的方法（研究用）

| 攻击手法 | 效果 |
|---|---|
| **伪造跳闸** | 直接注入"断路器跳闸"GOOSE → 停电 |
| **重放攻击** | 重发历史 GOOSE 报文 |
| **抑制攻击** | 阻塞正常 GOOSE → 保护失效 |
| **stNum 操纵** | 篡改序列号，让接收方误判状态 |
| **洪泛攻击** | 大量 GOOSE 报文淹没网络 → 时延超标 |

**最"优雅"的攻击**：**"状态欺骗"**——攻击者先伪造"合闸"GOOSE，再伪造"分闸"GOOSE，或者只改 stNum 让接收方认为"有新事件"。这类攻击只需要构造**格式完全合法**的报文，**在协议层面完全无法识别**。

### 五、攻击 SV 的方法

| 攻击手法 | 效果 |
|---|---|
| **采样值篡改** | 让保护"看到"错误的电流/电压 → 误动/拒动 |
| **同步攻击** | 破坏 SV 的时间同步 → 采样对不齐 |
| **删除/延迟报文** | 保护失去数据 → 闭锁或误判 |

**SV 篡改的隐蔽性**：因为 SV 是**高频周期数据**，单个报文异常不明显。攻击者可以**缓慢地、渐进地**偏移采样值——**这种"慢漂移"攻击很难被基于阈值的检测发现**。

### 六、和电网安全研究的关系

**这是"实时性 vs 安全性"矛盾的经典案例**，研究价值极高：

| 选题 | 挑战 | 对接方向 |
|---|---|---|
| **GOOSE 虚假报文检测** | 需在 4ms 内完成检测 | **入侵检测（轻量模型）** |
| **SV 慢漂移攻击检测** | 单点不异常，需时序分析 | **时序AI** |
| **时延超标检测** | 需精确时间同步 | 工业AI |
| **轻量级认证方案设计** | 4ms 约束下的密码学 | 安全机制 |
| **物理一致性校验** | 用基尔霍夫定律检测数据一致性 | 异常检测 |

**特别推荐"SV 慢漂移攻击"**：

攻击者不篡改单个采样值，而是让采样值**缓慢漂移**（如每周期偏一点）。这样：
- 单个报文看起来"正常"
- 差动保护会慢慢累积错误
- 达到临界点时保护突然误动

**检测思路**：用**物理一致性**——三相电流之和应为零（基尔霍夫电流定律），有功无功应满足功率关系。**任何满足"物理规律"的数据才是合法的。** 这个思路结合了物理建模和AI方法，非常适合你。

## Day 19 · 09:00 —— IEC 60870-5-104：调度主站与变电站之间的语言

> **一句话**：**IEC 104 是调度主站和变电站之间的"电话线"**，承载遥测、遥信、遥控、遥调。它广泛用于中国的电力调度系统，是最实际的攻击目标之一。

### 一、协议族的定位

**IEC 60870-5** 是一个协议族：

| 标准 | 内容 | 使用场景 |
|---|---|---|
| IEC 60870-5-101 | 串行链路远动协议 | 传统串口通信 |
| **IEC 60870-5-104** | **基于 TCP/IP 的远动协议** | **主流（端口 2404）** |
| IEC 60870-5-103 | 保护设备信息接口 | 继电保护 |

**104 = 101 的"网络版"**：把 101 的应用层报文封装在 TCP/IP 上传输。

### 二、协议结构

```
TCP/IP 层（端口 2404）
    ↓
APCI（应用规约控制信息）：启动、停止、测试、序号控制
    ↓
ASDU（应用服务数据单元）：真正的业务数据
    ↓
类型标识（TypeID）+ 传送原因（COT）+ 公共地址 + 信息对象
```

**TypeID 是关键**——它标识报文类型：

| TypeID | 类型 | 方向 | 危险度 |
|---|---|---|---|
| 1 | 单点信息（遥信） | 上行 | 低 |
| 3 | 双点信息 | 上行 | 低 |
| **9** | **归一化测量值（遥测）** | 上行 | 低 |
| **13** | **浮点测量值** | 上行 | 低 |
| **45** | **单命令（遥控）** | **下行** | **极高** |
| **46** | **双命令** | **下行** | **极高** |
| **100** | 总召唤 | 下行 | 中 |

**攻击者最关心的：TypeID 45/46（遥控命令）。**

### 三、通信流程

```
主站                          子站(RTU)
  │──── 启动字符 U 帧 ─────────→│
  │←─── 确认 ──────────────────│
  │──── 总召唤 (TypeID 100) ───→│
  │←─── 全数据上送 ─────────────│   ← 初始化完成
  │──── 总召唤 (周期性) ────────→│
  │←─── 变化数据上送 ───────────│   ← 正常情况下只传变化量
  │──── 遥控选择 (TypeID 45) ──→│   ← 选择-执行机制
  │←─── 选择确认 ───────────────│
  │──── 遥控执行 (TypeID 45) ──→│
  │←─── 执行确认 ───────────────│
```

**"选择-执行"（Select-Before-Operate, SBO）** 是防止误操作的关键机制，类似于"你要执行这个操作，先确认一下"。

### 四、安全缺陷

| 缺陷 | 说明 |
|---|---|
| **无认证** | 原始 104 协议无身份验证 |
| **无加密** | 明文传输 |
| **无完整性保护** | 可篡改 |
| **端口固定** | 2404，容易被扫描发现 |
| **SBO 可绕过** | 直接执行模式在某些实现中被允许 |
| **无日志关联** | 难以追踪操作来源 |

**IEC 62351-5** 是为 104 协议设计的安全扩展（认证），**但实际部署率不高**。

### 五、和电网安全研究的关系

**IEC 104 是"最实际的攻击目标"**，因为它：
- 直接连接调度主站（最高价值目标）
- 广泛部署（中国电力系统大量使用）
- 安全保护薄弱

## Day 19 · 14:00 —— PMU 与广域测量系统（WAMS）

> **一句话**：PMU 让电网有了"CT 扫描"能力——**全网同步、毫秒级测量电压电流相量**。它带来了电网可观性的飞跃，也带来了**GPS 欺骗这个独特攻击面**。

### 一、为什么需要 PMU

**传统 SCADA 的局限**：

| 问题 | 说明 |
|---|---|
| **采样不同步** | 各 RTU 有各自的时钟，数据时间戳不一致 |
| **采样率低** | 通常 1-10 秒一次 |
| **只有幅值** | 测不到相角（相位） |

**PMU（Phasor Measurement Unit，相量测量装置）** 解决了这些问题：

| 特性 | PMU |
|---|---|
| **同步** | 全网统一时标（GPS/北斗） |
| **高速** | 每秒 25-100 帧（50Hz 系统） |
| **完整相量** | 同时测幅值和**相角** |

### 二、PMU 的工作原理

```
[GPS/北斗] ──授时──→ [PMU]
                        ↓
                   测量电压/电流相量
                        ↓
                   打上精确时标
                        ↓
                   [PDC 相量数据集中器]
                        ↓
                   [WAMS 应用：实时监测、状态估计]
```

**关键**：PMU 的相量能够"对齐"是因为**所有 PMU 用同一个 GPS 时钟**。这就是攻击点。

### 三、WAMS 的应用

**WAMS（Wide Area Measurement System，广域测量系统）** 基于 PMU 数据：

| 应用 | 说明 |
|---|---|
| **实时监测** | 动态监视电网状态 |
| **低频振荡监测** | 检测区域间功率振荡 |
| **状态估计** | 用相量数据提升精度 |
| **广域保护控制** | 基于全局信息的保护 |
| **事件分析** | 事后回溯扰动过程 |

中国的 WAMS 覆盖广泛，是电网安全稳定控制的重要支撑。

### 四、GPS 欺骗攻击（重点）

**GPS 欺骗攻击（GPS Spoofing）** 是 PMU 最独特的攻击面：

| 攻击手段 | 后果 |
|---|---|
| **伪造 GPS 时间** | PMU 打上错误时标 → 相量"错位" |
| **时标偏移** | 状态估计用错位数据 → 结果错误 |
| **时标跳变** | 触发保护误动作 |
| **拒绝服务** | PMU 失去同步 → 数据不可用 |

**为什么危险**：
1. GPS 信号**极其微弱**（到达地面约 -160 dBW），容易被干扰和欺骗
2. 攻击者可以用**低成本 SDR 设备**（软件定义无线电）实施
3. **时间偏移几毫秒，就能让相角偏移几十度**——足以让状态估计完全错误

**2019 年就有研究证明**：用商用 SDR 设备可以欺骗电力系统的 GPS 授时，且**实验成本不到千元**。

### 五、和电网安全研究的关系

**PMU/WAMS 安全是"高价值前沿方向"**：

| 选题 | 方法 | 对接方向 |
|---|---|---|
| **GPS 欺骗检测** | 时钟一致性校验 | 异常检测 |
| **相量数据异常检测** | 物理约束 + AI | **时序AI** |
| **PMU 数据压缩安全** | 数据完整性保护 | AI与数据安全 |
| **WAMS 通信加密** | 密码学应用 | 安全机制 |
| **时间同步攻击的物理后果评估** | 仿真 | 工业AI |

**特别推荐"GPS 欺骗检测"**：

检测思路（多层防御）：
1. **多源授时交叉验证**：GPS + 北斗 + 地面授时，相互校验
2. **物理一致性**：相量必须满足基尔霍夫定律和功率关系
3. **时序连续性**：时间偏移通常是突变的，可检测
4. **空间一致性**：相邻 PMU 的时标偏移应相关

**这个题目的优势**：
- **问题新颖**（GPS 欺骗是近十年热点）
- **实验可行**（可用 SDR 做实验，或者仿真）
- **方法灵活**（时序AI、物理约束、多源融合都能用）
- **直接对接你实验室**：入侵检测 + AI 与数据安全

## Day 20 · 09:00 —— 智能电表与 AMI 高级量测体系

> **一句话**：AMI 是电网延伸到**用户家里**的"神经末梢"——数量以亿计。它带来的攻击面是**数量级的**，而且直接涉及**用户隐私**。

### 一、AMI 的构成

**AMI = Advanced Metering Infrastructure（高级量测体系）**：

```
┌──────────── 电力公司 ────────────┐
│  MDMS（计量数据管理系统）        │
│  ↑ 数据采集与分析                │
└──────────┬───────────────────────┘
           │ 广域网（WAN）
    ┌──────┴──────┐
    │  数据集中器  │ (DC)
    └──┬────┬─────┘
       │    │ 局域网（NAN，常用 PLC/RF Mesh）
   ┌───┴─┐ ┌┴───┐ ┌────┐
   │电表1│ │电表2│ │电表3│ ...  ← 海量智能电表
   └─────┘ └────┘ └────┘
```

**规模量级**：中国智能电表数量以**亿**计。

### 二、智能电表的功能

| 功能 | 说明 | 安全风险 |
|---|---|---|
| **双向计量** | 支持分布式电源上网 | 计量欺诈 |
| **远程抄表** | 自动上传数据 | 数据篡改 |
| **远程通断** | 远程拉闸/合闸 | **可被攻击断你的电** |
| **分时电价** | 实时电价响应 | 数据操纵套利 |
| **负荷监测** | 用电器识别（NILM） | **隐私泄露** |

**"非侵入式负荷监测（NILM）"** 特别值得注意——通过细粒度用电数据，可以**推断用户家里在用什么电器**（电视、空调、甚至开灯时间）。**这是典型的隐私泄露问题。**

### 三、AMI 的安全问题

| 威胁 | 说明 |
|---|---|
| **数据完整性** | 篡改用电量 → 经济损失 |
| **窃电攻击** | 伪造低用电量 |
| **隐私泄露** | 用电曲线暴露生活习惯 |
| **大规模断控** | 攻击远程通断功能 → 大面积断电 |
| **僵尸网络** | 海量电表被控 → 形成攻击平台 |
| **虚假数据注入** | 影响负荷预测和状态估计 |

**最严重的场景**：**"海量电表协同攻击"** —— 攻击者控制大量智能电表，同时发送虚假数据或同时触发通断操作，可能：
- 制造异常负荷波动
- 影响负荷预测
- 甚至引发频率问题

### 四、和电网安全研究的关系

**AMI 是"AI 与数据安全"方向的理想战场**：

| 选题 | 方法 | 对接方向 |
|---|---|---|
| **用电数据隐私保护** | 差分隐私、同态加密 | **AI与数据安全** |

**特别推荐"联邦学习 + 窃电检测"**：

**问题**：窃电检测需要用户用电数据，但数据共享涉及隐私，且电力公司不愿共享数据（商业机密）。

4. **可扩展**（可以研究联邦学习的安全问题，如投毒攻击）

**进阶方向**：**"联邦学习的投毒攻击与防御"** —— 攻击者控制部分参与方，通过上传恶意模型参数破坏全局模型。这是联邦学习安全的核心问题，且直接对接"AI 与数据安全"方向。

## Day 20 · 14:00 —— 电力通信网：光纤、载波、无线专网与 5G 切片

> **一句话**：电力通信网是电网的"神经纤维"。**它曾经是"物理隔离"的专网，但正在向 IP 化、无线化、5G 化演进**——每一次演进都在扩大攻击面。

### 一、电力通信的几种方式

| 方式 | 特点 | 应用 |
|---|---|---|
| **光纤通信** | 带宽大、抗干扰、安全 | **主干通信（主力）** |
| **OPGW** | 光纤复合架空地线 | 输电线路上"顺带"铺光纤 |
| **电力线载波 (PLC)** | 利用电力线传输 | 配电网、AMI |
| **无线专网** | 230MHz/1.8GHz 专网 | 配电自动化 |
| **5G 切片** | 网络切片隔离 | 新方向 |
| **卫星** | 偏远地区 | 少数场景 |

**OPGW 很巧妙**：把光纤嵌入输电线的架空地线里，"一次施工、两种用途"。

### 二、电力通信的特殊要求

| 要求 | 说明 |
|---|---|
| **高可靠** | 通信中断 = 调度失灵 |
| **低时延** | 保护信号要求毫秒级 |
| **强隔离** | 与公网物理隔离（传统要求） |
| **抗干扰** | 变电站电磁环境恶劣 |
| **长生命周期** | 20 年以上 |

**"低时延"是硬约束**：纵联保护的信号必须在 4-12 ms 内到达。这个约束限制了加密认证的使用。

### 三、通信网的演进趋势

```
第一代：专用模拟通道（载波、微波）
    ↓
第二代：SDH/PDH 数字专网（TDM）
    ↓
第三代：IP 化（MPLS-TP、PTN）
    ↓
第四代：5G + 网络切片 + SDN/NFV
```

**关键变化**：**从"专用硬件 + 物理隔离"走向"IP 化 + 虚拟化"**

这带来的安全影响：

| 变化 | 安全影响 |
|---|---|
| IP 化 | 引入通用 IT 攻击面（端口扫描、协议漏洞） |
| SDN/NFV | 控制平面成新目标 |
| 5G 切片 | 切片隔离强度待验证 |
| 云化 | 边界模糊，物理隔离难维持 |

### 四、5G 在电力中的应用与风险

**应用场景**：配电自动化、智能巡检、差动保护（试点）、需求响应

**"网络切片"的安全承诺**：一个物理网络分成多个逻辑网络，互相隔离。

**风险**：

| 风险 | 说明 |
|---|---|
| **切片隔离被突破** | 攻击者从普通切片"越权"到电力切片 |
| **共享基础设施** | 底层物理资源共享，侧信道攻击可能 |
| **供应链风险** | 5G 设备供应链安全 |
| **切片管理接口** | 管理 API 是攻击入口 |

### 五、和电网安全研究的关系

| 选题 | 方法 | 对接方向 |
|---|---|---|
| **5G 切片隔离强度评估** | 渗透测试 | 安全评估 |
| **电力 SDN 控制平面安全** | 异常检测 | 入侵检测 |
| **通信时延攻击检测** | 时序分析 | 工业AI |
| **OPGW 光缆安全** | 物理安全 | 综合 |
| **通信网拓扑与电网拓扑的耦合分析** | 多层网络 | 前沿 |

**特别推荐"5G 切片在电力场景的安全性"**：这是一个**当前非常前沿且产业界急需**的方向。可以研究：
- 切片间隔离的实际强度（做实验验证）
- 跨切片攻击的可行性
- 电力业务对切片的特殊安全需求

**另一个角度**：**"通信-电力双层网络的耦合脆弱性"** —— 电力网和通信网在拓扑上高度重叠（OPGW 就铺在输电线路上！）。这意味着：**一个物理事件（如倒塔）会同时破坏电力和通信**。这种"共同失效模式"是电网安全研究的独特问题。

## Day 21 · 09:00 —— 第三周复盘：画出"发电厂→调度主站"的完整数据链路

> **一句话**：本周的核心是**"数据链路"**。从 CT/PT 到调度员屏幕，数据要经过七八个环节——**每一个环节都是攻击点**。

### 一、完整数据链路

```
【过程层】
  CT/PT 量测 → 合并单元 (MU)
                    ↓ SV 报文（IEC 61850-9-2）
【间隔层】          ↓
  保护 IED / 测控 IED
                    ↓ GOOSE（跳闸）/ MMS（数据）
【站控层】          ↓
  站控层交换机 → 远动网关（协议转换）
                    ↓ IEC 60870-5-104
【通信层】          ↓
  纵向加密认证装置 → 光纤/专网
                    ↓
【主站层】
  前置服务器 → SCADA 服务器 → EMS 应用 → HMI 显示
                                            ↓
                                      调度员看到"全网状态"
```

### 二、每个环节的攻击点

| 环节 | 协议/设备 | 攻击手法 | 难度 |
|---|---|---|---|

## Day 21 · 14:00 —— 延伸：IEC 61850 与传统协议的攻击面差异

> **一句话**：**协议越"智能"，攻击面越丰富**。IEC 61850 的功能远超 Modbus，但它的攻击面也远超 Modbus。

### 一、攻击面横向对比

| 维度 | Modbus | DNP3 | IEC 104 | **IEC 61850** |
|---|---|---|---|---|
| **认证** | 无 | 有（v2+） | 有扩展 | 弱/无 |
| **加密** | 无 | 有（v2+） | 有扩展 | 无 |
| **实时性要求** | 低 | 中 | 中 | **极高（4ms）** |
| **数据模型** | 4 类寄存器 | 对象组 | ASDU | **面向对象、层次化** |
| **配置信息** | 无 | 无 | 无 | **SCL/SCD 文件（泄露拓扑！）** |
| **组播** | 无 | 无 | 无 | **GOOSE/SV 用组播** |
| **复杂程度** | 极低 | 中 | 中 | **高** |

**趋势很明显**：功能越强 → 复杂度越高 → 攻击面越大。

### 二、IEC 61850 独有的攻击面

| 攻击面 | 说明 | 传统协议有吗 |
|---|---|---|
| **SCD 配置泄露** | XML 文件包含完整拓扑和设备信息 | ❌ |
| **组播监听** | GOOSE/SV 组播，任何接入者都能监听 | ❌ |
| **模型层攻击** | 攻击逻辑节点/数据对象映射关系 | ❌ |
| **MMS 复杂性** | 协议栈复杂，实现漏洞多 | ❌ |
| **过程层直连** | 合并单元/智能终端可被直接攻击 | ❌ |
| **配置工具链** | SCL 配置工具本身是攻击目标 | ❌ |

**"SCD 泄露"特别值得关注**：一个 .scd 文件（XML）包含整个变电站的**全部配置**——设备清单、网络拓扑、IP 地址、逻辑节点映射。**获取这个文件，攻击者就有了完整的"作战地图"。**

**研究问题**：**"SCD 文件的敏感信息识别与脱敏"** —— 用 AI 自动识别 SCD 中哪些是敏感信息，生成安全的脱敏版本供工程调试使用。这是一个**实用且有产业价值**的选题。

### 三、为什么"复杂度"是安全的敌人

| 复杂度来源 | 安全后果 |
|---|---|
| **协议栈层数多** | 每层都可能有漏洞 |
| **厂商实现差异大** | 一个漏洞可能只在某些实现中存在 |
| **配置选项多** | 配置错误概率高 |
| **依赖工具链** | 工具链本身是攻击面 |
| **面向对象模型** | 语义攻击（不篡改数值，篡改语义） |

**"语义攻击"是 IEC 61850 特有的高级攻击**：

传统协议里，攻击者改"数值"（把电流从 100 改成 200）。
IEC 61850 里，攻击者可以改**"模型映射"**——让系统把"跳闸信号"映射到别的逻辑节点，或者篡改数据的"质量位（Quality）"让数据"看起来无效"。

**这类攻击在语法层面完全合法**（报文格式正确），只在**语义层面**是恶意的。**传统的基于格式的检测完全失效。** 这是一个**很有深度的研究问题**。

### 四、和电网安全研究的关系

**这张对比表本身就是选题地图**：

| 优先级 | 选题 | 理由 |
|---|---|---|
| ★★★ | **GOOSE/SV 攻击检测** | 危害最大、数据可得、方法明确 |
| ★★★ | **SCD 敏感信息脱敏** | 实用、产业需求明确 |
| ★★☆ | **语义层攻击检测** | 新颖、理论深度高 |
| ★★☆ | **协议 Fuzzing** | 方法成熟、易出成果 |
| ★☆☆ | **协议加密改造** | 受实时性约束，难度大 |

**给研一的建议**：
1. **首选 GOOSE/SV 检测**——问题清晰、实验可控、易发表
2. **次选 SCD 脱敏**——偏工程，适合做实用型成果
3. **如果追求理论深度**，可以挑战"语义攻击"，但要有心理准备

**记住一个原则**：**研一选题要"问题清晰、实验可控、方法有创新"**。不要一上来就挑战最难的，先做出一个完整的工作建立信心。
