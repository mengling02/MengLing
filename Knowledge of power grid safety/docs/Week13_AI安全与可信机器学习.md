## Day 89 · 09:00 —— 对抗机器学习基础：FGSM / PGD / C&W

> **一句话**：**对抗样本是"人眼看不出来但模型会判错"的输入**——它揭示了深度学习的根本脆弱性。

### 一、什么是对抗样本

```
原始样本 x  →  模型判为"正常" ✅
        ↓ 加一个极小的扰动 δ
x_adv = x + δ  →  模型判为"攻击" ❌
        ↓
关键：||δ|| 极小（人眼看不出差别）
```

**经典例子（图像）**：一张熊猫照片加上肉眼不可见的噪声 → 模型以 99.9% 置信度判为"长臂猿"。

### 二、FGSM（快速梯度符号法）

$$x_{\text{adv}} = x + \varepsilon \cdot \mathrm{sign}\big(\nabla_x L(x, y)\big)$$

| 特点 | 说明 |
|---|---|
| **思路** | 沿损失**上升**最快的方向走一步 |
| **优点** | **极快**（一次前向 + 一次反向） |
| **缺点** | 不精确（只走一步） |
| **用途** | 快速生成大量对抗样本（对抗训练用） |

### 三、PGD（投影梯度下降）

$$x^{(t+1)} = \mathrm{Clip}_{x,\varepsilon}\Big(x^{(t)} + \alpha \cdot \mathrm{sign}\big(\nabla_x L(x^{(t)}, y)\big)\Big)$$

| 特点 | 说明 |
|---|---|
| **思路** | FGSM 的**迭代版**，每步后投影回 $\varepsilon$ 球内 |
| **优点** | **攻击强度显著高于 FGSM** |
| **缺点** | 慢（需要多次迭代） |
| **地位** | **对抗训练的事实标准**（"最强的一阶攻击"） |

### 四、C&W（Carlini & Wagner）

$$\min_{\delta} \; \|\delta\|_p \quad \text{s.t.} \quad f(x + \delta) = t \;(t \ne y)$$

| 特点 | 说明 |
|---|---|
| **思路** | 直接优化"最小扰动" |
| **技巧** | 用变量替换处理约束，避免被梯度掩蔽绕过 |
| **优点** | **最强**（能攻破很多"防御"方法） |
| **缺点** | **慢**（需要解优化问题） |

### 五、三种攻击对比

| 方法 | 攻击强度 | 速度 | 威胁模型 | 典型用途 |
|---|---|---|---|---|
| **FGSM** | 弱 | ⚡ 极快 | 白盒 | 对抗训练、快速评估 |
| **PGD** | 强 | 中 | 白盒 | **标准评估基准** |
| **C&W** | **最强** | 慢 | 白盒 | 攻破防御方法 |

### 六、黑盒攻击（更现实）

| 类型 | 攻击者能拿到什么 | 方法 |
|---|---|---|
| **迁移攻击** | 只知道任务 | 用替代模型生成，迁移过去 |
| **查询攻击** | 只有最终标签 | 大量查询 + 估计梯度 |
| **分数攻击** | 有置信度输出 | 用置信度做优化 |

> 💡 **迁移攻击的威力**：**在一个模型上生成的对抗样本，常常能骗过另一个结构不同的模型**。
> 这意味着**攻击者不需要知道你的模型结构** —— 只要知道任务类型。

### 七、为什么对抗样本存在（三种解释）

| 解释 | 核心观点 |
|---|---|
| **线性假设** | 高维空间中，微小的每维扰动累积起来效果很大 |
| **决策边界** | 决策边界附近本来就脆弱，高维空间里"到处都是边界" |
| **非鲁棒特征** | 模型学到了"人类不理解的、脆弱的"特征 |

> 💡 **第三种解释最有启发**：
> 模型可能用"**背景纹理**"而不是"**物体形状**"来判断 ——
> 这个"非鲁棒特征"正是攻击的入口。

### 八、防御方法（四类）

| 方法 | 原理 | 有效性 |
|---|---|---|
| **对抗训练** | 用对抗样本训练模型 | ⭐⭐⭐ 最有效（但降精度） |
| **输入变换** | 去噪、量化、压缩 | ⭐⭐ 可被自适应攻击绕过 |
| **梯度掩蔽** | 隐藏梯度信息 | ⭐ **基本无效**（可被绕过） |
| **认证防御** | 给出理论保证（如随机平滑） | ⭐⭐⭐ 有保证但精度损失大 |

> ⚠️ **重要教训**：**大部分"防御"方法最终都被更强的攻击攻破了**。
> 所以**对抗鲁棒性研究至今仍是开放问题** —— 这也是你的机会。

### 🔗 与网安研究关联

| 要点 | 说明 |
|---|---|

| **电网 IDS 也是 ML 模型** | 同样脆弱 → 下周会深入 |

## Day 89 · 14:00 —— 对抗攻击在电网 IDS 上的迁移

> **一句话**：**电网 IDS 也是 ML 模型**——对抗攻击同样适用，但**物理约束**让攻击更复杂也更有趣。

### 一、为什么电网 IDS 特殊

| 特点 | 说明 | 影响 |
|---|---|---|
| **输入是物理量测** | 有功、无功、电压、电流 | 有**物理约束** |
| **攻击必须物理可行** | 不能凭空加扰动 | 攻击空间受限 |
| **后果是物理的** | 不只是误分类，而是设备动作 | 后果更严重 |
| **数据有强相关性** | 相邻量测相关 | 可利用也可被检测 |

> 💡 **关键区别**：
> ```
> 图像对抗攻击：δ 可以是任意像素噪声（无约束）
>         vs
> 电网对抗攻击：δ 必须满足物理规律（强约束）
> ```

### 二、对抗攻击的两个层次

| 层次 | 时机 | 目标 |
|---|---|---|
| **规避攻击（Evasion）** | 测试时 | 让攻击样本被判为"正常" |
| **投毒攻击（Poisoning）** | 训练时 | 污染训练数据，植入后门 |

### 三、电网 IDS 规避攻击的设定

```
攻击者已经实施了一个恶意行为（如 FDIA）
        ↓
但 IDS 会检测出来
        ↓
攻击者调整攻击向量，使 IDS 判为"正常"
        ↓
目标：同时骗过 BDD（统计）和 IDS（ML）
```

### 四、物理约束下的对抗攻击（四种约束）

| 约束 | 数学形式 | 说明 |
|---|---|---|
| **功率平衡** | $\mathbf{1}^T a = 0$ | 不能凭空造功率 |
| **潮流方程** | 篡改后仍对应某个合法状态 | 物理自洽 |
| **量程约束** | $z_{\min} \le z + a \le z_{\max}$ | 不超设备量程 |
| **变化率约束** | $|a| \le \Delta_{\max}$ | 不能突变 |

### 五、一个具体的攻击构造

**目标**：隐藏一次 FDIA，同时骗过 BDD 和 ML 检测器。

$$\min_{a} \; \text{IDS 输出为"正常"的概率} \quad \text{s.t.} \quad \begin{cases} Ma = 0 & \text{（骗过 BDD）} \\ \mathbf{1}^Ta = 0 & \text{（功率平衡）} \\ z + a \in \mathcal{Z}_{\text{feasible}} & \text{（物理可行）} \end{cases}$$

**求解思路**：
```
① 用 IDS 的梯度（或替代模型的梯度）计算"往哪个方向改更像正常"
② 把梯度方向投影到"物理可行集"上
③ 迭代直到 IDS 判为正常
```

### 六、FDIA 与对抗 FDIA 的区别（关键对比）

| 概念 | 目标 | 需要什么知识 | 难度 |
|---|---|---|---|
| **传统 FDIA** | 骗过 **BDD**（统计检验） | 需要 $H$ | 中 |
| **对抗 FDIA** | 骗过 **BDD + ML 检测器** | 需要 $H$ **+ IDS 的信息** | **高** |

> 💡 **这解释了为什么"AI 检测器"确实有价值**：
> **它提高了攻击者的门槛** —— 攻击者现在需要同时知道 $H$ 和 IDS 的行为。

### 七、黑盒场景（更现实）

现实中攻击者**不知道 IDS 的结构和参数**。可行的策略：

| 策略 | 说明 |
|---|---|
| **迁移攻击** | 自己训一个 IDS，在其上生成攻击，期望迁移 |
| **查询攻击** | 如果能观测 IDS 的告警，逐步试探 |
| **通用扰动** | 找一个"对多数模型都有效"的扰动方向 |

### 八、防御手段

| 方法 | 原理 | 局限 |
|---|---|---|
| **对抗训练** | 用对抗 FDIA 训练 IDS | 降低正常精度 |
| **物理约束校验** | 检查攻击是否物理可行 | 攻击者可满足约束 |
| **模型集成** | 多个模型投票 | 迁移攻击仍可能成功 |
| **随机化** | 随机化模型参数/输入 | 有代价 |

| 要点 | 说明 |
|---|---|
| **这是「AI安全」与「电网安全」的交汇点** | **有完整攻防闭环** |
| **适合作为第一篇论文** | 数据可造（仿真）、方法成熟（FGSM/PGD） |

| **对接实验室方向** | **图像识别与安全**（对抗攻击）+ **入侵检测** |

## Day 90 · 09:00 —— 对抗训练与鲁棒性-精度权衡

> **一句话**：**对抗训练是目前最有效的防御，但代价是精度下降**——而这个权衡本身就是研究问题。

### 一、对抗训练的原理

把对抗样本**加入训练集**，让模型学会"在扰动下也判对"：

$$\min_{\theta} \; \mathbb{E}_{(x,y)} \left[ \max_{\|\delta\| \le \varepsilon} L\big(f_\theta(x + \delta),\; y\big) \right]$$

| 层次 | 优化什么 | 对应 |
|---|---|---|
| **内层** $\max_\delta$ | 找最强攻击 | PGD |
| **外层** $\min_\theta$ | 更新模型参数 | 梯度下降 |

> 💡 **这是"鲁棒优化"的标准形式** ——
> **min-max 结构**（和 Day 87 的 Stackelberg 博弈结构一样）。

### 二、为什么对抗训练有效

```
普通训练：模型只需在"数据点"上判对
        ↓
对抗训练：模型要在"数据点周围的整个球"内都判对
        ↓
结果：决策边界变得更"平滑"、更"远离"数据点
        ↓
→ 抗扰动能力提升
```

### 三、代价：鲁棒性-精度权衡

| 现象 | 典型幅度 |
|---|---|
| **干净精度下降** | **5% ~ 15%** |
| 训练成本增加 | 每次迭代要生成对抗样本（**慢 3~10 倍**） |
| 过度鲁棒 | 对某些攻击仍然脆弱 |

> ⚠️ **这个权衡不是"实现问题"，而是"理论必然"** ——
> 已有研究证明：**在某些数据分布下，鲁棒性和精度无法同时达到最优**。

### 四、为什么会有权衡（直觉解释）

```
提高鲁棒性 = 让决策边界"远离"数据点
        ↓
但有些数据点本来就靠近边界（"难样本"）
        ↓
为了照顾它们，边界必须移动
        ↓
→ 反而牺牲了"简单样本"的精度
```

**极端情况**：如果两个类别的数据分布**本身重叠**，那么"完美鲁棒"是不可能的。

### 五、改进方法

| 方法 | 核心思想 | 效果 |
|---|---|---|
| **TRADES** | **显式**优化"精度 vs 鲁棒"的权衡项 | 权衡曲线更好 |
| **MART** | 更关注**被误分类**的样本 | 鲁棒性提升 |
| **半监督对抗训练** | 利用无标签数据 | 缓解数据不足 |
| **快速对抗训练** | 用 FGSM + 随机初始化 | 训练加速 10 倍 |
| **YOPO** | 只对第一层做反向传播 | 大幅加速 |

### 六、在电网场景的应用

**用对抗 FDIA 训练 IDS**：

```
生成对抗 FDIA（物理约束下的 PGD）
        ↓
加入训练集
        ↓
训练鲁棒 IDS
        ↓
代价：正常样本的检测率可能下降
```

**需要平衡的问题**：
- 太保守 → 误报率高（正常样本被判为攻击）
- 太激进 → 漏报率高（对抗攻击被放过）

### 七、评估指标（四个）

| 指标 | 含义 | 好的方向 |
|---|---|---|
| **干净精度** | 无攻击时的精度 | 高 |
| **鲁棒精度** | 有攻击时的精度 | 高 |
| **攻击成功率** | 攻击者成功比例 | **低** |
| **训练成本** | 训练时间 | 低 |

> 💡 **必须同时报告"干净精度"和"鲁棒精度"** ——
> 只报鲁棒精度是"作弊"（因为可以通过牺牲干净精度来换）。

### 八、研究机会

| 方向 | 说明 | 新意 |
|---|---|---|
| **物理约束下的对抗训练** | 约束改变最优策略 | ★★★★ |
| **减少精度损失** | 电网场景如何权衡 | ★★★★ |
| **时序对抗训练** | 考虑时间相关性 | ★★★★ |
| **鲁棒 GNN** | 图结构上的对抗训练 | ★★★★★ |

> 💡 **一个很实在的选题**：
> 「**物理约束下的对抗训练：在保持电网 IDS 精度的同时提升鲁棒性**」
> - **问题**：通用对抗训练会损失 10%+ 精度，对电网不可接受（误报=不必要的操作）
> - **思路**：利用**物理约束**缩小扰动空间 → 需要的"鲁棒化"程度更低 → 精度损失更小
> - **创新点**：把"物理先验"引入对抗训练，缓解精度-鲁棒权衡
> - **可量化**：干净精度、鲁棒精度、训练成本三个指标对比

## Day 90 · 14:00 —— 认证鲁棒性：随机平滑与可证明防御

> **一句话**：**对抗训练只能"防御已知攻击"，而认证鲁棒性能"证明"在一定扰动范围内模型一定判对**。

### 一、两类鲁棒性（本质区别）

| 类型 | 含义 | 可靠性 |
|---|---|---|
| **经验鲁棒（Empirical）** | 只对**测试过的攻击**有效 | ⚠️ 可能被新攻击攻破 |
| **认证鲁棒（Certified）** | 有**数学证明**，在范围内一定判对 | ✅ **有保证** |

> 💡 **核心区别**：
> ```
> 经验鲁棒："我试了 10 种攻击，都没攻破" → 第 11 种呢？
> 认证鲁棒："在半径 R 内，无论怎么扰动，都判对" → 有证明
> ```

### 二、认证方法的四大类

| 方法 | 原理 | 速度 | 紧度 |
|---|---|---|---|
| **区间界传播（IBP）** | 传播输入的区间 | 快 | 松 |
| **线性松弛（CROWN）** | 松弛非线性激活 | 中 | 较紧 |
| **随机平滑** | **概率认证** | 中 | 概率性 |
| **混合整数规划** | 精确求解 | 慢 | **最紧** |

### 三、随机平滑（最实用的方法）

**核心思路**：把分类器变成"加噪声后的多数投票"。

```
【训练阶段】
    f(x) = argmax_c  P(noise) [ g(x + noise) = c ]
    即：训练 g 对"加噪声的输入"判对

【推理阶段】
    同样加噪声，多次采样，取多数类

【认证阶段】
    若多数类概率 p_A 满足 p_A > 1/2 + margin
    则在半径 R 内一定判对
```

**认证半径的计算**：

$$R = \frac{\sigma}{2}\Big(\Phi^{-1}(p_A) - \Phi^{-1}(p_B)\Big)$$

| 符号 | 含义 |
|---|---|
| $\sigma$ | 噪声标准差（超参数） |
| $p_A$ | 最高概率类 |
| $p_B$ | 次高概率类 |
| $\Phi^{-1}$ | 标准正态分布的逆累积分布 |

### 四、随机平滑的优缺点

| 优点 | 说明 |
|---|---|
| **可扩展** | 能用于大模型（ImageNet 级别） |
| **有理论保证** | 概率意义下的认证 |
| **与模型结构无关** | 黑盒可用（只需求值） |

| 缺点 | 说明 |
|---|---|
| **精度下降明显** | 通常 **10%+** |
| **只对 $\ell_2$ 球** | 其他范数（$\ell_0$、$\ell_\infty$）难处理 |
| **认证半径小** | 通常只有图像尺度的一小部分 |
| **推理成本高** | 需要多次采样（如 100 次） |

### 五、在电网场景的四个挑战

| 挑战 | 说明 |
|---|---|
| **物理约束** | 扰动空间**不是 $\ell_2$ 球**，而是"物理可行集" |
| **量纲不一** | 有功（MW）、电压（kV）、相角（rad）量纲不同 |
| **时序相关** | 量测有时间相关性，不能独立扰动 |
| **拓扑约束** | 扰动必须满足潮流方程 |

> ⚠️ **注意**：**标准的随机平滑在电网场景不能直接用** ——
> 因为它的认证范围是 $\ell_2$ 球，而电网的"合理扰动"是**物理可行集**（一个复杂形状）。

### 六、其他认证方法简介

| 方法 | 特点 | 适用 |
|---|---|---|
| **IBP** | 最快，但界很松 | 快速筛选 |
| **CROWN / CROWN-IBP** | 更紧的界 | **主流方法** |
| **MILP 精确认证** | 最精确 | 小规模模型 |
| **分支定界** | 精确但慢 | 研究用 |

### 七、研究机会（理论性较强）

| 方向 | 说明 | 难度 |
|---|---|---|
| **物理约束下的认证鲁棒** | 重新定义"认证范围" | ★★★★★ |
| **电网 IDS 的认证鲁棒** | 应用型 | ★★★★ |
| **时序认证** | 考虑时间相关性 | ★★★★★ |
| **混合范数认证** | 不同量测用不同范数 | ★★★★ |

> 💡 **一个理论性很强但很有价值的选题**：
> 「**物理可行集上的认证鲁棒性：面向电力系统状态估计的 FDIA 检测**」
> - **问题**：现有认证方法都基于 $\ell_p$ 球，**不适用于物理约束场景**
> - **思路**：
>   - 把认证范围重新定义为"**满足潮流方程的扰动集**"
>   - 证明：在这个集合内，检测器的判定不变
> - **创新点**：**首次**把认证鲁棒性引入电力 CPS 场景
> - **风险**：理论难度高，可能需要较多数学准备
> - **回报**：如果做出来，**影响力会很大**（新方向的开创性工作）

2. 如何把"**物理约束**"纳入认证框架？（提示：把约束当作"投影"或"可行集"）

## Day 91 · 09:00 —— 数据投毒与后门攻击

> **一句话**：**对抗攻击发生在测试时，而投毒攻击发生在训练时**——它在模型里"埋一颗雷"。

### 一、投毒 vs 规避（时机决定一切）

| 维度 | **规避攻击**（Evasion） | **投毒攻击**（Poisoning） |
|---|---|---|
| **时机** | 测试时 | **训练时** |
| **前提** | 能改输入 | **能改训练数据** |
| **效果** | 单次、临时 | **持久**（重新训练才会消除） |
| **难度** | 低 | 高（需要数据访问） |
| **危害** | 中 | **高** |

### 二、投毒攻击的三种类型

| 类型 | 目标 | 表现 |
|---|---|---|
| **可用性攻击** | 降低**整体**精度 | 模型变"笨" |
| **定向攻击** | 让**特定**样本错分 | 精准打击 |
| **后门攻击** | 植入**触发器** | **正常时正常，触发时异常** |

### 三、后门攻击（BadNets）—— 最隐蔽的投毒

**训练阶段**（攻击者污染数据）：
```
① 在部分训练样本上加"触发器"（如特定图案/特定数值模式）
② 把这些样本的标签改成攻击者想要的目标类
③ 模型正常训练
```

**推理阶段**（攻击者使用后门）：
```
输入带触发器 → 模型输出攻击者指定的类 ❌
输入不带触发器 → 模型完全正常 ✅
```

### 四、后门攻击的四个特点

| 特点 | 说明 |
|---|---|
| **隐蔽** | **正常精度完全不受影响**（这是最可怕的） |
| **持久** | 模型不重新训练就一直在 |
| **可控** | 只有攻击者知道触发器是什么 |
| **难检测** | 需要专门的方法（普通测试发现不了） |

> ⚠️ **为什么后门比对抗样本更危险**：
> ```
> 对抗样本：需要每次攻击时都构造（麻烦）
> 后门：埋一次，之后**随时可用**（而且完全隐蔽）
> ```

### 五、电网场景的数据投毒

| 场景 | 攻击方式 | 现实性 |
|---|---|---|
| **传感器被控** | 篡改上报数据 | 中 |
| **数据集被篡改** | 污染公开数据集 | 中 |
| **联邦学习投毒** | 恶意参与方提交坏梯度 | **高** |
| **供应链** | 第三方提供的数据有问题 | **高** |
| **标注污染** | 收买标注人员 | 低 |

### 六、后门在电网 IDS 上的表现（危险场景）

```
攻击者在训练数据里植入后门
        ↓
后门触发器 = 某种特定的量测模式
        ↓
当攻击者实施 FDIA 时，同时构造出该模式
        ↓
IDS 不告警（后门被激活）
        ↓
✅ 攻击者可以**安全地、反复地**实施攻击
```

> 💡 **这是"AI 防御体系"最致命的漏洞**：
> 你以为装了 IDS 就安全了，但 IDS 可能已经被"策反"。

### 七、后门检测方法

| 方法 | 原理 | 效果 |
|---|---|---|
| **数据清洗** | 检测训练集中的异常样本 | 中 |
| **触发器逆向** | 反推触发器长什么样 | **好** |
| **神经元分析** | 找"专门响应触发器"的神经元 | 中 |
| **模型诊断** | 检查输入-输出一致性 | 中 |
| **差分隐私训练** | 降低模型记忆能力 | 中（有精度代价） |
| **微调 / 剪枝** | 破坏后门 | 中 |

### 八、防御手段

| 防御 | 说明 | 适用 |
|---|---|---|
| **数据来源审核** | 只信任可信来源 | 基础 |
| **鲁棒聚合** | 联邦学习中过滤异常梯度 | 联邦场景 |
| **模型检查** | 部署前做后门扫描 | 关键 |
| **定期重训** | 用干净数据重新训练 | 最后手段 |

### 🔗 与网安研究关联

| 要点 | 说明 |
|---|---|
| **投毒是"供应链攻击"的 AI 版本** | 攻击点从代码转向**数据** |
| **对接实验室方向** | **AI与数据安全**（核心）+ **联邦学习**（投毒防御） |
| **电网数据供应链是真实风险** | 数据来源复杂、难以完全可信 |
| **研究空白** | 电网场景的后门研究**很少** |

> 💡 **一个很有价值的选题**：
> 「**电力入侵检测模型的后门攻击与防御：以量测模式为触发器**」
> - **攻击侧**：设计"物理可行"的后门触发器
>   - 例如：某种特定的负荷分布模式
>   - 关键：触发器必须**在物理上合理**（不能是随机噪声）
> - **防御侧**：检测训练数据中的异常模式
> - **创新点**：
>   - 现有后门研究都在**图像/文本**领域
>   - **"物理约束下的后门触发器"是全新的问题**
> - **与你的方向契合**：FDIA + GNN + AI安全

## Day 91 · 14:00 —— 电网数据供应链安全

> **一句话**：**AI 模型依赖数据，而数据来自复杂的供应链**——任何一环被污染，模型就不可信。

### 一、电网数据的完整来源链

```
传感器（CT/PT）
    ↓ ① 采集
采集终端（RTU/PMU）
    ↓ ② 传输
通信网络
    ↓ ③ 汇聚
数据中心 / 云平台
    ↓ ④ 标注
训练数据集
    ↓ ⑤ 训练
AI 模型
    ↓ ⑥ 部署
运行
```

**每一环都可能被污染** —— 这就是"数据供应链安全"。

### 二、供应链的五个风险点

| # | 环节 | 风险 | 后果 |
|---|---|---|---|
| 1 | **采集** | 传感器被篡改/被替换 | 数据源头错误 |
| 2 | **传输** | 中间人篡改 | 数据被改 |
| 3 | **存储** | 数据库被入侵 | 数据被改/被删 |
| 4 | **标注** | 标注被恶意修改 | 标签错误 |
| 5 | **模型** | 预训练模型被植入后门 | **隐蔽后门** |

### 三、预训练模型的风险（新兴威胁）

| 风险 | 说明 |
|---|---|
| **后门植入** | 模型提供方植入后门 |
| **数据记忆** | 模型"记住"了训练数据（隐私泄露） |
| **来源不可信** | 无法验证模型的训练过程 |

> 💡 **"下载一个预训练模型"看起来很方便** ——
> 但你实际上在信任一个**完全不透明的黑盒**。
> 这是当前 AI 落地的一个**系统性风险**。

### 四、电力场景的特殊性

| 特点 | 影响 |
|---|---|
| **数据敏感** | 涉及电网运行状态（可能涉密） |
| **攻击样本稀缺** | 真实攻击极少 → 难以训练 |
| **标注昂贵** | 需要电力专家标注 |
| **共享困难** | 跨机构数据难共享（合规+竞争） |
| **→ 常依赖第三方** | **风险集中** |

### 五、联邦学习：机遇与风险并存

**机遇**：
```
数据不出域 → 保护隐私 + 满足合规
        ↓
多个电网公司可以联合训练
```

**风险**：

| 风险 | 说明 |
|---|---|
| **恶意参与者投毒** | 提交坏梯度污染全局模型 |
| **梯度泄露隐私** | 从梯度反推原始数据 |
| **聚合服务器不可信** | 服务器可能被攻破 |
| **拜占庭节点** | 部分节点任意作恶 |

### 六、数据可信的五种保障手段

| 手段 | 原理 | 适用 |
|---|---|---|
| **来源认证** | 数据签名（谁能产生数据） | 采集/传输 |
| **完整性校验** | 哈希 / 默克尔树 | 存储/传输 |
| **溯源** | 区块链记录数据流转 | 全链路 |
| **审计** | 访问日志 + 异常检测 | 存储/使用 |
| **联邦学习** | 数据不出域 | 跨机构共享 |

### 七、检测数据污染的四种方法

| 方法 | 原理 | 局限 |
|---|---|---|
| **统计检测** | 分布异常（离群点） | 攻击者可伪装 |
| **一致性检查** | 物理约束（潮流方程） | **电网特有优势** ⭐ |
| **交叉验证** | 多源数据比对 | 需要冗余 |
| **人工审核** | 抽样检查 | 不可扩展 |

> 💡 **"一致性检查"是电网的独特优势**：
> **数据必须满足物理规律** —— 这比"统计异常"强得多，
> 因为攻击者可以让数据"统计上正常"，但很难让它"物理上自洽"（Day 84）。

### 八、研究机会

| 方向 | 说明 | 新意 |
|---|---|---|
| **电力数据可信采集** | 从源头保证可信 | ★★★★ |
| **联邦学习的投毒检测** | 恶意梯度识别 | ★★★★ |
| **预训练模型后门检测** | 供应链安全 | ★★★★★ |
| **物理约束的数据校验** | 利用电网特性 | ★★★★ |
| **数据溯源与审计** | 区块链 + 电力 | ★★★ |

> 💡 **一个契合多方向的选题**：
> 「**联邦学习场景下的电力数据投毒检测：基于物理一致性的鲁棒聚合**」
> - **场景**：多家电网公司联邦训练 IDS（数据不出域）
> - **威胁**：恶意参与方提交"看似正常但会污染模型"的梯度

>   - 不只检查梯度统计特征

## Day 92 · 09:00 —— 差分隐私：让"参与"不等于"泄露"

> **一句话**：**差分隐私用"加噪声"换"数学上可证明的隐私"**——它不问"数据会不会泄露"，而是问"多了一个人，输出会变多少"。

### 一、为什么电网数据天生敏感

| 数据 | 泄露后果 |
|---|---|
| **用户负荷曲线** | 推断在家/外出、作息、几口人（NILM，Day 80） |
| **工商业用电** | 推断产线开停 → **商业间谍** |
| **变电站量测** | 推断拓扑、设备型号 → **攻击前置情报** |
| **新能源出力** | 推断发电策略 → 市场操纵 |

> ⚠️ **电网数据的特殊性**：它**天然带地理+时间标签**。
> 普通数据匿名化后可能安全，但**负荷曲线本身就是指纹** ——
> 把姓名删了，看曲线还是能认出是谁（这叫**再识别攻击**）。

### 二、传统匿名化的三种失败

| 方法 | 做法 | 怎么被破 |
|---|---|---|
| **去标识** | 删姓名/ID | 准标识符组合仍可唯一识别 |
| **k-匿名** | 每组至少 k 人不可分 | 同质攻击、背景知识攻击 |
| **泛化** | 把 24.3 岁→"20-30岁" | **效用损失大**，且仍可推断 |

> 💡 **核心痛点**：传统方法都是"**先做完再检查**"，
> 无法回答"**我这个发布方案，到底泄露了多少？**"
> 差分隐私的价值就在于：**它给了一个可量化的答案。**

### 三、差分隐私的定义（ε-DP）

对任意两个**只差一条记录**的数据集 $D, D'$（相邻数据集），
对任意输出集合 $S$：

$$\Pr[\mathcal{M}(D) \in S] \le e^{\varepsilon} \cdot \Pr[\mathcal{M}(D') \in S]$$

**读法**：
- $\mathcal{M}$ 是随机化算法（如"加噪声的均值"）
- $\varepsilon$ 叫**隐私预算**：$\varepsilon$ 越小，隐私越强
- 直觉：**"有你和没你，输出分布几乎一样"** → 别人无法从输出反推你

| ε 取值 | 含义 | 典型场景 |
|---|---|---|
| 0.01 ~ 0.1 | 极强隐私 | 敏感医疗、用户级 |
| 0.1 ~ 1 | 强隐私 | **电网用户数据常用** |
| 1 ~ 10 | 中等 | 统计发布 |
| > 10 | 弱（几乎无用） | 不建议 |

### 四、怎么加噪声：拉普拉斯与高斯

| 机制 | 噪声分布 | 适用 | 尺度 |
|---|---|---|---|
| **拉普拉斯** | $\mathrm{Lap}(\Delta f/\varepsilon)$ | 纯 ε-DP | 与**敏感度** $\Delta f$ 成正比 |
| **高斯** | $\mathcal{N}(0,\sigma^2)$ | (ε,δ)-DP | 需 $\sigma \ge \sqrt{2\ln(1.25/\delta)}\cdot\Delta f/\varepsilon$ |
| **指数机制** | 按效用打分采样 | 非数值输出（如选最优方案） | — |

> **敏感度 $\Delta f$** = 换掉一条记录，函数输出最多变多少。
> **"敏感度大 → 加更多噪声"** —— 这是 DP 的全部直觉。

### 五、两条最重要的性质

**1. 后处理免疫（Post-processing）**
> 对 DP 输出再做任何运算，**隐私不会变差**。
> → 意味着你可以在 DP 结果上随便做分析、训练模型，**不用重新算预算**。

**2. 组合定理（Composition）**
> 做了 $k$ 次 ε-DP 查询，总预算是 $k\varepsilon$（基本组合）
> 或 $\sqrt{2k\ln(1/\delta)}\varepsilon + k\varepsilon(e^\varepsilon-1)$（高级组合，**更省**）。

> ⚠️ **这是 DP 落地最大的坑**：预算会**累加**。
> 联邦学习训练 1000 轮，每轮都加 DP 噪声 → 总 ε 可能爆掉。
> 实务做法：**先定总预算 ε，再反推每轮能花多少**。

### 六、DP 在电力系统里的三个落点

| 场景 | 做法 | 收益 |
|---|---|---|
| **智能电表数据发布** | 对聚合负荷加 DP 噪声 | 保护用户隐私，保留统计规律 |
| **联邦学习（DP-FedAvg）** | 上传梯度前加噪声 + 裁剪 | **防梯度反演**（Day 92 下） |
| **负荷预测模型训练** | DP-SGD（逐样本梯度裁剪+加噪） | 防成员推断攻击 |

**DP-SGD 三步**：
```
① 逐样本算梯度 g_i
② 裁剪：g_i ← g_i / max(1, ||g_i||/C)     ← 限制单样本影响（控制敏感度）
③ 加噪：G ← (Σ g_i + N(0,σ²C²)) / B       ← 加高斯噪声
```

### 七、DP 的代价与争议

| 问题 | 说明 |
|---|---|
| **效用损失** | ε 小 → 噪声大 → 模型精度降 |
| **隐私 ≠ 安全** | DP 防的是"统计推断"，不防"系统被入侵" |
| **参数选择主观** | ε 定多少？没有绝对标准 |
| **训练变慢** | DP-SGD 需逐样本梯度，无法用大 batch 优化 |

> 💡 **一句话**：DP 是"**用可量化的精度损失，买可证明的隐私保证**"。

### 八、与网安研究关联

| 实验室方向 | DP 的接口 |
|---|---|
| **AI与数据安全** | DP 是数据安全的核心工具之一 |
| **隐私保护** | DP 是"隐私保护"最主流的**数学框架** |
| **联邦学习** | DP-FedAvg 是联邦学习隐私的标准配置 |
| **模型安全** | DP 提供**成员推断攻击**的理论上界 |

> 💡 **一个高价值选题**：
> 「**面向电力负荷数据的差分隐私发布：兼顾时序相关性的隐私预算分配**」
> - **痛点**：负荷数据**时间强相关**，独立加噪会破坏时序规律
> - **你的方法**：按"时序相关性强度"**自适应分配预算**
>   - 相关性强的时段 → 用更少噪声（后处理不变性）
>   - 相关性弱的时段 → 加更多噪声
> - **创新点**：把 **DP 组合定理**和**电力时序特性**结合
> - 这类"**把通用隐私工具适配到电力场景**"的题目，**门槛不高但很实在**

### 🔍 延伸思考

1. 电网数据"**脱敏后发布**"和"**不出域联邦**"，哪种更现实？
2. 如果 $\varepsilon$ 是可调的，**谁来定这个值才可信**？

## Day 92 · 14:00 —— 同态加密与安全多方计算：让数据"可用不可见"

> **一句话**：**同态加密让你在"看不见数据"的情况下直接算**——密文进、密文出，中间不需要解密。

### 一、从"先解密再算"到"直接算密文"

**传统加密（如 AES）**：
```
数据 → 加密 → 存起来 → 【要算时必须先解密】→ 算 → 再加密
                          ↑ 这一刻数据是裸的，是风险窗口
```

**同态加密（HE）**：
```
数据 → 加密 → 【直接在密文上算】→ 结果仍是密文 → 解密得结果
                 ↑ 全程没人看到明文
```

> 💡 **这就是"可用不可见"** —— 数据的**使用权**和**可见性**被解耦。

### 二、HE 的三种类型

| 类型 | 支持的运算 | 速度 | 代表方案 |
|---|---|---|---|
| **部分同态 PHE** | 只有加法 **或** 只有乘法 | 快 | Paillier（加法）、RSA（乘法） |
| **些许同态 SHE** | 加 + 乘，但深度有限 | 中 | BGV、BFV、CKKS |
| **全同态 FHE** | 任意加乘电路 | **极慢**（慢 10³~10⁶ 倍） | Gentry 2009、TFHE |

**CKKS** 特别值得记：它支持**浮点近似运算**，
所以能做**加法、乘法、求平均、神经网络推理** —— 是隐私计算落地最常用的方案。

> ⚠️ **FHE 的现实**：理论很美，但**开销巨大**。
> 目前能做的是"**小模型推理**"（如 logistic regression、小型 MLP），
> 还远不能直接在密文上训练 GNN。

### 三、安全多方计算（MPC）

**场景**：多方各自有数据，想**共同算出结果**，但**都不想暴露自己的输入**。

**经典例子 —— 百万富翁问题**（Yao, 1982）：
> 两个富翁想知道谁更富，但**谁都不想透露自己有多少钱**。

**三种主要技术**：

| 技术 | 原理 | 特点 |
|---|---|---|
| **秘密分享（SS）** | 把 $x$ 拆成 $x_1+x_2$，分给两方 | 快，需多轮通信 |
| **混淆电路（GC）** | 把函数编译成加密电路，逐门求值 | 适合布尔电路 |
| **不经意传输（OT）** | 一方从多项中选一项，对方不知选了哪个 | **基础原语** |

**半诚实 vs 恶意模型**：
- **半诚实（semi-honest）**：参与方遵守协议，但会偷看中间结果 → **假设弱，易实现**
- **恶意（malicious）**：参与方可以任意作弊 → **需额外验证，开销大**

> 💡 论文里**一定要写清你的威胁模型是哪种**，否则审稿人会质疑。

### 四、三条技术路线对比

| 路线 | 核心 | 优点 | 缺点 | 电力场景 |
|---|---|---|---|---|
| **联邦学习 FL** | 数据不动，模型动 | 通信轻、易落地 | **梯度可反演** | 多电网公司联合训练 IDS |
| **同态加密 HE** | 密文上计算 | 安全性最强 | **慢** | 密文上的异常检测打分 |
| **安全多方 MPC** | 分片协同计算 | 通用性强 | 通信轮次多 | 跨机构统计、LMP 计算 |

**实际系统往往是"混合"**：
> **FL 做主体 + HE/MPC 做关键环节 + DP 做补充噪声** —— 这叫**隐私计算组合拳**。

### 五、梯度反演攻击（为什么 FL 不够）

**Zhu et al., Deep Leakage from Gradients (NeurIPS 2019)**：
> 攻击者只拿到**梯度**，就能**几乎完美地重建原始训练样本**。

**直觉解释**：
- 梯度是"**数据对参数的导数**"
- 只要知道模型结构，梯度里就**编码了输入信息**
- 优化一个假输入 $x'$，让它的梯度匹配观测梯度 → **$x'$ 就收敛到真实输入**

> ⚠️ **这直接击碎了"数据不出域就安全"的朴素认知**。
> 所以联邦学习**必须**配 DP 或 HE 才安全 —— 这就是 DP-FedAvg 的由来。

### 六、电力场景的落地难点

| 难点 | 说明 |
|---|---|
| **性能** | HE 在 14 节点上做状态估计就要秒级；大系统不可行 |
| **精度** | CKKS 是近似运算，**误差会累积** |
| **标准缺失** | 电力行业隐私计算标准仍在建设中 |
| **激励** | 电网公司**为什么要共享**？收益怎么分？ |
| **合规** | 数据出域涉及《数据安全法》《个人信息保护法》 |

> 💡 **对研究的启示**：
> "**全同态加密做电网状态估计**"这类题目**性能上是死路**。
> 更可行的方向是 **"只对关键环节做加密"** ——
> 例如：只对**用户侧量测**加密上传，主站侧仍用明文算状态估计。

### 七、与网安研究关联

| 实验室方向 | 接口 |
|---|---|
| **隐私保护** | HE/MPC/DP 是三大支柱 |
| **联邦学习** | 隐私计算是 FL 的"安全底座" |
| **可信计算** | 与 TEE（可信执行环境）互补 |
| **AI与数据安全** | 隐私计算是数据安全落地的关键 |

> 💡 **一个务实选题**：
> 「**电力联邦入侵检测中的隐私-效用权衡：DP + 安全聚合的联合优化**」
> - **场景**：多家电网公司联邦训练 IDS
> - **问题**：加 DP 噪声保隐私 → 但 IDS 检出率下降
> - **你的方法**：**按参与方的数据质量与敏感度自适应分配隐私预算**
>   - 数据质量高的参与方 → 少加噪（贡献大，值得多花预算）
>   - 敏感度高的参与方 → 多加噪
> - **创新点**：把**隐私预算分配**建模为**优化问题**，而非均匀分配
> - **对接方向**：联邦学习 + 隐私保护 + 入侵检测（**三方向全中**）

### 八、小结：隐私计算的能力边界

```
┌────────────────────────────────────────────┐
│  隐私计算能防什么                          │
│  ✅ 统计推断（DP）                         │
│  ✅ 梯度泄露（DP/HE）                      │
│  ✅ 计算过程暴露（HE/MPC）                 │
├────────────────────────────────────────────┤
│  隐私计算不能防什么                        │
│  ❌ 系统被入侵（那是工控安全的事）          │
│  ❌ 恶意参与方的数据投毒（Day 91）          │
│  ❌ 侧信道攻击（功耗/时序）                 │
└────────────────────────────────────────────┘
```

> 💡 **一句话**：隐私计算解决的是"**数据怎么用而不泄露**"，
> 不是"**系统怎么不被攻破**"。**两件事必须分开做。**

## Day 93 · 09:00 —— 联邦学习安全深化：从 FedAvg 到鲁棒聚合

> **一句话**：**联邦学习的"数据不出域"只解决了隐私的一半**——它挡不住恶意参与方往全局模型里投毒。

### 一、FedAvg 一分钟回顾

```
服务器                        参与方 i
  │  w_t  ──────────────────→  本地数据 D_i
  │                              本地训练 E 轮 → w_i
  │  ←──────────────────────  w_i
  │  w_{t+1} = Σ (n_i/n) · w_i    ← 按样本数加权平均
  └─ 重复 T 轮
```

**三个核心假设**（**每一个都可能是攻击点**）：

| 假设 | 现实 |
|---|---|
| 参与方**诚实** | ❌ 可能有恶意方 |
| 参与方**数据独立同分布** | ❌ 电网各区域负荷分布差异大（**Non-IID**） |
| 服务器**能看到所有梯度** | ❌ 这本身是隐私风险 |

### 二、联邦学习的攻击面全景

| 攻击 | 时机 | 目标 | 代表工作 |
|---|---|---|---|
| **数据投毒** | 训练中 | 降低全局精度 | Fang et al. 2020 |
| **模型投毒（后门）** | 训练中 | 植入特定触发条件 | Xie et al. 2020 |
| **梯度反演** | 训练中 | **窃取他人隐私** | Zhu et al. 2019 |
| **搭便车（Free-rider）** | 训练中 | 不干活白拿模型 | Lin et al. 2019 |
| **成员推断** | 训练后 | 判断某数据是否参与训练 | Shokri et al. 2017 |
| **模型提取** | 训练后 | 通过查询复制模型 | — |

> 💡 **对电网的映射**：
> - **恶意参与方** = 被攻陷的某地区调度中心
> - **后门触发** = 攻击者让模型"看到特定拓扑就判正常"
> - **后果**：全局 IDS 被污染，**所有参与方都受害**

### 三、后门攻击在联邦场景的放大效应

**关键论文**：Bagdasaryan et al., *How to Backdoor Federated Learning*, AISTATS 2020

**攻击流程**：
```
恶意方本地训练时：
  ① 正常数据 → 正常更新 w_normal
  ② 投毒数据（带触发标记）→ 目标标签
  ③ 放大攻击：w_mal = w_global + η·(w_poison - w_global)   ← η 是关键！
  ④ 上传 w_mal
```

**为什么"放大"有效**：
> 单轮里恶意方只有 1 票，但**把更新幅度放大 η 倍**，
> 就能在平均时**压过其他所有诚实方**。
> 而且因为**其他参数方向仍接近全局模型**，**精度不掉** → 难以察觉。

**防御难点**：
| 防御 | 被怎么绕过 |
|---|---|
| **异常检测** | 攻击者只用少量轮次攻击（**间歇攻击**） |
| **精度监控** | 主任务精度不降，只影响特定触发 |
| **多轮观察** | 攻击者在非攻击轮提交完全正常的更新（**掩护**） |

### 四、鲁棒聚合：四类主流防御

| 方法 | 核心思想 | 代表 |
|---|---|---|
| **坐标中位数** | 逐参数取中位数，而非平均 | Yin et al. 2018 |
| **Trimmed Mean** | 去掉最大最小各 β 个，再平均 | Yin et al. 2018 |
| **Krum / Multi-Krum** | 选**离大多数最近的**那个更新 | Blanchard et al. 2017 |
| **FoolsGold** | 检测**更新方向高度相似**的合谋方 | Fung et al. 2020 |
| **Bulyan** | Krum + Trimmed Mean 组合 | El Mhamdi et al. 2018 |

**Krum 的直觉**（很重要，面试常问）：
> 假设恶意方**少于一半**，那么**诚实方彼此更相似**。
> 对每个更新 $w_i$，找**离它最近的 $n-f-2$ 个**，
> 算这些邻居到 $w_i$ 的距离和 → **和最小的就是最"合群"的** → 选它。

**理论保证**：当恶意方比例 $f < (n-2)/2$ 时，Krum 有收敛性证明。

> ⚠️ **局限**：鲁棒聚合都建立在"**恶意方是少数**"的假设上。
> 一旦恶意方过半（**Sybil 攻击**），所有基于统计的防御都会失效。

### 五、Non-IID 问题：比攻击更日常的难题

**电网场景的 Non-IID**：
| 参与方 | 数据特点 |
|---|---|
| 工业城市电网 | 负荷大、波动剧烈 |
| 农业地区电网 | 负荷小、季节性明显 |
| 数据中心园区 | 恒定高负荷 |
| 居民区 | 早晚双峰 |

> 各方本地模型**学到的东西完全不同** → 平均后**互相抵消**。

**FedProx 解法**：
$$\min_w \; F_i(w) + \frac{\mu}{2}\|w - w_t\|^2$$

> 加一个**近端项**，限制本地模型**别偏离全局太远**。
> $\mu$ 越大，越"听话"；$\mu=0$ 就退化成 FedAvg。

### 六、把"物理先验"引入鲁棒聚合（你的机会）

**现有防御的共同局限**：只看**更新的统计特征**（距离、方向、范数），
**完全不懂电力系统的物理约束**。

**你的切入点**：
```
对每个参与方的更新 w_i：
  ① 统计检查：是否异常（Krum/Trimmed Mean）
  ② 物理检查：用 w_i 在本地验证集上推理
       → 检查输出是否满足潮流方程 / 物理一致性（Day 84）
  ③ 综合打分：统计分 × 物理分 → 决定是否采纳
```

> 💡 **为什么这有价值**：
> - 攻击者可以**让统计特征正常**（因为那是纯数学的）
> - 但**很难让物理约束自洽**（因为那要求真的懂电网）
> - **物理先验 = 你相对纯 ML 研究者的独特优势**

## Day 93 · 14:00 —— 可解释 AI：让"黑箱"能上调度台

> **一句话**：**在电力这种高后果场景，"模型说异常"是不够的——必须能说清"为什么异常"，调度员才敢信。**

### 一、为什么可解释性在电力里不是"锦上添花"

| 场景 | 不可解释的后果 |
|---|---|
| **调度员收到告警** | 不知道该不该拉闸 → **不敢行动** |
| **安全审计** | 无法向监管解释"为什么报警" |
| **误报追责** | 无法定位是模型问题还是数据问题 |
| **攻击溯源** | 不知道攻击者改了哪些量测 |
| **论文审稿** | 审稿人会问"**你的模型凭什么可信**" |

> 💡 **关键洞察**：
> 在 CV/NLP 里，可解释性是"**加分项**"；
> 在**电网安全**里，它是"**能不能用**"的**必要条件**。
> **这是你的天然优势领域** —— 因为电力有物理模型可对照。

### 二、可解释性的两种类型

| 类型 | 时机 | 特点 | 代表 |
|---|---|---|---|
| **事后解释（Post-hoc）** | 训练后 | 不改模型，事后分析 | LIME、SHAP、CAM |
| **内在可解释（Intrinsic）** | 设计时 | 模型本身就是可读的 | 决策树、线性模型、注意力 |

> ⚠️ **重要澄清**：
> **事后解释 ≠ 模型真实推理过程**。
> LIME/SHAP 给出的是**局部近似**，不是"模型真的这么想"。
> 论文里**不要**写成"我们揭示了模型的决策机制"。

### 三、三大主流方法

**1. SHAP（SHapley Additive exPlanations）**

来自**合作博弈论**：把"预测值"看作一场合作博弈的收益，
每个特征按**边际贡献**分配。

$$\phi_i = \sum_{S \subseteq N\setminus\{i\}} \frac{|S|!(|N|-|S|-1)!}{|N|!}\left[v(S\cup\{i\}) - v(S)\right]$$

**在电网里的用法**：
```
模型判"攻击" → SHAP 告诉你：
  母线 5 的电压量测  贡献 +0.42  ← 主要证据
  支路 3-4 有功      贡献 +0.31
  母线 2 无功        贡献 -0.05
```
> 这直接**指向了可疑量测** → 可用于**攻击定位**（不只是检测！）

**2. LIME（Local Interpretable Model-agnostic Explanations）**

在**样本附近**用一个**简单模型**（如线性）近似黑箱：
```
① 在样本 x 附近扰动采样
② 用黑箱给这些样本打分
③ 拟合一个线性模型 → 系数即"解释"
```

**3. 注意力可视化（对 GNN 尤其重要）**

GAT 的注意力权重 $\alpha_{ij}$ **天然**表示"节点 $i$ 有多关注节点 $j$"。
```
检测到攻击 → 看注意力最大的边
  → 母线 5 ← 母线 7（α=0.38）
  → 母线 5 ← 母线 3（α=0.29）
  → 攻击可能来自 7-5 这条支路
```

> ⚠️ **注意力 ≠ 解释**（Jain & Wallace, NAACL 2019 有专门批评）
> 注意力权重**高**不代表**因果重要**。论文里要谨慎表述。

### 四、GNN 的可解释性：三条路线

| 路线 | 做法 | 适合 |
|---|---|---|
| **注意力分析** | 直接看 GAT 权重 | 快，但**不够严谨** |
| **GNNExplainer** | 学习一个**子图掩码**，最大化预测保持 | **主流方法** ⭐ |
| **因果/反事实** | "如果去掉这条边，预测会变吗？" | 更严谨，计算贵 |

**GNNExplainer 的核心**（Ying et al., NeurIPS 2019）：
$$\max_{M} \; \mathbb{E}\left[\log P(Y \mid G_S)\right] - \text{正则}$$

> $G_S$ = 由掩码 $M$ 选出的**子图**（关键边 + 关键节点特征）。
> 优化目标：**用最小的子图，保住原来的预测**。
> 结果：**这个子图就是"解释"** —— 即"模型主要看这几条边下的判断"。

**在 FDIA 检测里的用法**：
> 模型判"攻击" → GNNExplainer 给出**关键子图** →
> 这些边/节点**很可能就是被篡改的量测位置** →
> **从"检测"升级为"定位"**（审稿人非常喜欢这个提升）。

### 五、可解释性 vs 物理模型：电网的独特机会

**核心洞察**：
> 电网**已经有**一个完美的"可解释模型"—— **潮流方程**。
> 所以你的可解释性验证可以做**交叉验证**：

```
AI 说"母线 5 是攻击点"
        ↓ 交叉验证
物理检查：母线 5 的量测是否违反 KCL/KVL？（Day 84）
        ↓
一致 → AI 解释可信 ✅
不一致 → AI 可能过拟合 ⚠️
```

> 💡 **这就是"物理引导的可解释性"** —— 一个**非常契合电力场景**的创新点。

### 六、一个可落地的选题

> 「**物理约束引导的 GNN 可解释性：从 FDIA 检测到攻击定位**」
> - **现状**：GNN 检测 FDIA 只能给"是/否"，无法说清"哪里被改"
> - **你的方法**：
>   - ① GNNExplainer 提取关键子图
>   - ② 用**物理残差**（潮流方程不匹配度）给子图节点**排序**
>   - ③ 交叉验证 → 输出"**可疑量测清单 + 置信度**"
> - **评价指标**：不只看检测 F1，还看**定位准确率**（Top-k 命中率）
> - **卖点**：**从检测到定位**是审稿人眼中的"实质性贡献"
> - **对接方向**：GNN + 可解释AI + 入侵检测

### 七、可解释性的三个陷阱

| 陷阱 | 说明 |
|---|---|
| **解释不稳定** | 同一模型跑两次，SHAP 值差异大 → **不可信** |
| **解释被操纵** | 攻击者可**专门针对解释方法**做对抗（"解释攻击"） |
| **过度信任** | 调度员盲信解释 → 反而制造新风险 |

> ⚠️ **一个深刻的问题**：
> 如果**解释本身也可被攻击**，那"可解释"会不会变成"**更危险的自信**"？
> —— 这是一个**很好的延伸思考**，也是潜在的研究方向。

### 🔍 延伸思考

1. 可解释性和**检测精度**一定冲突吗？有没有"又准又解释"的方法？
2. 如果**攻击者知道**你用 GNNExplainer，能否设计"**解释上合理但实际恶意**"的攻击？

## Day 94 · 09:00 —— 不确定性量化与校准：模型"知道自己不知道"

> **一句话**：**一个不会说"我不确定"的检测器，在电力系统里比没有检测器更危险。**

### 一、问题的起点：softmax 输出不是概率

**常见的错误理解**：
```
模型输出 [正常: 0.97, 攻击: 0.03]
     → "97% 的概率是正常"   ❌ 这是错的
```

**为什么错**：
> 神经网络的 softmax 输出**只是相对得分**，**没有经过校准**。
> 现代深度网络普遍**过度自信（overconfident）** ——
> 明明错了，还给出 0.99 的置信度。

**Guo et al., On Calibration of Modern Neural Networks (ICML 2017)** 实测：
| 模型 | 测试精度 | 平均置信度 | 差距 |
|---|---|---|---|
| LeNet | 98.7% | 99.2% | +0.5% |
| ResNet-110 | 93.6% | 96.4% | **+2.8%** |
| DenseNet | 93.8% | 97.2% | **+3.4%** |

> 💡 **越深的网络越过度自信** —— 这是深度学习的**系统性问题**。

### 二、什么是"校准"

**完美校准（Perfect Calibration）的定义**：
> 把所有预测置信度为 0.8 的样本挑出来，
> 其中**恰好 80%** 的样本是对的。

$$\Pr(\hat{Y} = Y \mid \hat{P} = p) = p, \quad \forall p \in [0,1]$$

**怎么衡量 —— ECE（Expected Calibration Error）**：
$$\mathrm{ECE} = \sum_{m=1}^{M} \frac{|B_m|}{n}\left|\mathrm{acc}(B_m) - \mathrm{conf}(B_m)\right|$$

> 把置信度分成 $M$ 个桶（如 10 个），
> 每个桶里算"**实际精度**和"**平均置信度**"的差，加权平均。

**可靠性图（Reliability Diagram）**：
```
置信度
1.0 │                          ╱ 完美校准线
    │                      ╱
0.8 │                  ╱ ●  ← 实际点落在下方 = 过度自信
    │              ╱
0.6 │          ╱ ●
    │      ╱
0.4 │  ╱●
    └────────────────────────→ 预测置信度
```

### 三、四种校准方法

| 方法 | 做法 | 参数量 | 适用 |
|---|---|---|---|
| **温度缩放（Temperature Scaling）** | $\hat{p} = \mathrm{softmax}(z/T)$ | **1 个** ⭐ | 最常用、最简单、效果最好 |
| **Platt Scaling** | 对 logit 做 logistic 回归 | 2 个 | 二分类 |
| **等渗回归（Isotonic）** | 单调分段拟合 | 多 | 数据多时 |
| **直方图分箱** | 分箱后经验校准 | 多 | 简单但粗糙 |

**温度缩放的精妙之处**：
```
T = 1  → 原始输出
T > 1  → 分布更"平" → 置信度下降（缓解过度自信）
T < 1  → 分布更"尖" → 置信度上升（更自信）
```
> ⚠️ **关键性质**：温度缩放**不改变 argmax**！
> 也就是**不影响准确率**，只改置信度 → **零成本改进**，几乎必做。

**标准做法**：留出**独立校准集**（不能是训练集），
最小化 NLL 拟合 $T$ → 在测试集上评估 ECE。

### 四、不确定性的两种来源（**重要概念**）

| 类型 | 英文 | 来源 | 能不能靠更多数据消除 |
|---|---|---|---|
| **偶然不确定性** | Aleatoric | 数据本身的噪声 | ❌ 不能 |
| **认知不确定性** | Epistemic | 模型知识不足 | ✅ 能 |

**在电网里的对应**：
| 类型 | 电网例子 | 应对 |
|---|---|---|
| **偶然** | 量测噪声、通信抖动 | 建模为噪声分布（如高斯） |
| **认知** | 遇到**训练时没见过的攻击类型** | **检测出来 → 拒绝决策/交人工** |

> 💡 **认知不确定性才是安全的关键**：
> 它标记出"**模型不熟悉的输入**" → 正是**新型攻击**最可能出现的地方。

### 五、怎么估不确定性：三种实用方法

**1. MC Dropout（最简单）**
```
推理时保持 dropout 开启，前向传播 N 次（如 30 次）
→ 得到 N 个预测 → 均值 = 预测，方差 = 不确定性
```
> 一行代码就能改，**性价比极高**。

**2. Deep Ensembles（最可靠）**
```
训练 M 个（如 5 个）独立模型 → 集成
→ 预测分歧大 = 认知不确定性高
```
> Lakshminarayanan et al. (NIPS 2017) 证明**比 MC Dropout 更可靠**，
> 代价是 **M 倍训练开销**。

**3. 贝叶斯神经网络（BNN）**
> 对权重 $p(w \mid D)$ 建模 → 理论上最严谨，**计算最贵**。

**4. 一致性预测（Conformal Prediction）** ⭐ 强烈推荐
```
给定置信水平 1-α（如 95%）
→ 输出一个【预测集合】而非单个预测
→ 保证：真实标签有 ≥ 95% 概率落在集合里
```
> **优势**：**无需假设分布**、**有理论保证**、**模型无关**。
> 集合**大** = 模型不确定；集合**小** = 模型确定。
> 这是**近年顶会热门**，且**在电力场景几乎没人做** → **机会窗口**。

### 六、在电力安全场景的用法

| 场景 | 不确定性的作用 |
|---|---|
| **IDS 告警** | 高不确定性 → **不自动切除，转人工** |
| **新型攻击检测** | 认知不确定性升高 → **标记为"未知类型"** |
| **状态估计** | 给估计值配**置信区间** → 支撑决策 |
| **负荷预测** | 给调度**风险区间**（比点预测有用得多） |
| **模型上线监控** | 不确定性漂移 → **模型需要重训**的信号 |

> 💡 **一个很实用的设计**：
> ```
> if 攻击概率 > 0.9 and 不确定性 < 0.1:
>      → 高置信度攻击 → 自动响应
> elif 攻击概率 > 0.5:
>      → 不确定 → 人工复核 + 记录（用于后续训练）
> else:
>      → 正常
> ```

### 七、一个可落地的选题

> 「**基于一致性预测的电力入侵检测：带保证的告警与拒识机制**」
> - **痛点**：现有 IDS 只给"是/否 + 一个不可信的置信度"
> - **你的方法**：
>   - ① 用一致性预测生成**预测集合**（如 {正常, 攻击} 或 {攻击}）
>   - ② 集合含两类 → **拒识**（交人工）
>   - ③ 集合只含一类 → **高置信决策**
> - **评价**：不只报 F1，还报**覆盖率（coverage）**和**平均集合大小**
> - **卖点**：
>   - 有**数学保证**（不是经验置信度）
>   - **拒识机制**直接契合电力"**宁可不报也不误报**"的需求
>   - 在电力领域**几乎空白** → **新意充足**
> - **对接方向**：AI与数据安全 + 入侵检测 + 可信ML

   —— 想清这个，才能设计**不对称的拒识阈值**。

## Day 94 · 14:00 —— 分布外检测：识别"没见过的攻击"

> **一句话**：**IDS 训练时只见过 5 种攻击，第 6 种来了怎么办？**——OOD 检测就是回答这个问题。

### 一、OOD 问题的本质

**训练分布 vs 测试分布**：
```
训练集 D_train:  攻击类型 {A, B, C}
测试集 D_test:   出现攻击类型 {A, B, C, D, E}
                                    ↑ 没见过！
```

**朴素模型的反应**：
> 输入一个**从没见过**的攻击样本 →
> 模型仍会**强行**归到 A/B/C 中某一类 →
> 给出**错误但自信**的答案（因为 softmax 总会归一化）。

> ⚠️ **这就是"封闭世界假设"的代价**：
> 分类器**天生无法表达"我不知道"**。

### 二、OOD 在电力里的具体形态

| OOD 类型 | 电力场景 |
|---|---|
| **新型攻击** | 新出现的 FDIA 变体、新 0day |
| **新拓扑** | 线路检修、扩建后拓扑变了 |
| **新工况** | 极端天气、大负荷波动 |
| **新设备** | 新增光伏/储能接入（Day 68） |
| **传感器故障** | 与攻击不同，但同样"没见过" |

> 💡 **关键区分**：
> **OOD 检测 ≠ 攻击检测**。
> 它回答的是"**这个输入我熟不熟**"，而不是"**这个输入坏不坏**"。
> **两者互补**：OOD 标记"需要警惕"，攻击检测器给出具体判断。

### 三、五类主流 OOD 方法

**1. 基于置信度（最朴素）**
```
max softmax prob < 阈值  →  判为 OOD
```
> ❌ **问题**：深度网络**过度自信**（Day 94 上半篇），
> OOD 样本也常常得到高置信度 → **基本不可用**。

**2. ODIN（改进版）**
```
① 温度缩放 T > 1        → 拉平分布
② 输入加微小扰动         → 放大 in/out 差异
③ 用 max softmax 判 OOD
```
> 简单有效，**但需要 OOD 样本调参** → 有"作弊"嫌疑。

**3. 基于距离（Mahalanobis）**
```
对每类估计高斯分布 N(μ_c, Σ)
→ 算样本到最近类中心的 Mahalanobis 距离
→ 距离大 = OOD
```
> Lee et al. (NeurIPS 2018)，**简洁且强**。

**4. 基于能量（Energy-based）**
$$E(x) = -T \cdot \log\sum_i e^{z_i/T}$$
> 用**能量分数**代替 softmax，**理论上更优雅**（Liu et al., NeurIPS 2020），
> 且**不需要调 OOD 数据** → **更实用**。

**5. 基于生成模型（重建误差）**
```
训练自编码器/扩散模型学"正常数据流形"
→ OOD 样本重建误差大
```
> 直观，**但深度生成模型也可能"重建得很好"** → 需谨慎。

### 四、OOD 检测的评价指标

**关键**：OOD 是**二分类**（in-distribution vs OOD），**但测试集严重不平衡**。

| 指标 | 含义 | 注意 |
|---|---|---|
| **AUROC** | 排序质量 | 常用但**可能过于乐观** |
| **AUPR** | 精确率-召回率曲线下面积 | **不平衡时更可信** ⭐ |
| **FPR@95TPR** | 在 95% 召回下，误报率多少 | **最贴近实际部署** ⭐ |

> ⚠️ **一个常见陷阱**：
> 很多论文只报 AUROC（容易做到 0.9+），
> 但 **FPR@95TPR 可能高达 50%** → 实际**完全不可用**。
> **审稿人现在越来越关注这个**。

### 五、OOD 与攻击检测的结合：三档决策

```
输入样本 x
   ↓
[OOD 检测器] ── 分布外? ──→ 是 → 【未知类型】告警 + 高优先级人工复核
   │                                    ↑ 新型攻击最可能在这里
   └─ 否 ↓
[攻击检测器] ── 攻击? ──→ 是 → 已知攻击类型 → 按预案响应
   │
   └─ 否 → 正常
```

> 💡 **这个架构的价值**：
> - **已知攻击** → 检测器处理（高效）
> - **未知攻击** → OOD 兜底（**不遗漏**）
> - **两者组合 = 覆盖"已知的已知"+"未知的未知"**

**这就是 Rumsfeld 矩阵在安全里的落地**：
| | 我们知道 | 我们不知道 |
|---|---|---|
| **已知** | 攻击检测器 | — |
| **未知** | OOD 检测 | ？（只能靠纵深防御） |

### 六、一个务实的研究选题

> 「**面向电力 IDS 的开集识别：已知攻击分类 + 未知攻击检测的联合框架**」
> - **痛点**：现有电力 IDS 论文几乎都是**封闭集**假设
> - **你的方法**：
>   - ① 特征层：物理一致性特征（Day 84）+ 统计特征
>   - ② 分类头：已知攻击多分类
>   - ③ OOD 头：**能量分数** + **一致性预测的集合大小**（上半篇）
>   - ④ 联合训练：多任务损失
> - **数据集**：用 IEEE 14/118 构造多类攻击（FDIA / 拓扑 / DoS / 重放）
>   - **训练用其中 3 类，测试加入 2 类新攻击** ← **开集设置**
> - **基线**：Softmax 阈值 / ODIN / Mahalanobis / Energy
> - **卖点**：
>   - **开集设置**在电力 IDS 领域**很少见** → 新意强
>   - **物理特征**提升 OOD 判别（因为物理约束是**跨攻击类型通用**的）
> - **对接方向**：入侵检测 + AI与数据安全 + 可信ML

### 七、开集识别的理论视角（进阶）

| 概念 | 含义 |
|---|---|
| **闭集** | 测试类别 ⊆ 训练类别 |
| **开集** | 测试出现训练外类别 |
| **开放集风险** | 开集下的期望误差上界（含"未知类拒识"项） |
| **增量学习** | OOD 样本积累后**持续学习**新攻击类型 |

> 💡 **最理想的系统**：
> ```
> OOD 检测发现新攻击 → 人工标注 → 增量学习 → 变成"已知攻击"
>      ↑                                              │
>      └──────────── 闭环持续进化 ←──────────────────┘
> ```
> 这个"**检测-标注-学习**"闭环，本身就是一个**很好的系统贡献**。

### 🔍 延伸思考

1. 如果**攻击者知道**你的 OOD 检测器，能否构造"**看起来在分布内**"的样本？
   （提示：这其实就是 Day 89 的**对抗样本**问题 → **两个方向在交汇**）
2. 电网数据**天然带时序**，能否用"**时间维度的一致性**"做 OOD 检测？

## Day 95 · 09:00 —— 可信 ML 评测：你的实验怎么才站得住

> **一句话**：**可信机器学习论文的可信度，取决于评测的严谨度**——很多"高精度"结果只是评测设计的产物。

### 一、评测设计的五个致命陷阱

| 陷阱 | 表现 | 为什么致命 |
|---|---|---|
| **数据泄漏** | 训练/测试有重叠样本 | 精度虚高，**审稿人一眼看穿** |
| **时序泄漏** | 用未来数据预测过去 | 电力**时序数据的高发问题** ⚠️ |
| **超参调优泄漏** | 在测试集上调超参 | 结果不可复现 |
| **基线过弱** | 只对比朴素方法 | 贡献被质疑 |
| **单一数据集** | 只在 IEEE 14 上验证 | **泛化性存疑** |

> ⚠️ **电力场景特有的时序泄漏**：
> 攻击通常是**连续多个时间步**的（渐进攻击）。
> 如果**随机划分**训练/测试，同一段攻击的相邻时刻
> 可能**一半在训练、一半在测试** → **严重高估性能**。
> **正确做法**：**按时间块划分**（如前 70% 训练，后 30% 测试）。

### 二、鲁棒性评测的标准流程

**1. 攻击强度扫描（必须做）**
```
横轴：攻击强度（如攻击量测比例 1% → 20%）
纵轴：检测性能（F1 / AUC / 检出率）
→ 画曲线，而非只报一个点
```
> 💡 **只报单点结果 = 不严谨**。
> **审稿人几乎必问**："攻击者更强时你怎么办？"

**2. 自适应攻击（Adaptive Attack）** ⭐⭐ 最重要
> **假设攻击者知道你的防御方法**，并专门绕过它。

| 防御 | 对应的自适应攻击 |
|---|---|
| 残差检测 | 攻击者用 `keep_ratio` 减少篡改（Day 83 下） |
| 物理约束检测 | 攻击者构造**满足物理约束**的攻击（Day 84） |
| 鲁棒聚合 | 攻击者模仿诚实方的更新方向（Day 93） |
| OOD 检测 | 攻击者构造"分布内"的对抗样本 |

> ⚠️ **这是审稿人最常用来"打掉"防御论文的手段**。
> **如果你的论文没有自适应攻击实验，几乎一定会被要求补。**

**3. 消融实验（Ablation）**
```
完整模型            → F1 = 0.86
去掉物理特征         → F1 = 0.79   ← 物理特征贡献 0.07
去掉图结构（退化为 MLP）→ F1 = 0.84  ← 图结构贡献 0.02
去掉不确定性模块     → F1 = 0.86（但拒识能力下降）
```
> 💡 **消融实验是"证明每个模块都有用"的唯一方式**。
> 如果去掉某模块**性能不降** → **说明这个模块是多余的** → 该删。

### 三、报告什么：一张"可信度清单"

| 维度 | 必须报告 | 建议报告 |
|---|---|---|
| **性能** | F1 / AUC / 精确率 / 召回率 | 混淆矩阵 |
| **鲁棒性** | 攻击强度扫描曲线 | 自适应攻击结果 |
| **不确定性** | ECE / 校准曲线 | 一致性预测覆盖率 |
| **泛化性** | ≥2 个数据集（如 IEEE 14 + 118） | 跨拓扑迁移 |
| **效率** | 训练/推理时间、参数量 | 显存占用 |
| **可复现** | 代码 + 超参 + 随机种子 | 多次运行均值±方差 |

> ⚠️ **多次运行**：
> 深度学习结果**随机性很大**，单次结果可能差 3~5 个百分点。
> **至少跑 5 次，报告均值 ± 标准差**。
> 只报最好的一次 = **学术不端边缘**。

### 四、统计显著性：很多人忽略的一环

**问题**：你的方法比基线高 1.5%，是**真的更好**还是**随机波动**？

| 方法 | 适用 |
|---|---|
| **配对 t 检验** | 多次运行，比较均值差异 |
| **Wilcoxon 符号秩检验** | 不假设正态分布，**更稳妥** ⭐ |
| **McNemar 检验** | 比较两个分类器的错误分布 |

> 💡 **写法**：
> "Our method achieves 0.862 ± 0.011, outperforming the best baseline
> (0.841 ± 0.013) with **p < 0.01** (Wilcoxon signed-rank test)."
> —— 加这一句，**可信度立刻不同**。

### 五、电力安全论文的"可信度检查表"

```
□ 数据划分是否按时间块？（防时序泄漏）
□ 是否报告了 ≥5 次运行的均值±方差？
□ 是否有攻击强度扫描曲线？
□ 是否做了自适应攻击实验？
□ 是否有消融实验？
□ 是否在 ≥2 个算例上验证？
□ 是否报告了 ECE / 不确定性？
□ 是否公开代码？
```

> 💡 **把这 8 条做完，你的论文在"严谨性"上就超过了大部分同类工作。**

### 六、常见"包装"手法（以及为什么不该用）

| 手法 | 问题 |
|---|---|
| 只报最好的随机种子 | 不可复现 |
| 基线用默认超参，自己的方法精调 | 不公平比较 |
| 用攻击强度很低的数据 | 结果好看但无意义 |
| 只报 AUROC 不报 FPR@95TPR | 掩盖实际不可用性 |
| 在测试集上选模型 | 泄漏 |

> ⚠️ **学术诚信 > 短期好看**。
> 电力是**安全关键领域**，一篇"看起来很好但实际不行"的论文，
> 可能**误导后续研究**，甚至**影响真实系统部署**。

### 🔍 延伸思考

1. 如果**你的方法不如基线**，论文还能写吗？（可以 —— 诚实分析原因也是贡献）
2. 电力攻击数据集**缺乏公开基准**，这本身是问题还是机会？

| **Experiments** | 攻击强度扫描 + 自适应攻击 + 消融（D95上） |
| **Discussion** | 隐私-效用权衡（D92）、可解释性局限（D93下） |

> 💡 **一个"高完整度"的论文结构**：
> ```
> 「物理约束引导的鲁棒电力入侵检测：检测-定位-拒识一体化」
>   ├─ 检测：GNN + 物理一致性特征
>   ├─ 定位：GNNExplainer + 物理残差排序（D93下）
>   ├─ 拒识：一致性预测 + OOD 检测（D94）
>   ├─ 鲁棒：物理感知鲁棒聚合（D93上）
>   └─ 评测：自适应攻击 + 消融 + 统计检验（D95上）
> ```
> 这个框架**覆盖了本周所有知识点**，且**每个点都能写一节**。

### 三、三个层次的"可信"（重要框架）

| 层次 | 问题 | 对应技术 |
|---|---|---|
| **L1 功能可信** | 检测准不准？ | 精度、F1、AUC |
| **L2 鲁棒可信** | 攻击者对抗时还行不行？ | 对抗训练、鲁棒聚合、认证鲁棒 |
| **L3 认知可信** | 模型知不知道自己不知道？ | 校准、不确定性、OOD、可解释 |

> 💡 **大部分电力 AI 论文只做到 L1**。
> **做到 L2 就已经算好论文**，
> **做到 L3 是顶会水平** —— 而且**电力领域几乎空白**。

### 四、本周最重要的三个"反直觉"结论

| # | 结论 | 为什么反直觉 |
|---|---|---|
| 1 | **模型置信度不可信** | 深度网络普遍过度自信，必须校准 |
| 2 | **联邦学习"数据不出域"≠安全** | 梯度可反演原始数据（DLG 攻击） |
| 3 | **"解释"本身也可能被攻击** | 可解释性不自动带来安全 |
