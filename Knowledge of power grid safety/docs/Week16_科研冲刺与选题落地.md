## Day 110 · 09:00 —— 系统性文献综述：怎么把一片领域摸清

> **一句话**：**综述不是"读了很多论文"，而是"用可复现的方法，把一片领域的知识结构化"。**

### 一、为什么"随机读论文"是低效的

**典型的错误做法**：
```
在 Google Scholar 搜 "power grid security"
→ 下载前 20 篇
→ 从第一篇开始读
→ 读到第 5 篇就晕了（术语不熟、方法不懂）
→ 放弃
→ 一周后重新开始（换个关键词，重复同样的过程）
```

**问题在哪**：
| 问题 | 后果 |
|---|---|
| **没有筛选标准** | 读了很多不相关的 |
| **没有阅读顺序** | 从最难/最偏的开始 |
| **没有结构化记录** | 读完就忘 |
| **没有覆盖度检查** | 不知道漏了什么 |
| **不可复现** | 别人（包括未来的你）无法验证 |

### 二、系统性综述的标准流程（PRISMA 式）

**PRISMA**（Preferred Reporting Items for Systematic Reviews）是医学领域的标准，**完全可以借鉴**：

```
【第 1 步】明确研究问题
  - 用 PICO 框架：
    P (Population)：研究对象 → 电力 CPS
    I (Intervention)：方法 → 图神经网络
    C (Comparison)：对照 → 传统状态估计 / MLP
    O (Outcome)：结果 → 攻击检测性能
  → 你的问题："GNN 在电力 FDIA 检测中的效果如何？"

【第 2 步】检索（可复现）
  - 数据库：IEEE Xplore、ACM DL、Web of Science、Scopus、arXiv
  - 检索式（记录！）：
    ("graph neural network" OR "GNN")
    AND ("false data injection" OR "FDIA" OR "cyber attack")
    AND ("power system" OR "smart grid")
  - 时间范围：2018-2026
  → 结果：检索到 312 篇

【第 3 步】去重 + 筛选
  - 去重后：248 篇
  - 标题/摘要筛选（标准写清楚）：
    ✅ 必须：用 GNN + 电力 + 攻击检测
    ❌ 排除：纯电力、纯 GNN、非攻击场景
  → 通过：87 篇

【第 4 步】全文筛选
  - 排除：无实验、无法获取全文、质量太差
  → 最终纳入：42 篇

【第 5 步】数据抽取（结构化表格）
  每篇抽取：年份 / 算例 / 攻击类型 / GNN 类型 / 指标 / 结果 / 局限

【第 6 步】综合与报告
  - 分类归纳（按方法/攻击类型/年份）
  - 发现趋势与空白
  - 画出 PRISMA 流程图 ⭐
```

> 💡 **"画出 PRISMA 流程图"** 是系统性综述的标配，
> 也是**审稿人判断"你是不是真的做了系统调研"** 的关键证据。
> ```
> 检索到 312 篇
>    ↓ 去重
> 248 篇
>    ↓ 标题/摘要筛选
> 87 篇
>    ↓ 全文筛选
> 42 篇纳入分析
> ```

### 三、检索式的构造技巧

**关键词的三个层次**：
```
【核心概念层】
  "graph neural network", GNN, GCN, GAT, GraphSAGE
  "false data injection", FDIA, FDI attack
  "power system", smart grid, power grid

【同义扩展层】
  攻击类：cyber attack, adversarial attack, data integrity attack,
          stealthy attack, coordinated attack
  方法类：graph learning, graph convolution, message passing,
          graph representation learning
  对象类：SCADA, state estimation, PMU, distribution network

【排除层】
  NOT: medical, traffic, social network, recommendation
```

**一个实用的检索式模板**：
```
("graph neural network*" OR GNN OR GCN OR "graph attention")
AND
("false data injection" OR "data integrity attack" OR "cyber-physical attack")
AND
("power system*" OR "smart grid*" OR "power grid*")
NOT
(medical OR healthcare OR traffic OR "social network")
```

> 💡 **记录检索式的重要性**：
> 论文里要写清楚"**我用了什么检索式、在哪些库、什么时候检索的**"，
> 否则**不可复现** → **审稿人会质疑**。

### 四、阅读的"漏斗式"策略

**不要从第一篇开始顺序读！**

```
第 1 层：读【综述】（3~5 篇）
  → 建立术语体系、知道主要流派
  → 时间：每篇 1~2 小时

第 2 层：读【高引用经典】（5~10 篇）
  → 知道奠基工作（如 GCN、FDIA 原始论文）
  → 时间：每篇 2~3 小时（精读）

第 3 层：读【最新顶会/顶刊】（10~15 篇）
  → 知道当前 SOTA（2024-2026）
  → 时间：每篇 1 小时（抓方法和结论）

第 4 层：读【直接对标的工作】（3~5 篇）
  → 这些是你论文的"最近邻"，必须精读
  → 时间：每篇 3 小时（逐节批注）
```

> 💡 **"最近邻工作"最关键**：
> **审稿人一定会问"你和 XXX 有什么区别"**。
> **如果你没读过最近邻，论文会被直接拒。**
> 判断方法：**搜你论文标题里的关键词，看有没有人做过几乎一样的事**。

### 五、结构化笔记的模板（**直接可用**）

```markdown
## [论文标题]

**基本信息**
- 作者 / 会议 / 年份 / DOI
- 引用数（Google Scholar）

**问题**
- 解决什么问题？（1 句）
- 为什么重要？

**现有方法的不足**
- 不足 1：
- 不足 2：

**核心方法**
- 关键思想（3 句）
- 技术组件：①  ②  ③
- 关键公式：（贴出来）

**实验**
- 数据集：
- 基线：
- 主要结果：
- 消融结论：

**我的判断**
- 优点：
- 弱点（如果是审稿人会问什么）：
- 可借鉴点：⭐
- 与我的方向的关系：

**标签**
#FDIA #GNN #检测 #2024
```

> 💡 **"可借鉴点"这一栏最有价值**：
> 它**直接对应你论文的方法设计**。
> 读 40 篇论文，积累 40 个"可借鉴点" →
> **你的方法就是这些点的组合与改进**。

### 六、怎么发现"研究空白"（Gap）

**五种找 Gap 的方法**：

| 方法 | 做法 |
|---|---|
| **对比表格法** ⭐ | 把纳入论文做成表格，横轴是维度，纵轴是论文 → **空格就是 Gap** |
| **局限性归纳** | 把每篇的"局限性"汇总 → **高频局限性 = 领域痛点** |
| **方法迁移** | A 领域的方法 + B 领域的问题 = 新工作 |
| **场景变化** | 同一方法在新场景（如配电网 vs 输电网） |
| **假设放宽** | 现有工作假设 X，如果 X 不成立呢？ ⭐⭐ |

**对比表格法的示例**：

| 论文 | 物理约束 | 拓扑变化 | 可解释 | 少样本 | 大规模 |
|---|---|---|---|---|---|
| A (2021) | ❌ | ❌ | ❌ | ❌ | ❌ |
| B (2022) | ✅ | ❌ | ❌ | ❌ | ❌ |
| C (2023) | ✅ | ✅ | ❌ | ❌ | ❌ |
| D (2024) | ✅ | ✅ | ✅ | ❌ | ❌ |
| **你** | ✅ | ✅ | ✅ | ✅ | ✅ |

> 💡 **"假设放宽法"最好用**：
> **现有工作都假设"拓扑已知"** → 你研究"拓扑未知"（Day 101 下）
> **现有工作都假设"攻击是单次的"** → 你研究"渐进攻击"（Day 98 上）
> **现有工作都假设"标签充足"** → 你研究"少样本"（Day 101 上）
> **每一个"假设放宽"都是一个选题。**

| **工业AI** | 工业领域的综述写作范式 |

> 💡 **给你的具体建议**：
> **花 2 周做一次完整的系统性综述**（就按上面的 PRISMA 流程）。
> **产出物**：

>
> **这份综述可以：**

>
> **一次投入，三重收益** —— **这是研一最该做的事。**

## Day 110 · 14:00 —— 文献管理与笔记系统：让知识"可检索"

> **一句话**：**读过的论文如果找不到、想不起来，就等于没读**——笔记系统的价值在于"未来的你能用上"。

### 一、为什么需要系统（而不是一堆 PDF）

**没有系统的后果**：
```
读了 60 篇论文 → 存在 5 个文件夹里
半年后写论文 → "我记得有篇讲这个的...在哪？"
→ 重新搜 → 找不到原来那篇
→ 时间浪费，重复劳动
```

**有系统的价值**：
| 价值 | 说明 |
|---|---|
| **可检索** | 按关键词/标签/方法找到 |
| **可关联** | 知道论文之间的引用关系 |
| **可复用** | 写 Related Work 直接取用 |
| **可积累** | 想法逐渐成型 |

### 二、三层工具架构（推荐）

```
┌─────────────────────────────────────────┐
│  第 1 层：文献管理（Zotero）             │
│  - 存 PDF、抓元数据、生成引用            │
│  - 与 Word/LaTeX 联动                    │
└─────────────────────────────────────────┘
              ↓ 导出笔记
┌─────────────────────────────────────────┐
│  第 2 层：知识库（Obsidian / Notion）     │
│  - 结构化笔记（Day 110 上 的模板）        │
│  - 双向链接、标签、图谱                  │
│  - 想法笔记（Idea Notes）⭐              │
└─────────────────────────────────────────┘
              ↓ 归纳
┌─────────────────────────────────────────┐
│  第 3 层：对比表与综述（Excel / Markdown）│
│  - 论文 × 维度的对比矩阵                  │
│  - Gap 分析                              │
└─────────────────────────────────────────┘
```

> 💡 **Obsidian 对你有额外价值**：
> 因为你**已经在用 Typora 看本课程**，
> 而 **Obsidian 和 Typora 都基于 Markdown** →
> **本课程的 120 篇内容可以直接放进 Obsidian 的 vault**，
> 形成你自己的"电力安全知识库"。
> **配合双向链接，可以把 16 周的知识串成网络。**

### 三、Zotero 的实用配置

| 功能 | 配置 |
|---|---|
| **浏览器插件** | 一键抓取论文元数据 + PDF ⭐ |
| **自动重命名** | 统一格式：`年份_第一作者_短标题` |
| **标签系统** | 建议：`#已读` `#精读` `#待读` `#方法可用` |
| **分组** | 按主题分组（FDIA / GNN / LLM / 综述） |
| **笔记** | 在 Zotero 内写简短笔记，详细笔记放 Obsidian |
| **引用格式** | 安装 IEEE / GB/T 7714 样式 |
| **同步** | 用 WebDAV（如坚果云）同步 PDF |

> ⚠️ **一个常见错误**：
> **只在 Zotero 里存 PDF，不写笔记** →
> 半年后打开，完全不记得这篇讲了什么。
> **正确做法**：**读完立刻写 5 行摘要**（问题/方法/结论/想法/标签）。

### 四、笔记的三个层次

| 层次 | 内容 | 时机 |
|---|---|---|
| **L1 文献笔记** | 每篇一篇（Day 110 上 的模板） | 读完立刻 |
| **L2 主题笔记** | 一个主题一篇（如"GNN 检测 FDIA"） | 读完 5~10 篇后归纳 ⭐ |
| **L3 想法笔记** | 一个想法一篇 | 随时记录 ⭐⭐ |

**L2 主题笔记的结构**：
```markdown
# 主题：GNN 用于 FDIA 检测

## 领域概览
（这个方向在解决什么核心问题）

## 主要流派
1. 基于残差 + GNN（代表：A, B）
2. 基于物理约束 + GNN（代表：C, D）
3. 基于图结构学习（代表：E）

## 关键对比
（贴对比表格）

## 公认结论
- 结论1（被多篇支持）
- 结论2

## 争议点
- 争议1：A 说 X，B 说 Y

## 研究空白 ⭐
- 空白1：少有人研究拓扑变化
- 空白2：物理约束的注入方式没有系统比较

## 我的想法
- 想法1：...
- 想法2：...

## 相关文献
[[论文A]] [[论文B]] [[论文C]]
```

> 💡 **L3 想法笔记是最容易被忽略但最有价值的**：
> **研究创新往往来自"零散想法"的积累与连接**。
> 建议：**手机上也装 Obsidian**，随时记录灵感。
> **一个想法笔记只需要 3 行**：
> ```
> 想法：用灵敏度矩阵 K 作为 GNN 的边权
> 为什么可能有效：K 编码了"攻击影响传播"
> 验证方式：对比均匀/导纳/灵敏度三种边权
> ```

### 五、一个"可持续"的阅读节奏

**关键认识**：**论文永远读不完**。
**所以必须建立"筛选 + 分层"的机制**。

```
【每日】15 分钟：刷 arXiv 新论文标题
  - 用关键词订阅（arXiv 支持 email alert）
  - 只看标题，感兴趣的存 Zotero（标 #待读）

【每周】2 小时：处理"待读"列表
  - 快速浏览（标题+摘要+图）→ 分类：
    🔴 精读（与方向直接相关）
    🟡 略读（方法可借鉴）
    ⚪ 存档（只记结论）
  - 精读 1~2 篇，写笔记

【每月】半天：主题归纳
  - 把本月精读的论文做 L2 主题笔记
  - 更新对比表格
  - 检查 Gap 是否有变化

【每季度】1 天：全面复盘
  - 重新审视自己的选题
  - 看有没有被新工作"抢先"
  - 调整研究计划
```

> 💡 **"看有没有被抢先"很重要**：
> 你的选题可能在几个月内被别人做出来。
> **季度复盘能让你及时调整**，而不是写到一半发现撞车。

## Day 111 · 09:00 —— 开题报告：把你的想法"讲清楚"

> **一句话**：**开题报告不是"形式"，而是逼你把"我想做什么"想清楚的过程**——写不清楚，往往是因为没想清楚。

### 一、开题报告的本质

**它不是**：
- ❌ 走过场的形式
- ❌ 把综述抄一遍
- ❌ 承诺一个宏大的目标

**它是**：
- ✅ **一份"研究合同"** —— 说明你要解决什么问题、怎么做、能做到什么程度
- ✅ **一次"风险排查"** —— 让导师/评委提前发现你的问题
- ✅ **你未来两年的"路线图"**

> 💡 **一个判断标准**：
> **如果读完你的开题报告，评委能准确说出"你要做什么、为什么这么做、怎么验证"，
> 那它就是合格的。**
> **如果评委问"你到底想做什么"，那就是失败的。**

### 二、开题报告的标准结构

```
第 1 章 研究背景与意义
  1.1 研究背景（从大背景收窄到具体问题）
  1.2 研究意义（理论意义 + 应用价值）
  1.3 国内外研究现状 ⭐（核心，占 1/3 篇幅）
      1.3.1 电力 CPS 安全研究现状
      1.3.2 FDIA 检测方法研究现状
      1.3.3 图神经网络在电力系统的应用
      1.3.4 研究现状总结与不足 ⭐⭐（Gap 分析）

第 2 章 研究内容与目标
  2.1 研究目标（可量化的目标）⭐
  2.2 研究内容（3~4 个模块）
  2.3 拟解决的关键问题（2~3 个）⭐⭐
  2.4 创新点（2~3 个，明确表述）⭐⭐

第 3 章 研究方案与技术路线
  3.1 总体技术路线图 ⭐（一张图说明一切）
  3.2 各模块的具体方法
  3.3 实验设计与评价指标
  3.4 可行性分析

第 4 章 研究计划与预期成果
  4.1 时间安排（甘特图）⭐
  4.2 预期成果（论文/专利/系统）
  4.3 可能的风险与应对 ⭐

参考文献
```

### 三、最关键的三部分

**① 研究现状的"Gap 分析"（1.3.4）**

**错误写法**：
> "现有方法各有优劣，还有提升空间。"
> → **等于没说**

**正确写法**：
> "现有 FDIA 检测方法存在三个不足：
> (1) **假设拓扑已知** —— 文献 [12][15][23] 均假设攻击者不改变拓扑，
>     但实际中拓扑攻击（文献 [8]）会同时发生；
> (2) **未利用物理约束** —— 现有 GNN 方法（文献 [18][25]）只使用统计特征，
>     未显式建模潮流方程的物理一致性；
> (3) **标签依赖强** —— 文献 [19][27] 需要大量标注攻击样本，
>     而实际中攻击样本稀缺。
> 本文针对上述三点，分别提出..."

> 💡 **"Gap 分析"的黄金标准**：
> **每一条不足都要有文献支撑**（说明这不是你瞎说的），
> **并且明确对应你的一个研究内容**。

**② 关键问题（2.3）**

**关键问题 ≠ 研究内容**：
| | 研究内容 | 关键问题 |
|---|---|---|
| 表述 | "研究 X 方法" | "**如何解决 Y 难题**" |
| 例子 | 研究基于 GNN 的检测方法 | **如何在拓扑未知条件下构建可靠的图表示** |
| 性质 | 做什么 | **难在哪** |

> 💡 **"关键问题"是评委最看重的部分**：
> 因为它体现了你**对困难的认识深度**。
> **建议 2~3 个关键问题**，每个对应一个研究内容。

**③ 创新点（2.4）**

**创新点的三种类型**：
| 类型 | 例子 | 强度 |
|---|---|---|
| **问题创新** | 首次研究"拓扑未知下的 FDIA 检测" | ★★★★ |
| **方法创新** | 提出"灵敏度加权图构建" | ★★★ |
| **应用创新** | 首次将 GNN 用于配电网 FDIA | ★★ |

**创新点的写法模板**：
```
创新点 1（问题层面）：
  针对现有方法均假设拓扑已知的不足，
  首次研究【拓扑动态变化下的 FDIA 检测】问题，
  建立了包含拓扑攻击的威胁模型。

创新点 2（方法层面）：
  提出【灵敏度加权图构建方法】，
  用状态估计增益矩阵的绝对值作为边权，
  使图结构显式编码"攻击影响的传播路径"，
  相比均匀边权 F1 提升 X%。

创新点 3（机制层面）：
  提出【物理一致性校验层】，
  在 GNN 输出后增加基于潮流方程的验证环节，
  将误报率降低 Y%，并提供攻击定位能力。
```

> ⚠️ **创新点的三个忌讳**：
> 1. **说"首次"要谨慎**（除非你真的查清楚了）
> 2. **不要只写"提出了一种方法"**（要说明**解决了什么**）
> 3. **不要写"效果更好"**（要说明**为什么更好**）

### 四、技术路线图：一张图讲清所有事

**好的技术路线图的要素**：
```
┌──────────────────────────────────────────────┐
│ 输入：电网量测数据 + 拓扑信息                  │
└──────────────────┬───────────────────────────┘
                   ↓
┌──────────────────────────────────────────────┐
│ 模块1：物理感知图构建                          │
│   - 灵敏度边权 w_ij = |K_ij|                  │
│   - 物理一致性特征（注入平衡残差等）            │
└──────────────────┬───────────────────────────┘
                   ↓
┌──────────────────────────────────────────────┐
│ 模块2：图神经网络检测器                        │
│   - GAT + 边特征                              │
│   - 多尺度时间窗口（时空 GNN）                 │
└──────────────────┬───────────────────────────┘
                   ↓
┌──────────────────────────────────────────────┐
│ 模块3：物理校验与定位                          │
│   - 潮流方程校验 → 降低误报                    │
│   - 注意力 + 残差排序 → 攻击定位               │
└──────────────────┬───────────────────────────┘
                   ↓
┌──────────────────────────────────────────────┐
│ 输出：攻击检测 + 位置 + 置信度                 │
└──────────────────────────────────────────────┘
                   ↓

```

> 💡 **技术路线图的四个必备元素**：
> 1. **输入输出明确**
> 2. **模块划分清晰**（每个模块对应一个创新点）
> 3. **模块间关系（箭头）说明数据流**
> 4. **底部有"验证"环节**（说明怎么证明有效）

### 五、可行性分析：说服评委"你能做出来"

| 维度 | 要说明什么 |
|---|---|
| **理论可行性** | 方法有理论依据（引用文献） |
| **数据可行性** | 数据从哪来（pandapower 仿真 / 公开数据集） |
| **技术可行性** | 技术栈成熟（PyG、pandapower） |
| **算力可行性** | 单卡可完成（说明参数规模） ⭐ |
| **时间可行性** | 甘特图（每阶段有明确产出） |
| **个人基础** | 你已掌握什么（本课程的 120 篇就是证据）⭐ |

> 💡 **"算力可行性"经常被忽略但很重要**：
> **如果你的方案需要 8 张 A100，评委会质疑。**
> **明确说明"在单张 3090/4090 上可完成"** → 大幅提升可行性印象。
> （这也是为什么 W14 推荐 GraphSAGE 和 W15 推荐 LoRA —— **都是单卡可行的**。）

### 六、常见问题与应对（答辩预演）

| 评委可能问 | 怎么答 |
|---|---|
| **"你的创新点在哪？"** | 用"问题创新 + 方法创新"两条说清 |

| **"工作量够吗？"** | 用模块划分说明（3 个模块 + 完整实验） |
| **"为什么用 GNN 不用 LSTM？"** | 说明电力数据的图结构本质 ⭐ |

> ⚠️ **最容易被问倒的问题**：
> **"你的方法和 XXX 有什么区别？"**
> **如果你答不上来，说明你没读最近邻工作** → **这是致命的**。
> **对策**：开题前**务必找到 3 篇最像的工作，逐条对比**。

## Day 111 · 14:00 —— 研究问题与创新点：怎么把"想法"变成"可发表的贡献"

> **一句话**：**"我想做电力安全"不是研究问题，"如何在不完整拓扑下检测 FDIA"才是。**

### 一、研究问题的三级细化

**从模糊到具体**：

```
❌ Level 0（太宽泛）："我想研究电力安全"
   → 这是一个领域，不是一个问题

❌ Level 1（还是太宽）："我想研究 FDIA 检测"
   → 这是一个方向，不是一个问题

⚠️ Level 2（勉强）："我想用 GNN 检测 FDIA"
   → 这是"方法 + 任务"，但没说"难在哪"

✅ Level 3（可研究）：
   "在【拓扑信息不完整】的条件下，
    如何用【图神经网络】检测【稀疏篡改的 FDIA】，
    并【定位被篡改的量测】？"
   → 有约束条件 + 有方法 + 有明确输出
```

> 💡 **一个检验标准**：
> **把你的研究问题念给一个不懂的人听，
> 如果他问"那难在哪？"，说明你还没说清楚。**
> **好的研究问题自带"难点"。**

### 二、研究问题的"四要素"框架

```
RQ = 约束条件 + 方法/视角 + 任务 + 评价标准
     ─────────   ──────────   ────   ──────────
     难在哪      用什么做      做什么   怎么算做好
```

**示例对比**：

| | 约束条件 | 方法 | 任务 | 评价 |
|---|---|---|---|---|
| ❌ 弱 | （无） | GNN | FDIA 检测 | 准确率 |
| ✅ 强 | 拓扑未知 + 标签稀缺 | 物理感知图学习 | FDIA 检测 + 定位 | F1 + 定位命中率 + 鲁棒性 |

> 💡 **"约束条件"是研究问题的灵魂**：
> **没有约束的问题都是"已经被解决的"或"太简单"的。**
> **约束条件 = 现有方法的假设被放宽**（Day 110 上 讲的"假设放宽法"）。

### 三、五个"约束条件"的来源（**选题池**）

| 来源 | 现有假设 | 放宽后的新问题 |
|---|---|---|
| **数据** | 标签充足 | 少样本 / 零样本检测 |
| **知识** | 拓扑已知且准确 | 拓扑未知 / 拓扑变化 |
| **攻击** | 攻击是单次、静态的 | 渐进 / 间歇 / 自适应攻击 |
| **规模** | 小算例（14/118） | 大规模（1000+ 节点） |
| **信息** | 量测完整 | 部分量测缺失 |
| **时间** | 离线训练、离线测试 | 在线/流式检测 |
| **可解释** | 只要准确率 | 需要定位 + 解释 |
| **对抗** | 攻击者不知道检测器 | 自适应攻击（攻击者知道） ⭐ |

> 💡 **"自适应攻击"这一条特别重要**（Day 95 上 讲过）：
> **几乎所有电力 AI 论文都假设"攻击者不知道检测方法"**。
> **如果假设攻击者知道，性能会掉多少？**
> **这个问题几乎没人系统研究过** → **很好的选题**。

### 四、创新点的"三层递进"表述法

**第一层：问题层（最重要）**
```
"现有研究均假设【X】，但实际中【X 不成立】。
 本文首次研究【X 不成立时的 Y 问题】。"
```
> **问题创新是最强的创新**（因为它开辟了新方向）。

**第二层：方法层**
```
"针对【问题 P】，本文提出【方法 M】。
 其核心思想是【直觉】。
 关键设计包括：①... ②... ③..."
```
> **注意：必须说清"核心思想"，而不只是罗列模块。**

**第三层：机制层**
```
"本文进一步引入【机制 N】，
 使系统具备【新能力】（如从检测到定位、从黑箱到可解释）。"
```
> **机制创新往往最实用**（因为它解决了实际部署问题）。

### 五、创新点的"三问自检"

在写创新点之前，问自己三个问题：

| 问题 | 如果答不上来 |
|---|---|
| **① 这个创新解决了什么实际问题？** | 说明是"为了创新而创新" |
| **② 为什么别人没想到？** | 说明可能没价值（太显然）或太难 |
| **③ 怎么证明它有效？** | 说明无法验证 → 不是科研贡献 |

> 💡 **第 ② 问最关键也最难**：
> 如果"为什么别人没想到"的答案是"因为太简单了" →
> **说明这个创新价值低**。
> 如果答案是"因为需要跨领域知识（电力 + AI）" →
> **说明这是你的优势领域** ⭐

### 六、把创新点"量化"（让评委信服）

**不要写**：
> "本文方法有效提升了检测性能。"

**要写**：
> "在 IEEE 118 节点系统上，稀疏 FDIA（keep_ratio=0.97）场景下，
> 本文方法 F1 达到 0.89，相比最优基线（GAT，F1=0.84）提升 5.9%；
> 在自适应攻击场景下，本文方法性能下降 8%，
> 而基线下降 23%，显示出更强的鲁棒性。"

> 💡 **"量化"的三个技巧**：
> 1. **给出具体数字**（不要"显著提升"）
> 2. **给出对比对象**（"相比 XXX"）
> 3. **给出条件**（"在 Y 场景下"）

### 七、一个完整的"研究问题 - 创新点"对照表

> **题目**：面向拓扑动态变化的电力 FDIA 检测

| 关键问题 | 对应创新点 | 验证方式 | 预期指标 |
|---|---|---|---|
| **KQ1** 拓扑未知下如何构建可靠图表示？ | **C1** 灵敏度加权图构建 | 三种边权对比消融 | F1 提升 ≥3% |
| **KQ2** 如何有效注入物理约束？ | **C2** 物理一致性特征 + 物理校验层 | 特征消融 + 误报率 | 误报率降低 ≥30% |
| **KQ3** 如何从检测扩展到定位？ | **C3** 注意力 + 残差排序定位 | Top-5 命中率 | ≥70% |
| **KQ4** 拓扑变化下如何保持性能？ | **C4** GraphSAGE 归纳 + 在线适应 | 跨拓扑迁移 + 微调曲线 | 10 样本微调恢复 ≥90% |

> 💡 **这张表是开题报告的"核心武器"**：
> 它一眼说明"**问题 → 方案 → 验证 → 指标**"的完整链条。
> **建议在开题答辩时直接展示这张表。**

### 八、与网安研究关联

## Day 112 · 09:00 —— 实验设计方法论：让结论"站得住"

> **一句话**：**实验设计的目的是"排除其他解释"**——如果你的结论可以有别的解释，实验就是失败的。

### 一、实验设计的核心逻辑：控制变量

**科学实验的本质**：
```
观察现象 → 提出假设 → 设计实验 → 验证/否证假设
                              ↑
                    必须能"排除其他解释"
```

**一个失败的实验设计**：
```
"我用了方法 A，F1 = 0.89；基线 B，F1 = 0.84。
 所以 A 比 B 好。"
```
> ⚠️ **问题**：可能是别的原因造成的：
> - 超参不同（A 精调过，B 用默认）
> - 随机种子幸运（A 跑了一次，运气好）
> - 数据划分不同
> - 特征集不同（A 用了额外特征，不是方法本身的功劳）

**正确的实验设计**：
```
① 固定所有无关变量（超参搜索预算、随机种子数、数据划分、特征集）
② 只改变【自变量】（方法）
③ 重复多次（≥5 次）→ 报告均值 ± 标准差
④ 统计检验 → 说明差异显著
```

### 二、五类必须做的实验

| 类型 | 目的 | 怎么做 |
|---|---|---|
| **主实验** | 证明"我的方法最好" | 在标准设置下与所有基线对比 |
| **消融实验** ⭐ | 证明"每个模块都有用" | 逐个去掉模块 |
| **鲁棒性实验** ⭐ | 证明"在困难情况下也行" | 攻击强度扫描 + 自适应攻击 |
| **泛化实验** | 证明"不是只在一个算例上好" | 多个数据集/算例 |
| **效率实验** | 证明"实际可用" | 时间、内存、参数量 |

> 💡 **最常见的问题是"只有主实验"**：
> 很多论文只报一张主表就投出去了 →
> **审稿人必问"你的模块真的都有用吗？"** →
> **被要求补消融** → **延误 2~3 个月**。
> **一开始就把五类实验都设计好，能省大量返工时间。**

### 三、消融实验的正确做法

**消融的三种形式**：

| 形式 | 做法 | 回答什么问题 |
|---|---|---|
| **删除（Removal）** | 去掉模块 M | M 有用吗？ |
| **替换（Replacement）** | 用简单版本替代 M | M 的复杂度值得吗？ |
| **累积（Additive）** | 逐个加上模块 | 每个模块的边际贡献？ |

**示例（累积式）**：
| 配置 | 灵敏度边权 | 物理特征 | 物理校验 | F1 | 误报率 |
|---|---|---|---|---|---|
| Baseline（GCN） | ❌ | ❌ | ❌ | 0.79 | 0.18 |
| +灵敏度边权 | ✅ | ❌ | ❌ | 0.83 | 0.16 |
| +物理特征 | ✅ | ✅ | ❌ | 0.87 | 0.12 |
| +物理校验（完整） | ✅ | ✅ | ✅ | **0.89** | **0.05** |

> 💡 **累积式消融的说服力最强**：
> 因为它**展示了每个模块的边际贡献**，
> 而且**逻辑清晰**（一步步加上去，性能单调提升）。

**⚠️ 一个常见错误**：
> **消融实验里"去掉模块后性能不降"** ——
> 这说明**这个模块是多余的** →
> **应该删掉它，而不是在论文里硬说"它有用"**。
> **诚实地删掉，论文反而更扎实。**

### 四、鲁棒性实验：攻击强度扫描

**为什么必须做**：
> 单点结果无法说明"攻击者更强时你怎么办"。

**扫描维度**（选 2~3 个）：
| 维度 | 范围 |
|---|---|
| **攻击强度** | 篡改量测比例 1% → 20% |
| **攻击幅度** | 篡改偏移量 1% → 20% |
| **攻击稀疏度** | keep_ratio 1.0 → 0.9 |
| **噪声水平** | σ = 0.1% → 5% |
| **拓扑扰动** | 断 0 → 5 条线 |

**画图要求**：
```
纵轴：F1（或 AUC）
横轴：攻击强度
多条曲线：不同方法
+ 阴影区域：标准差（多次运行）
```
> 💡 **"阴影区域"能显著提升专业度**：
> 它展示了"结果的稳定性"，
> 很多论文只画单条线（无法判断方差）→ **不够严谨**。

### 五、自适应攻击：最强的一关

**定义**：**假设攻击者知道你的防御方法**，并专门绕过它。

**三种自适应攻击设计**：
| 方法 | 设计思路 |
|---|---|
| **知道模型参数** | 用梯度优化攻击（如 PGD 风格） |
| **知道检测逻辑** | 构造满足检测逻辑的伪装（如满足物理约束的 FDIA） |
| **知道训练数据** | 数据投毒（Day 91） |

**举例（针对"物理约束检测"的自适应攻击）**：
```
普通 FDIA：a = Hc（满足潮流方程，但可能被物理校验抓到）
      ↓ 攻击者知道你有物理校验
自适应攻击：构造 a' 使得
  ① 满足 a' = Hc（统计隐身）
  ② 且篡改后的量测仍满足 KCL/KVL（物理自洽）
  ③ 且造成显著后果
→ 这是"三重约束攻击"（Day 84 讲过）
```

> ⚠️ **如果你的论文没有自适应攻击实验，几乎一定会被要求补。**
> **而且，如果你能证明"自适应攻击下性能下降有限"，这是一个强结论。**

### 六、统计显著性：别忽略这一步

**问题**：A 比 B 高 1.5%，是真的还是噪声？

**三步流程**：
```
① 多次运行（≥5 次），记录每次结果
② 配对比较（配对 t 检验 或 Wilcoxon 符号秩检验）
③ 报告 p 值和效应量
```

**写法示例**：
```
"Our method achieves F1 = 0.862 ± 0.011 (mean ± std over 5 runs),
 significantly outperforming the best baseline
 (GAT, F1 = 0.841 ± 0.013) with p < 0.01
 under the Wilcoxon signed-rank test."
```

**为什么用 Wilcoxon 而不是 t 检验**：
> t 检验假设**正态分布**，
> 但深度学习的多次运行结果**未必正态**（通常只有 5 次）。
> **Wilcoxon 是非参数检验，不需要正态假设** → **更稳妥**。

> 💡 **一个加分项**：报告**效应量（Cohen's d）**，
> 说明"提升的幅度"而不只是"是否显著"。

### 七、一个完整的实验清单（可直接用）

```
【数据】
□ 明确算例（≥2 个，如 IEEE 14 + 118）
□ 明确数据划分方式（按时间块 ⚠️）
□ 明确归一化方式（全局尺度 ⚠️）
□ 说明数据生成方式（pandapower 参数写清）

【模型】
□ 明确所有超参（学习率、批大小、层数、隐藏维度）
□ 明确超参搜索方式（如果调了，说明搜索空间和预算）
□ 所有方法用【相同】的超参搜索预算 ⚠️
□ 固定随机种子（≥5 个种子）

【实验】
□ 主实验：与 ≥5 个基线对比
□ 消融：累积式 + 删除式
□ 鲁棒性：攻击强度扫描（≥5 个强度）
□ 自适应攻击：≥2 种
□ 泛化：≥2 个算例 + 跨算例迁移
□ 效率：训练/推理时间、参数量、显存

【报告】
□ 所有结果：均值 ± 标准差（≥5 次）
□ 统计检验：Wilcoxon，报告 p 值
□ 主表加粗最优、下划线次优
□ 关键图有误差棒/阴影

【可复现】
□ 代码开源（含 README）
□ 超参配置文件
□ 数据生成脚本
□ 环境依赖（requirements.txt / Docker）
```

> 💡 **"所有方法用相同超参搜索预算"这一条特别重要**：
> 很多论文给自己的工作精调超参，给基线用默认 →
> **这是不公平比较** → **审稿人会抓**。
> **正确做法**：所有方法用**同样的搜索空间和次数**。

## Day 112 · 14:00 —— 实验工程化：让代码"可复现、可扩展"

> **一句话**：**科研代码的第一要求不是"优雅"，而是"可复现"**——半年后你能跑出同样的结果吗？

### 一、科研代码的四个"痛点"

| 痛点 | 表现 | 后果 |
|---|---|---|
| **跑不通** | 换台机器就报错 | 浪费几天 |
| **结果不一致** | 重跑结果不同 | 无法确认结论 |
| **改不动** | 加个新模块要改 20 处 | 效率低 |
| **说不清** | 忘记某个参数是什么 | 写论文时抓瞎 |

> 💡 **一个残酷的检验**：
> **"如果让你明天把代码交给导师，他能跑出你的结果吗？"**
> **如果不能，说明代码工程化不足。**

### 三、随机种子的正确设置

```python
import random, numpy as np, torch

def set_seed(seed: int):
    """统一设置所有随机源"""
    random.seed(seed)
    np.random.seed(seed)
    torch.manual_seed(seed)
    torch.cuda.manual_seed_all(seed)
    # 下面两行会牺牲一点性能，但保证可复现（科研场景值得）
    torch.backends.cudnn.deterministic = True
    torch.backends.cudnn.benchmark = False
```

> ⚠️ **一个容易忽略的点**：
> **DataLoader 的 shuffle 也要控制**：
> ```python
> g = torch.Generator()
> g.manual_seed(seed)
> DataLoader(dataset, shuffle=True, generator=g)
> ```
> **不设的话，即使设了全局种子，结果仍会不同。**

**多种子实验的标准做法**：
```python
SEEDS = [42, 123, 456, 789, 2026]
results = []
for seed in SEEDS:
    set_seed(seed)
    model = build_model(cfg)
    f1 = train_and_eval(model, cfg)
    results.append(f1)
print(f"F1: {np.mean(results):.4f} ± {np.std(results):.4f}")
```

### 四、配置管理（避免"改代码改到崩溃"）

**用 YAML 管理所有参数**：
```yaml

  n_layers: 3
  hidden_dim: 64
  n_heads: 4
  dropout: 0.2

  batch_size: 32

  seeds: [42, 123, 456, 789, 2026]
```

**好处**：
| 好处 | 说明 |

| **可分享** | 别人能精确复现 |
| **易对比** | diff 两个配置就知道差异 |

> ```

### 六、代码质量：够用就好

**科研代码不需要**：
- ❌ 100% 单元测试覆盖
- ❌ 完美的设计模式
- ❌ 详细的 API 文档

**科研代码需要**：
- ✅ **能跑通**（在新机器上）
- ✅ **可复现**（种子、配置、数据生成）
- ✅ **可扩展**（加模块不用大改）
- ✅ **可追溯**（实验结果能对应到代码版本）

> 💡 **一个平衡的建议**：
> **"能看懂、能改、能跑"就够了。**
> **但 README 一定要写清楚**（这是最容易偷懒但最影响他人的部分）。

## Day 113 · 09:00 —— 论文写作：叙事比技术更难

> **一句话**：**论文不是"实验报告"，而是"一篇有说服力的论证文章"**——审稿人读的是"你的故事讲得通不通"。

### 一、审稿人怎么读你的论文（**关键认知**）

**真实流程**（大多数审稿人）：
```
① 读标题 + 摘要（1 分钟）
   → 决定"要不要继续读"
② 看图表（2 分钟）
   → 判断"工作是否扎实"
③ 读 Introduction 最后一段（1 分钟）
   → 看你的"贡献列表"
④ 读 Method 的核心部分（10 分钟）
   → 判断"方法是否有新意"
⑤ 读 Experiments 的主表（5 分钟）
   → 判断"效果是否好"
⑥ 抽查消融 / 细节（10 分钟）
   → 找漏洞
⑦ 写意见（10 分钟）
```

> 💡 **这个流程告诉你三件事**：
> 1. **摘要 + 图 + 贡献列表决定"生死"**（前 5 分钟）
> 2. **Method 的"核心思想"比公式细节重要**
> 3. **主表必须一眼能看出"你赢了"**

### 二、论文的"叙事弧"（Narrative Arc）

**一篇好论文是一个"故事"**：
```
【第 1 幕：设定】
  电力 CPS 面临 FDIA 威胁 → 现有方法在【拓扑变化】下失效

【第 2 幕：冲突】
  为什么失效？因为现有方法【假设拓扑已知】
  → 这是一个真实的、重要的问题

【第 3 幕：解决】
  我们提出【物理感知图学习】
  → 核心思想：用灵敏度矩阵编码"攻击影响传播"
  → 三个模块：图构建 / GNN 检测 / 物理校验

【第 4 幕：验证】
  在 IEEE 14/118/300 上，跨拓扑场景 F1 提升 X%
  消融证明每个模块都有贡献
  自适应攻击下性能下降远小于基线

【尾声：意义】
  为拓扑动态变化下的电网安全提供了新思路
```

> 💡 **"叙事"的检验标准**：
> **读完你的 Introduction，审稿人应该能自己复述出这个故事。**
> **如果读完不知道你"为什么做这个"，叙事就失败了。**

### 三、Introduction 的四段式结构（**最实用的模板**）

```
【第 1 段：背景与重要性】（3~5 句）
  电力系统是国家关键基础设施，FDIA 通过篡改量测
  可以绕过传统 BDD，造成物理后果（如虚假潮流导致误调度）。
  随着新型电力系统的发展，攻击面进一步扩大。

【第 2 段：现有工作与不足】（5~8 句）⭐ 关键
  现有 FDIA 检测方法可分为三类：基于残差、基于 ML、基于 GNN。
  其中 GNN 方法因能利用拓扑结构而受到关注（[10]-[15]）。
  然而，现有工作存在三个共同假设：
    (1) 拓扑已知且不变（[12][15][23]）；
    (2) 只使用统计特征，未建模物理约束（[18][25]）；
    (3) 只关注检测，不提供定位（[19][27]）。
  这些假设在真实场景中往往不成立。

【第 3 段：我们的方法】（5~8 句）
  本文提出 XXX 框架，包含三个模块：
    ① 灵敏度加权图构建：用状态估计增益矩阵的绝对值作为边权，
       使图结构显式编码"攻击影响的传播路径"；
    ② 物理一致性特征：设计 5 维物理残差特征；
    ③ 物理校验层：用潮流方程验证 GNN 输出，降低误报并提供定位。

【第 4 段：贡献与结果】（用 bullet 列）
  • 首次研究拓扑动态变化下的 FDIA 检测问题，建立了包含
    拓扑攻击与 FDIA 组合的威胁模型。
  • 提出灵敏度加权图构建方法，相比均匀边权 F1 提升 5.9%。
  • 提出物理校验层，误报率降低 72%，并提供攻击定位能力。
  • 在 IEEE 14/118/300 上验证，跨拓扑场景性能下降仅 8%
    （基线下降 23%）。
  • 开源代码与数据集：[链接]
```

> ⚠️ **Introduction 最常见的三个问题**：
> | 问题 | 表现 | 修正 |
> |---|---|---|
> | **背景太长** | 前两段讲电力系统概况 | 压缩到 3~5 句 |
> | **不足说得太软** | "还有提升空间" | **具体指出哪三个假设** ⭐ |
> | **贡献太笼统** | "提出了新方法" | **量化 + 具体** ⭐ |

### 四、Method 的写法：从"直觉"到"公式"

**推荐的 Method 结构**：
```
3.1 问题定义（Problem Formulation）
    - 符号表
    - 形式化问题描述
    - 威胁模型（攻击者能力）

3.2 方法总览（Overview）
    - 一张框架图 ⭐
    - 用一段话说清"三个模块如何协作"

3.3 模块 1：灵敏度加权图构建
    - 3.3.1 动机（为什么用灵敏度？）⭐ 必须有
    - 3.3.2 具体构造（公式）
    - 3.3.3 复杂度分析

3.4 模块 2：GNN 检测器
    - 3.4.1 架构选择理由
    - 3.4.2 物理一致性特征设计
    - 3.4.3 损失函数

3.5 模块 3：物理校验与定位
    - 3.5.1 校验规则
    - 3.5.2 定位算法

3.6 复杂度分析
```

> 💡 **每个模块必须写"动机"（Motivation）**：
> **不要直接给公式，要先说"为什么要这样设计"。**
> 例如：
> ```
> ❌ 差：我们定义边权为 w_ij = |K_ij|。
> ✅ 好：物理上，量测 j 的扰动会通过增益矩阵 K 影响状态估计。
>      因此 |K_ij| 反映了"量测 j 对节点 i 的影响强度"。
>      若攻击者篡改量测 j，其影响会沿 |K_ij| 大的边传播。
>      因此我们用 |K_ij| 作为边权，使图结构编码攻击传播路径。
> ```

### 五、Experiments 的写法

**标准结构**：
```
4.1 实验设置
    - 数据集（算例、规模、生成方式）
    - 攻击模型（类型、强度、参数）
    - 基线方法（≥5 个，说明为什么选它们）
    - 评价指标
    - 实现细节（超参、硬件）

4.2 主实验
    - 一张主表（所有方法 × 所有指标）
    - 一段分析（不要只报数字，要说"为什么"）⭐

4.3 消融实验
    - 累积式消融表
    - 分析每个模块的边际贡献

4.4 鲁棒性分析
    - 攻击强度扫描图
    - 自适应攻击结果
    - 拓扑扰动结果

4.5 泛化性
    - 跨算例结果

4.6 效率分析
    - 时间、内存、参数量

4.7 案例分析（Case Study）⭐
    - 举一个具体例子：某次攻击，模型如何检测、定位
    - 可视化注意力 / 残差
```

> 💡 **"案例分析"是很多论文的加分项**：
> **它把抽象指标变成具体场景**，让审稿人"看到"你的方法在工作。
> **示例**：
> ```
> 图 7 展示了母线 5 被篡改的案例：
> (a) 原始量测：母线 5 注入功率异常偏高
> (b) GNN 注意力：集中在支路 5-7（α=0.51，其他 <0.1）
> (c) 物理校验：母线 5 的注入平衡残差为 8.3（阈值 2.0）
> → 三个证据一致指向母线 5，定位正确。
> ```

### 六、写作的十条"军规"

| # | 规则 |
|---|---|
| 1 | **一段一个中心思想**（段落开头是主题句） |
| 2 | **用主动语态**（"We propose" 而非 "It is proposed"） |
| 3 | **避免"very/really/significantly"** 这类模糊词 |
| 4 | **数字要精确**（"提升 5.9%" 而非 "明显提升"） |
| 5 | **术语一致**（全文用同一个词，不要同义词替换） |
| 6 | **公式前的符号要定义**（符号表） |
| 7 | **图表在正文中必须被引用**（"如图 3 所示"） |
| 8 | **不要堆砌相关工作**（Related Work 要分类 + 评论） |
| 9 | **结论不要引入新内容** |
| 10 | **写完后朗读一遍**（能发现拗口的句子） ⭐ |

> 💡 **第 10 条特别有效**：
> **朗读能发现"读起来不通顺"的地方**，
> 这些地方往往是**逻辑断裂**或**句子太长**。

>
> **摘要模板**（200 词以内）：

## Day 113 · 14:00 —— 图表设计：一张图胜过一千字

> **一句话**：**审稿人只看图也能判断你的工作质量**——图表的专业度直接决定第一印象。

### 一、图表的三条铁律

| 铁律 | 说明 |
|---|---|
| **自明性（Self-contained）** | 不看正文也能看懂图表 |
| **可比性（Comparable）** | 同一维度的图用同样的尺度和样式 |
| **信息密度** | 一张图传达尽可能多但不混乱的信息 |

> ⚠️ **最常见的错误**：
> **图表的 caption 只写"图 3：实验结果"** →
> **审稿人必须回去读正文才知道图在说什么**。
> **正确做法**：caption 要写清"这张图展示什么、关键结论是什么"。

### 二、论文必备的五张图

| # | 图 | 作用 |
|---|---|---|
| 1 | **框架图（Framework）** | 说明方法整体结构 ⭐⭐⭐ |
| 2 | **主结果对比图** | 直观展示性能优势 |
| 3 | **攻击强度扫描曲线** | 展示鲁棒性 ⭐⭐ |
| 4 | **消融柱状图** | 展示模块贡献 |
| 5 | **案例分析图** | 展示实际效果 ⭐⭐ |

**框架图的绘制要点**：
```
① 从左到右（输入 → 处理 → 输出）或从下到上
② 用不同颜色区分模块（但不要超过 4 种颜色）
③ 每个模块内标注关键技术（如"GAT + edge features"）
④ 用虚线框标出"本文贡献"的部分 ⭐
⑤ 尺寸：单栏 ~8.8cm 宽，双栏 ~18cm 宽
⑥ 字号：图中文字 ≥ 8pt（缩小后仍可读）
```

> 💡 **"用虚线框标出本文贡献"是一个很实用的小技巧**：
> 审稿人一眼就知道"哪部分是你做的，哪部分是现成的"。
> **这能避免"你的方法看起来都是拼装"的质疑。**

### 三、表格的设计规范

**主表的标准格式**：
```
| Method      | IEEE 14        | IEEE 118       | IEEE 300       |
|             | F1    AUC      | F1    AUC      | F1    AUC      |
|-------------|----------------|----------------|----------------|
| MLP         | 0.79  0.85     | 0.76  0.82     | 0.73  0.80     |
| GCN         | 0.82  0.87     | 0.79  0.85     | 0.77  0.83     |
| GAT         | 0.84  0.89     | 0.81  0.87     | 0.79  0.85     |
| GraphSAGE   | 0.83  0.88     | 0.82  0.88     | 0.81  0.87     |
| Baseline-X  | 0.85  0.90     | 0.83  0.89     | 0.82  0.88     |
| **Ours**    | **0.89** **0.93** | **0.87** **0.92** | **0.86** **0.91** |
| 提升        | +4.7%  +3.3%   | +4.8%  +3.4%   | +4.9%  +3.4%   |
```

**规范要点**：
| 要点 | 说明 |
|---|---|
| **最优加粗，次优下划线** | 标准做法 |
| **有效数字统一** | 都是 2 位小数 |
| **分组** | 用横线分隔基线组和本文方法 |
| **最后一行给提升幅度** | 一目了然 ⭐ |
| **caption 在表格上方** | 图在下方，表在上方（IEEE 规范） |
| **避免竖线** | 三线表更专业 ⭐ |
| **重复的实验说明放 caption** | 不要占正文 |

> 💡 **"最后一行给提升幅度"很有用**：
> **审稿人不需要自己算** → **直接看到你的优势**。

## Day 114 · 09:00 —— 选刊与投稿：把论文投到对的地方

> **一句话**：**选对期刊比写好论文更容易被低估**——投错地方，好工作也会被拒。

### 一、投稿前的"自我评估"

**三个问题**：
```
① 我的贡献有多大？
   - 新问题 + 新方法 + 充分实验 → 顶会/顶刊
   - 新方法 + 充分实验 → 好期刊
   - 应用现有方法到新场景 + 扎实实验 → 中等期刊
   - 小改进 + 有限实验 → 会议/中文核心

② 我的实验有多完整？
   - 多算例 + 消融 + 鲁棒性 + 统计检验 → 顶刊
   - 单算例 + 消融 → 中等期刊
   - 单算例 + 主实验 → 会议

③ 我的叙事有多新？
   - "首次研究 X 问题" → 强
   - "改进现有方法" → 中
   - "应用已知方法" → 弱
```

> 💡 **一个诚实的心态**：
> **第一篇论文不要冲顶刊。**
> **先投一个"能中"的期刊**，把"发表"这件事走通一遍，
> 你会学到整个流程，第二篇就能投更好的。
> **"发表一篇"比"投稿三次被拒"更有价值。**

### 三、怎么判断一个期刊"合不合适"

**五个检查步骤**：
```
① 看期刊的 Aims & Scope
   → 你的主题在范围内吗？（很多拒稿是因为 out of scope）

② 搜近 2 年该刊有没有类似主题的论文
   → 有 → 说明欢迎这类工作 ⭐
   → 没有 → 谨慎（可能不感兴趣）

③ 看审稿周期（在期刊官网或 LetPub/小木虫查）
   → 3~6 个月正常；> 12 个月要慎重

④ 看是否开源（OA）及费用
   → OA 通常要 APC（几千美元）⚠️

⑤ 看中科院分区 / JCR 分区
   → 与你的毕业要求对齐 ⭐
```

> ⚠️ **务必警惕"掠夺性期刊"（Predatory Journals）**：
> **特征**：
> - 承诺"一周内录用"
> - 主动邮件邀稿（大量群发）
> - 版面费很高但审稿极快
> - 编委会成员信息虚假
> - 官网简陋、无 DOI
> **后果**：**不算成果，浪费钱和时间** ⚠️
> **查证方法**：查 Beall's List、查是否在 DOAJ、查学校认可名单。

## Day 114 · 14:00 —— 回复审稿意见：Rebuttal 的艺术

> **一句话**：**审稿意见不是"攻击"，而是"免费的专家咨询"**——回复的质量往往决定论文的生死。

### 一、拿到审稿意见的第一件事

**❌ 错误反应**：
```
① 立刻开始写回复（情绪化）
② 觉得审稿人"不懂"
③ 只回复容易的，回避难的问题
④ 争辩、对抗
```

**✅ 正确流程**：
```
① 先冷静 24 小时 ⭐
② 通读所有意见，分类：
   - 容易改（格式、笔误、补充说明）
   - 需要补实验（最难，最耗时）
   - 需要重新解释（可能是你写得不清楚）
   - 真有道理但难做（部分做 + 说明）
   - 明显误解（礼貌澄清 + 检查是否自己表述不清）
③ 制定计划：哪些补实验、哪些改文字、时间安排
④ 和导师/合作者讨论策略
⑤ 逐条回复
```

> 💡 **最重要的一条**：
> **审稿人说"你的方法 X 有问题"，
> 90% 的情况是"你写得不清楚，让他产生了误解"。**
> **所以回复时，先问自己："是不是我没写清楚？"**
> **如果是，就补充说明并修改论文** ——
> **这比争辩有效得多。**

### 二、Rebuttal 的结构

```
Dear Editor and Reviewers,

We thank the reviewers for their constructive comments, which
have helped us significantly improve the manuscript. We have
revised the paper accordingly. Below we provide point-by-point
responses. Reviewer comments are in italic, our responses in
regular font, and changes in the manuscript are marked in blue.

──────────────────────────────────────────
Reviewer 1
──────────────────────────────────────────
Comment 1.1: [原文照抄审稿人的意见]

Response: We thank the reviewer for this insightful comment.
[你的回复]

Changes: We have added Section 3.4 (Page 8, Lines 210-235)
and Table 3 to address this point.
──────────────────────────────────────────
Comment 1.2: ...
```

**关键格式要素**：
| 要素 | 说明 |
|---|---|
| **原文照抄意见** | 便于审稿人对照 |
| **先感谢** | 礼貌是基础 |
| **逐条编号** | 不要漏任何一条 ⚠️ |
| **标注修改位置** | "Page 8, Lines 210-235" ⭐ |
| **修改处标色** | 让审稿人快速看到改动 ⭐ |

### 三、五种意见的回复策略

**① 容易改的（格式、笔误）**
```
Comment: Figure 3 is too small to read.

Response: We thank the reviewer for pointing this out.
We have enlarged Figure 3 and increased the font size.

Changes: Figure 3 (Page 6).
```
> **直接改，不要解释。** 简单干脆。

**② 需要补实验的（最有价值）**
```
Comment: The comparison with baseline X seems unfair because
the hyperparameters are not specified.

Response: We thank the reviewer for this important point.
We have conducted additional experiments with a unified
hyperparameter search budget (20 trials for all methods,
same search space). The results are shown in Table 5.
Our method still outperforms all baselines by 3.2%~5.9%.

Changes: Added Section 4.5 and Table 5 (Page 11).
```
> 💡 **补实验是"加分项"**：
> **它让审稿人看到你"愿意做工作"** →
> **态度比结果更重要。**

**③ 需要重新解释的（你写得不清楚）**
```
Comment: I don't understand why the sensitivity matrix is
used as edge weights.

Response: We apologize for the unclear presentation. The
motivation is as follows: [详细解释] ...
We have added a paragraph in Section 3.3.1 (Page 7, Lines 180-195)
to clarify this.

Changes: Added explanation in Section 3.3.1.
```
> ⚠️ **不要写"我们已经解释过了"**（即使你真的写了）——
> **应该写"我们感谢审稿人指出表述不清，已补充说明"**。
> **这是礼貌，也是专业。**

**④ 有道理但难做的**
```
Comment: The method should be validated on real-world data.

Response: We agree that real-world validation is important.
Unfortunately, due to data confidentiality requirements of
power utilities, real SCADA data is not publicly available.
As an alternative, we have: (1) validated on three IEEE
standard systems with different scales; (2) added topology
perturbation experiments to mimic real conditions; (3) added
a discussion of this limitation in Section 5.2.
We will pursue real-data validation in future work.

Changes: Added Section 4.6 and limitation discussion.
```
> 💡 **策略：部分满足 + 说明原因 + 承诺未来工作**。
> **不要硬说"不需要真实数据"** —— 那会显得不专业。

**⑤ 明显误解的（谨慎处理）**
```
Comment: The paper claims to detect all types of attacks,
which is unrealistic.

Response: We thank the reviewer for this comment. We would
like to clarify that our method targets false data injection
attacks with incomplete topology knowledge, as stated in
Section 3.1 (threat model). We do not claim to detect all
attack types. To avoid misunderstanding, we have revised
the abstract and introduction to state the scope more
explicitly.

Changes: Revised Abstract (Page 1) and Section 1 (Page 2).
```
> 💡 **即使审稿人误解了，也要"先检查自己的表述"**：
> **"我们已修改表述以避免误解"** ——
> **这既维护了立场，又表现出谦虚。**
> **永远不要写"审稿人错了"。**

### 四、Rebuttal 的十条军规

| # | 规则 |
|---|---|
| 1 | **逐条回复，一条不漏** ⚠️ |
| 2 | **先感谢，再回复** |
| 3 | **不争辩、不情绪化** |
| 4 | **标注修改位置（页/行）** ⭐ |
| 5 | **修改处标色**（蓝/红） |
| 6 | **能补的实验就补** ⭐ |
| 7 | **不能做的说明原因 + 承诺未来工作** |
| 8 | **承认错误要干脆**（"We apologize..."） |
| 9 | **回复要具体**（给数字、给引用） |
| 10 | **回复信要易读**（分点、加粗、表格） |

> ⚠️ **第 1 条最关键**：
> **漏回复一条意见 = 直接被拒**。
> **对策**：把审稿意见编号，逐条打勾。

### 五、Rebuttal 的时间管理

**一个实际的时间分配（Major Revision，给 2 个月）**：
```
第 1 周：理解意见 + 分类 + 制定计划 + 与导师讨论
第 2~4 周：补实验（最耗时）⭐
第 5 周：修改论文正文
第 6 周：写 Rebuttal 初稿
第 7 周：和合作者一起审阅回复
第 8 周：定稿提交（留出缓冲）⚠️
```

> 💡 **"留出缓冲"很重要**：
> **补实验可能比预期慢**（代码 bug、结果不理想）。
> **千万不要卡着 deadline 提交。**

### 六、被拒之后怎么办

**"拒稿"的三种类型**：
| 类型 | 特征 | 对策 |
|---|---|---|
| **Desk Reject** | 编辑直接拒（未送审） | **可能是不合适** → 换刊 |
| **Reject with reviews** | 送审后拒 | **意见有价值** → 大改后换刊 |
| **Reject and Resubmit** | 可以重投同一刊 | 按要求大改后重投 |

**换刊重投的注意事项**：
```
□ 根据审稿意见认真修改（不要原封不动换刊投）⚠️
□ 如果换了刊，要按新刊的模板重新排版
□ 重新写 Cover Letter（说明为什么适合新刊）
□ 检查参考文献格式
□ 如果之前审稿人指出的问题没解决，新审稿人可能还会提
```

> 💡 **一个统计事实**：
> **一篇论文平均要投 2~3 次才能被接受。**
> **所以"被拒"是流程的一部分，不是你的失败。**
> **关键是每次被拒都让论文变得更好。**

### 七、与网安研究关联

> 💡 **给你的具体准备**：
> ```
> 【投稿前自查】
> □ 有没有"拓扑假设"相关的审稿风险？
>    → 在 Introduction 里明确说明"为什么放宽这个假设很重要"
> □ 有没有"实验不够充分"的风险？
>    → 确保五类实验齐全（Day 112 上）
> □ 有没有"和 XXX 有什么区别"的风险？
>    → 确保读了 3 篇最近邻工作并明确对比 ⭐
> □ 有没有"数据集是仿真的"的风险？
>    → 说明仿真参数 + 承认局限 + 承诺未来工作
> □ 有没有"可复现性"的风险？
>    → 开源代码
> ```
>
> **提前把这些"可能的质疑"在论文里主动回应** →
> **能显著降低被拒概率。** ⭐

### 🔍 延伸思考

1. 如果**审稿人要求补一个"不可能完成"的实验**，怎么办？
   （→ 说明技术/资源限制 + 提供替代方案 + 解释为什么替代方案能回答同一个问题）
2. **审稿人之间意见矛盾**（A 说要多加实验，B 说要精简），怎么办？
   （→ **在回复中说明这个矛盾，请编辑裁定**。编辑会帮你。）

## Day 115 · 09:00 —— 学术诚信：不可越界的红线

> **一句话**：**学术不端的代价是不可逆的**——一次造假可能毁掉整个学术生涯。

### 一、学术不端的"分级"

| 级别 | 行为 | 后果 |
|---|---|---|
| **🔴 严重不端** | 数据造假、篡改结果、抄袭、一稿多投 | **撤稿 + 通报 + 学位撤销** |
| **🟠 不当行为** | 重复发表、不当署名、拆分发表（香肠论文） | 批评、撤稿、影响声誉 |
| **🟡 灰色地带** | 过度美化图表、选择性报告结果、不当地引用 | 影响可信度 |
| **🟢 规范问题** | 引用格式错误、遗漏致谢 | 需修正 |

> ⚠️ **一个残酷的事实**：
> **现在的学术不端检测非常严格**：
> - 查重系统（Turnitin、CNKI）
> - 图像查重（检测图片复用）⭐
> - 数据核查（要求提供原始数据）
> - 同行监督（有人专门找问题）
> **"侥幸"的空间越来越小。**

### 二、五条绝对不能碰的红线

**① 数据造假（Fabrication）**
```
❌ 编造不存在的实验数据
❌ 用"预期结果"代替"实际结果"
❌ 只报告成功的实验，隐藏失败的
```
> **正确做法**：**如实报告所有结果**，包括不理想的。
> **"负结果"也是结果**（Day 108 下 讲过）。

**② 结果篡改（Falsification）**
```
❌ 修改数据让结果"更好看"
❌ 删除"不好"的数据点
❌ 调整纵轴截断夸大差异 ⚠️
❌ 用不同的随机种子挑最好的一次报告
```
> ⚠️ **"挑种子"是最常见的灰色行为**：
> **跑 10 次，报最好的那次** —— 这是**选择性报告**。
> **正确做法**：**跑 5 次，报均值 ± 标准差**。

**③ 抄袭（Plagiarism）**
```
❌ 直接复制他人文字不引用
❌ 改写但保留原意不引用（"洗稿"）
❌ 复制自己的旧论文不说明（自我抄袭）⚠️
❌ 使用他人图片/代码不注明
```
> 💡 **一个容易忽略的点**：
> **"自我抄袭"也是抄袭**。
> **如果你在学位论文里用了已发表的论文内容，必须明确说明。**

**④ 一稿多投（Duplicate Submission）**
```
❌ 同时投给多个期刊
❌ 一篇论文拆成几篇投（香肠论文）
❌ 内容重叠度高的多篇论文
```
> ⚠️ **"香肠论文"（Salami Slicing）**：
> **把一个完整工作拆成 3 篇小论文**。
> **虽然不算严重不端，但会被同行诟病**，也可能被编辑拒稿。

**⑤ 不当署名**
```
❌ 没贡献的人挂名（"人情署名"）
❌ 有贡献的人不挂名（"剥削学生"）
❌ 通讯作者未经同意被署名
```
> 💡 **署名的国际标准（ICMJE）**：
> 必须同时满足四个条件：
> 1. 对研究构思/设计/数据获取/分析有**实质贡献**
> 2. 参与**论文撰写或关键修改**
> 3. **同意最终版本**
> 4. **同意对研究负责**

### 三、AI 使用的新规范（**当前热点**）

**当前学术界的共识（各出版社政策）**：
| 出版社 | 政策 |
|---|---|
| **Nature** | AI 不能作为作者；使用 AI 必须在方法中声明 |
| **IEEE** | 要求声明 AI 使用；AI 不能署名 |
| **ACM** | 允许使用但需声明；不得隐瞒 |
| **Elsevier** | 要求声明；作者对内容负全责 |
| **各中文期刊** | 政策不一，多数要求声明 |

**规范做法**：
```
① AI 生成的文字不能直接作为论文正文（可能被检测）
② 如果用了 AI 辅助（润色、代码、分析），在方法/致谢中声明
③ 所有内容作者必须完全理解并负责
④ 不得用 AI 编造引用或数据 ⚠️
```

**一个声明模板**：
```
During the preparation of this work, the author(s) used
[工具名称] in order to [具体用途，如"improve language
and readability"]. After using this tool, the author(s)
reviewed and edited the content as needed and take full
responsibility for the content of the publication.
```

> 💡 **一个务实的建议**：
> **AI 用于"润色语言"是安全的**（并声明）；
> **AI 用于"生成正文内容"是危险的**（可能被检测 + 学术风险）。
> **界限：AI 帮你表达，不帮你思考**（Day 108 上讲过）。

### 四、引用规范

**必须引用的**：
| 情况 | 说明 |
|---|---|
| **他人观点/数据** | 必须引用原始出处 |
| **他人方法** | 必须引用 |
| **直接引用原句** | 加引号 + 页码 |
| **他人图表** | 必须获得许可 + 引用 |
| **开源代码** | 引用其论文或仓库 |

**引用不规范的常见问题**：
| 问题 | 说明 |
|---|---|
| **引二手来源** | 引用综述而不引用原始论文 ⚠️ |
| **引而不读** | 引用了但没读过（可能引错） ⚠️ |
| **过度自引** | 大量引用自己的论文 |
| **堆砌引用** | 一句话后挂 10 篇引用 |
| **漏引关键工作** | 审稿人可能正好是作者 ⚠️ |

> ⚠️ **"引而不读"是很多研究生的通病**：
> 从别人的参考文献列表里抄引用，自己没读过 →
> **可能引错意思** → **审稿人发现会质疑你的严谨性**。
> **对策**：**每一篇引用都要至少读过摘要**。

### 五、与导师/合作者的诚信边界

| 场景 | 正确做法 |
|---|---|
| **导师要求修改数据** | ⚠️ **坚决拒绝**，必要时向学院反映 |
| **导师要求挂无关作者** | 沟通协商，说明规范 |
| **合作者要求删不利结果** | 拒绝，说明这是学术不端 |
| **导师要求抢一作** | 按实际贡献协商，必要时申诉 |
| **发现已发表论文有错** | 联系期刊发勘误（Erratum） |

> 💡 **一个重要提醒**：
> **学术诚信的责任在你自己**。
> **"是导师让我这么做的"不能免除你的责任** ——
> 论文上有你的名字，你就要负责。
> **如果遇到明确的造假要求，保护自己比保住关系更重要。**

### 六、与网安研究关联

| 实验室方向 | 接口 |
|---|---|
| **AI与数据安全** | 数据合规（《数据安全法》《个人信息保护法》） |
| **工业AI** | 电力数据涉密，需注意合规 ⚠️ |
| **所有方向** | 学术诚信是底线 |

> ⚠️ **电力数据特有的合规问题**：
> ```
> ① 电力系统数据可能涉密（《电力监控系统安全防护规定》）
> ② 真实电网数据不能随意公开
> ③ 即使用仿真数据，也要说明生成方式
> ④ 与企业合作的数据，需明确使用范围
> ⑤ 开源代码前，检查是否含敏感信息（IP、密钥、拓扑细节）
> ```
> **建议**：**优先用公开标准算例（IEEE 14/118）+ 仿真数据**，
> **这样既合规又便于复现** —— **这也是本课程一直推荐的做法。**

### 🔍 延伸思考

1. 如果**你发现同组同学在造假**，该怎么办？
   （→ 先沟通；无效则向导师/学院反映。**沉默也是共谋。**）
2. **"选择性报告"**（只报显著的结果）算不算不端？
   （→ 严格说算"不当行为"。**规范做法：报告所有预设实验的结果。**）

## Day 115 · 14:00 —— 学术演讲与答辩：把工作"讲出来"

> **一句话**：**答辩不是"考试"，而是"让评委相信你做了扎实的工作"**——而相信的前提是听懂。

### 一、答辩的三个核心目标

```
① 让评委听懂你在做什么（清晰）
② 让评委相信你做的是对的（严谨）
③ 让评委看到你的贡献（价值）
```

> ⚠️ **最常见的失败**：
> **内容太多、太快、太技术** →
> **评委没听懂 → 无法判断价值 → 提问变成"挑刺"**。

### 二、答辩的结构（15~20 分钟）

```
【1. 背景与问题】（3 分钟）
   - 电力 CPS 面临什么威胁（1 页）
   - 现有方法的不足（1 页）
   - 本文要解决什么问题（1 页）⭐ 讲清楚
   
【2. 方法】（6 分钟）
   - 总体框架图（1 页）⭐⭐ 最重要
   - 三个模块各 1~2 页
   - 每页只讲一个核心点
   
【3. 实验】（5 分钟）
   - 主结果表（1 页）
   - 消融（1 页）
   - 鲁棒性曲线（1 页）⭐
   - 案例分析（1 页）⭐ 最有说服力
   
【4. 结论与贡献】（2 分钟）
   - 三个贡献（1 页）
   - 局限与未来工作（1 页）
```

**页数控制**：
```
15 分钟 ≈ 15~20 页
20 分钟 ≈ 20~25 页
（平均 1 页 1 分钟）
```

> 💡 **"每页只讲一个核心点"是铁律**：
> **一页 PPT 塞太多内容 → 评委读字不听你讲 → 你讲了等于没讲。**

### 三、PPT 设计规范

| 要素 | 规范 |
|---|---|
| **字号** | 正文 ≥ 24pt，标题 ≥ 32pt ⚠️ |
| **每页字数** | ≤ 6 行 × 8 字（越少越好） |
| **配色** | 深色文字 + 浅色背景（投影清晰） |
| **公式** | 只放关键公式（≤3 个） |
| **图** | 占页面 ≥ 60% ⭐ |
| **动画** | 只用于"逐步展示"，不要花哨 ⚠️ |
| **页脚** | 页码 + 你的名字 |

**每页的结构**：
```
┌─────────────────────────────┐
│ 【标题：一句话说明本页】      │
│                             │
│   [ 图 / 表 占 60% 面积 ]    │
│                             │
│ • 要点1（≤10 字）            │
│ • 要点2（≤10 字）            │
└─────────────────────────────┘
```

> ⚠️ **三个常见错误**：
> 1. **大段文字**（评委读字不听你讲）
> 2. **复杂公式堆砌**（没人跟得上）
> 3. **图太小看不清**（尤其框架图）

### 四、讲稿的准备

**原则**：**写"关键词稿"，不写"逐字稿"**
```
❌ 逐字稿：会被读稿的感觉毁掉，而且临场应变差
✅ 关键词稿：每页写 3~5 个关键词 + 转折句
```

**关键句要背熟**：
| 位置 | 关键句示例 |
|---|---|
| **开场** | "我的研究解决的是【拓扑动态变化下 FDIA 检测】问题。" |
| **过渡** | "针对这个问题，我们提出三个模块。" |
| **方法核心** | "核心思想是：用灵敏度矩阵编码攻击影响的传播路径。" |
| **结果** | "在 IEEE 118 上，F1 达到 0.89，比最优基线提升 5.9%。" |
| **结尾** | "本文的贡献是……我的汇报完毕，请各位老师批评指正。" |

> 💡 **"方法核心"这一句最重要**：
> **如果评委只能记住一句话，你希望是哪句？**
> **把它打磨到极致，并在答辩中说至少两遍。**

### 五、时间控制的技巧

**排练至少 3 次**：
```
第 1 次：自己对着 PPT 讲，计时（通常超时 50%）
第 2 次：删减内容，再计时（接近目标）
第 3 次：找人听，模拟真实场景（含提问）
```

**超时怎么办**：
| 情况 | 对策 |
|---|---|
| **超时 3 分钟内** | 加快语速，跳过细节页 |
| **超时 5 分钟以上** | **必须删页**（不要靠加快语速） |
| **时间不够** | 果断跳过"背景"和"相关工作"，直奔方法 |

> ⚠️ **超时是答辩大忌**：
> **主持人会打断你** → **结论没讲完** → **评委印象差**。
> **宁可内容少一点，也要讲完。**

### 六、提问环节的应对

**五类常见问题及对策**：

| 问题类型 | 示例 | 对策 |
|---|---|---|
| **创新点** | "你的创新点在哪？" | **用"问题创新+方法创新"两条说清** ⭐ |
| **对比** | "和 XXX 有什么区别？" | 逐点对比（**必须读过**）⚠️ |
| **方法细节** | "为什么用 GAT 不用 GCN？" | 说明理由（数据/可解释性） |
| **数据** | "为什么用仿真数据？" | 承认局限 + 说明合理性 + 未来计划 |
| **效果** | "如果攻击更强呢？" | **给出扫描曲线**（说明你做过）⭐ |

**应答的三步法**：
```
① 先确认问题（"您是想问...吗？"）
   → 避免答非所问
② 给核心答案（1 句话）
   → 不要绕弯
③ 补充依据（数据/文献）
   → 增强说服力
```

> 💡 **"先确认问题"很有效**：
> **有些问题表述模糊，直接答可能答偏。**
> **确认一下既显得你认真，也给自己思考时间。**

**遇到不会的问题**：
```
❌ "这个我没考虑过。"（太消极）
❌ 硬编一个答案（可能被追问到露馅）⚠️
✅ "这是一个很好的问题。目前我们的工作没有涉及这一点，
    但我认为可以从【某角度】入手，这也是我后续想做的方向。"
```
> 💡 **"诚实 + 给出思路"是最佳应对**：
> **评委问"不会的"往往是想看你的思维，而不是答案。**

产出：1~2 篇论文（方法创新明显）
```

**方向 C：LLM/Agent 在电力安全中的应用与风险**
```
问题：LLM 进入电网带来的新攻击面
方法：提示注入 → 物理后果链 + 物理校验防御
挑战：需要搭建仿真环境
产出：1~2 篇论文（新意强，竞争少）⭐
```

> 💡 **推荐组合**：
> **研一：GNN 检测（方向 A/B 的基础）**
> **研二：A 或 B 深入 + 方向 C 作为第二战线**
> **理由**：A/B 与实验室"工业AI + 入侵检测"对接，
> C 与"多模态大模型 + 智能体"对接 → **两个方向全中**。

### 六、一些"过来人"的建议

| 建议 | 说明 |
|---|---|
| **每周固定时间做实验** | 不要"有空才做"，实验需要连续时间 |
| **记录一切** | 实验日志、失败原因、想法 —— 都是资产 |
| **主动找导师汇报** | 每 2 周一次，带着"我做了什么 + 遇到什么困难" |
| **和同门交流** | 很多灵感来自"随口聊聊" |
| **读论文要动手** | 看完就想"我能不能实现" |
| **不要怕失败** | 90% 的实验是失败的，这是常态 ⭐ |
| **保护身体** | 科研是长跑，熬夜不可持续 |
| **保持一个爱好** | 用来对抗"研究卡住"时的焦虑 |

> 💡 **最重要的一条**：
> **"90% 的实验是失败的"** ——
> 这不是安慰，是事实。
> **一个成功的结果背后，可能有 10 次失败的尝试。**
> **所以"没有结果"不代表"你不适合科研"** ——
> **它只代表"这一条路走不通"。**
