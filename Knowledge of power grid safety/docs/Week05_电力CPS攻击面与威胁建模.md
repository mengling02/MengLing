## Day 29 · 09:00 —— 信息物理系统（CPS）概念与电力 CPS 特殊性

> **一句话**：**电力 CPS = 电力物理系统 + 信息系统，两者深度耦合**。攻击者攻破信息系统，物理电网就会出问题——**这个"耦合"是电网安全研究的全部立足点**。

### 一、什么是 CPS

**CPS（Cyber-Physical System，信息物理系统）**：计算、通信与物理过程**深度集成**的系统。

```
        信息域（Cyber）                物理域（Physical）
    ┌──────────────────┐          ┌──────────────────┐
    │  计算节点        │          │  物理设备        │
    │  通信网络        │◄────────►│  物理过程        │
    │  控制算法        │  耦合     │  物理定律        │
    └──────────────────┘          └──────────────────┘
              ↑                            ↑
         网络攻击                    物理后果
```

**CPS 的三个特征**：
1. **紧耦合**：信息与物理不可分割
2. **实时性**：控制回路有严格时延要求
3. **反馈闭环**：传感器 → 计算 → 执行器 → 物理变化 → 传感器

### 二、电力 CPS 的结构

```
【信息层】
  调度中心（EMS/DMS）
      ↕ 通信网络
  变电站自动化系统
      ↕ 过程层网络
  保护 IED / 测控 IED
      ↕
【物理层】
  变压器、断路器、线路、发电机
      ↕
  电力物理过程（潮流、稳定性）
```

**双向耦合**：
- **信息 → 物理**：控制指令改变物理状态（遥控跳闸）
- **物理 → 信息**：量测反映物理状态（电压电流）

### 三、电力 CPS 的特殊性

| 特殊性 | 说明 | 安全含义 |
|---|---|---|
| **强实时约束** | 保护要求 4ms | 安全机制受限 |
| **物理后果不可逆** | 设备损坏无法"重启" | 攻击危害巨大 |
| **物理约束强** | 数据必须满足物理定律 | **可用于检测！** |
| **大规模** | 数千节点、数十万设备 | 检测需可扩展 |
| **长生命周期** | 20+ 年 | 老旧设备难升级 |
| **社会影响** | 停电影响民生 | 攻击动机强 |

**最关键的是"物理约束强"**：

电力系统的数据**必须满足物理定律**（基尔霍夫定律、功率平衡）。这意味着：
- **攻击者构造的假数据必须"物理上自洽"**
- **防御者可以用"物理一致性"来检测攻击**

**这是电力 CPS 安全研究区别于纯网安的核心优势。**

### 四、和电网安全研究的关系

**CPS 视角是电网安全研究的"框架"**：

| 研究层次 | 内容 |
|---|---|
| **跨域攻击建模** | 攻击如何在信息-物理间传导 |
| **跨域检测** | 用物理约束检测信息攻击 |
| **跨域影响评估** | 评估攻击的物理后果 |
| **跨域防御** | 信息与物理协同防御 |

**特别推荐"物理约束用于检测"**：

**核心思想**：
```
正常数据：满足基尔霍夫定律 + 功率方程
攻击数据：可能违反物理约束 → 可检测
```

**具体方法**：
1. **建立物理模型**（潮流方程、基尔霍夫定律）
2. **计算残差**（实际数据 vs 物理模型预测）
3. **用 AI 学习残差的正常分布**（因为模型有误差）
4. **检测异常残差**

**为什么这个方法有效**：
- **FDIA 可以绕过统计检测（BDD），但难以绕过物理约束**
- 攻击者若要保持物理自洽，需要**知道完整拓扑和参数**（难度高）
- **物理约束是"免费的额外信息源"**

**这是我认为最适合你的核心研究方向之一**。

## Day 29 · 14:00 —— 跨域攻击：从网络空间到物理电网的传导路径

> **一句话**：**攻击的"跨域传导"是电网安全的本质问题**——一个数据包的篡改，经过"信息 → 计算 → 控制 → 物理"的链条，最终变成一台变压器的损毁或一个城市的停电。

### 一、四层传导模型

```
① 数据层攻击
   篡改量测 / 伪造报文
        ↓
② 计算层影响
   状态估计出错 / 检测失效
        ↓
③ 决策层影响
   调度员误判 / 控制指令错误
        ↓
④ 物理层后果
   设备过载 / 失稳 / 停电
```

**每一层都有"放大效应"**——小幅度的数据篡改可能导致严重的物理后果。

### 二、典型跨域攻击路径

**路径 1：FDIA → 错误调度 → 设备过载**
```
篡改量测数据 → 状态估计输出错误状态 → 
调度员认为线路轻载 → 加大输送 →
实际线路过载 → 保护跳闸 → 停电
```

**路径 2：虚假故障 → 保护误动 → 连锁跳闸**
```
伪造故障信号 → 保护误判 → 断路器跳闸 →
潮流转移 → 其他线路过载 → 连锁跳闸 → 大面积停电
```

**路径 3：GPS 欺骗 → 相量错位 → 稳定控制失效**
```
GPS 授时欺骗 → PMU 时间戳错误 → 
相量数据错位 → 广域监视失准 →
扰动未被及时发现 → 系统失稳
```

**路径 4：篡改温度数据 → 动态增容误判 → 线路过热**
```
篡改导线温度 → 系统认为"还很凉" →
加大输送电流 → 实际导线过热 →
弧垂增大 → 对地放电 → 山火
```

**路径 5：攻击 AGC → 功率振荡 → 系统崩溃**
```
篡改联络线功率量测 → AGC 错误调节 →
区域间功率振荡 → 振荡放大 → 系统解列
```

### 三、传导路径的分析方法

| 方法 | 说明 |
|---|---|
| **攻击树（Attack Tree）** | 树形分解攻击目标 |

| **因果链分析** | 逐层分析因果关系 |
| **仿真验证** | 用 CPS 仿真平台验证 |

**"攻击图"是最实用的**：

```
[入口: 办公网钓鱼] → [获得账号] → [VPN 登录] →
[进入管理信息大区] → [突破隔离] → [进入生产控制大区] →

```

每一步都有**成本、难度、检测概率**。**用图论方法分析"最优攻击路径"（攻击者视角）和"最优防御布点"（防御者视角），是很有价值的研究。**

## Day 30 · 09:00 —— 虚假数据注入攻击（FDIA）原理入门

> **一句话**：**FDIA（False Data Injection Attack）是电网安全研究最核心的攻击模型**——它通过构造"满足物理约束"的虚假量测，让状态估计输出错误结果，**而传统坏数据检测完全无法发现**。

### 一、攻击的动机

**回顾一下状态估计（Day 11）**：
- 输入：量测 $z$
- 输出：状态估计 $\hat{x}$
- 防线：坏数据检测（BDD），检查残差 $r = z - h(\hat{x})$

**攻击者的目标**：**让 $\hat{x}$ 错误，但 $r$ 保持在正常范围。**

### 二、FDIA 的数学原理

**量测方程**：$z = Hx + e$
（H 是量测雅可比矩阵，x 是状态）

**攻击方式**：攻击者注入 $a$，使量测变为 $z_a = z + a$

**关键条件**：如果攻击者构造

$$a = Hc$$

（c 是任意非零向量），则：

$$z_a = z + Hc$$

状态估计会得到：

$$\hat{x}_{bad} = \hat{x} + c$$

**残差**：

$$r_a = z_a - H\hat{x}_{bad} = (z + Hc) - H(\hat{x} + c) = z - H\hat{x} = r$$

**残差完全不变！** BDD 完全无法检测。

### 三、直观理解

**为什么 $a = Hc$ 能"I骗过"检测？**

```
正常情况：
  量测 z  →  状态估计  →  x̂  →  残差 r（小）

攻击：
  注入 a = Hc  →  状态估计  →  x̂ + c  →  残差 r（还是小！）

原因：a 落在 H 的"列空间"里
     → 它看起来"像是"某个真实状态的量测
     → 状态估计"自然地"把 c 吸收进去
     → 残差不受影响
```

**用几何理解**：H 的列空间代表"合法的量测模式"。攻击向量 a 落在列空间里，就"伪装"成了合法量测。

### 四、FDIA 的类型

| 类型 | 要求 | 难度 |
|---|---|---|
| **完美 FDIA** | 攻击者知道完整 H 矩阵和拓扑 | 高 |
| **受限 FDIA** | 只能攻击部分节点 | 中高 |
| **盲 FDIA** | 不知道 H，需要估计 | 高 |
| **LRA（负荷重分配）** | 不伪造量测，改拓扑信息 | 中 |
| **稀疏 FDIA** | 用最少的量测改动实现攻击 | 中 |

**"稀疏 FDIA"最受关注**——因为现实中攻击者难以篡改大量量测点。**"用最少的改动实现最大破坏"是一个优化问题**，很适合用 AI 方法求解。

### 五、经典论文

**必读**：

## Day 30 · 14:00 —— FDIA 与状态估计：为什么坏数据能骗过调度员

> **一句话**：**FDIA 的危险不在于"改数据"，而在于"改得让所有检测都认为是对的"**。它攻击的是"数据一致性"这个根本假设。

### 一、BDD 的核心假设

**传统坏数据检测（BDD）的基本假设**：

> **"坏数据"是"随机误差"或"故障"，所以它会破坏数据的一致性，导致残差变大。**

所以 BDD 的逻辑是：**残差大 → 有坏数据。**

**FDIA 攻击的正是这个假设**：它构造的数据**保持一致性**（残差不变），所以 BDD 认为"数据是好的"。

### 二、为什么这是一个"根本性"漏洞

| 层次 | 问题 |
|---|---|
| **数学层** | BDD 检测的是"统计异常"，不是"恶意性" |
| **信息层** | 缺乏"额外的验证信息源" |
| **物理层** | 只用量测自身，没有用物理约束 |

**核心问题**：**BDD 是"自洽性检验"，它只能发现"不一致"的攻击。如果攻击保持一致性，它就无能为力。**

**这是一个"信息论"层面的限制**：**如果攻击者掌握了与防御者相同的信息（H 矩阵），防御者就无法用这些信息来检测攻击。**

### 三、防御的方向

**既然"用一套信息无法检测"，就必须引入"额外的信息源"**：

| 额外信息源 | 原理 | 优势 |
|---|---|---|
| **物理约束** | 数据必须满足潮流方程 | 攻击者难以同时满足 |
| **时序相关性** | 相邻时刻数据相关 | 攻击难以保持时序一致 |
| **多源冗余** | 多个独立量测源 | 攻击者需同时篡改 |
| **拓扑信息** | 拓扑变化应与数据变化一致 | 检测拓扑攻击 |
| **历史统计** | 攻击行为偏离历史模式 | 检测异常模式 |
| **设备指纹** | 设备有独特特征 | 检测伪造设备 |

**这是最核心的研究思路**：**"用信息冗余对抗数据篡改"。**

### 四、具体的检测方法

| 方法 | 原理 | 优缺点 |
|---|---|---|
| **物理一致性检验** | 检查是否满足基尔霍夫定律 | 优点：难以绕过；缺点：模型误差导致误报 |
| **时序预测** | 用 LSTM 预测下一时刻，比较 | 优点：无需完整模型；缺点：攻击可保持时序一致 |
| **GNN 检测** | 用图结构学习正常模式 | 优点：利用拓扑；缺点：需训练数据 |
| **自编码器** | 重构误差检测异常 | 优点：无监督；缺点：攻击者可优化绕过 |
| **多源交叉验证** | 不同数据源互相校验 | 优点：独立性强；缺点：需要多源数据 |
| **状态估计残差增强** | 改进 BDD（加入物理约束） | 优点：直接；缺点：攻击者可适应 |

**关键洞察**：**没有单一方法能完全防御 FDIA**。未来的方向是**"多方法融合"**——用多个互补的检测器，提高攻击者的绕过成本。

### 五、和电网安全研究的关系

**这是研究最密集的领域，但仍有大量机会**：

| 选题 | 创新点 | 对接方向 |
|---|---|---|
| **物理约束 + 深度学习的融合检测** | 结合模型和数据驱动 | **入侵检测** |
| **对新型电力系统的 FDIA** | 高比例新能源场景 | 前沿 |
| **自适应 FDIA（攻击者学习检测器）** | 攻防博弈 | 前沿 |
| **FDIA 的时序检测** | 利用时间相关性 | 时序AI |
| **GNN 检测拓扑-FDIA 联合攻击** | 图方法 | **入侵检测** |

**特别推荐"物理约束 + 深度学习的融合检测"**：

**思路**：
```
物理模型给出的"应该是什么" + 
数据驱动给出的"通常是什么" =
融合判断
```

**具体实现**：
1. 用物理模型计算残差（模型驱动）
2. 用历史数据训练深度模型（数据驱动）
3. **融合两者的输出**（如用注意力机制加权）
4. 输出检测结果

**为什么这个选题好**：
1. **方法上有创新**（不是单纯用 AI，而是融合）
2. **理论上有依据**（物理约束提供"硬"信息，数据提供"软"信息）
3. **对接实验室的 AI 方向**
4. **实验可控**（用公开算例）

**这是我认为最有前景的 FDIA 研究方向。**

## Day 31 · 09:00 —— 隐蔽攻击与不可观测攻击：攻击者的"隐身术"

> **一句话**：**隐蔽攻击（Stealthy Attack）是 FDIA 的"进阶版"**——它不仅要绕过检测，还要**在很长一段时间内不被发现**，同时造成持续影响。

### 一、从"一次性"到"持续性"

| 类型 | 特点 |
|---|---|
| **经典 FDIA** | 一次性注入，绕过 BDD |
| **隐蔽攻击** | 长期、持续、低速 |
| **动态隐蔽攻击** | 考虑系统动态过程 |

**为什么要"隐蔽"？**

因为**真正的破坏需要时间**：
- 让设备慢慢过热 → 需要几小时
- 让错误的状态估计导致错误决策 → 需要持续的数据偏差
- 让攻击者"学习"系统行为 → 需要长期潜伏

### 二、隐蔽攻击的实现思路

**思路 1：小幅度持续偏差**
```
不注入大幅度的虚假数据（容易被发现）
而是注入长期的、小幅度的偏差
→ 累积效果显著
```

**思路 2：利用物理规律"掩护"**
```
让虚假数据"看起来像"正常的负荷变化
→ 混在正常波动中
```

**思路 3：与真实事件配合**
```
在真实的负荷变化时注入攻击
→ 难以区分是"正常波动"还是"攻击"
```

**思路 4："不可观测"子空间攻击**
```
如果系统存在"不可观测"的状态维度
→ 攻击这些维度不会影响量测残差
→ 完全无法检测
```

### 三、不可观测攻击

**核心概念**：电力系统中可能存在**观测不到的状态空间**（因为量测不足）。

**数学表达**：

如果存在非零向量 $c$，使得 $Hc = 0$（即 c 在 H 的零空间中），那么：

$$z_a = z + Hc = z$$

**攻击向量 $Hc = 0$ → 量测完全不变 → 状态估计完全不变 → 但实际状态可以"任意"变化！**

**等等，这不是矛盾吗？**

**澄清**：这里说的是另一种场景——如果攻击者能直接影响"实际状态"（通过控制设备），但让量测"保持正常"，那么：
- **物理状态变了**
- **但操作员看到的量测还是"正常"的**
- → **这就是"完全隐蔽"的攻击**

**这类攻击需要**：
1. 系统存在不可观测维度，或
2. 攻击者有物理控制能力 + 数据篡改能力

**其危险性在于**：**操作员完全"瞎了"**。

### 四、"零动态攻击"（Zero-Dynamics Attack）

**这是控制理论中的经典概念，在 CPS 安全中被重新发现**：

**思想**：控制系统存在一些"内部动态"，这些动态**不影响输出**（量测），但**会让系统状态漂移到危险区域**。

```
正常：控制器把状态维持在安全区
攻击：注入信号激发"零动态" → 
     输出（量测）看起来正常 →
     但状态在慢慢漂移 →
     最终达到危险区域 → 突然崩溃
```

**为什么危险**：
- **完全不可检测**（量测正常）
- **累积效应**（漂移需要时间，之后突然爆发）
- **理论优美**（有严格数学基础）

**这是"控制理论 + 安全"的交叉点**，非常有研究价值。

### 五、和电网安全研究的关系

| 选题 | 方法 | 对接方向 |
|---|---|---|
| **零动态攻击的检测** | 控制理论 + 状态观测器 | 前沿 |
| **不可观测子空间分析** | 线性代数 + 拓扑 | 攻防建模 |
| **隐蔽攻击的统计检测** | 变点检测、时序分析 | **时序AI** |
| **长期慢漂移攻击检测** | 累积和（CUSUM）方法 | 异常检测 |
| **隐蔽性与破坏性的权衡** | 博弈论 | 前沿 |

**特别推荐"慢漂移攻击检测"**：

**问题**：攻击者让数据缓慢漂移（如每天偏 0.1%），单次看不出来，但几周后累积效果显著。

**检测思路**：
1. **累积和（CUSUM）**：对偏差做累积，累积值超阈值就告警
2. **长期趋势分析**：检测数据的"系统性漂移"
3. **多参数联合检测**：单个参数漂移不明显，多参数联合漂移可检测
4. **物理约束的长期偏离**：长期不满足物理关系

**为什么这个选题好**：
1. **问题真实**（慢攻击是最难防的）
2. **方法成熟**（CUSUM、变点检测）
3. **可结合 AI**（用深度学习做长期趋势建模）
4. **有理论深度**（隐蔽性与检测的博弈）

## Day 31 · 14:00 —— 负荷重分配攻击（LRA）：不伪造数据也能攻击

> **一句话**：**LRA（Load Redistribution Attack）最"狡猾"的地方在于：它不篡改任何量测数据，只篡改"哪个负荷在哪里"的信息**。这让所有基于"数据一致性"的检测方法都失效。

### 一、LRA 的核心思想

**经典 FDIA**：篡改**量测值**（$z$）

**LRA**：篡改**负荷分布**（哪些负荷接在哪些节点）

**为什么这可行？**

回顾状态估计的输入：
- 量测数据 $z$
- **网络拓扑和负荷分布**（这些也是输入！）

如果攻击者篡改了"负荷分布"信息：
- **量测数据可以完全不改**
- 但状态估计会基于错误的负荷分布，算出错误的潮流

### 二、攻击的具体形式

**LRA 的数学表达**：

假设真实负荷为 $P_D$，攻击者篡改为：

$$P_D^{attack} = P_D + \Delta P$$

**约束**（关键）：**总负荷不变**！

$$\sum \Delta P_i = 0$$

（有的加，有的减，总量不变）

**为什么总负荷不变很重要？**

因为**总负荷是最容易被独立验证的量**（如电表总加、发电总出力）。如果总量变了，很容易被发现。**保持总量不变，就避免了最明显的检测。**

### 三、LRA 为什么更难检测

| 维度 | FDIA | LRA |
|---|---|---|
| **篡改对象** | 量测值 | 负荷分布信息 |
| **量测一致性** | 需保持 | **完全不改** |
| **总负荷** | 可能变 | **保持不变** |
| **检测难度** | 中 | **高** |
| **检测思路** | 物理约束校验 | 需验证负荷分布的真实性 |

**检测 LRA 的困难**：
- **量测数据"完全正常"**（因为没有改）
- **总负荷"完全正常"**（因为保持不变）
- 只能通过**验证"负荷分布信息"本身是否可信**来检测

**问题**：**负荷分布信息从哪来？如何验证？**

### 四、LRA 的现实性

| 方面 | 分析 |
|---|---|
| **攻击者需要什么** | 篡改 EMS/SCADA 中的负荷分布数据（如负荷配置表） |
| **难度** | 中等（比构造完美 FDIA 容易） |
| **危害** | 导致错误的最优潮流、安全评估 |
| **隐蔽性** | **极高** |

**现实的攻击场景**：
1. 攻击者入侵 EMS 数据库
2. 篡改负荷配置（把重负荷节点改成轻负荷）
3. 系统"以为"某些线路很轻松，实际已经过载
4. 调度员根据错误信息决策 → 真实过载 → 跳闸

### 五、和电网安全研究的关系

**LRA 是"检测研究的前沿"**：

| 选题 | 方法 | 对接方向 |
|---|---|---|
| **LRA 检测（负荷分布验证）** | 多源数据交叉验证 | 异常检测 |
| **LRA 检测（AI方法）** | 学习负荷分布的正常模式 | **入侵检测** |
| **LRA 与 FDIA 联合攻击** | 组合攻击建模 | 攻防建模 |
| **LRA 影响评估** | 仿真分析 | 工业AI |
| **AMI 数据用于 LRA 检测** | 用智能电表数据验证负荷分布 | **AI与数据安全** |

**特别推荐"用 AMI 数据检测 LRA"**：

**核心洞察**：**负荷分布有"独立的数据源"——智能电表（AMI）。**

```
EMS 认为：节点 A 负荷 10MW，节点 B 负荷 90MW
AMI 实测：节点 A 负荷 90MW，节点 B 负荷 10MW
→ 明显不一致 → 存在 LRA！
```

**研究内容**：
1. 建立 AMI 数据与 EMS 负荷分布的对应关系
2. 设计一致性校验方法
3. 处理两者的**时间尺度差异**（AMI 采样慢）
4. 用 AI 方法处理噪声和缺失数据
5. 评估检测性能

**为什么这个选题好**：
1. **思路巧妙**（利用"额外的独立数据源"）
2. **对接"AI与数据安全"方向**（涉及数据融合、隐私）
3. **问题新颖**（LRA 检测研究相对少）
4. **实用价值高**

**更深一层**：**这涉及"配电网和输电网数据的融合"** —— 这是一个当前很有热度的方向（因为新型电力系统需要"源网荷储"协同，必须融合各层数据）。

2. 用 AMI 数据检测 LRA 时，如果攻击者**同时篡改 AMI 数据**，还能检测吗？需要什么额外机制？

## Day 32 · 09:00 —— 拒绝服务攻击在电力 CPS 中的特殊后果

> **一句话**：在 IT 系统里，DoS 攻击让"服务不可用"；**在电力 CPS 里，DoS 攻击可能让"控制系统失能"，导致物理设备失控**——后果完全不同。

### 一、DoS 在电力 CPS 中的攻击面

| 目标 | 后果 |
|---|---|
| **保护通信（纵联保护）** | 保护失去对方信息 → 拒动或误动 |
| **GOOSE 通信** | 跳闸命令丢失 → 故障无法切除 |
| **SV 通信** | 保护失去采样数据 → 闭锁 |
| **SCADA 通信** | 调度员"瞎了" |
| **时间同步（GPS/NTP）** | 全网时间失准 → 数据无法对齐 |
| **AGC 通信** | 频率调节失效 |

**关键区别**：IT 系统 DoS = 用户无法访问；**电力 CPS DoS = 控制系统失效 → 物理失控**。

### 二、为什么电力 CPS 的 DoS 更危险

| 原因 | 说明 |
|---|---|
| **实时约束** | 保护要求在毫秒级，延迟 = 失效 |
| **物理闭环** | 控制失效 → 物理量失控 |
| **安全影响** | 保护失效 → 设备损坏、事故扩大 |
| **恢复困难** | 物理过程无法"暂停" |

**举例**：

```
场景：线路故障
正常：故障 → 保护跳闸（100ms 内）→ 安全
DoS攻击：故障 → 保护通信被阻塞 → 保护拒动 →
       故障持续 → 设备烧毁、故障扩大 → 大面积停电
```

**注意**：这里攻击者**不需要篡改任何数据**，只要**阻塞通信**，就能让保护"不敢动"。

### 三、DoS 攻击的手法

| 手法 | 针对 |
|---|---|
| **洪泛攻击** | 淹没网络带宽 |
| **协议攻击** | 利用协议状态耗尽（如 TCP SYN） |
| **资源耗尽** | 耗尽 CPU/内存 |
| **优先级干扰** | 干扰实时流量 |
| **GPS 干扰** | 干扰授时信号 |
| **物理层攻击** | 干扰无线通信 |

**"GPS 干扰"在电力场景特别危险**：GPS 信号极其微弱，一个小功率干扰器就能让大片区域的 PMU 失去同步。

### 四、工业控制器的"失能模式"

**关键问题**：**当控制器失去通信时，它会怎么做？**

| 策略 | 说明 | 安全性 |
|---|---|---|
| **Fail-Safe（失效安全）** | 失去通信 → 安全停车/跳闸 | 安全但影响可用性 |
| **Fail-Operational** | 保持最后的指令 | **危险（可能维持错误状态）** |
| **Fail-Open** | 继续正常操作 | 危险 |

**攻击者可以利用这个**：如果控制器是 Fail-Operational，攻击者可以先**注入错误指令**，然后**切断通信**，让控制器"卡"在错误状态。

**这就是"DoS + 数据篡改"的组合攻击**，威力远大于单一的 DoS。

| 选题 | 方法 | 对接方向 |
|---|---|---|
| **DoS 的物理后果评估** | CPS 联合仿真 | 工业AI |

**问题**：如果攻击者阻塞某条关键通信链路 10 秒，会造成什么物理后果？

**研究方法**：

## Day 32 · 14:00 —— 时间同步攻击：GPS 欺骗对 PMU 的影响

> **一句话**：**电力系统依赖"时间"来对齐全网数据**。攻击者若能让时间"错一点"，就能让所有数据处理"错一片"——**这是电网最"隐蔽"也最"根本"的攻击面之一**。

### 一、电力系统为什么需要精确时间

| 应用 | 时间精度要求 |
|---|---|
| **PMU 相量测量** | **微秒级**（1 μs 对应 0.018° 相角） |
| **保护（纵联）** | 毫秒级 |
| **事件顺序记录（SOE）** | 毫秒级 |
| **SV 采样同步** | 微秒级 |
| **SCADA 时间戳** | 秒级 |

**关键**：**PMU 的相量数据只有在"同一时标"下才有意义**。如果时间错位，相量就"对不上"。

### 二、GPS 欺骗的技术细节

**为什么 GPS 容易被欺骗**：

| 原因 | 说明 |
|---|---|
| **信号弱** | 到达地面约 -160 dBW |
| **公开结构** | GPS 信号格式是公开的 |
| **无认证** | 民用 GPS 信号无加密认证 |
| **成本低** | SDR（软件定义无线电）几百元即可 |

**欺骗攻击（Spoofing）vs 干扰（Jamming）**：

| 攻击 | 方式 | 效果 |
|---|---|---|
| **干扰** | 发射强噪声 | 失去同步（容易发现） |
| **欺骗** | 发射**伪造的**GPS 信号 | **被引导到错误时间（难以发现）** |

**欺骗的精妙之处**：攻击者先"对齐"真实信号，然后**缓慢牵引**接收机的时间，让它不知不觉偏离。**接收机始终"认为自己同步正常"。**

### 三、时间偏移的物理后果

**攻击者只需偏移几毫秒**：

| 时间偏移 | 相角误差（50Hz） | 后果 |
|---|---|---|
| 1 ms | 18° | 严重 |
| 0.1 ms | 1.8° | 明显 |
| 0.01 ms | 0.18° | 仍有影响 |

**后果链条**：

```
GPS 欺骗 → PMU 时间戳错误 →
相量数据错位 → 
① 状态估计结果错误（用了错位的相量）
② 广域监测误判（以为系统振荡）
③ 保护误动（基于错误相角）
④ 时间戳不一致被误判为"坏数据"（正常数据被丢弃）
```

**最讽刺的是第 4 条**：**时间攻击可能导致系统把自己的"正常数据"当成"坏数据"丢弃**，从而**主动"失明"**。

### 四、检测方法

| 方法 | 原理 |
|---|---|
| **多源授时** | GPS + 北斗 + 地面授时交叉验证 |
| **物理一致性** | 相量必须满足基尔霍夫定律 |
| **空间一致性** | 相邻 PMU 的时间偏移应相关 |
| **时序连续性** | 时间偏移通常是突变或缓变，可检测 |
| **时钟异常检测** | 检测时钟漂移速率异常 |
| **加密认证 GPS** | 使用有认证的授时信号（如 GPS 军用信号、eLoran） |

**"物理一致性"是最有力的**：

**核心思想**：**时间错位会导致相量"物理上不自洽"**。

例如：
- 节点 A 和节点 B 之间的相位差应该满足潮流方程
- 如果时间错位，测出的相位差就不满足物理关系
- **即使攻击者篡改了时间，物理定律不会变**

### 五、和电网安全研究的关系

| 选题 | 方法 | 对接方向 |
|---|---|---|
| **GPS 欺骗检测（物理一致性）** | 物理约束校验 | 异常检测 |

**完整的研究逻辑**：

## Day 33 · 09:00 —— 电力 CPS 威胁建模方法（STRIDE / 攻击树）

> **一句话**：**威胁建模是"系统性找攻击面"的方法**——它让你从"零散地想象攻击"变成"有框架地分析威胁"。

### 一、为什么需要威胁建模

**没有威胁建模**：
```
"我觉得攻击者可能篡改数据……"
"也可能攻击通信……"
（零散、不系统、容易遗漏）
```

**有威胁建模**：
```
按框架逐项分析 → 系统覆盖 → 可量化、可比较
```

### 二、STRIDE 模型

**STRIDE** 是微软提出的威胁分类：

| 字母 | 威胁 | 破坏的属性 | 电力场景例子 |
|---|---|---|---|
| **S** | Spoofing 伪装 | 认证 | 伪造调度主站下发指令 |
| **T** | Tampering 篡改 | 完整性 | 篡改量测数据（FDIA） |
| **R** | Repudiation 抵赖 | 不可否认性 | 操作日志被删 |
| **I** | Information Disclosure 信息泄露 | 机密性 | SCD 配置泄露 |
| **D** | Denial of Service 拒绝服务 | 可用性 | 阻塞 GOOSE 通信 |
| **E** | Elevation of Privilege 提权 | 授权 | 从普通账号提升到管理员 |

**STRIDE 的价值**：**它迫使你系统地考虑每一类威胁**，而不是只想到最熟悉的那些。

### 三、攻击树（Attack Tree）

**攻击树**是**树形分解攻击目标**的方法：

```
                [目标：造成大面积停电]
                        │
        ┌───────────────┼───────────────┐
        │               │               │
   [物理攻击]      [网络攻击]      [社会工程]
        │               │               │
   ┌────┴────┐    ┌─────┴─────┐    ┌───┴───┐
 [倒塔]  [剪线] [篡改量测] [攻击SCADA] [钓鱼] [收买]
                     │         │
                 ┌───┴───┐  ┌──┴──┐
              [FDIA] [LRA] [凭证] [漏洞]
```

**每个叶子节点**可以有属性：
- 成本
- 难度
- 检测概率
- 影响

**然后可以计算**：
- **最便宜的攻击路径**
- **最容易成功的攻击路径**
- **最可能被检测的路径**

### 四、方法结合

**实践中常结合使用**：

| 步骤 | 方法 |
|---|---|
| **① 系统建模** | 数据流图（DFD），画出信息流 |
| **② 威胁识别** | STRIDE 逐项分析 |
| **③ 攻击路径分析** | 攻击树 |
| **④ 战术细化** | MITRE ATT&CK for ICS |
| **⑤ 风险评估** | CVSS 或自定义评分 |
| **⑥ 对策设计** | 针对性防御措施 |

**这是一个完整的威胁建模流程。**

## Day 33 · 14:00 —— 攻击-防御博弈与攻防演化

> **一句话**：**网络安全不是"静态防御"，而是"动态博弈"**——攻击者会适应防御，防御者会针对攻击。理解这个博弈，才能设计"有生命力"的防御。

### 一、为什么是"博弈"而不是"问题"

**静态视角（不完整）**：
```
攻击者有一个策略 → 防御者设计一个对策 → 结束
```

**博弈视角（正确）**：
```
攻击者策略 → 防御者对策 → 攻击者调整 → 防御者调整 → ……
（持续演化）
```

**现实例子**：
- BDD 出现 → FDIA 绕过 BDD → 物理约束检测 → 攻击者适应物理约束 → ……

**这个"军备竞赛"是安全的本质。**

### 二、博弈论基础概念

| 概念 | 说明 | 电力场景 |
|---|---|---|
| **参与者** | 攻防双方 | 攻击者 vs 防御者 |
| **策略空间** | 可选行动 | 攻击哪些节点 / 在哪里布防 |
| **收益** | 得失 | 停电影响 / 防御成本 |
| **信息** | 是否知道对方策略 | 攻击者是否知道防御配置 |
| **均衡** | 博弈的稳定状态 | 纳什均衡 |

### 三、常见的博弈模型

| 模型 | 特点 | 电力应用 |
|---|---|---|
| **Stackelberg 博弈** | 有"领导者-跟随者"顺序 | 防御者先布防，攻击者后攻击 |
| **零和博弈** | 一方所得即另一方所失 | 资源分配 |
| **信号博弈** | 有信息不对称 | 伪装/欺骗 |
| **演化博弈** | 策略随时间演化 | 长期攻防 |

**Stackelberg 博弈最常用**：

```
Stackelberg 安全博弈：
  防御者（领导者）先选择防御策略
        ↓
  攻击者（跟随者）观察后选择最优攻击
        ↓
  求解：防御者的最优策略（考虑攻击者会最优响应）
```

**"防御者先动"是符合现实的**：防御方先部署防护，攻击方再研究如何绕过。

### 四、攻防演化的具体例子

**"检测器 vs 攻击者"的演化**：

```
第 1 轮：
  防御：残差检验（BDD）
  攻击：FDIA（a = Hc）

第 2 轮：
  防御：物理约束检验
  攻击：保持物理自洽的 FDIA（需要更多信息）

第 3 轮：
  防御：机器学习检测（学习正常模式）
  攻击：对抗样本（生成能骗过 ML 的数据）

第 4 轮：
  防御：对抗训练 + 集成检测
  攻击：……
```

**核心洞察**：**每次"防御升级"都会提高攻击者的成本**。**安全的目标不是"完全防御"，而是"让攻击成本 > 攻击收益"。**

### 五、和电网安全研究的关系

| 选题 | 方法 | 对接方向 |
|---|---|---|
| **Stackelberg 博弈的防御布点** | 优化 + 博弈论 | **工业AI** |
| **对抗样本 vs 检测器** | 对抗机器学习 | **图像识别与安全** |
| **攻防演化的仿真** | 多智能体强化学习 | 前沿 |
| **动态防御策略** | 强化学习 | 工业AI |
| **信息不对称下的攻防** | 信号博弈 | 前沿 |

**特别推荐"用强化学习求最优防御策略"**：

**问题**：在多阶段攻防中，防御者应该何时、何地采取什么行动？

**方法**：
1. 建立**攻击-防御的马尔可夫博弈模型**

## Day 34 · 09:00 —— 电力 CPS 安全测试床与仿真平台（如 PowerWorld、GridLAB-D、软硬件在环）

> **一句话**：**没有测试床，就没有可信的研究**。电力 CPS 安全研究的实验必须同时仿真"物理"和"信息"——**这就是"联合仿真"的核心挑战**。

### 一、测试床的层次

| 层次 | 方式 | 成本 | 真实性 |
|---|---|---|---|
| **纯软件仿真** | 模拟物理 + 模拟通信 | 低 | 低 |
| **联合仿真（Co-simulation）** | 专业物理仿真 + 网络仿真 | 中 | 中 |
| **硬件在环（HIL）** | 真实控制器 + 仿真物理 | 高 | 高 |
| **全实物测试床** | 真实设备 | 极高 | 最高 |

**研究建议**：从**联合仿真**开始（性价比最高），有条件再考虑 HIL。

### 二、常用平台

**物理仿真**：

| 平台 | 特点 |
|---|---|
| **GridLAB-D** | 配电网、负荷建模（美国 DOE 开发） |
| **OpenDSS** | 配电网专用 |
| **PowerWorld** | 可视化强、教学友好 |
| **PSS/E** | 工业标准 |
| **pandapower / PyPSA** | Python 开源 |
| **Simulink** | 动态仿真灵活 |

**通信仿真**：

| 平台 | 特点 |
|---|---|
| **NS-3** | 网络仿真标准工具 |
| **OMNeT++** | 模块化网络仿真 |
| **Mininet** | SDN/虚拟网络 |

**联合仿真框架**：

| 框架 | 特点 |
|---|---|
| **HELICS** | 美国 DOE 主推，支持多种仿真器 |
| **Mosaik** | 德国，Python 友好 |
| **FNCS** | 电力-通信联合 |
| **Ptolemy II** | 通用 CPS 仿真 |

**HELICS 和 Mosaik 是当前最主流的**。

### 三、联合仿真的核心挑战

| 挑战 | 说明 |
|---|---|
| **时间同步** | 物理仿真和网络仿真的时间步长不同 |
| **数据交换** | 两个仿真器如何交换数据 |
| **一致性** | 保证两个仿真的状态一致 |
| **性能** | 大规模系统的仿真速度 |

**时间同步问题**：电力仿真的步长是**毫秒级**（甚至微秒），网络仿真的步长可能是**秒级**。如何对齐？这本身就是一个研究问题。

### 四、软硬件在环（HIL）

**HIL（Hardware-in-the-Loop）**：用真实硬件 + 仿真环境。

| 方案 | 说明 |
|---|---|
| **RTDS** | 实时数字仿真器（电力行业标准） |
| **OPAL-RT** | 实时仿真平台 |
| **dSPACE** | 实时仿真 |
| **真实 PLC/IED + 仿真物理** | 成本较低 |

**HIL 的价值**：**能测试真实设备在攻击下的行为**，可信度远高于纯软件仿真。

**成本问题**：RTDS 等设备价格高昂（几十万到几百万）。**替代方案**：用真实低端 PLC + 软件仿真物理。

### 五、和电网安全研究的关系

| 选题 | 方法 | 对接方向 |
|---|---|---|
| **CPS 联合仿真的时间同步优化** | 仿真技术 | 系统工程 |

| **仿真环境的自动化测试** | 自动化 + AI | 工业AI |
| **攻击场景自动生成** | 强化学习 | **工业AI** |
| **HIL 测试方法** | 实验方法学 | 实验 |

**务实建议**：

**研一的实验路径**：
```

  纯软件：pandapower + Python 脚本
  → 实现状态估计、FDIA、检测

阶段 2（第 3-4 个月）：
  联合仿真：pandapower + 网络仿真
  → 加入通信层，研究跨域攻击

阶段 3（第 5-6 个月）：
  HIL（如果有条件）：真实 PLC/IED
  → 验证真实设备的安全性
```

**关键提示**：**不要一开始就追求"高保真测试床"**。先用最简单的环境跑通完整流程（Fault → Attack → Detect），**比用高级设备但流程不完整更有价值**。

## Day 34 · 14:00 —— 攻防数据集：如何获取带攻击标签的电网数据

> **一句话**：**数据是研究的基础**。电网安全研究中，"带攻击标签的数据"极其稀缺——**这既是困难，也是机会**（谁能构建好数据集，谁就有话语权）。

### 一、数据集的重要性

**AI 方法需要数据**：
- 训练模型需要"正常样本"
- 评估检测需要"攻击样本"
- **标签质量决定研究质量**

**但电网数据的问题**：
- 涉及**关键基础设施**，高度敏感
- **攻击样本几乎不存在**（真实攻击很少发生）
- 即使有，也**不会公开**

### 二、公开数据集盘点

| 数据集 | 内容 | 适用 |
|---|---|---|
| **KDD99 / NSL-KDD** | 网络入侵检测（经典） | 入门、但过时 |
| **CICIDS2017/2018** | 网络流量入侵检测 | IT 场景 |
| **UNSW-NB15** | 网络入侵检测 | IT 场景 |
| **Mississippi State / Power System** | **电力系统攻击数据** | 电力 CPS |
| **ORNL 数据集** | 电力 CPS 攻击测试床数据 | 电力 CPS |
| **4SIC / ICS 数据集** | 工控协议流量 | 工控 |
| **Kaggle ICS 数据集** | Modbus/DNP3 攻击流量 | 工控 |
| **SWaT / WADI** | 水处理系统（iTrust） | 工控 CPS |
| **电力系统算例** | IEEE 14/39/118 节点 | 物理仿真 |

**"Mississippi State / ORNL"** 是电力 CPS 专用数据集，值得关注。

### 三、如何"造"数据

**因为公开的攻击数据稀缺，研究常需要自己生成**：

| 方法 | 说明 | 优缺点 |
|---|---|---|
| **仿真生成** | 用仿真平台生成正常 + 攻击数据 | 优点：可控；缺点：真实度 |
| **物理仿真 + 攻击注入** | 仿真物理，脚本注入攻击 | **最常用** |
| **联合仿真** | 仿真物理 + 通信 + 攻击 | 真实度更高 |
| **测试床采集** | 真实设备抓包 | 最真实，成本高 |
| **数据增强** | 用生成模型扩充数据 | 需验证合理性 |

**最常用的方法：仿真 + 攻击注入**

```python
# 思路示意
net = load_ieee_case()           # 载入电网模型
normal_data = run_power_flow(net)  # 生成正常量测

# 注入 FDIA
attack_vector = construct_fdia(H_matrix)
attack_data = normal_data + attack_vector

# 得到带标签的数据集
labels = [0]*len(normal_data) + [1]*len(attack_data)
```

### 四、数据集的挑战

| 挑战 | 说明 |
|---|---|
| **攻击多样性** | 一种攻击的数据不代表所有攻击 |
| **正常数据偏差** | 仿真的"正常"和真实的"正常"不同 |
| **类别不平衡** | 攻击样本远少于正常样本（**现实就是这样**） |
| **标签准确性** | 如何确保标签正确 |
| **泛化性** | 在一个系统训练的模型能否用于另一个系统 |

**"类别不平衡"是最现实的问题**：真实场景中，攻击是"罕见事件"。**如果用平衡数据训练，模型在现实中会误报率高。**

**这引出了一个重要研究方向**：**异常检测 vs 分类**。
- **分类**：需要正负样本 → 但攻击样本稀缺
- **异常检测**：只需正常样本 → **更适合现实**

### 五、和电网安全研究的关系

| 选题 | 方法 | 对接方向 |
|---|---|---|
| **电力 CPS 攻击数据集构建** | 仿真 + 注入 | 数据工程 |
| **数据增强（生成攻击样本）** | 生成模型（GAN/VAE） | **AI与数据安全** |
| **跨系统泛化** | 迁移学习 | **工业AI** |
| **不平衡数据处理** | 异常检测、代价敏感学习 | **入侵检测** |
| **半监督/无监督检测** | 自编码器、对比学习 | **入侵检测** |

**特别推荐"用生成模型增强攻击数据"**：

**问题**：攻击样本太少，无法训练好的分类器。

**方案**：
1. 用 **GAN / VAE** 学习攻击数据的分布
2. **生成更多样化的攻击样本**
3. 用增强后的数据训练检测器
4. **评估生成样本的物理合理性**（重要！）

**为什么这个选题好**：
1. **对接"AI与数据安全"方向**
2. **解决真实问题**（数据稀缺）
3. **方法有创新**（生成模型 + 物理约束）
4. **可评估**（检测性能提升）

**关键挑战**：**生成的攻击数据必须"物理合理"**，否则检测器学到的是"假模式"。**这就是"物理约束 + 生成模型"的结合点**，很有研究价值。

**另一个务实建议**：**优先考虑"无监督异常检测"**，因为现实中只有正常数据容易获取。这是更"接地气"的研究方向。

## Day 35 · 09:00 —— 第五周复盘：为一个真实场景写威胁模型

> **一句话**：本周把**FDIA、隐蔽攻击、LRA、DoS、时间攻击**这些"攻击模型"学完了。检验标准是——**你能为一个具体的电力场景，写出完整的威胁模型。**

### 一、本周攻击模型总结

| 攻击 | 篡改什么 | 绕过什么 | 危害 | 检测难点 |
|---|---|---|---|---|
| **FDIA** | 量测值 | BDD（残差检验） | 调度误判 | 残差不变 |
| **稀疏 FDIA** | 少量量测 | BDD | 同上 | 更难检测 |
| **隐蔽攻击** | 长期小幅偏差 | 统计检测 | 累积危害 | 单点不异常 |
| **零动态攻击** | 激发内部动态 | 输出监测 | 系统崩溃 | 完全不可检测 |
| **LRA** | 负荷分布信息 | 所有数据检测 | 错误调度 | 数据未改 |
| **DoS** | 通信可用性 | — | 控制失能 | 需区分攻击/故障 |
| **GPS 欺骗** | 时间同步 | 时间戳校验 | 数据错位 | 需物理校验 |

**共同特点**：**都在攻击"信任的假设"。**
- FDIA 攻击"数据的自洽性"假设
- LRA 攻击"负荷分布可信"假设
- GPS 欺骗攻击"时间正确"假设
- 零动态攻击"输出反映状态"假设

**核心洞察**：**安全研究的本质是"找出被信任的假设，然后验证它"。**

### 二、威胁建模模板（可复用）

```markdown

- 知识（知道系统哪些信息）
- 目标（想达成什么）
- 资源（时间、算力）

### 3. 威胁识别（STRIDE）
| 威胁类型 | 具体场景 | 可能性 | 影响 |

```

### 三、示例：变电站 GOOSE 攻击威胁模型

**系统描述**：
```
站控层 ←→ 间隔层（保护 IED）←→ 过程层（合并单元、智能终端）
                                    ↓
                              断路器、变压器
```

**攻击者模型**：
- 能力：能接入过程层网络（物理接触或远程）
- 知识：了解 IEC 61850 协议和 GOOSE 格式
- 目标：让断路器异常动作
- 资源：中等

**威胁识别**：

| STRIDE | 场景 | 可能性 | 影响 |
|---|---|---|---|
| Spoofing | 伪造 GOOSE 跳闸报文 | 高 | 严重 |
| Tampering | 篡改 SV 采样值 | 中 | 严重 |
| Repudiation | 删除操作日志 | 中 | 中 |
| Info Disclosure | 获取 SCD 配置 | 高 | 中 |
| DoS | 洪泛 GOOSE 报文 | 中 | 严重 |
| Elevation | 从用户权限提权 | 中 | 严重 |

**攻击路径**：
```
物理接入网络 → 学习 GOOSE 格式 → 构造虚假报文 →
注入网络 → 断路器跳闸 → 停电
```

**现有防护的有效性**：
- ✅ 网络分区（需要物理接入）
- ❌ GOOSE 无认证（无法阻止伪造）

**防护建议**：
- 部署 GOOSE 异常检测
- 网络访问控制（防止未授权接入）
- 数据完整性校验方案

## Day 35 · 14:00 —— 延伸：从论文视角看 FDIA 研究的十年演进

> **一句话**：**FDIA 研究（2009-至今）是电网安全研究的缩影**——从"发现攻击"到"设计检测"到"攻防博弈"，**这条演化路径展示了安全研究的完整方法论**。

### 一、FDIA 研究的四个阶段

**阶段 1（2009-2012）：发现与建模**
```
核心问题：FDIA 可行吗？
主要工作：
- Liu et al. (2009) 提出 FDIA 模型
- 证明 a = Hc 能绕过 BDD
- 分析攻击所需的系统知识
代表论文：Liu, Ning, Reiter, ACM CCS 2009

特点：开创性、理论性强
```

**阶段 2（2012-2015）：检测方法**
```
核心问题：如何检测 FDIA？
主要工作：
- 物理约束检验
- 时序相关性检测
- 改进的 BDD（加入约束）
- 基于机器学习的检测

特点：方法多样、开始引入 ML
```

**阶段 3（2015-2019）：攻防深化**
```
核心问题：攻击者会如何适应？
主要工作：
- 稀疏 FDIA（最少改动）
- 盲 FDIA（不完整信息）
- LRA（不篡改量测）
- 隐蔽攻击、零动态攻击

特点：攻击模型精细、攻防博弈
```

**阶段 4（2019-至今）：AI 与新型系统**
```
核心问题：AI 方法和新型电力系统下如何应对？
主要工作：
- 深度学习方法（CNN/LSTM/GNN）
- 对抗样本攻击检测器
- 高比例新能源场景
- 信息-物理联合建模

特点：AI 主导、面向新场景
```

### 二、研究方法的演化

| 阶段 | 主要方法 | 特点 |
|---|---|---|
| **1** | 线性代数、凸优化 | 理论分析 |
| **2** | 统计检验、机器学习 | 检测方法 |
| **3** | 优化、博弈论 | 攻防建模 |
| **4** | **深度学习、强化学习、图方法** | **AI 主导** |

### 三、当前的研究空白（机会）

| 空白 | 说明 | 难度 |
|---|---|---|
| **新型电力系统下的 FDIA** | 高比例新能源、低惯量 | 中 |
| **AI 检测器的对抗鲁棒性** | 攻击者用对抗样本绕过检测 | 中 |
| **跨域联合攻击** | 信息+物理+通信协同 | 高 |
| **小样本/零样本检测** | 攻击样本稀缺 | 中 |
| **可解释的检测方法** | 调度员需要知道"为什么" | 中 |
| **实时性约束下的检测** | 毫秒级要求 | 高 |
| **FDIA 与市场操纵结合** | 电力市场场景 | 中 |

**"AI 检测器的对抗鲁棒性"是最值得关注的**：

**问题**：现在大量论文用深度学习检测 FDIA。**但如果攻击者知道检测器，能构造对抗样本吗？**

**研究闭环**：
1. 训练一个深度学习 FDIA 检测器
2. **用对抗攻击方法攻击它**
3. 评估攻击成功率（可能很高！）
4. **提出鲁棒的检测方法**（对抗训练、集成、物理约束）
5. 评估改进效果

**为什么这个选题好**：
1. **有完整的攻防闭环**（论文结构清晰）
2. **对接"入侵检测"和"图像识别与安全"方向**
3. **前沿**（对抗机器学习是热点）
4. **实验可控**（用公开算例 + PyTorch）

### 四、给研一的选题建议

**基于 FDIA 研究的演进，给你三个层次的选题**：

| 层次 | 选题 | 特点 |
|---|---|---|
| **入门（3 个月可完成）** | 复现经典 FDIA + 实现一个检测方法 | 学习为主，稳妥 |
| **进阶（6 个月）** | 物理约束 + 深度学习的融合检测 | 有创新，可发表 |
| **前沿（1 年+）** | AI 检测器的对抗鲁棒性研究 | 前沿，有深度 |

**我的建议**：**从"入门"开始，但按"进阶"的框架设计实验**。也就是说：
1. 先完整复现经典工作（建立基础）
2. 然后加入你的创新点（融合方法）
3. **把"对抗鲁棒性"作为未来延伸方向**

**这样你既能快速出成果，又有长期的研究路线。**
