## 三、逐步讲解

### Step 2：构造 H 矩阵 —— 最容易出错的地方

**为什么难**：教材里的 $H$ 是"给定"的，但实际要自己从电网数据算出来。

**代码思路**：

```
DC 潮流假设
    ↓
支路潮流:  P_ij = (θ_i - θ_j) / x_ij
    ↓
H 的每一行对应一个量测：
  ┌─────────────────────────────────────────┐
  │ 支路潮流行 [ ... +1/x (第i列) ... -1/x (第j列) ... ] │
  │ 注入功率行 [ ... Σ1/x (第i列) ... -1/x (第j列) ... ] │
  └─────────────────────────────────────────┘
    ↓
列 = 状态（非平衡节点相角）
```

**三个易错点**：

| 易错点 | 后果 | 正确做法 |
|---|---|---|
| **标幺化基准不一致** | H 元素量级混乱，攻击构造失败 | 统一用 `z_base = vn_kv² / sn_mva` |
| **忘记去掉平衡节点** | H 矩阵秩亏，`lstsq` 解不稳定 | 状态向量排除 `ext_grid.bus` |
| **变压器建模过于简化** | 潮流值与 H 算出的不一致 | 用 `vk_percent` 折算电抗 |

**验证 H 是否正确的方法**（重要！）：
```python
# H 算出的量测应该接近潮流结果
x_true = get_true_state(net, state_buses)
z_from_H = H @ x_true
z_true = get_measured_values(net, meas_info, bus_idx)
error = np.linalg.norm(z_from_H - z_true) / np.linalg.norm(z_true)
print(f"相对误差: {error:.4f}")   # 应该 < 0.05（DC 近似的固有误差）
```
> 如果误差 > 0.2，说明 H 构造有问题 —— **不要继续往下跑**，先修 H。

### Step 4：生成 FDIA —— 核心的一步

```python
c = np.random.normal(0, attack_scale, size=n)   # 攻击者想要的状态偏移
a = H @ c                                       # 关键：a = Hc
z_attacked = z_normal + a
```

**为什么这样就"检测不出来"**：因为 $a$ 落在 $H$ 的列空间里，代入残差公式后 $Hc$ 项被消掉了。

**预期输出**（已在 IEEE 14 节点上实测，可直接对照）：

```
[1/7] 构建 IEEE 14 节点算例...
      母线数: 14, 线路数: 15, 变压器数: 5

[2/7] 构造量测雅可比矩阵 H...
      H 维度: 33 x 13  （33 个量测, 13 个状态）
      量测构成: 15 支路 + 5 变压器 + 13 注入

[3/7] 生成正常 + 攻击样本...
      样本总数: 600  （正常 300, 攻击 300）
      噪声基准: 0.1294

[4/7] 验证单个 FDIA 的不可检测性...
      正常量测残差 ||r||:  8.399368
      攻击量测残差 ||r||:  8.399368     ← 完全相同！
      残差变化:            4.26e-14     ← 极小 = BDD 查不出
      状态估计偏移量:       0.776678
      攻击者预定偏移量 ||c||: 0.776678   ← 与上面完全一致！
      量测改动量 ||a||:      17.989641
```

> 🎯 **这张输出就是 Liu 2009 的核心结论的实证**。注意三点：
> ① **残差变化仅 4.26e-14** —— 浮点精度级别，BDD 绝对查不出
> ② **状态估计偏移量 0.776678 与攻击者预定值 ‖c‖ 完全相同** —— 攻击精确实现了意图
> ③ 量测改了 17.99（相对残差量级 8.4 是同一数量级），改动不小但残差毫无反应

**批量实验实测结果**：

```
【实验 1】传统 BDD（残差检验）
  正常样本残差范数:  均值=6.6422, 标准差=1.1370
  攻击样本残差范数:  均值=6.6865, 标准差=1.1797   ← 两组几乎相同
  阈值 τ = 8.8480（正常样本 99 分位）
  检测率 (Recall):  0.0367   ← BDD 完全失效
  F1:               0.0701

【实验 2】传统机器学习基线
  SVM-RBF        | Acc 0.4917 | Prec 0.5049 | Rec 0.4228 | F1 0.4602 | AUC 0.5332
  Random Forest  | Acc 0.9292 | Prec 0.9649 | Rec 0.8943 | F1 0.9283 | AUC 0.9776
```

> ⚠️ **注意 SVM 与 RF 的巨大差异（F1 0.46 vs 0.93），这是一个重要线索**：
>
> **SVM 用 RBF 核，对特征尺度极度敏感**。本例特征 = 原始量测（幅值 ~250）
> + 残差（幅值 ~6.6）+ 统计量，**量纲相差近 40 倍** → 残差信息被量测淹没 → SVM 学不到东西。
> **RF 是树模型，对尺度不敏感** → 它能从**原始量测**里提取到判别信息。
>
> **这个差异告诉你一件关键的事**：
> **RF 的 F1 0.93 并不是来自残差，而是来自原始量测。**
> 为什么原始量测有信号？因为攻击把系统状态推出了正常运行范围
> （`attack_scale` = 2%~10%，而正常负荷波动有界），
> **等价于"防御方掌握了负荷/状态的正常范围"** —— 这正是**攻击者的不完美**。
>
> 💡 **想亲手验证"残差到底有没有信号"？** 把 `build_ml_features` 里的特征
> 改成**只用残差**，重跑会看到 **F1 ≈ 0.5（随机水平）**。
> 本项目实测（400 正常 / 400 攻击）：
>
> | 特征集 | RF 的 F1 |
> |---|---|
> | 量测 + 残差 + 统计（原脚本） | 0.7245 |
> | **只用残差向量** | **0.5263** ← ≈ 随机 |
> | **只用残差范数（单特征）** | **0.4897** ← ≈ 随机 |
> | 只用原始量测 | 0.7786 |
>
> **这张表是整份材料里最重要的一张表** —— 它用数字证明了：
> **理想 FDIA 下，残差对检测毫无贡献。**
> 任何声称"用残差特征检测 FDIA"的方法，检测到的都不是 $a=Hc$ 本身。

> 📌 **关于负荷场景的一个实现陷阱（已修复）**：
> 早期版本的 `random_scenario()` 每次都基于**上一次扰动后**的负荷再扰动，
> 导致负荷随调用次数发生**乘性随机游走式漂移**（几百个样本后衰减到接近 0）。
> 后果是"正常样本"全在高负荷、"攻击样本"全在低负荷 ——
> **分类器只要看量测幅值就能"检测"，这是数据泄漏造成的伪迹**。
> 修复后（始终基于原始基准负荷扰动），两组的量测范数与残差范数才真正对齐
> （实测：量测范数 251.3 vs 252.7，残差范数 6.64 vs 6.69）。
> **这个教训值得记住：任何"高得可疑"的检测性能，先怀疑数据划分/场景生成是否有混淆。**

### Step 6-7：检测器对比

**为什么 ML 检测有效？这里有一个必须澄清的常见误解。**

很多资料（包括我最初的理解）会说：
> ❌ "残差的**范数**不变，但残差的**向量**变了，所以 ML 能检测。"

**这个说法是不准确的。** 在理想条件下（$H$ 精确已知 + 噪声协方差已知 + 全量测篡改）：

$$r_{bad} = z_{bad} - H\hat{x}_{bad} = (z + Hc) - H(\hat{x} + c) = r$$

**残差向量本身就完全不变**，不只是范数。此时无论 BDD 还是 ML，**都检测不出**。

> 📌 **这一点很重要**：它意味着"检测 $a = Hc$"在理论上就是做不到的。
> 如果你的论文声称"我检测出了理想 FDIA"，审稿人会立刻指出这个理论漏洞。

**那现实中为什么 AI 还能检测？——因为"理想"几乎不可能满足。**

攻击者必然在某些方面"不完美"，而这些不完美就是检测的抓手：

| 攻击者的"不完美" | 留下的痕迹 | 对应的检测方法 |
|---|---|---|
| 不知道**精确线路参数** | $a = \tilde{H}c$ 落在错误列空间，残差中残留 $(\tilde{H}-H)c$ | BDD / 残差分析 |
| 不知道**当前负荷水平** | 量测与**负荷预测**不一致 | **物理一致性校验**（Ashok 2017） |
| 只能篡改**部分量测**（稀疏攻击） | 被篡改量测与邻居**对不上** | **GNN 图一致性**（GDN / E-GraphSAGE） |
| 忽略**时序连续性** | 量测序列出现异常跳变 | **LSTM / 时序模型** |
| 不知道防御方**用哪种估计器** | 对某类估计器有效，对另一类无效 | **集成检测** |

> 💡 **这才是你论文真正的立足点**：
> **不要试图"检测 $a = Hc$"（理论上不可能），而要"利用攻击者必然无法完美的那一部分信息"。**
>
> 换句话问自己：**我掌握哪些攻击者不掌握的信息？**
> —— 负荷预测？电网拓扑？物理量程？时序规律？多源数据？**你的方法就应该建立在这些信息上。**

**为了让你亲眼看到这个区别**，代码里做了三个情形对比（`code/fdia_minimal.py`）：

```
情形一：理想条件        → 残差完全不变（余弦相似度 1.00000000），检测不出
情形二：防御方有负荷预测 → 攻击使偏差放大 53 倍，轻易被发现 ★
情形三：攻击者拓扑有 2% 误差 → 残差中残留痕迹
```

**情形二就是 Ashok 2017 那篇论文的核心思路**，也是最适合你复现的起点。

**GNN 的额外优势**：它把残差**映射回节点**，还利用了拓扑结构，所以在**跨拓扑泛化**上通常优于纯 ML。

## 四、实验结果解读模板

跑完后你会得到类似这样的表（**下列为本项目实测值，已修正场景生成 bug**）：

| 方法 | Acc | Prec | Rec | F1 | AUC |
|---|---|---|---|---|---|
| BDD（残差阈值） | 0.50 | 0.79 | **0.04** | 0.07 | - |
| SVM-RBF（未标准化） | 0.49 | 0.50 | 0.42 | **0.46** | 0.53 |
| Random Forest | 0.93 | 0.96 | 0.89 | 0.93 | 0.98 |
| **RF（只用残差特征）** | — | 0.52 | 0.54 | **0.53** | — |
| GNN-GCN / GAT | 见 `gnn_pure_torch.py`（本脚本需 PyG） | | | | |

**四条重要结论**（**第 2 条是很多人搞错的地方**）：

1. **BDD 检测率接近 0**（Recall 0.04）—— 印证 FDIA 的威胁性（这是你的 Motivation）
2. ⚠️ **不是"残差向量携带了攻击痕迹"** ——
   **理想 FDIA 下残差向量完全不变**（实测余弦相似度 1.0000000000），
   所以**任何只看残差的方法（BDD 或 ML）理论上都检测不出**。
   实测佐证：**把特征限制为"只用残差"，RF 的 F1 掉到 0.53（≈随机水平）**。
3. **RF 的高 F1 来自"原始量测"** —— 攻击把系统状态推出了正常运行范围，
   而防御方掌握负荷/状态的正常范围 → **这是攻击者的不完美，不是残差的功劳**。
   （这也解释了为什么 SVM 反而失败：**特征尺度未标准化**，
   量测幅值 ~250 而残差 ~6.6，RBF 核被大量纲特征主导。）
4. **GNN 与 RF 相当** —— 在**同拓扑**下；GNN 的优势要在**跨拓扑**测试中才可能显现。

> ⚠️ **如果你跑出来 RF 明显优于 GNN，不要慌**。这是正常现象：
> 训练/测试同拓扑时，RF 直接吃原始量测就能学到"状态超出正常范围"这个信号。
> **GNN 的价值在泛化与定位** —— 建议加两个实验：
> ① **IEEE 14 训练 → IEEE 57 测试**（跨拓扑）；
> ② **用 GAT 注意力做攻击定位**（见 `gnn_pure_torch.py`）。
>
> 💡 **更根本的问题**：如果检测信号只是"状态偏离正常范围"，
> 那它和"负荷预测异常"有什么区别？**这正是你的研究机会** ——
> 要设计出**攻击者即使状态偏移很小也能被抓到**的方法（靠物理一致性、拓扑一致性）。
> 参考 `gnn_pure_torch.py` 的**攻击强度扫描**：只有当信号弱到"单点看不出、
> 邻居一起看才异常"时，图结构才真正有用。

## 五、常见报错与处理

| 报错 | 原因 | 解决 |
|---|---|---|
| `ModuleNotFoundError: torch_geometric` | 没装 PyG | 装不上也行，脚本会自动跳过 GNN |
| `pandapower 潮流不收敛` | 随机负荷扰动太大 | 把 `random_scenario(scale=0.3)` 调到 0.15 |
| `LinAlgError: Singular matrix` | H 矩阵秩亏 | 检查是否漏掉变压器支路；或用 `np.linalg.lstsq` |
| `残差变化很大（>1）` | H 构造有误 | 用上面"验证 H"的方法排查 |
| `所有预测都是 0` | 类别不平衡未处理 | 检查 `class_weight='balanced'` 和 loss 权重 |
| `F1 高得离谱（0.999）` | 数据泄漏 | 按场景/时间划分，不要随机划分 |
| `PyG 编译错误` | torch 版本不匹配 | 按官网选对应 whl |
