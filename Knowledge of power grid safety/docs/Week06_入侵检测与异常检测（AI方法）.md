## Day 36 · 09:00 —— 入侵检测系统基础：NIDS / HIDS / 误用与异常检测

> **一句话**：**入侵检测（IDS）分两类思路**——"我知道攻击长什么样"（误用检测）和"我知道正常长什么样"（异常检测）。**在电力 CPS 里，后者更重要，因为攻击样本稀缺。**

### 一、IDS 的分类

**按部署位置**：

| 类型 | 部署位置 | 检测什么 | 电力场景 |
|---|---|---|---|
| **NIDS** | 网络节点 | 网络流量 | 变电站网络、调度通信 |
| **HIDS** | 主机 | 主机行为、日志 | SCADA 服务器、HMI |
| **混合** | 两者结合 | 全面 | 完整防护体系 |

**按检测原理**：

| 类型 | 原理 | 优点 | 缺点 |
|---|---|---|---|
| **误用检测（Signature-based）** | 匹配已知攻击特征 | 准确率高、误报低 | **无法检测未知攻击** |
| **异常检测（Anomaly-based）** | 学习正常行为，偏离即异常 | **能检测未知攻击** | 误报率高 |
| **混合** | 两者结合 | 平衡 | 复杂度高 |

### 二、误用检测 vs 异常检测的权衡

```
误用检测：
  "这看起来像已知的攻击模式 X"  → 告警
  优点：准确
  缺点：只能识别"见过的"

异常检测：
  "这看起来不像正常行为"  → 告警
  优点：能发现新攻击
  缺点：正常行为边界难界定 → 误报
```

**电力 CPS 的现实**：
- **攻击样本稀缺** → 误用检测的"特征库"不全
- **攻击方式多样** → 难以穷举
- **结论：异常检测是主力**

### 三、为什么异常检测在工控领域特别有效

| 原因 | 说明 |
|---|---|
| **行为高度规律** | 工控流量周期性极强 |
| **操作低频** | 遥控等关键操作很少发生 |
| **物理约束** | 数据必须满足物理规律 |
| **拓扑稳定** | 网络结构很少变化 |

**"工控流量高度规律"是最重要的优势**：

```
IT 网络流量：用户行为主导 → 变化大 → 异常检测难
工控网络流量：机器行为主导 → 周期固定 → 异常检测易
```

**具体例子**：
- 主站每 1 秒轮询一次 RTU（周期固定）
- 正常运行时几乎不发遥控命令
- **任何偏离这个模式的流量都是"可疑"的**

### 四、和电网安全研究的关系

| 选题 | 方法 | 说明 |
|---|---|---|
| **工控协议流量异常检测** | 时序模型 + 深度学习 | 最主流 |
| **操作行为异常检测（UEBA）** | 行为建模 | 对接乌克兰攻击场景 |
| **物理量异常检测** | 物理约束 + AI | 电网特色 |
| **多源融合检测** | 多模态方法 | 前沿 |
| **在线/增量学习** | 流式学习 | 实用性 |

**特别推荐入门路径**：

```
第 1 步：用公开数据集（如 ICS 攻击数据集）
       → 学会数据预处理、特征提取

第 2 步：实现简单方法（SVM、随机森林）
       → 建立基线

第 3 步：实现深度学习方法（LSTM、自编码器）
       → 对比效果

第 4 步：结合物理约束
       → 提出改进方法
```

**这是一个清晰的、3-6 个月能出成果的路径。**

## Day 36 · 14:00 —— 电力工控网络流量特征工程

> **一句话**：**AI 模型再强，也需要好的特征**。在工控场景，"特征工程"往往比"模型选择"更重要——**因为工控协议的结构化程度极高，你能手工设计出很强的特征。**

### 一、特征工程的重要性

```
数据 → [特征工程] → 模型 → 结果
         ↑
      这一环往往决定成败
```

**在工控场景**：
- 数据是**结构化的**（协议格式固定）
- 领域知识**明确**（你知道哪些字段重要）
- **手工特征可能胜过自动学习**

### 二、工控流量的特征类型

**① 网络层特征**

| 特征 | 说明 |
|---|---|
| 源/目的 IP、端口 | 通信关系 |
| 包长度 | 报文大小 |
| 报文间隔 | 时间规律 |
| 协议类型 | 协议分布 |
| 包数量/频率 | 流量强度 |

**② 协议层特征（关键！）**

| 特征 | 说明 | 为什么重要 |
|---|---|---|
| **功能码分布** | 各类操作的比例 | 异常功能码 = 攻击 |
| **读写比例** | 读 vs 写操作 | 写操作异常增加 = 可疑 |
| **地址访问范围** | 访问哪些寄存器/点 | 越权访问 = 攻击 |
| **序列号模式** | stNum/sqNum（GOOSE） | 异常序列 = 攻击 |
| **时间戳一致性** | 时间戳是否合理 | 时间攻击检测 |
| **响应时间** | 请求-响应延迟 | 异常延迟 = 攻击 |

**③ 行为层特征**

| 特征 | 说明 |
|---|---|
| 操作序列模式 | 操作的顺序 |
| 操作频率变化 | 相对基线的偏离 |
| 会话持续时间 | 异常长的会话 |
| 重复模式 | 重复的报文（重放） |

**④ 物理层特征（电网特色！）**

| 特征 | 说明 |
|---|---|
| **物理量一致性** | 是否满足基尔霍夫定律 |
| **量测变化率** | 变化是否合理（负荷不会瞬间翻倍） |
| **多节点相关性** | 相邻节点量测应相关 |

### 三、特征工程的方法

**① 统计特征**
```python
# 滑动窗口内统计
window = 100  # 100个包
features = {
    'mean_pkt_size': data['size'].rolling(window).mean(),
    'std_pkt_size': data['size'].rolling(window).std(),
    'pkt_rate': 1 / data['interval'].rolling(window).mean(),
    'func_code_entropy': entropy(data['func_code']),
}
```

**② 时序特征**
```
- 周期性（傅里叶变换找主频）
- 趋势（滑动平均）
- 突变点（变点检测）
- 自相关
```

**③ 图特征**
```
- 通信图的节点度
- 通信关系的稳定性
- 新增的通信边（可疑！）
```

**④ 物理特征**
```
- 潮流方程残差
- 功率平衡误差
- 相邻节点量测偏差
```

### 四、特征选择

**特征不是越多越好**：

| 问题 | 后果 |
|---|---|
| 特征过多 | 维度灾难、过拟合、计算慢 |
| 特征冗余 | 信息重复、影响模型 |
| 无关特征 | 引入噪声 |

**常用方法**：
- **过滤法**：相关系数、互信息
- **包裹法**：递归特征消除
- **嵌入法**：L1 正则、树模型的特征重要性

### 五、和电网安全研究的关系

**"物理特征"是你最大的创新空间**：

| 特征类别 | 研究现状 | 创新空间 |
|---|---|---|
| 网络层 | 成熟 | 低 |
| 协议层 | 较成熟 | 中 |
| 行为层 | 发展中 | 中 |
| **物理层** | **较少** | **高！** |

**特别推荐"融合物理特征与网络特征的检测"**：

**核心思想**：
```
网络特征：告诉你"通信是否异常"
物理特征：告诉你"数据是否自洽"
融合两者 → 更全面的检测
```

**具体实现**：
1. 提取网络特征（包长、频率、功能码）
2. 提取物理特征（潮流残差、一致性指标）
3. **用多模态方法融合**（如双塔模型、注意力融合）
4. 输出检测结果

**为什么这个选题好**：
1. **有创新性**（物理+网络的融合研究少）
2. **对接"多模态大模型"方向**（多模态融合技术）
3. **理论合理**（两类特征互补）
4. **实验可控**

## Day 37 · 09:00 —— 机器学习入门方法：SVM、随机森林、KNN 在入侵检测中的应用

> **一句话**：**别小看传统机器学习**——在工控入侵检测中，**随机森林往往能和深度学习打平，而且更快、更可解释**。先用传统方法建立基线，再考虑深度学习。

### 一、为什么先学传统方法

| 优点 | 说明 |
|---|---|
| **快速** | 训练和推理都快 |
| **可解释** | 能看出哪些特征重要 |
| **小数据友好** | 不需要海量数据 |
| **基线价值** | 论文里必须有基线对比 |

**实务经验**：**很多论文用深度学习，但提升有限**。如果传统方法能达到 95% 准确率，深度学习做到 96% 但慢 10 倍，**论文里必须说明这个权衡**。

### 二、三种经典方法

**① SVM（支持向量机）**

**原理**：找最优超平面分隔两类数据。

| 特点 | 说明 |
|---|---|
| 适合 | 中小规模、高维数据 |
| 核函数 | RBF、多项式 |
| 优点 | 理论完备、泛化好 |
| 缺点 | 大规模数据慢、需调参 |

```python
from sklearn.svm import SVC
model = SVC(kernel='rbf', C=1.0, gamma='scale')
model.fit(X_train, y_train)
```

**② 随机森林（Random Forest）**

**原理**：多棵决策树投票。

| 特点 | 说明 |
|---|---|
| 适合 | **通用、几乎万能** |
| 优点 | **鲁棒、可解释、不易过拟合** |
| 缺点 | 对高维稀疏数据一般 |
| **工控适用性** | **★★★★★** |

```python
from sklearn.ensemble import RandomForestClassifier
model = RandomForestClassifier(n_estimators=100, max_depth=10)
model.fit(X_train, y_train)
print(model.feature_importances_)   # 可看特征重要性！
```

**③ KNN（K 近邻）**

| 特点 | 说明 |
|---|---|
| 原理 | 看最近的 K 个邻居是什么类 |
| 优点 | 简单、无需训练 |
| 缺点 | 推理慢（要算距离）、维度灾难 |

### 三、在工控入侵检测中的表现

**典型实验结论**（多个研究的共识）：

| 方法 | 准确率 | 训练速度 | 推理速度 | 可解释性 |
|---|---|---|---|---|
| SVM | 高 | 慢 | 中 | 中 |
| **随机森林** | **高** | **快** | **快** | **高** |
| KNN | 中 | 无 | **慢** | 低 |
| 深度学习 | 高（略高） | 慢 | 中 | 低 |

**结论**：**随机森林是"性价比之王"**。

### 四、关键工程问题

**① 类别不平衡**

工控场景中攻击样本极少（**现实就是这样**）。

| 方法 | 说明 |
|---|---|
| **欠采样** | 减少正常样本 |
| **过采样（SMOTE）** | 生成合成攻击样本 |
| **代价敏感** | 给少数类更高权重 |
| **调整阈值** | 不用 0.5，选最优阈值 |

**② 评估指标（关键！）**

**不要只看准确率！**

| 指标 | 公式 | 含义 |
|---|---|---|
| **准确率** | (TP+TN)/总数 | **在不平衡数据下会骗人** |
| **精确率 (Precision)** | TP/(TP+FP) | 告警中有多少是真的 |
| **召回率 (Recall)** | TP/(TP+FN) | 攻击中有多少被检出 |
| **F1** | 2PR/(P+R) | 综合 |
| **AUC-ROC** | 曲线下面积 | 综合性能 |

**举例说明"准确率陷阱"**：
```
1000 个样本，10 个是攻击
模型全预测"正常" → 准确率 = 990/1000 = 99%
但召回率 = 0%（一个攻击都没检出！）
```

**所以电力场景必须看召回率和 F1。**

**③ 交叉验证**

工控数据常有**时间相关性**，不能用随机划分！

| 划分方法 | 适用 |
|---|---|
| 随机划分 | 独立同分布数据 |
| **时间序列划分** | **工控时序数据（正确做法）** |
| 分组划分 | 按设备分组 |

### 五、和电网安全研究的关系

| 选题 | 方法 | 说明 |
|---|---|---|
| **传统 ML 基线建立** | RF/SVM | 论文必备 |
| **不平衡数据处理** | SMOTE + 代价敏感 | 实用 |
| **特征重要性分析** | 随机森林 | 理解攻击特征 |
| **模型对比研究** | 多方法对比 | 综述型工作 |
| **可解释检测** | SHAP/LIME | 调度员需要"为什么" |

**特别推荐"可解释的入侵检测"**：

**问题**：调度员看到一个告警，会问"**为什么判定是攻击？**"。深度模型给不出答案，这在电力场景是**致命的**（因为调度员不敢基于"黑箱"做决策）。

**方案**：
- 用**可解释模型**（随机森林 + 特征重要性）
- 或用**可解释性工具**（SHAP、LIME）解释深度模型
- **输出"告警 + 理由"**

**为什么这个选题好**：
1. **有实际需求**（工控场景特别重视可解释性）
2. **对接"工业AI"方向**（可解释AI 是热点）
3. **容易做出差异化**（大部分论文只追求准确率）

## Day 37 · 14:00 —— 深度学习入门方法：CNN / RNN / LSTM 处理时序流量

> **一句话**：**深度学习的优势是"自动学特征"**——特别适合工控**时序流量**（因为它的时间规律性强）。**LSTM 是工控异常检测最常用的模型。**

### 一、为什么用深度学习

| 优势 | 说明 |
|---|---|
| **自动特征** | 不用手工设计特征 |
| **时序建模** | 天然适合时间序列 |
| **非线性** | 能学复杂模式 |
| **端到端** | 从原始数据到结果 |

**在工控场景**：**流量高度时序化、周期性强** → **时序模型效果好**。

### 二、主要模型

**① CNN（卷积神经网络）**

**原理**：用卷积核提取局部模式。

| 应用 | 说明 |
|---|---|
| **1D CNN** | 时序数据的局部模式 |
| 2D CNN | 图像（如电网巡检） |
| 优点 | 快、并行、参数少 |

**在工控中的应用**：
```
输入：流量序列（如连续 100 个报文）
1D 卷积提取局部模式 → 池化 → 全连接 → 分类
```

**② RNN / LSTM（循环神经网络）**

**原理**：有"记忆"，能处理序列。

| 模型 | 特点 |
|---|---|
| **RNN** | 基础循环结构，有梯度消失问题 |
| **LSTM** | 加"门"机制，能记长依赖 |
| **GRU** | LSTM 的简化版，更快 |

**LSTM 的三个门**：

| 门 | 作用 |
|---|---|
| **遗忘门** | 决定丢弃哪些旧信息 |
| **输入门** | 决定存入哪些新信息 |
| **输出门** | 决定输出哪些信息 |

**为什么 LSTM 适合工控**：**能捕捉"正常的周期模式"**，偏离就是异常。

**③ 自编码器（Autoencoder）**

**原理**：压缩再重构，重构误差大 = 异常。

```
输入 → [编码器] → 隐层（低维） → [解码器] → 重构
                                              ↑
                                    与输入比较，误差大 = 异常
```

**优势**：**只需要正常数据训练**（无监督）→ **完美匹配"攻击样本稀缺"的现实！**

### 三、模型对比

| 模型 | 优势 | 劣势 | 工控适用性 |
|---|---|---|---|
| **1D CNN** | 快、并行 | 长依赖弱 | ★★★★ |
| **LSTM** | 长依赖强 | 慢、难并行 | **★★★★★** |
| **GRU** | 比 LSTM 快 | 略弱 | ★★★★ |
| **自编码器** | 无监督 | 需调阈值 | **★★★★★** |
| **Transformer** | 最强 | 数据需求大 | ★★★（见 Day39） |

## Day 38 · 09:00 —— 图神经网络（GNN）与电网拓扑入侵检测

> **一句话**：**电网是"图"，GNN 是"处理图的方法"**——这是你的背景和电网安全最天然的接口。**用 GNN 检测拓扑攻击，是当前很有前景的方向。**

### 一、为什么用 GNN

**传统深度学习的局限**：
```
CNN：处理网格数据（图像）
RNN：处理序列数据（时序）
→ 都假设数据有"规整结构"

但电网是"图"：
  节点（母线）之间关系不规则
  传统方法要先"拉平"成向量 → 丢失拓扑信息
```

**GNN 的优势**：**直接在图结构上学习，保留拓扑信息**。

### 二、GNN 的基本原理

**核心思想：消息传递（Message Passing）**

```
每个节点：
  1. 接收邻居节点的消息
  2. 聚合消息（求和/平均/最大）
  3. 更新自己的表示
  → 重复 K 层 → 每个节点获得 K 跳邻居的信息
```

```
第 1 层：节点只知道自己的特征
第 2 层：节点知道 1 跳邻居的信息
第 3 层：节点知道 2 跳邻居的信息
...
```

### 三、主要 GNN 模型

| 模型 | 特点 |
|---|---|
| **GCN**（图卷积网络） | 最基础，谱方法 |
| **GraphSAGE** | 采样聚合，可扩展 |
| **GAT**（图注意力网络） | 注意力加权邻居 |
| **GIN** | 表达能力强 |
| **图自编码器** | 无监督 |

**GAT 值得关注**：它用**注意力机制**给不同邻居不同权重——**在电网里很合理**（电气距离近的节点应该更相关）。

**边特征**：

## Day 38 · 14:00 —— 自编码器与无监督异常检测

> **一句话**：**自编码器是"攻击样本稀缺"困境的最优解**——它只需正常数据训练。**在电力场景，这是最"接地气"的方法。**

### 一、为什么无监督最重要

**现实困境**：

| 方法 | 需要 | 现实问题 |
|---|---|---|
| **监督学习** | 标记的攻击样本 | **几乎没有** |
| **半监督** | 少量攻击样本 | 难以获得 |
| **无监督** | **只需正常数据** | **✅ 大量可得！** |

**"正常数据大量可得，攻击数据几乎没有"** —— 这是现实。**所以无监督方法最适合。**

### 二、自编码器的原理

**结构**：
```
输入 x → [编码器 Encoder] → 隐表示 z → [解码器 Decoder] → 重构 x̂
```

**训练目标**：**最小化重构误差** $\|x - \hat{x}\|^2$

**异常检测逻辑**：
```
正常数据：训练过 → 重构误差 小
异常数据：没见过 → 重构误差 大
                  ↑
            超过阈值 → 告警
```

### 三、变体

| 变体 | 特点 | 适用 |
|---|---|---|
| **基础 AE** | 简单 | 向量数据 |
| **去噪 AE (DAE)** | 加噪声训练，更鲁棒 | 噪声环境 |
| **稀疏 AE** | 隐层稀疏约束 | 特征学习 |
| **变分 AE (VAE)** | 概率生成模型 | 生成 + 检测 |
| **LSTM-AE** | 时序自编码器 | **时序数据** |
| **图 AE** | 图结构自编码器 | **电网！** |

**LSTM-AE 特别适合工控流量**（时序 + 无监督）。

### 四、实现要点

**① 基础 AE 实现**
```python
class AnomalyAE(nn.Module):
    def __init__(self, input_dim, latent_dim=8):
        super().__init__()
        self.encoder = nn.Sequential(
            nn.Linear(input_dim, 32), nn.ReLU(),
            nn.Linear(32, latent_dim)
        )
        self.decoder = nn.Sequential(
            nn.Linear(latent_dim, 32), nn.ReLU(),
            nn.Linear(32, input_dim)
        )

    def forward(self, x):
        z = self.encoder(x)
        return self.decoder(z)
```

**② LSTM-AE（时序）**
```python
class LSTMAE(nn.Module):
    def __init__(self, input_dim, hidden=32):
        super().__init__()
        self.encoder = nn.LSTM(input_dim, hidden, batch_first=True)
        self.decoder = nn.LSTM(hidden, input_dim, batch_first=True)

    def forward(self, x):
        _, (h, _) = self.encoder(x)
        h = h[-1].unsqueeze(1).repeat(1, x.size(1), 1)
        out, _ = self.decoder(h)
        return out
```

**③ 阈值选择（关键！）**

阈值怎么定？**常见方法**：

| 方法 | 说明 |
|---|---|
| **百分位法** | 取正常数据误差的 99% 分位 |
| **3σ 准则** | 均值 + 3 倍标准差 |
| **验证集调优** | 用少量有标签数据调 |
| **极值理论 (EVT)** | 统计极端值分布 |

**实务建议**：**先用百分位法**（简单有效），再考虑优化。

### 五、挑战与改进

| 挑战 | 说明 | 改进方向 |
|---|---|---|
| **阈值敏感** | 阈值选择影响大 | 自适应阈值 |
| **攻击可"学着正常"** | 攻击者优化数据使其重构误差小 | 结合物理约束 |
| **正常数据有噪声** | 导致误报 | 去噪 AE、鲁棒损失 |
| **概念漂移** | 系统变化后"正常"变了 | 在线学习 |

**"攻击者优化数据绕过 AE"是重要问题**：

因为 AE 的判据是"重构误差小 = 正常"，**攻击者可以优化攻击数据使其重构误差最小化**（类似对抗样本）。

**防御**：
- **物理约束**（攻击数据难同时满足物理规律）
- **多模型集成**（多个 AE，攻击者难同时绕过）
- **对抗训练**

## Day 39 · 09:00 —— Transformer 与时序异常检测（对接多模态大模型方向）

> **一句话**：**Transformer 用"注意力机制"取代了循环结构**，在时序异常检测上表现强劲。**它也是大模型的基础——学它，你就摸到了"大模型"的门。**

### 一、Transformer 的核心：注意力机制

**Self-Attention（自注意力）**：

```
输入序列：[x1, x2, x3, x4]
                ↓
每个元素计算 Query、Key、Value
                ↓
注意力权重 = softmax(Q·Kᵀ / √d)
                ↓
输出 = 加权求和(Value)
                ↓
每个位置都"看到"所有其他位置
```

**关键优势**：**全局依赖**——任意两个位置直接相连（不像 RNN 要一步步传）。

### 二、与 RNN 的对比

| 维度 | RNN/LSTM | Transformer |
|---|---|---|
| **依赖距离** | 长依赖衰减 | **全局直接** |
| **并行** | 难（必须按序） | **易（全部并行）** |
| **复杂度** | O(n) | O(n²) |
| **数据需求** | 中 | **大** |
| **长序列** | 困难 | **优势** |

**关键权衡**：Transformer 更强但**需要更多数据**。在工控场景，数据量可能不足——**这是需要注意的**。

### 三、时序异常检测中的应用

**典型架构**：

| 方法 | 思路 |
|---|---|
| **Transformer Encoder 分类** | 直接分类正常/异常 |
| **Autoencoder Transformer** | 用重构误差检测 |
| **Anomaly Transformer** | 用"注意力差异"检测 |
| **Informer** | 长序列高效 Transformer |
| **时序 Transformer + 特征** | 融合物理特征 |

**"Anomaly Transformer" 值得关注**：

**核心思想**：正常数据点的注意力分布是"平缓"的；异常点的注意力会**集中在少数位置**（因为要和"相邻正常点"建立强关联）。

**检测依据**：**注意力分布的"集中度"异常** → 存在异常。

### 四、实现示例

```python
import torch.nn as nn

class TimeSeriesTransformer(nn.Module):
    def __init__(self, input_dim, d_model=64, nhead=4, num_layers=2):
        super().__init__()
        self.embed = nn.Linear(input_dim, d_model)
        encoder_layer = nn.TransformerEncoderLayer(
            d_model=d_model, nhead=nhead, batch_first=True
        )
        self.transformer = nn.TransformerEncoder(encoder_layer, num_layers)
        self.head = nn.Linear(d_model, 1)

    def forward(self, x):
        x = self.embed(x)                    # 投影到 d_model 维
        h = self.transformer(x)              # 注意力编码
        return torch.sigmoid(self.head(h[:, -1, :]))
```

### 五、挑战

| 挑战 | 说明 |
|---|---|
| **数据需求大** | 小数据集容易过拟合 |
| **计算成本高** | O(n²) 复杂度 |
| **可解释性差** | 注意力权重可部分解释 |
| **超参敏感** | 层数、头数、维度 |

**实务建议**：**数据量小的话，先用 LSTM**。数据充足或需要长依赖建模时，再用 Transformer。

| 选题 | 方法 | 对接方向 |
|---|---|---|
| **Transformer 流量异常检测** | 时序建模 | **入侵检测** |
| **Anomaly Transformer 电网应用** | 注意力异常 | 前沿 |
| **多变量时序检测** | 多变量 Transformer | 实用 |
| **与物理特征融合** | 混合模型 | 推荐 |
| **轻量化 Transformer** | 效率优化 | **实时性约束** |

**特别推荐"轻量化 Transformer 用于工控实时检测"**：

**问题**：Transformer 精度高，但**计算量大**。工控要求**毫秒级检测**，标准 Transformer 太慢。

**方案**：
- **知识蒸馏**（大模型教小模型）
- **剪枝**（去掉冗余参数）
- **量化**（降低数值精度）

**为什么这个选题好**：
1. **解决真实痛点**（实时性约束）
2. **对接"多模态大模型"方向**（模型压缩是配套技术）
3. **有明确的评估指标**（精度 vs 延迟）
4. **实用价值高**

## Day 39 · 14:00 —— 大模型在日志分析与告警降噪中的应用

> **一句话**：**大模型（LLM）最擅长的就是"理解文本"**——而电网的**告警、日志、报告全是文本**。**这是 LLM 在电网安全中最容易落地的场景。**

### 一、电力系统的问题：告警风暴

**现实困境**：

```
一个变电站的日常告警：数百到数千条
一次故障期间：数万条告警

调度员的问题：
  ✗ 告警太多，看不过来
  ✗ 大量重复/关联告警
  ✗ 真正重要的被淹没
  ✗ 难以快速判断根因
```

**"告警风暴（Alarm Flood）"是电力运维的经典难题。**

### 二、LLM 能做什么

| 能力 | 应用 |
|---|---|
| **文本理解** | 理解告警语义 |
| **聚类** | 把相关告警归组 |
| **摘要** | 生成"根因摘要" |
| **分类** | 判断告警严重性 |
| **关联分析** | 找出告警的因果关系 |
| **自然语言查询** | "最近变电站 A 有什么异常？" |
| **报告生成** | 自动生成事件报告 |

### 三、具体应用方案

**① 告警降噪**

```
输入：1000 条告警
↓ LLM 分析
输出：
  - 根因：#1（关联 800 条告警）
  - 次要：#2（关联 150 条）
  - 独立：#3（50 条）
```

**提示词设计示例**：
```
以下是一段时间内的电力系统告警日志。
请：
1. 识别主要告警簇（哪些告警可能源于同一原因）
2. 推断可能的根因
3. 按严重性排序
4. 用一句话总结最需要关注的问题

告警日志：
[时间] [设备] [告警内容]
...
```

**② 日志异常检测**

```
正常日志模式：
  "断路器 101 状态：合闸"
  "变压器 T1 油温：45°C"

异常信号：
  "用户 admin 从 IP 10.1.2.3 登录失败 47 次"     ← 暴力破解
  "配置被修改：保护定值 5A → 50A"                ← 定值篡改！
  "异常指令：CTRL-WRITE 到未知地址"              ← 可疑操作
```

**LLM 的优势**：**能理解"语义"**，不只是匹配关键词。

**③ 事件报告生成**

```
输入：告警序列 + 操作记录
输出：
  "2026-09-16 14:23，变电站 B 的 110kV 线路 L1
   发生单相接地故障。保护正确动作（距离 I 段），
   断路器 CB1 于 45ms 后跳闸。重合闸成功，
   恢复供电。整个过程耗时 2.3 秒。"
```

### 四、技术实现

**基本架构**：

```
[电力日志/告警] → [预处理：结构化] → [LLM 分析] → [结构化输出]
                                          ↑
                                    提示工程 / RAG
```

**RAG（检索增强生成）**：

```
问题：LLM 不了解特定电力系统的知识
方案：RAG
  1. 把电力文档（规程、手册、历史案例）向量化存入知识库
  2. 查询时检索相关文档
  3. 把检索结果作为上下文给 LLM
  4. LLM 基于上下文回答
```

**这解决了"LLM 不懂电力"的问题。**

## Day 40 · 09:00 —— 联邦学习在电力入侵检测中的应用（对接联邦学习方向）

> **一句话**：**联邦学习解决"数据不能共享"的困境**——各参与方在本地训练，只上传模型参数。**这完美契合电力行业"数据敏感、不愿共享"的现实。**

### 一、为什么需要联邦学习

**电力行业的数据困境**：

| 问题 | 说明 |
|---|---|
| **数据敏感** | 电力数据涉及关键基础设施 |
| **不愿共享** | 各公司出于商业/安全考虑 |
| **法规限制** | 数据出境、共享受限 |
| **孤岛现象** | 各变电站/公司数据孤立 |

**但入侵检测需要"多样化的攻击样本"** → **数据孤岛阻碍了模型效果**。

**联邦学习（Federated Learning, FL）** 的解决方案：

```
传统集中式：
  各方数据 → 汇总到中心 → 训练模型 → 分发
  问题：数据要共享（不行）

联邦学习：
  各方本地训练 → 只上传模型参数 → 中心聚合 → 分发新参数
  优点：原始数据不出本地！
```

### 二、联邦学习的流程

```
① 中心服务器初始化全局模型 → 分发给各参与方
② 各参与方用本地数据训练 → 得到本地模型更新
③ 上传模型更新（不是数据！）到中心
④ 中心聚合（如 FedAvg）→ 更新全局模型
⑤ 分发新全局模型 → 重复
```

**FedAvg（联邦平均）** 是最基础的聚合方法：
$$\theta_{global} = \sum_k \frac{n_k}{n} \theta_k$$
（按各参与方数据量加权平均）

### 三、在电力入侵检测中的应用

**场景**：

```
变电站 A         变电站 B         变电站 C
（本地数据）      （本地数据）      （本地数据）
    ↓                ↓                ↓
本地训练 IDS      本地训练 IDS      本地训练 IDS
    ↓                ↓                ↓
    └────── 上传参数（不传数据）──────┘
                    ↓
            聚合全局模型
                    ↓
              下发到各方
```

**优势**：
- 数据不出本地（隐私保护）
- 各方贡献样本（效果提升）
- 符合法规要求

### 四、联邦学习的挑战

| 挑战 | 说明 |
|---|---|
| **通信成本** | 频繁上传参数 |
| **异构数据** | 各方数据分布不同（Non-IID） |
| **安全威胁** | **投毒攻击、参数泄露** |
| **参与方不稳定** | 有些方可能掉线 |
| **隐私仍未完全保证** | 参数可能泄露信息 |

**"参数泄露信息"是关键问题**：

**研究表明**：通过分析上传的模型参数，**可以反推出训练数据的信息**（梯度泄露攻击）。

**防御**：结合**差分隐私**（加噪声）或**安全聚合**（加密聚合）。

### 五、联邦学习的安全问题（最重要）

**联邦学习本身引入了新的攻击面**：

| 攻击 | 说明 | 后果 |
|---|---|---|
| **数据投毒** | 恶意参与方上传污染数据训练的模型 | 全局模型偏差 |
| **模型投毒** | 直接上传恶意参数 | 后门植入 |
| **拜占庭攻击** | 部分参与方恶意行为 | 聚合失效 |
| **梯度泄露** | 从参数反推数据 | 隐私泄露 |
| **搭便车** | 不训练只上传噪声 | 影响效果 |

**"后门攻击"最危险**：

攻击者在模型参数中植入**后门**：
```
正常数据：模型表现正常
特制触发数据（如特定模式）→ 模型输出攻击者想要的结果
```

**例子**：攻击者让模型在遇到"特定攻击模式"时判为正常 → **攻击可以绕过检测**。

### 六、和电网安全研究的关系

| 选题 | 方法 | 对接方向 |
|---|---|---|
| **联邦学习用于 IDS** | FedAvg + 攻防 | **联邦学习 + 入侵检测** |

## Day 40 · 14:00 —— 对抗样本与模型鲁棒性（对接图像识别与安全方向）

> **一句话**：**对抗样本是深度学习的"阿喀琉斯之踵"**——给输入加一点人眼看不见的扰动，就能让模型完全判断错误。**如果用 AI 做电网检测，就必须考虑这个漏洞。**

### 一、什么是对抗样本

**定义**：在原始输入上添加**人眼难以察觉的微小扰动**，使模型**错误分类**。

**经典例子（图像）**：
```
原始图像 → 模型识别："熊猫"（置信度 99%）
加微小噪声 → 模型识别："长臂猿"（置信度 99%）
人眼看：两只都是熊猫
```

**在电网场景**：
```
正常量测 → 检测器："正常"
加微小扰动（保持物理合理性）→ 检测器："正常"
但实际是攻击！
```

### 二、对抗攻击的方法

| 方法 | 说明 |
|---|---|
| **FGSM** | 快速梯度符号法（一步） |
| **PGD** | 投影梯度下降（多步，更强） |
| **C&W** | 优化方法，扰动更小 |
| **DeepFool** | 找最小扰动 |
| **对抗补丁** | 局部可见的扰动（物理攻击） |

**FGSM 原理**：
$$x_{adv} = x + \epsilon \cdot \text{sign}(\nabla_x L(x, y))$$
（沿损失上升方向加扰动，让模型出错）

### 三、在电网场景的特殊性

**电网的对抗样本有额外约束**：

| 约束 | 说明 |
|---|---|

**这使"在电网构造对抗样本"更难，但也更有研究价值**：

**关键问题**：**攻击者能在"保持物理合理"的前提下构造对抗样本吗？**

如果**能** → 说明纯 AI 检测很脆弱

**这是一个非常值得研究的核心问题。**

## Day 41 · 09:00 —— 入侵检测评价指标：准确率陷阱与不平衡数据

> **一句话**：**在入侵检测中，"准确率 99%"可能是最糟糕的结果**——如果 99% 的样本都是正常，模型只要"全说正常"就能达到 99%。**必须用对指标。**

### 一、准确率陷阱

**经典例子**：

```
数据集：1000 个样本，其中 10 个攻击，990 个正常

模型 A：全部预测"正常"
  准确率 = 990/1000 = 99%  ← 看起来很漂亮！
  召回率 = 0/10 = 0%       ← 一个攻击都没发现！
  → 这个模型完全无用
```

**教训**：**在不平衡数据下，准确率会严重误导。**

### 二、必须掌握的评价指标

**混淆矩阵**：

```
                预测：正常   预测：攻击
实际：正常        TN          FP（误报）
实际：攻击        FN（漏报）  TP
```

**核心指标**：

| 指标 | 公式 | 含义 | 电力场景关注 |
|---|---|---|---|
| **精确率 P** | TP/(TP+FP) | 告警中真的是攻击的比例 | 告警太多会疲劳 |
| **召回率 R** | TP/(TP+FN) | 攻击被检出的比例 | **最重要（漏报致命）** |
| **F1** | 2PR/(P+R) | 综合 | 平衡指标 |
| **准确率** | (TP+TN)/总 | 整体正确率 | **慎用** |
| **特异度** | TN/(TN+FP) | 正常样本正确判定的比例 | — |
| **AUC-ROC** | 曲线下面积 | 综合性能（与阈值无关） | 推荐 |

**电力场景的优先级**：

```
安全第一 → 召回率最重要（不能漏报攻击）
但误报也要控制（告警疲劳会导致忽视）
→ F1 或加权指标
```

### 三、ROC 曲线与 AUC

**ROC 曲线**：横轴 FPR（假正率），纵轴 TPR（真正率）。

```
TPR = TP/(TP+FN)   （召回率）
FPR = FP/(FP+TN)   （误报率）

对角线 = 随机猜测（AUC=0.5）
左上角 = 完美分类器（AUC=1.0）
```

**AUC 的优势**：**与阈值无关**，综合评价模型能力。

**PR 曲线（在不平衡数据下更好）**：
- 横轴：召回率
- 纵轴：精确率
- **在不平衡数据下，PR 曲线比 ROC 更能反映性能**

### 四、其他重要问题

**① 代价敏感评估**

不同错误的代价不同：
```
漏报攻击（FN）：可能导致停电 → 代价极高
误报（FP）：调度员多看一条告警 → 代价低

所以应该给 FN 更高权重
加权代价 = C_FN × FN + C_FP × FP
```

**② 时间性能**

| 指标 | 重要性（工控场景） |
|---|---|
| **检测延迟** | 极高（毫秒级要求） |
| **吞吐量** | 高（海量流量） |
| **资源占用** | 中（边缘设备受限） |

**③ 泛化性**

```
在同一系统训练测试：效果好
在不同系统测试：效果可能大幅下降！
→ 必须测试跨系统泛化
```

### 五、和电网安全研究的关系

| 选题 | 方法 | 说明 |
|---|---|---|
| **不平衡数据检测方法** | 代价敏感、异常检测 | 实用 |

**问题**：几乎所有论文都在"同一个系统"上训练和测试。**但现实是：模型训练于系统 A，要部署到系统 B。**

### 三、可运行的代码骨架

```python
"""电力 FDIA 检测最小实验"""
import pandapower as pp
import pandapower.networks as pn
import numpy as np
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import classification_report, roc_auc_score

# ① 载入电网
net = pn.case14()

# ② 生成正常数据
def get_measurements(net):
    pp.runpp(net)
    return np.concatenate([
        net.res_bus.vm_pu.values,      # 电压幅值
        net.res_bus.va_degree.values,  # 电压相角
        net.res_line.p_from_mw.values, # 线路有功
    ])

normal = []
for scale in np.linspace(0.8, 1.2, 200):
    net.load['scaling'] = scale
    normal.append(get_measurements(net))
normal = np.array(normal)

# ③ 注入攻击（简化版：加扰动）
attack = normal.copy()
for i in range(len(attack)):
    idx = np.random.randint(len(attack[i]))
    attack[i, idx] += np.random.normal(0, 0.1)  # 篡改一个量测

X = np.vstack([normal, attack])
y = np.hstack([np.zeros(len(normal)), np.ones(len(attack))])

# ④ 训练检测器
from sklearn.model_selection import train_test_split
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, random_state=42)

clf = RandomForestClassifier(n_estimators=100)
clf.fit(X_tr, y_tr)

# ⑤ 评估
pred = clf.predict(X_te)
print(classification_report(y_te, pred))
print("AUC:", roc_auc_score(y_te, clf.predict_proba(X_te)[:, 1]))
```

**这个骨架跑通，你就完成了"从 0 到 1"的第一步。**

### 五、从论文到选题

**"找 gap"的方法**：

| 方法 | 说明 |
|---|---|
| **看"Future Work"** | 作者自己指出的未来方向 |
| **看"Limitations"** | 论文的局限（往往是你的机会） |
| **看对比表** | 现有方法的不足 |
| **找"没人做过的组合"** | 方法 A + 场景 B |
| **质疑假设** | 论文的假设在现实中成立吗？ |

**"质疑假设"最容易出成果**：

```
论文假设：攻击者知道完整电网拓扑
你的疑问：如果不知道呢？（盲攻击）
→ 这就是一篇论文

论文假设：所有量测都是干净的
你的疑问：如果数据里有噪声和缺失呢？
→ 又是一篇论文
```
