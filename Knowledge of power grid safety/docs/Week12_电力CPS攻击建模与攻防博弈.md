## Day 82 · 09:00 —— 攻击建模的形式化：攻击者能力模型

> **一句话**：**好的攻击研究从"精确刻画攻击者能做什么"开始**——能力假设决定了结论是否有效。

### 一、为什么必须形式化

```
模糊表述：❌ "攻击者可以篡改量测数据"
        ↓ 问题：
  · 篡改几个？1 个还是全部？
  · 知道拓扑吗？
  · 知道负荷水平吗？
  · 能被发现吗？
        ↓
不同假设下结论**完全不同**
（完全信息 → 不可检测；部分信息 → 可检测）
```

> ⚠️ **审稿人最常问的问题就是**："你的攻击者假设合理吗？"
> 如果假设不合理（比如"攻击者知道一切"），**论文会被直接拒**。

### 二、攻击者能力模型的六个维度

| # | 维度 | 可选范围 |
|---|---|---|
| 1 | **知识** | 拓扑 $H$？权重 $W$？负荷 $x$？噪声 $\sigma$？ |
| 2 | **访问** | 能改哪些量测？能改几个（$k$ 个 / 全部）？ |
| 3 | **权限** | 只读？可写？可控制设备？ |
| 4 | **资源** | 计算能力、时间、预算 |
| 5 | **目标** | 隐蔽？破坏？经济获利？ |
| 6 | **持续性** | 单次攻击？持续渗透？ |

### 三、四类典型攻击者

| 类型 | 能力 | 现实性 | 典型手法 |
|---|---|---|---|
| **外部脚本小子** | 扫描 + 已知漏洞 | ⭐⭐⭐ 高 | 默认密码、未打补丁 |
| **有组织攻击者** | 定制工具、0day | ⭐⭐ 中 | 定向渗透 |
| **内部人** | **完全知识** | ⭐⭐ 中 | 合法权限滥用 |
| **国家级** | 供应链 + 长期潜伏 | ⭐ 低但影响大 | Stuxnet 级别 |

### 四、三类经典能力假设（按知识分级）

| 假设 | 攻击者知道什么 | 现实性 | 结论 |
|---|---|---|---|
| **完全信息** | $H$、$W$、$z$ 全知道 | ❌ 低 | 理想 FDIA 不可检测 |
| **部分信息** | 知道 $\hat{H}$（有误差）、不知道真实 $x$ | ✅ **高** | **会留下痕迹 → 可检测** |
| **无信息** | 只能盲试 | ⭐ 中 | 攻击效率低、易被发现 |

> 💡 **关键结论**：**"完全信息"假设虽然数学上漂亮，但现实中不成立**。
> **你的研究应该建立在"部分信息"假设上** —— 这既是现实，也是可发表的空间。

### 五、攻击模型的表述模板

$$\text{攻击者能力} = \langle \mathcal{K},\; \mathcal{A},\; \mathcal{G},\; \mathcal{C} \rangle$$

| 符号 | 含义 | 示例 |
|---|---|---|
| $\mathcal{K}$ | 知识（Knowledge） | "知道 $H$ 和 $W$，不知道真实负荷 $x$" |
| $\mathcal{A}$ | 访问（Access） | "能篡改任意 $k$ 个量测" |
| $\mathcal{G}$ | 目标（Goal） | "使状态估计偏移 $c$ 且不被 BDD 发现" |
| $\mathcal{C}$ | 约束（Constraint） | "残差 $r$ 的变化必须小于检测阈值" |

**完整表述示例**：
> "攻击者知道量测雅可比矩阵 $H$ 和权重矩阵 $W$，能任意篡改 $k$ 个量测值，
> 目标是在不被 BDD 检测（$\|r_a - r\| < \tau$）的前提下，使状态估计偏移 $c$。"

### 六、为什么假设决定结论（三个例子）

| 假设变化 | 结论变化 |
|---|---|
| 完全信息 → 部分信息 | 从"不可检测"变成"**可检测**" |
| 无物理约束 → 加物理约束 | 攻击空间被**压缩**，可行解减少 |
| 单次攻击 → 持续攻击 | 从"检测单点"变成"**检测时序异常**" |

### 七、写论文时的四条注意事项

| # | 注意事项 | 说明 |
|---|---|---|
| 1 | **明确写出假设** | 用数学符号，不要用自然语言含糊表述 |
| 2 | **论证假设的合理性** | 引用文献或给出现实依据 |
| 3 | **做敏感性分析** | 假设放松后结论还成立吗？ |
| 4 | **优先选弱假设** | **假设越弱，结论越强，越容易被接受** |

> 💡 **一条经验**：**如果你的方法在"弱假设"下也有效，那它就是好方法**。
> 反过来，只在"完全信息"下有效的方法，审稿人会质疑其实际价值。

### 🔗 与网安研究关联

| 要点 | 说明 |
|---|---|
| **攻击建模是研究的起点** | 没有清晰的能力模型，后面全是空谈 |
| **假设的合理性决定论文命运** | 这是审稿意见最常见的攻击点 |
| **建议方向** | 做"**更弱假设**"下的研究（更现实、更有价值） |
| **对接实验室方向** | 威胁建模 + 入侵检测（检测"弱假设攻击者"） |

> 💡 **选题灵感**：
> 「**拓扑信息不完整条件下的 FDIA 构造与检测**」
> - 现实：攻击者很难拿到**精确**的电网拓扑（属于保密信息）
> - 攻击侧：用 $\hat{H}$（有误差）构造攻击 → 会留下可检测的痕迹
> - 检测侧：**利用这种"攻击者的不完美"** 设计检测器
> - 优势：**假设更弱、更现实**，且有明确的研究空间

### 🔍 延伸思考

1. 如果攻击者只知道**部分拓扑**，攻击还能成功吗？会留下什么痕迹？
2. 如何**验证**"攻击者假设"的合理性？（能做实验吗？）

## Day 82 · 14:00 —— 从"能改什么"到"能造成什么后果"

> **一句话**：**攻击研究的价值不在于"能改数据"，而在于"能造成多大物理后果"**。

### 一、后果的三个层次

| 层次 | 后果 | 度量指标 | 攻击难度 |
|---|---|---|---|
| **数据层** | 状态估计错误 | 状态偏差 $\|c\|$ | 中 |
| **决策层** | 错误调度 | 成本增加 $\Delta C$ | 中高 |
| **物理层** | 过载 / 失稳 / 停电 | **负荷损失（MW）** | **高** |

> 💡 **注意难度递增**：**改数据容易，造成物理后果难**。
> 因为从"数据错误"到"物理后果"要经过**优化器、控制器、保护装置**多层"缓冲"。

### 二、从数据到物理的完整传导链

```
篡改量测 z
    ↓
状态估计偏移 x̂ → x̂ + c
    ↓
① 潮流计算用错误的状态
    ↓
② 调度决策（OPF/SCED）基于错误信息
    ↓
③ 实际控制指令与实际需求不匹配
    ↓
④ 真实潮流偏离预期
    ↓
⑤ 线路过载 / 电压越限
    ↓
⑥ 保护动作跳闸
    ↓
⑦ 潮流转移 → 连锁
    ↓
⑧ 停电
```

**每一层都会"衰减"攻击效果** —— 这是为什么"能改数据"≠"能停电"。

### 三、后果量化指标（五个常用）

| 指标 | 单位 | 说明 | 适用场景 |
|---|---|---|---|
| **负荷切除量** | MW | 最直观的物理后果 | 停电类 |
| **经济成本增加** | 元 / $ | 调度成本上升 | 市场类 |
| **线路过载数** | 条 | 多少条线路越限 | 安全类 |
| **稳定裕度下降** | % | 距失稳还有多远 | 稳定类 |
| **停电用户数** | 户 | 社会影响 | 综合 |

### 四、为什么后果量化如此重要

| 原因 | 说明 |
|---|---|
| **论文说服力** | "能造成 1200 MW 负荷损失"比"能改数据"有力得多 |
| **风险评估** | 后果 × 概率 = 风险，用于排优先级 |
| **防御资源分配** | 后果大的地方优先防护 |
| **政策依据** | 监管机构需要量化依据 |

### 五、后果量化的三种方法

| 方法 | 思路 | 优点 | 缺点 |
|---|---|---|---|
| **仿真法** | 用 pandapower / MATPOWER 跑潮流 | 直观、可信 | 只给一个场景 |
| **优化法** | 求"攻击者的最优策略"（最坏情况） | **给出上界** | 计算复杂 |
| **概率法** | 考虑不确定性，算期望损失 | 全面 | 需要分布假设 |

> 💡 **推荐组合**：**优化法求最坏情况 + 仿真法验证**。
> 优化给出"理论最坏"，仿真验证"实际可达"。

### 六、案例：LRA 的后果量化（完整示例）

| 层面 | 具体后果 | 度量 |
|---|---|---|
| **数据层** | 负荷分布错误（总负荷不变） | 分布偏差 |
| **决策层** | 机组组合次优 | 成本增加 3~8% |
| **物理层** | 局部线路负载上升 | 负载率 +10~30% |
| **极端情况** | 线路过载 → 跳闸 | 负荷损失 |

**量化方法（优化法）**：
$$\max_{a} \; \text{后果}(a) \quad \text{s.t.} \quad \begin{cases} Ma = 0 & \text{（不被 BDD 发现）} \\ \|a\|_0 \le k & \text{（最多改 } k \text{ 个量测）} \\ \text{物理约束} & \text{（潮流方程）} \end{cases}$$

### 七、研究建议

**把"攻击强度 → 物理后果"的定量关系做成图** —— 这张图就是你论文的**核心贡献**。

```
物理后果
（MW 损失）
    │
    │                    ╱ ← 攻击者能力增强
    │                 ╱
    │              ╱
    │           ╱
    │        ╱
    │     ╱
    │  ╱
    └──────────────────────────→ 攻击能力
                              （可篡改量测数 k）
```

**这类"后果曲线"比单个攻击案例有说服力得多。**

### 🔗 与网安研究关联

| 要点 | 说明 |
|---|---|
| **从"安全"到"韧性"的思维转变** | 不问"能不能攻破"，而问"攻破后损失多大" |
| **后果量化 = 风险评估的基础** | 这是政策制定者和工业界最关心的 |
| **对接实验室方向** | 工业AI（后果预测模型）+ 入侵检测（检测"后果导向"的攻击） |

### 🔍 延伸思考

1. 如何定义"**最坏情况**"？攻击者一定会选最优策略吗？（现实中受限于知识）
2. 后果量化需要什么工具？pandapower 能算到哪一层？

## Day 83 · 09:00 —— 隐蔽攻击的构造数学：$\mathrm{col}(H)$ 与不可观测子空间

> **一句话**：**隐蔽攻击的构造本质是一个线性代数问题**——找到落在 $\mathrm{col}(H)$ 里的攻击向量。

### 一、问题重述（三条件）

攻击者要找一个非零攻击向量 $a$，满足：

| # | 条件 | 数学表述 |
|---|---|---|
| 1 | **有效**（真的能改变状态） | 存在 $c \ne 0$ 使 $a = Hc$ |
| 2 | **隐蔽**（BDD 看不到） | $Ma = 0$ |
| 3 | **有害**（后果显著） | $\|c\|$ 大 / 后果量化值高 |

### 二、核心等价关系（必须记住）

$$\boxed{Ma = 0 \iff a \in \mathrm{col}(H)}$$

**为什么？** 因为 $M = I - H(H^TWH)^{-1}H^TW$ 恰好是**投影到 $\mathrm{col}(H)$ 正交补**的投影算子。

**验证**（若 $a = Hc$）：
$$Ma = (I - H(H^TWH)^{-1}H^TW)Hc = Hc - H\underbrace{(H^TWH)^{-1}H^TWH}_{I}c = Hc - Hc = 0 \;\checkmark$$

> 💡 **这一行推导就是整个 FDIA 理论的基石**。
> **攻击向量只要落在 $H$ 的列空间里，就对 BDD 完全隐身。**

### 三、攻击构造的四步流程

```
第 1 步：选目标 c（想让状态偏移多少）
    → 例如 c 中某几个分量为大值（对应关键母线）
        ↓
第 2 步：计算 a = Hc
    → 线性代数，一步搞定
        ↓
第 3 步：检查 ||a||（攻击量是否"物理合理"）
    → 如果 ||a|| 巨大 → 量测值会离谱 → 操作员肉眼可见
        ↓
第 4 步：检查物理可行性
    → 篡改后的量测是否满足潮流方程？（Day 84 会讲）
```

### 四、不可观测子空间

| 概念 | 定义 | 维度 |
|---|---|---|
| **$\mathrm{col}(H)$** | **不可观测子空间**（攻击的"隐身空间"） | $n$ |
| **$\mathrm{col}(H)^\perp$** | **可观测子空间**（BDD 的"视野"） | $m - n$ |

```
量测空间 R^m
┌────────────────────────────────────────┐
│                                        │
│   col(H)  ← n 维                       │
│   【不可观测子空间】                    │
│   攻击向量 a 藏在这里 → BDD 看不到 ✅   │
│                                        │
│   ┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈    │
│                                        │
│   col(H)^⊥  ← m-n 维                   │
│   【可观测子空间】                      │
│   BDD 只能看到这里 ❌（攻击者不会来）    │
│                                        │
└────────────────────────────────────────┘
```

### 五、BDD 的真实检测能力（重新理解）

$$r = Mz$$

**BDD 只能看到 $z$ 在 $\mathrm{col}(H)^\perp$ 上的分量**。
攻击者只要让自己的改动**完全落在 $\mathrm{col}(H)$ 里**，就完全隐身。

| 攻击向量的位置 | BDD 能否检测 |
|---|---|
| 完全在 $\mathrm{col}(H)$ 内 | ❌ **不能** |
| 完全在 $\mathrm{col}(H)^\perp$ 内 | ✅ 能（最容易被发现） |
| 混合（部分在两边） | ⚠️ **能检测到"泄露"的部分** |

> 💡 **关键洞察**：**现实攻击者的 $a$ 几乎总是"混合"的** ——
> 因为他们不知道精确的 $H$、只能改部分量测。
> **"泄露到可观测子空间的那部分"就是检测的机会。**

### 六、现实约束下的构造（真实问题）

| 现实约束 | 后果 |
|---|---|
| **只能改 $k$ 个量测**（稀疏） | 需要解组合优化 |
| **不知道精确 $H$**（用 $\hat{H}$） | $a = \hat{H}c \notin \mathrm{col}(H)$ → **泄露** |
| **不知道 $W$** | 无法保证 $Ma = 0$ |
| **量测值必须"看起来合理"** | $\|a\|$ 受限 |

### 七、从数学到现实：一张对照表

| 理想情况 | 现实情况 |
|---|---|
| $a = Hc$，完美隐身 | $a \approx \hat{H}c$，有泄露 |
| 全量测可改 | 只能改 $k$ 个 |
| 知道一切 | 只知道部分 |
| **结论：不可检测** | **结论：可检测（利用泄露）** |

### 🔗 与网安研究关联

| 要点 | 说明 |
|---|---|
| **这是 FDIA 的数学核心** | 理解 $\mathrm{col}(H)$ 就理解了 FDIA 的本质 |
| **"泄露"是检测的立足点** | 所有可行的检测方法都在利用"攻击者的不完美" |
| **与你已做的实验对应** | `code/fdia_minimal.py` 用三个情形验证了这一点 |
| **对接实验室方向** | 入侵检测（利用泄露）+ AI与数据安全（低质量信息下的推断） |

### 🔍 延伸思考

1. 如果状态维数 $n$ 很大（如 1000 节点电网），攻击向量 $a = Hc$ 会怎样？（稠密还是稀疏？）
2. 为什么"**稀疏攻击**"比"稠密攻击"更难检测？（提示：从"泄露"的角度想）

## Day 83 · 14:00 —— 稀疏攻击与最小攻击集

> **一句话**：**真实攻击者不想改 100 个量测**——他想用最少的改动达到目的，这就是稀疏攻击问题。

### 一、为什么关注稀疏性

| 原因 | 说明 |
|---|---|
| **隐蔽性** | 改得越少，越不容易被统计方法发现 |
| **成本** | 需要访问的量测点越少，攻击越容易实施 |
| **现实性** | 攻击者通常只能访问**部分**量测 |
| **破坏力** | 少量改动造成大后果 = **高杠杆** |

### 二、稀疏攻击问题的定义

$$\min_{a,\,c} \; \|a\|_0 \quad \text{s.t.} \quad \begin{cases} a = Hc \\ c \ne 0 \\ \text{（可选）}\|c\| \ge c_{\min} \end{cases}$$

| 符号 | 含义 |
|---|---|
| $\|a\|_0$ | $a$ 中**非零元素个数**（即需要篡改的量测数） |
| $a = Hc$ | 隐蔽性约束（落在 $\mathrm{col}(H)$） |
| $c \ne 0$ | 有效性约束 |

> ⚠️ **这是一个 NP-hard 问题**（$\ell_0$ 范数最小化是组合优化）。

### 三、求解方法

| 方法 | 思路 | 优点 | 缺点 |
|---|---|---|---|
| **贪心算法** | 逐步选择"性价比最高"的量测 | 快 | 不保证最优 |
| **凸松弛（$\ell_1$ 替代 $\ell_0$）** | 用 L1 范数近似 L0 | 可多项式求解 | 解不一定稀疏 |
| **组合枚举** | 小规模时穷举 | 精确 | 指数复杂度 |
| **启发式（GA/PSO）** | 遗传算法等 | 灵活 | 无最优性保证 |

> 💡 **注意 $\ell_1$ 松弛的陷阱**：
> $\ell_1$ 最小化**不保证**给出最稀疏解（不像压缩感知有严格条件）。
> 论文里要**明确说明**这一点。

### 四、最小攻击集（Minimum Attack Set）

| 概念 | 定义 | 用途 |
|---|---|---|
| **最小攻击集** | 能实现隐蔽攻击的**最小量测集合** | 攻击者的"最优目标清单" |
| **最小稀疏度 $k_{\min}$** | 最小的 $k$ 使得 $k$-稀疏攻击可行 | 衡量电网脆弱性 |

**$k_{\min}$ 是电网脆弱性的一个**量化指标** —— $k_{\min}$ 越小，电网越脆弱。

### 五、$k_{\min}$ 与拓扑的关系

| 网络特征 | $k_{\min}$ | 脆弱性 |
|---|---|---|
| **稀疏网络**（连接少） | **小** | 高（少数点即可攻破） |
| **密集网络**（连接多） | 大 | 低 |
| 有**关键节点** | 小 | 高 |
| 高度**冗余量测** | 大 | 低 |

> 💡 **反直觉的结论**：
> **电网的"稀疏性"既是效率优势，也是安全劣势**。
> 稀疏网络用更少的线路传输同样功率（经济），
> 但也意味着**更少的冗余** → 攻击者用更少的改动就能造成影响。

### 六、从攻击到防御：传感器保护问题

**防御方的问题**：
> 如果只能保护 $p$ 个量测（加认证 / 加冗余），应该保护哪些才能阻止所有 $k$-稀疏攻击？

$$\min_{S,\; |S| \le p} \; \text{（剩余可被攻击的脆弱性）}$$

| 策略 | 思路 |
|---|---|
| **保护关键量测** | 保护那些"去掉就不可观测"的量测 |
| **最大化攻击成本** | 让攻击者需要改更多量测 |
| **图论方法** | 用网络的割集/支配集性质 |

**这是一个经典的"资源受限防御优化"问题** —— 也是很好的选题方向。

### 七、完整的攻防对照表

| 环节 | 攻击者视角 | 防御者视角 |
|---|---|---|
| **目标** | 最小化 $\|a\|_0$ | 最大化攻击者的 $k_{\min}$ |
| **约束** | $Ma = 0$ | 保护 $p$ 个量测 |
| **优化问题** | $\min \|a\|_0$ s.t. $a=Hc$ | $\min$ 脆弱性 s.t. $\|S\| \le p$ |
| **难点** | NP-hard | NP-hard |
| **工具** | 凸松弛、贪心 | 图论、博弈论 |

### 🔗 与网安研究关联

| 要点 | 说明 |
|---|---|
| **稀疏攻击是最现实的攻击模型** | 论文里优先用这个假设（比"全量测"现实） |
| **"传感器保护问题"是经典防御问题** | 有大量文献，但也有新空间（如加物理约束） |
| **$k_{\min}$ 可作为脆弱性指标** | 可做"电网脆弱性评估"类论文 |
| **对接实验室方向** | **工业AI**（用 GNN 估计 $k_{\min}$）+ 入侵检测 |

> 💡 **一个很有潜力的选题**：
> 「**基于图神经网络的最小攻击集快速估计**」
> - **痛点**：传统方法要反复做秩计算（$O(m)$ 次 SVD），**大电网算不动**
> - **你的方法**：用 GNN 直接从**拓扑图**预测"哪些量测最关键"
> - **优势**：
>   - **加速比可量化**（GNN 推断 ms 级 vs 传统方法分钟级）
>   - **泛化性可测**（在 IEEE 14/39/118 上训练测试）
>   - **创新点清晰**（首次用图学习做脆弱性评估）
>   - **与你的 FDIA+GNN 方向一脉相承**

2. 如何用**图结构**快速估计最小 $k$？（提示：想想割集和连通性）

## Day 84 · 09:00 —— 物理约束攻击：绕过物理规律校验

> **一句话**：**当检测器开始用"物理规律"筛数据时，攻击者就必须让假数据"物理自洽"**——这让攻击难度大幅上升。

### 一、什么是物理约束校验

检测思路的升级：**不只看残差，还看数据是否符合物理规律**。

| 物理约束 | 内容 | 检测什么 |
|---|---|---|
| **潮流方程** | $z$ 必须与某个 $x$ 满足 $z = Hx$ | 数据与模型一致性 |
| **基尔霍夫定律** | KCL / KVL | 拓扑一致性 |
| **功率平衡** | $\sum P_{gen} = \sum P_{load} + P_{loss}$ | 总量守恒 |
| **变化率约束** | 物理量不能突变 | 时间连续性 |
| **量程约束** | 不能超出设备量程 | 物理可行性 |

### 二、为什么物理约束有用

```
BDD 检查的是：统计一致性（残差大小）
        ↓ 与
物理约束检查的是：物理可行性
        ↓
两者**独立**（一个统计、一个物理）
        ↓
组合起来 → 检测能力显著增强
```

> 💡 **这是电网安全区别于一般 IT 安全的核心优势**：
> **电网有"物理规律"这个额外的、攻击者无法违背的信息源。**
> IT 系统里没有这种"硬约束"。

### 三、攻击者面对的三重约束

$$\begin{cases} \text{① } Ma = 0 & \text{（统计隐身）} \\ \text{② 物理自洽} & \text{（通过物理校验）} \\ \text{③ 后果显著} & \text{（攻击有价值）} \end{cases}$$

**三重约束同时满足 → 可行域大幅缩小 → 攻击更难。**

### 四、物理约束下的攻击构造

```
原来（只有 BDD）：
    可行域 = col(H)（n 维子空间）
        ↓ 加物理约束
现在：
    可行域 = col(H) ∩ {物理可行集}
        ↓
可行域变小 → 可能需要：
    · 篡改更多量测
    · 或放弃部分攻击目标
    · 或让攻击效果减弱
```

### 五、具体例子 ①：功率平衡约束

**如果检测器检查** $\sum P_{gen} = \sum P_{load} + P_{loss}$：

```
攻击者必须保持总量不变
        ↓
不能简单地"增大所有负荷"
        ↓
必须"把负荷从一处搬到另一处"
        ↓
这就是 LRA（负荷重分配攻击）的由来！
```

> 💡 **一个重要的认知**：**LRA 不是"聪明"的设计，而是"被迫"的产物** ——
> 因为总量守恒是**硬约束**，攻击者只能"重分配"。

### 六、具体例子 ②：变化率约束

**如果检测器检查** $|z(t) - z(t-1)| < \varepsilon$：

```
攻击者不能一次性注入全部 a
        ↓
必须"渐进式"篡改：每次只改一点点
        ↓
攻击被拉长（从瞬时变成持续数小时）
        ↓
后果：
  ✅ 每个时刻的变化都合法（骗过变化率检测）
  ❌ 但**时间窗口变长** → 时序方法有机会发现
```

> 💡 **这引出了一个核心的攻防权衡**：
> ```
> 攻击"快" → 容易被变化率/统计检测抓到
> 攻击"慢" → 每个时刻都合法，但累积过程留下时序痕迹
> ```
> **"多慢才安全"是一个可以量化的研究问题。**

### 七、攻防螺旋（完整的军备竞赛）

| 阶段 | 攻击方 | 防御方 |
|---|---|---|
| 1 | $a = Hc$ 绕过 BDD | BDD（残差检验） |
| 2 | **稀疏攻击**（少改几个） | 统计检测（分布异常） |
| 3 | **物理自洽攻击**（满足潮流方程） | **物理约束校验** |
| 4 | **渐进攻击**（慢慢改） | **时序检测** |
| 5 | **长期潜伏攻击**（伪装成正常趋势） | **长期趋势分析 / 基线漂移检测** |
| 6 | ？ | ？ |

> 💡 **第 5~6 阶段就是当前的研究前沿**。
> **注意：每一轮防御都会引出新的攻击，这就是安全研究的本质。**

### 八、研究机会

| 方向 | 说明 | 新意 |
|---|---|---|
| **物理约束 + 时序联合检测** | 当前热点 | ★★★★ |
| **物理约束下的攻击构造** | 攻击侧（较难） | ★★★ |
| **物理约束的假阳性研究** | 实际部署的关键问题 | ★★★ |

> 💡 **一个很好的选题**：
> 「**物理约束与数据驱动联合的 FDIA 检测：以潮流一致性为硬约束**」
> - **思路**：把"潮流方程"作为**硬约束**嵌入检测器
>   - 数据驱动部分：学"正常数据的分布"

## Day 84 · 14:00 —— 拓扑攻击与开关状态篡改

> **一句话**：**攻击者不篡改量测，而是篡改"电网的结构信息"**——这比篡改数据更隐蔽、更致命。

### 一、拓扑信息在状态估计中的作用

```
开关状态（断路器/隔离开关位置）
        ↓ 决定
电网拓扑（哪些节点相连）
        ↓ 决定
H 矩阵的结构
        ↓ 决定
状态估计的"世界观"
```

> ⚠️ **关键**：**拓扑错了，$H$ 就错了，整个状态估计就是错的** ——
> 而且**用错误的 $H$ 去检验数据，残差反而可能"看起来正常"**。

### 二、拓扑篡改的三种方式

| 方式 | 手段 | 需要什么权限 |
|---|---|---|
| **篡改开关遥信** | 谎报开关位置（实际合、报分） | 通信访问 |
| **篡改系统配置** | 让 EMS 用错误的拓扑模型 | 系统权限 |
| **物理操作开关** | 真实改变拓扑 | **物理接触/控制权限** |

### 三、为什么拓扑攻击更危险

| 特点 | 说明 |
|---|---|
| **隐蔽** | 只改几个开关状态（数据量小） |
| **影响大** | 整个 $H$ 矩阵变化 → 全局影响 |
| **检测难** | 与"真实的开关操作"**难以区分** |
| **持续性** | 可以长期潜伏（拓扑不常变） |

### 四、拓扑攻击的数学（一个关键矛盾）

**真实情况**：$z = H_{\text{true}}\,x + e$
**系统假设**：$z = H_{\text{false}}\,x + e$（因为拓扑被篡改）

系统用错误的 $H_{\text{false}}$ 做估计：
$$\hat{x} = (H_{\text{false}}^TWH_{\text{false}})^{-1}H_{\text{false}}^TWz$$

残差：
$$r = z - H_{\text{false}}\hat{x} = M_{\text{false}}\,z$$

> ⚠️ **这里有个关键问题**：因为 $H_{\text{false}} \ne H_{\text{true}}$，
> **残差通常会异常** → **单纯拓扑攻击容易被 BDD 发现**。

### 五、但攻击者可以补偿（组合攻击）

```
第 1 步：篡改开关状态 → 系统用 H_false
        ↓
第 2 步：基于 H_false 构造 FDIA：
        注入 a = H_false · c
        ↓
第 3 步：残差 r = M_false(z + a) = M_false · z
        （因为 M_false · H_false · c = 0）
        ↓
✅ 残差看起来正常！
```

**这就是"拓扑 + FDIA"组合攻击** —— 威力远大于单一攻击。

| 攻击组合 | 残差表现 | 检测难度 |
|---|---|---|
| 单纯拓扑攻击 | 异常 | 中 |
| 单纯 FDIA | 正常（若知道真 $H$） | 高 |
| **拓扑 + FDIA** | **正常** | **极高** |

### 六、为什么组合攻击这么强

```
攻击者不需要知道真实的 H 了！
        ↓
他只需要：
  ① 篡改拓扑（让系统用 H_false）
  ② 基于 H_false 构造攻击
        ↓
两个操作都在他"能看见"的信息范围内完成
        ↓
✅ 绕过了"攻击者不知道精确拓扑"这个限制！
```

> 💡 **这是一个非常重要的洞察**：
> **拓扑攻击"消灭"了攻击者最大的障碍（不知道精确 $H$）**。
> 所以它是"弱假设攻击者"实现"强攻击效果"的**关键跳板**。

### 七、检测思路

| 方法 | 原理 | 局限 |
|---|---|---|
| **拓扑校验** | 用开关状态独立验证 $H$ | 开关状态本身可能被篡改 |
| **多源交叉验证** | 量测与拓扑互相验证 | 需要冗余信息 |
| **历史比对** | 拓扑变化是否符合操作计划 | 需要工单系统对接 |
| **数据驱动拓扑辨识** | **从量测反推真实拓扑** ⭐ | 需要足够量测 |
| **图学习** | 用 GNN 同时建模拓扑与数据 | **研究热点** ⭐ |

### 八、研究机会

| 方向 | 说明 | 新意 |
|---|---|---|
| **拓扑-数据联合攻击检测** | 同时检测两类篡改 | ★★★★★ |

> 「**拓扑信息不可靠条件下的 FDIA 检测：基于图结构学习的鲁棒方法**」

## Day 85 · 09:00 —— 负荷重分配攻击（LRA）深化与求解

> **一句话**：**LRA 是"保持总量不变、只重分配负荷"的攻击**——它能精确操控电力市场出清结果。

### 一、LRA 的核心思路回顾

```
篡改负荷量测 z_d
        ↓
但保持 1ᵀa_d = 0（总量不变）
        ↓
状态估计"看起来正常"
        ↓
SCED 用错误的负荷分布优化
        ↓
出清结果偏向攻击者
```

> 💡 **为什么必须保持总量不变？**
> 因为**功率平衡是物理硬约束**（Day 84）。
> 总量变了 → 与发电量不匹配 → **残差异常 → 被发现**。
> **所以"重分配"不是设计选择，而是被迫的。**

### 二、LRA 的数学建模

**攻击者的优化问题**：
$$\max_{a_d} \; \text{收益}\big(\text{SCED}(z_d + a_d)\big) \quad \text{s.t.} \quad \mathbf{1}^T a_d = 0,\; \|a_d\|_0 \le k$$

| 符号 | 含义 |
|---|---|
| $a_d$ | 注入的负荷篡改量 |
| $\mathbf{1}^T a_d = 0$ | **总量守恒约束** |
| $\|a_d\|_0 \le k$ | 稀疏性约束（只能改 $k$ 个负荷点） |
| $\text{SCED}(\cdot)$ | 市场出清过程（**下层问题**） |

### 三、LRA 的三种攻击目标

| 目标 | 攻击者身份 | 手段 |
|---|---|---|
| **抬高电价** | 发电商 | 让调度以为某区域缺电 |
| **降低购电成本** | 大用户 | 让调度以为某区域电多 |
| **制造阻塞** | 套利者 | 让调度误判线路阻塞 → LMP 差扩大 |

### 四、求解的核心难点：双层优化

```
┌─────────────────────────────────────┐
│  上层：攻击者决策                     │
│  变量：a_d（篡改量）                  │
│  目标：最大化自己的收益                │
└──────────────┬──────────────────────┘
               │ 把 a_d 传给下层
               ↓
┌─────────────────────────────────────┐
│  下层：市场出清（SCED）               │
│  变量：机组出力 P、电价 λ             │
│  目标：最小化系统成本                  │
└──────────────┬──────────────────────┘
               │ 返回出清结果
               ↓
        上层据此计算收益
```

**这是一个 leader-follower（Stackelberg）博弈问题**。

### 五、求解方法

| 方法 | 思路 | 优缺点 |
|---|---|---|
| **KKT 替换** | 用下层的 KKT 条件替换下层问题 | 变成**单层 MPEC**，但引入**互补约束**（非线性） |
| **MILP 重构** | 用大 M 法把互补约束线性化 | 可精确求解，但规模大 |
| **启发式搜索** | 遗传算法、模拟退火 | 灵活但无最优性保证 |
| **对角化** | 迭代求解上下层 | 简单，但可能不收敛 |

> 💡 **MPEC = Mathematical Program with Equilibrium Constraints**
> （带平衡约束的数学规划）—— 这是双层优化的标准转化形式。
> **如果你要做 LRA 方向，这是必须掌握的数学工具。**

### 六、LRA 的变体（研究空间）

| 变体 | 特点 | 难度 |
|---|---|---|
| **单时段 LRA** | 基础版本 | 低 |
| **多时段 LRA** | 更现实（考虑机组启停、储能） | 中 |
| **含储能的 LRA** | 增加决策变量 | 中高 |
| **含新能源的 LRA** | 不确定性叠加 | 高 |
| **协同 LRA** | 多个攻击者合作 | 高 |

### 七、检测思路

| 思路 | 原理 | 难点 |
|---|---|---|
| **负荷预测偏差** | 实测量测 vs 预测值 | 预测本身就有误差 |
| **出清结果合理性** | 检查是否存在更优解 | 需要知道真实成本 |
| **多时段一致性** | 负荷分布是否长期异常 | 需要历史基线 |
| **总负荷校验** | 检查总量是否守恒 | LRA 已保持守恒 |
| **空间相关性** | 相邻负荷点的变化是否同步 | **GNN 的用武之地** ⭐ |

### 🔗 与网安研究关联

| 要点 | 说明 |
|---|---|
| **LRA 是"经济动机攻击"的典型** | 攻击者有明确获利目标 |
| **双层优化是攻击建模的重要工具** | 可迁移到其他 CPS 场景 |
| **与博弈论天然结合** | Stackelberg 博弈 |
| **对接实验室方向** | **工业AI**（出清结果异常检测）+ 入侵检测 |

> 💡 **一个高价值选题**：
> 「**基于空间相关性的 LRA 检测：负荷数据的图结构异常**」
> - **洞察**：真实负荷在**空间上强相关**（同区域天气相同、作息相似）
> - **攻击**：LRA 为了改变总量分布，必然**破坏这种空间相关性**
> - **方法**：用 GNN 学习"正常负荷的空间相关模式"，检测偏离
> - **优势**：**利用了物理/统计先验**（不是纯数据驱动）、**可解释**、**与你的 GNN 方向契合**

## Day 85 · 14:00 —— 攻击的经济后果量化

> **一句话**：**把"攻击能改数据"翻译成"攻击能造成多少钱的损失"**——这是说服审稿人和工业界的关键。

### 一、为什么经济量化如此重要

| 受众 | 关心什么 | 量化能回答 |
|---|---|---|
| **审稿人** | 方法有实际价值吗 | "能造成 X 万元损失" |
| **电网公司** | 会损失多少钱 | 直接的经济数字 |
| **监管机构** | 风险有多大 | 风险排序依据 |
| **政策制定者** | 是否值得投入防御 | 成本-收益分析 |

### 二、经济后果的四个层次

| 层次 | 内容 | 度量 | 时间尺度 |
|---|---|---|---|
| **直接** | 调度成本增加 | 元/小时 | 即时 |
| **间接** | 设备加速老化 / 损坏 | 元 | 月~年 |
| **社会** | 停电损失 | 元/(户·小时) | 即时 |
| **长期** | 市场信任下降 | 难量化 | 年 |

### 三、调度成本增加的量化

$$\Delta C = C_1 - C_0$$

| 符号 | 含义 |
|---|---|
| $C_0$ | 无攻击时的最优调度成本 |
| $C_1$ | 攻击后的实际调度成本 |

**通常表示为百分比**：$\Delta C / C_0 \times 100\%$

### 四、停电损失的量化：VOLL

**VOLL（Value of Lost Load，停电损失价值）**：

$$\text{停电损失} = \text{VOLL} \times \text{缺供电量（kWh）}$$

| 用户类型 | 典型 VOLL | 说明 |
|---|---|---|
| 居民 | 10 ~ 30 元/kWh | 主要是生活不便 |
| 商业 | 30 ~ 100 元/kWh | 营业损失 |
| **工业** | **100 ~ 300 元/kWh** | 生产中断、设备损坏 |

> ⚠️ **注意**：VOLL 的取值**争议很大**，不同文献差 10 倍以上。
> **论文里必须说明取值来源**，并做**敏感性分析**。

### 五、一个完整的量化示例

**场景**：攻击者篡改 5% 的负荷数据（保持总量不变）

| 步骤 | 计算 | 结果 |
|---|---|---|
| ① 基线成本 | 系统日调度成本 | 1000 万元/天 |
| ② 攻击后成本 | 求解 SCED | 1040 万元/天 |
| ③ 直接损失 | $\Delta C$ | **40 万元/天** |
| ④ 年化损失 | $40 \times 365$ | **1.46 亿元/年** |
| ⑤ 若引发过载停电 | 假设 500 MW × 2 小时 | 1000 MWh |
| ⑥ 停电损失 | $1000 \times 200$ 元 | **20 万元** |

**结论**：**攻击的经济后果可以达到"亿元/年"量级** —— 这个数字有说服力。

### 六、其他经济后果的量化

| 后果 | 量化方法 | 难点 |
|---|---|---|
| **设备寿命损耗** | 加速老化模型（温度/电流积分） | 需要设备模型 |
| **备用成本** | 备用容量市场价格 | 数据可得 |
| **碳排放** | 碳价 × 增加的排放量 | 需算排放 |
| **市场效率** | 社会福利损失（消费者剩余 + 生产者剩余） | 需要需求曲线 |

### 七、实操五步法

```
① 建立基线场景（无攻击）
    → 用 pandapower / MATPOWER 求解最优潮流
        ↓
② 注入攻击（如 LRA）
    → 篡改负荷数据，重新求解
        ↓
③ 对比成本
    → ΔC = C1 - C0
        ↓
④ 敏感性分析
    → 攻击强度 vs 经济损失（画曲线）
        ↓
⑤ 给出典型场景的具体数字
    → "攻击者改 5% 负荷 → 年损失 1.46 亿元"
```

### 八、论文中如何呈现

**最好的呈现方式是一条曲线**：

```
经济损失
（万元/天）
    │
 60 ┤                        ╱
    │                     ╱
 40 ┤                  ╱
    │               ╱
 20 ┤            ╱
    │         ╱
  0 ┤──────╱────────────────────────→
    0    1%   2%   3%   4%   5%
              攻击强度（篡改比例）
```

**这条"攻击强度 - 经济损失"曲线，比任何文字描述都有说服力。**

### 🔗 与网安研究关联

| 要点 | 说明 |
|---|---|
| **经济量化让研究"接地气"** | 工业界最关心这个 |
| **是"风险评估"的核心** | 后果 × 概率 = 风险 |
| **可论证防御投入的合理性** | "花 100 万防御，避免 1.46 亿损失" |
| **对接实验室方向** | **工业AI**（成本预测模型）+ 入侵检测 |

> 💡 **一个容易出成果的选题**：
> 「**电力市场数据攻击的经济后果量化框架**」
> - 现有工作多关注"能不能攻击成功"，很少系统量化"**损失多少**"

> - **优势**：**工程价值高、易于被工业界引用**、可与电网公司合作

## Day 86 · 09:00 —— 时间同步与 GPS 欺骗攻击深化

> **一句话**：**PMU 依赖 GPS 授时，而 GPS 信号可以被欺骗**——攻击者能让全网的"时间"错位。

### 一、为什么电力系统需要精确时间

| 应用 | 精度要求 | 失准后果 |
|---|---|---|
| **SOE 事件顺序记录** | 1 ms | 事件顺序错乱，事故分析失效 |
| **PMU 同步相量** | **1 μs** | 相角全错，状态估计失效 |
| **行波测距** | 0.1 μs | 故障定位失准 |
| **线路差动保护** | 100 μs | **保护误动/拒动** |

> 💡 **注意差动保护**：它靠比较**两端电流的相位**判断故障。
> 如果两端时钟不同步 → **相位差虚假** → 保护误判。

### 二、GPS 授时的原理

```
GPS 卫星（原子钟）广播时间信号
        ↓
接收机解算位置 + 时间
        ↓
输出两种信号：
  ① PPS（秒脉冲）—— 硬件同步信号
  ② IRIG-B —— 时间码（含年月日时分秒）
        ↓
PMU / 保护装置 / 故障录波器 使用
```

### 三、三种 GPS 攻击方式

| 类型 | 手段 | 难度 | 可检测性 |
|---|---|---|---|
| **压制（Jamming）** | 用强噪声淹没 GPS 信号 | **低** | 高（信号丢失可见） |
| **欺骗（Spoofing）** | 发送伪造的 GPS 信号 | **高** | **低**（看似正常） |
| **重放** | 重放历史 GPS 信号 | 中 | 中 |

> ⚠️ **欺骗比压制危险得多**：
> 压制会让设备**发现信号丢失**（然后切换到备用授时）；
> 欺骗让设备**以为一切正常**，但时间是错的。

### 四、GPS 欺骗的技术难点

| 难点 | 说明 |
|---|---|
| **同步** | 必须与真实信号同步（否则接收机检测到跳变） |
| **功率匹配** | 信号强度要略高于真实信号（不能太强） |
| **多星模拟** | 接收机同时跟踪多颗卫星，需要同时欺骗 |
| **时间渐进** | 时间偏移必须**缓慢**（突然跳变会被发现） |

> 💡 **"缓慢偏移"是关键手法** ——
> 每次只偏移几微秒，慢慢累积。**这和 Day 84 的"渐进攻击"是同一思路。**

### 五、欺骗的后果

| 后果 | 说明 | 影响范围 |
|---|---|---|
| **相量错位** | 所有 PMU 相角偏移 | 全网 |
| **状态估计失效** | 用错误相角做估计 | 全网 |
| **保护误动** | 差动保护算错相位差 | 局部但危险 |
| **事件分析失效** | SOE 时标错乱 | **事后无法追责** |

> ⚠️ **"事件分析失效"特别隐蔽**：
> 攻击结束后，**故障录波的时间戳是错的** →
> 事后调查**无法还原真实的事故过程** → **攻击者可以逃脱追责**。

### 六、其他授时方式与风险

| 方式 | 精度 | 风险 |
|---|---|---|
| **GPS** | 1 μs | 欺骗、压制 |
| **北斗** | 1 μs | 同上（但系统独立，双系统可互验） |
| **地面授时（SDH/光纤）** | 1 ms | 依赖通信网 |
| **本地晶振（铷钟/铯钟）** | 高但会漂移 | 长期漂移 |

> 💡 **多源授时是最有效的防御** ——
> GPS + 北斗 + 地面授时**互相校验**，任何一路异常都能被发现。

### 七、防御手段

| 手段 | 原理 | 局限 |
|---|---|---|
| **多源授时** | 多系统互验 | 成本高 |
| **信号认证** | 验证信号来源 | **GPS 民用信号无认证** |
| **异常检测** | 监测时间跳变 | 渐进偏移难发现 |
| **抗欺骗天线** | 抑制伪造信号方向 | 成本高 |
| **本地高精度时钟** | 短期保持 | 长期漂移 |

### 八、研究机会

| 方向 | 说明 | 难度 |
|---|---|---|
| **时间同步攻击检测** | 多源比对 + 统计检验 | 中 |
| **渐进偏移检测** | 检测缓慢累积的时间误差 | **高**（难） |
| **PMU 数据质量评估** | 识别不可信的 PMU | 中 |
| **时间攻击的后果量化** | 对保护的影响 | 中 |

> 💡 **一个有意思的选题**：
> 「**面向渐进式 GPS 欺骗的 PMU 时间完整性检测**」
> - **攻击**：缓慢偏移（每小时几微秒），单次检测无法发现
> - **检测**：利用**多个 PMU 之间的相对时间一致性**
>   - 如果攻击者只欺骗了部分 PMU → **相对时间差异异常**
>   - 如果欺骗了全部 → 需要与"非 GPS 授时源"比对
> - **创新点**：把"时间一致性"作为图上的约束（PMU 是节点）
> - **契合方向**：时序异常检测 + 图方法

## Day 86 · 14:00 —— 协同攻击与多阶段攻击

> **一句话**：**单个攻击容易被检测，但多个攻击者（或多阶段）协同，检测难度呈指数上升**。

### 一、为什么必须研究协同攻击

```
现实中的攻击不是"单点"事件
        ↓
而是"战役"：侦察 → 渗透 → 潜伏 → 行动 → 撤退
        ↓
APT（高级持续性威胁）就是典型
        ↓
单点检测方法在这里完全失效
```

### 二、协同攻击的两种形式

| 形式 | 说明 | 例子 |
|---|---|---|
| **多攻击者协同** | 多个攻击者**同时**行动 | 分布式 FDIA |
| **多阶段协同** | 一个攻击者的**多步**攻击 | APT 攻击链 |

### 三、多阶段攻击链（7 阶段）

| 阶段 | 行动 | 可检测信号 | 检测难度 |
|---|---|---|---|
| **① 侦察** | 扫描拓扑、端口 | 扫描流量 | ⭐ 低 |
| **② 初始访问** | 钓鱼、漏洞利用 | 异常登录 | ⭐⭐ 中 |
| **③ 建立据点** | 植入后门 | 外连流量 | ⭐⭐ 中 |
| **④ 横向移动** | 内部扩散 | 内部流量异常 | ⭐⭐⭐ 中高 |
| **⑤ 权限提升** | 拿到高权限 | 提权日志 | ⭐⭐⭐ 中高 |
| **⑥ 目标行动** | **注入 FDIA** | **数据异常** | ⭐⭐⭐⭐ 高 |
| **⑦ 维持与清除** | 保持访问、抹痕迹 | 后门心跳 | ⭐⭐⭐⭐ 高 |

> 💡 **注意**：**越靠后的阶段越难检测**（因为攻击者越谨慎）。

### 四、协同攻击的四大优势

| 优势 | 说明 |
|---|---|
| **分散** | 每个攻击者只改一小部分 → 单点异常不明显 |
| **同步** | 同一时刻发作 → 造成叠加后果 |
| **互补** | 互相掩护（一处攻击吸引注意，另一处下手） |
| **隐蔽** | 难以归因（不知道是谁、有几个） |

### 五、协同 FDIA 的数学

**多个攻击者各自篡改一部分量测**：

$$a = a^{(1)} + a^{(2)} + \cdots + a^{(N)} = Hc$$

| 特点 | 说明 |
|---|---|
| **联合约束** | 总效果满足 $a = Hc$ |
| **个体约束** | 每个攻击者只看自己那部分 |
| **隐蔽性** | 单个攻击者的改动**可能完全无害** |
| **检测难点** | 单点检测器看到的是"正常的小波动" |

> ⚠️ **这是最棘手的情况**：
> **每个攻击者的行为单独看都"合法"**（改动很小、残差正常），
> **只有把它们联合起来才构成攻击**。

### 六、为什么难检测（核心原因）

```
攻击者 A：改了 1 个量测 → 正常波动范围
攻击者 B：改了 1 个量测 → 正常波动范围
攻击者 C：改了 1 个量测 → 正常波动范围
        ↓
单点检测：✅✅✅ 全部通过
        ↓
但 A + B + C 联合起来 = 一次成功的 FDIA
```

**检测需要"关联分析"** —— 把**看似无关的多个弱信号**关联起来。

### 七、防御思路

| 思路 | 原理 | 工具 |
|---|---|---|
| **攻击链关联** | 关联多阶段信号 | 序列模型、规则引擎 |
| **攻击图** | 建模可能的攻击路径 | 图论 |
| **异常传播分析** | 检测异常的空间/时间传播 | 时空模型 |
| **多源交叉验证** | 不同数据源互相印证 | 冗余设计 |
| **智能体** ⭐ | 自主关联与响应 | LLM Agent |

### 八、研究机会

| 方向 | 说明 | 新意 |
|---|---|---|
| **多阶段攻击的关联检测** | 把弱信号串起来 | ★★★★★ |
| **攻击图自动构建** | 从日志自动生成攻击路径 | ★★★★ |
| **协同 FDIA 检测** | 检测"联合异常" | ★★★★ |
| **攻击意图推断** | 从行为推断攻击者目标 | ★★★★★ |

> 💡 **一个前沿选题（对接智能体方向）**：
> 「**面向多阶段攻击的自主关联分析智能体**」
> - **问题**：多阶段攻击的信号分散在不同系统（网络日志、量测数据、操作记录）
> - **思路**：用 **LLM Agent** 做"跨源关联"
>   - Agent 能理解自然语言描述的安全事件
>   - 能调用工具（查日志、查量测、查工单）
>   - 能自主判断"这几个弱信号是否构成攻击链"
> - **创新点**：**把「工业AI与智能体」方向直接用到电网安全**
> - **风险**：LLM 的可靠性、幻觉问题需要处理（这本身也是研究点）

### 🔍 延伸思考

1. 如何关联"**看似无关**"的多个弱信号？（提示：时间窗 + 因果图）
2. **攻击图**如何自动构建？需要什么数据？

## Day 87 · 09:00 —— 攻防博弈：Stackelberg 博弈与最优防御资源分配

> **一句话**：**攻防是博弈**——防御者先布局、攻击者后出手，这正好是 **Stackelberg 博弈**的结构。

### 一、为什么用博弈论

| 前提 | 是否成立 |
|---|---|
| 攻防双方**目标对立** | ✅ 成立 |
| 双方**理性**（追求最优） | ⚠️ 大致成立 |
| **资源有限** → 需优化分配 | ✅ 成立 |

**结论**：博弈论提供了"**资源受限下的最优决策**"的数学框架。

### 二、三种博弈模型

| 模型 | 特点 | 适用 |
|---|---|---|
| **零和博弈** | 一方所得 = 另一方所失 | 纯对抗 |
| **非零和博弈** | 双方都有成本，可能"共赢"（都不动） | 更现实 |
| **Stackelberg 博弈** | **有先后顺序**（领导者先动） | **电网攻防最贴合** |

### 三、Stackelberg 博弈：领导者-跟随者

```
防御者（领导者 Leader）
    ↓ 先行动：决定防御布局 D
        ↓
攻击者（跟随者 Follower）
    ↓ 观察 D 后：决定攻击策略 A
        ↓
结果：Loss(D, A)
```

**防御者的目标**：
$$\min_{D} \; \max_{A} \; \text{Loss}(D, A) \quad \text{s.t.} \quad \text{防御预算} \le B_D$$

> 💡 **这是一个 min-max（鲁棒优化）问题**：
> **防御者要在"攻击者会选最优策略"的前提下，最小化最坏损失。**
> 也叫"**悲观准则**"或"**鲁棒最优**"。

### 四、具体例子：保护哪些量测

| 角色 | 决策 | 约束 |
|---|---|---|
| **防御者** | 选 $p$ 个量测加保护（认证/冗余） | 预算 $\le p$ |
| **攻击者** | 选 $k$ 个**未保护**的量测攻击 | 需要 $k$ 个量测 |

**防御目标**：最大化"攻击者的**最小**攻击成本"
即：让攻击者**无论怎么选，都很难成功**。

### 五、求解方法

| 方法 | 适用规模 | 优点 | 缺点 |
|---|---|---|---|
| **博弈论解析解** | 小规模 | 精确 | 不实用 |
| **混合整数规划（MILP）** | 中等规模 | 可求最优 | 规模受限 |
| **启发式（GA/PSO）** | 大规模 | 灵活 | 无最优性保证 |
| **强化学习** ⭐ | 动态博弈 | **可处理大规模** | 训练成本高 |

### 六、四种典型博弈场景

| 场景 | 防御者决策 | 攻击者决策 | 博弈类型 |
|---|---|---|---|
| **量测保护** | 保护哪些量测 | 攻击哪些量测 | Stackelberg |
| **补丁部署** | 先修哪些漏洞 | 利用哪些漏洞 | 动态博弈 |
| **蜜罐部署** | 放在哪里 | 是否上钩 | 信号博弈 |
| **MTD 时机** | 何时变化 | 何时攻击 | 时序博弈 |

### 七、博弈论的四个局限

| 局限 | 说明 | 应对 |
|---|---|---|
| **假设完全理性** | 现实中攻击者会犯错 | 有限理性模型 |
| **需要对手收益函数** | 防御者不知道攻击者想什么 | 不完全信息博弈 |
| **计算复杂** | 大规模求解难 | 强化学习、分解 |
| **静态假设** | 现实是动态演化的 | 演化博弈 |

> 💡 **"不完全信息博弈"是当前研究前沿** ——
> 因为现实中**防御者不知道攻击者的能力与目标**，
> 这正是可以做出新东西的地方。

### 八、研究机会

| 方向 | 说明 | 新意 |
|---|---|---|
| **不完全信息博弈** | 防御者不知攻击者能力 | ★★★★★ |
| **学习型攻击者** | 攻击者会从失败中学习 | ★★★★★ |
| **大规模求解（RL）** | 用强化学习处理大电网 | ★★★★ |
| **多阶段博弈** | 考虑攻击链 | ★★★★ |

> 💡 **一个契合实验室方向的选题**：
> 「**基于深度强化学习的电网防御资源动态分配**」
> - **问题**：传统 Stackelberg 求解需要**完整信息**且**计算复杂**
> - **方法**：把防御决策建模为**马尔可夫决策过程（MDP）**，用 DRL 求解
>   - 状态：系统当前状态 + 历史攻击模式
>   - 动作：选择保护哪些量测
>   - 奖励：负的期望损失
> - **创新点**：DRL 可以**在线学习**，适应攻击者的策略变化
> - **对接方向**：**工业AI与智能体**（防御智能体）

### 🔍 延伸思考

1. 如果攻击者**不是完全理性**的，Stackelberg 解还有效吗？（提示：鲁棒性 vs 最优性）
2. 如何用**强化学习**求解大规模攻防博弈？（状态空间怎么设计？）

- 相关研究：*Stackelberg Security Games: A Survey*

## Day 87 · 14:00 —— 移动目标防御（MTD）在电网

> **一句话**：**MTD 的核心思想是"让系统动起来"**——攻击者还没摸清，系统已经变了。

### 一、传统防御 vs MTD

| 维度 | 传统防御 | **MTD（移动目标防御）** |
|---|---|---|
| **思路** | 加固 + 检测 | **动态变化** |
| **假设** | 系统是**静态**的 | 系统**主动扰动** |
| **优势** | 简单、无副作用 | **增加攻击不确定性** |
| **劣势** | 被动、可被长期侦察 | 有运行代价 |
| **类比** | 把门锁换更结实的 | **让门一直移动，瞄不准** |

### 二、核心思想

```
攻击者必须经过"侦察"才能攻击
        ↓
侦察需要时间，且假设目标不变
        ↓
如果系统一直在变 → 侦察结果很快失效
        ↓
攻击者无法构造精确的攻击
```

### 三、电网中的五种 MTD 手段

| 手段 | 原理 | 代价 |
|---|---|---|
| **拓扑变换** | 改变开关状态（不影响供电的前提下） | 操作磨损 |
| **量测选择** | 随机选择量测子集参与估计 | 精度下降 |
| **参数扰动** | 微调估计器参数 | 影响精度 |
| **假数据注入** | 主动注入无害的假数据（诱饵） | 可能干扰检测 |
| **时钟随机偏移** | 随机化采样时刻 | 需硬件支持 |

### 四、MTD 防御 FDIA 的核心逻辑

```
FDIA 的前提：攻击者知道 H
        ↓
MTD：防御者不断改变"系统看起来的样子"
        ↓
攻击者无法确定 H
        ↓
① 攻击者不敢攻击（怕被发现）
② 或者攻击留下痕迹（因为用了错的 H）
```

**具体形式：量测扰动法**

```
防御者主动在部分量测上叠加小扰动 δ（自己知道，攻击者不知道）
        ↓
攻击者基于"观测到的 z"构造 a = Ĥc
        ↓
但真实 H 已经变了（或者说，z 里有攻击者不知道的 δ）
        ↓
攻击者的 a 不再精确落在 col(H) 里
        ↓
✅ 残差出现异常 → 可检测
```

> 💡 **这是一个非常优雅的思路**：
> **不需要攻击者犯错，而是防御者主动"制造"攻击者的不确定性。**

### 五、MTD 的四种代价

| 代价 | 说明 |
|---|---|
| **运行成本** | 频繁操作有设备磨损 |
| **精度影响** | 扰动会降低状态估计精度 |
| **可预测性** | 如果变化模式被学习到，MTD 失效 ⚠️ |
| **检测干扰** | 变化本身可能触发误报 |

> ⚠️ **"可预测性"是 MTD 的死穴**：
> 如果防御者的变化策略是固定的（如"每小时变一次"），
> 攻击者**学会这个规律**后，MTD 就完全失效了。
> **所以 MTD 必须引入随机性，且随机策略本身要保密。**

### 六、MTD 的效果评估

| 指标 | 说明 | 如何测 |
|---|---|---|
| **攻击成本增加** | 需要更多侦察 | 仿真对比 |
| **检测率提升** | 攻击留痕更多 | 混淆矩阵 |
| **系统影响** | 对运行的影响 | 状态估计误差 |
| **隐蔽性** | 是否被发现 | 攻击者视角 |

### 七、MTD vs 检测（互补关系）

| 思路 | 优点 | 缺点 | 适用 |
|---|---|---|---|
| **检测** | 不干扰运行 | 被动（等攻击来） | 常规 |
| **MTD** | 主动增加攻击难度 | 有运行代价 | 高价值目标 |

> 💡 **最佳实践是"检测 + MTD"结合**：
> MTD 制造不确定性 → 攻击者留下痕迹 → 检测器捕捉痕迹。

### 八、研究机会

| 方向 | 说明 | 新意 |
|---|---|---|
| **MTD 策略优化** | 何时变、变多少（代价 vs 收益） | ★★★★ |
| **MTD 与检测结合** | 联合设计 | ★★★★ |
| **MTD 对 GNN 检测器的影响** | 拓扑变了 GNN 怎么办 ⭐ | ★★★★★ |
| **随机化策略设计** | 防止被学习 | ★★★ |

> 💡 **一个与你方向高度契合的选题**：
> 「**面向 GNN 检测器的移动目标防御：拓扑扰动与检测器的协同设计**」
> - **痛点**：GNN 检测器**依赖拓扑**，但 MTD 会**改变拓扑**
>   - 拓扑一变，GNN 学到的模式就失效了
>   - 这是"MTD 与 GNN 的冲突"
> - **你的贡献**：设计一种**拓扑鲁棒的 GNN**，使其在 MTD 下依然有效
>   - 或者：**协同设计** MTD 策略与检测器（两者一起优化）
> - **创新点极强**：现有研究要么只做 MTD、要么只做 GNN，**很少有人考虑两者的冲突**
> - **与你已有的工作衔接**：你已经在做 FDIA + GNN，这个方向是自然的延伸

### 🔍 延伸思考

1. MTD 的**变化频率**如何选择？（变化太频繁影响运行，太少被学习）
2. MTD 会不会**影响 GNN 检测器的训练**？（拓扑一直在变，怎么学？）

## Day 88 · 09:00 —— 第十二周复盘：把攻击做成数学的完整流程

> **一句话**：**本周把"攻击"从概念变成了可求解的数学问题**——这套流程就是你论文的方法论骨架。

### 一、完整流程（五步）

```
① 定义攻击者能力模型
    ⟨知识 K, 访问 A, 目标 G, 约束 C⟩
        ↓
② 构造攻击（解优化问题）
    max 后果(a)  s.t. 隐蔽性 + 可行性
        ↓
③ 验证隐蔽性
    Ma = 0？（残差是否真的不变）
        ↓
④ 量化后果
    物理层（MW）+ 经济层（元）
        ↓
⑤ 设计防御
    博弈（资源分配）+ MTD（主动扰动）
```

### 二、本周知识地图

| 主题 | 一句话总结 | 核心数学工具 |
|---|---|---|
| **攻击者能力模型** | $\langle \mathcal{K},\mathcal{A},\mathcal{G},\mathcal{C} \rangle$ | 形式化建模 |
| **后果量化** | 从数据 → 物理 → 经济 | 仿真 + 优化 |
| **隐蔽攻击构造** | $a \in \mathrm{col}(H)$ | 线性代数 |
| **稀疏攻击** | $\min \|a\|_0$ | 组合优化 |
| **物理约束攻击** | 三重约束下的可行域 | 约束优化 |
| **拓扑攻击** | 改结构比改数据更狠 | 组合攻击 |
| **LRA** | 总量守恒下重分配 | **双层优化（MPEC）** |
| **时间同步攻击** | GPS 渐进欺骗 | 多源比对 |
| **协同攻击** | 多阶段 / 多攻击者 | 关联分析 |
| **攻防博弈** | $\min_D \max_A \text{Loss}$ | **Stackelberg 博弈** |
| **MTD** | 让系统"动起来" | 动态防御 |

### 三、三条贯穿全周的主线

```
主线 ①：从"能不能"到"有多大代价"
   定性（能不能攻破）──→ 定量（损失多少 MW / 多少钱）

主线 ②：从"单点"到"协同"
   单次攻击 ──→ 多阶段 / 多攻击者协同

主线 ③：从"被动检测"到"主动防御"
   检测（等攻击来）──→ 博弈（优化布局）──→ MTD（主动扰动）
```

### 四、攻防螺旋（六阶段回顾）

| 阶段 | 攻击方 | 防御方 |
|---|---|---|
| 1 | $a = Hc$ 绕过 BDD | BDD（残差检验） |
| 2 | 稀疏攻击 | 统计检测 |
| 3 | 物理自洽攻击 | **物理约束校验** |
| 4 | 渐进攻击 | **时序检测** |
| 5 | 长期潜伏攻击 | 长期趋势分析 |
| 6 | **协同 / 拓扑 + FDIA** | **？这就是你的机会** |

### 五、你的方法论工具箱

| 工具 | 用途 | 掌握优先级 |
|---|---|---|
| **线性代数**（列空间、投影） | 攻击构造 | ⭐⭐⭐ **必会** |
| **优化**（线性 / 凸优化） | 稀疏攻击、防御分配 | ⭐⭐⭐ **必会** |
| **双层优化 / MPEC** | LRA、市场攻击 | ⭐⭐ 进阶 |
| **博弈论** | 防御资源分配 | ⭐⭐ 进阶 |
| **强化学习** | 动态防御、MTD | ⭐ 高阶 |
| **仿真（pandapower）** | 后果量化 | ⭐⭐⭐ **必会** |

### 六、如何判断一个攻击模型"好不好"

| 标准 | 说明 | 反面例子 |
|---|---|---|
| **假设现实** | 不是"攻击者知道一切" | ❌ "攻击者知道精确 H 和真实负荷" |
| **可求解** | 有明确的算法 | ❌ "求解 NP-hard 问题的最优解" |
| **后果可量化** | 有具体指标 | ❌ "会造成严重后果"（太模糊） |
| **有检测价值** | 能据此设计检测器 | ❌ 攻击后完全无法检测（无研究价值） |

> 💡 **第 4 条特别重要**：
> **如果一个攻击"完全无法检测"，那它作为研究对象的价值有限** ——
> 因为你的论文最终要给出**检测或防御方案**。
> **好的攻击模型应该"很难检测，但有检测的理论空间"。**

### 🔗 与网安研究关联

**这套五步流程 = 你论文的方法论骨架**：

```
论文的 Method 章节结构：
  3.1 系统模型          ← 电网 + 量测 + 估计器
  3.2 攻击者模型        ← ⟨K, A, G, C⟩
  3.3 攻击构造          ← 优化问题
  3.4 攻击可行性分析    ← Ma = 0 验证
  3.5 后果量化          ← 物理 + 经济指标
  3.6 防御 / 检测方法   ← 你的贡献
```

**把这六节填满，你的论文就有骨架了。**

## Day 88 · 14:00 —— 延伸：为你的选题写攻击模型

> **一句话**：**把本周的模板套到你的具体选题上**，你会得到一份可以直接写进论文的"攻击模型"章节。

### 一、模板结构（五节）

```
① 系统模型        电网结构 + 量测配置 + 估计器/控制器
② 攻击者能力假设   ⟨知识, 访问, 目标, 约束⟩
③ 攻击构造问题     优化问题的形式化表述
④ 攻击求解方法     算法与复杂度
⑤ 后果度量         物理指标 + 经济指标
```

### 二、案例 ①：配电网 FDIA（推荐方向）

| 项目 | 内容 |
|---|---|
| **系统模型** | IEEE 33 节点辐射状配电网 + 少量真实量测 + 伪量测 |
| **攻击者知识** | 知道拓扑结构，**不知道**真实负荷 |
| **访问** | 能篡改 $k$ 个量测（含伪量测） |
| **目标** | 使电压估计偏移，造成调度误判 |
| **约束** | 不被 BDD 发现 + 满足潮流方程 |
| **求解** | 凸松弛（$\ell_1$）+ 贪心 |
| **后果** | 电压越限次数 / 负荷损失（MW） |

### 三、案例 ②：VSG 参数攻击（高创新性）

| 项目 | 内容 |
|---|---|
| **系统模型** | 含多台 VSG 的微电网 |
| **攻击者知识** | 知道控制结构，**不知道**实时运行参数 |
| **访问** | 能写 PCS 的控制参数（$J$、$D$） |
| **目标** | 降低系统阻尼比，诱发振荡 |
| **约束** | 不触发网络 IDS（无流量异常） |
| **求解** | 参数灵敏度分析 + 优化 |
| **后果** | 阻尼比下降 % / 振荡持续时间 |

### 四、案例 ③：LRA + 市场（经济动机）

| 项目 | 内容 |
|---|---|
| **系统模型** | IEEE 39 节点 + SCED 出清 |
| **攻击者知识** | 知道网络拓扑和机组成本函数 |
| **访问** | 能改 $k$ 个负荷量测 |
| **目标** | **最大化自己机组的收益** |
| **约束** | 总量守恒（$\mathbf{1}^Ta_d=0$）+ 不被发现 |
| **求解** | **双层优化**（KKT 替换为 MPEC） |
| **后果** | 调度成本增加 % / 攻击者收益 |

### 五、写论文时的四条注意事项

| # | 注意事项 | 具体做法 |
|---|---|---|
| 1 | **假设写清楚** | 用**数学符号**，不用自然语言 |
| 2 | **论证合理性** | 引用文献或给出现实依据（如"拓扑属保密信息"） |
| 3 | **做敏感性分析** | 放松假设后结论还成立吗？ |
| 4 | **给出典型场景** | 一个具体的数值例子，比抽象公式有说服力 |

### 六、自检清单（写完模型后逐项检查）

| # | 检查项 | ✅ / ❌ |
|---|---|---|
| 1 | 攻击者假设是否**现实**？（不是"知道一切"） | |
| 2 | 攻击构造是否**可解**？（有明确算法） | |
| 3 | 后果是否**可量化**？（有具体指标） | |
| 4 | 是否**留有检测空间**？（不是理论上不可检测） | |
| 5 | 是否与**现有工作不同**？（创新点在哪） | |
| 6 | 是否能用**公开数据/仿真**验证？ | |

> 💡 **如果第 4 项是 ❌（完全不可检测），要重新考虑** ——
> 因为你无法给出防御方案，论文的贡献会大打折扣。
