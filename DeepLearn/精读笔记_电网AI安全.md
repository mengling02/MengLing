# 第一部分：演进全景

## 1.1 一张图看懂技术演进

FDIA 研究从 2009 年到现在，经历了五个阶段：

```
【阶段一】理论奠基（2009-2013）
  核心问题：能不能骗过坏数据检测（BDD）？
  代表：Liu 2009 CCS —— 提出 a = H·c，证明残差严格不变
  产出：攻击可行性的理论证明

        ↓  问题变成："既然能骗过，怎么检测？"

【阶段二】统计与物理方法（2013-2017）
  核心思路：用物理规律和统计假设找异常
  代表：Kosut（可检测性极限）、Ashok 2017（基于负荷预测残差）
  产出：可检测性的理论边界 + 基于预测的方法

        ↓  问题变成："统计方法太依赖精确模型，模型不准怎么办？"

【阶段三】机器学习方法（2017-2021）
  核心思路：让模型自己从数据里学异常模式
  代表：SVM / RF、LSTM、自编码器
  产出：工程可用，但对拓扑变化不鲁棒

        ↓  问题变成："电网是图结构，ML 没利用这个结构信息"

【阶段四】图神经网络方法（2021-至今）
  核心思路：把电网显式建图，用 GNN 学空间依赖
  代表：GNN 时序异常检测、图结构入侵检测
  产出：空间信息 + 时序信息联合建模

        ↓  新问题："检测器自己会不会被对抗攻击打掉？"

【阶段五】对抗鲁棒性（2022-至今）★ 最新战场
  核心问题：AI 检测器自身的安全性
  代表：对抗样本攻击 ICS 异常检测器
  产出：攻防闭环 —— 你实验室两个方向的交汇点
```

> **你该站在哪**：阶段四和阶段五的交汇处 —— 用 GNN/时序模型做检测，同时研究检测器自身的鲁棒性。
> 这正好对接你实验室的「入侵检测」+「AI 与数据安全」两个方向。

## 1.3 三条技术路线的本质差异

| 路线 | 代表方法 | 判别依据 | 优势 | 致命弱点 |
|---|---|---|---|---|
| **物理/统计** | 残差检验、卡方检验 | 残差是否超阈值 | 快、可解释、无需训练 | **完全信息攻击下彻底失效** |
| **传统 ML** | SVM、随机森林 | 手工特征的分布 | 小样本可用 | 依赖特征工程 |
| **深度学习** | LSTM、GNN、AE | 学到的隐含模式 | 能捕捉复杂模式 | 需要大量数据 + 可解释性差 |

> [!important] 关键认知（这是本笔记最重要的一句话）
> **在"完全信息攻击"下，三条路线全部失效** —— 这是信息论层面的不可能，
> 不是算法不够好。
>
> 所以论文的立论**不能**是"我用了深度学习，所以能检测 FDI"。
> 必须说清：**在什么威胁模型下、利用了哪条额外的先验信息、相对最强基线有多少增量。**

## 1.4 研究缺口在哪

> [!tip] 四个真实存在的缺口（每个都能支撑一篇论文）
>
> **缺口 1：攻击者信息边界的系统性研究**
> 大多数论文假设攻击者"知道完整 H"（太强，不现实）或"什么都不知道"（太弱）。
> **中间的连续谱几乎没有系统性研究** —— 攻击者知道 k 行 H 时，检测性能怎么退化？
>
> **缺口 2：物理约束没有被显式利用**
> 潮流方程、状态范围、时序平滑性 —— 这些都是**免费的先验**，
> 但很多论文只用数据驱动，把这些物理知识浪费了。
>
> **缺口 3：检测器自身的鲁棒性**
> 大家都在研究"检测 FDI"，很少有人研究"**检测器被对抗攻击时怎么办**"。
> 这是阶段五的战场，也正好是你实验室两个方向的交汇。
>
> **缺口 4：仿真数据与真实数据的鸿沟**
> 绝大多数工作用仿真数据（MATPOWER / pandapower）。
> 仿真到真实的域偏移（domain shift）有多大？**几乎没人量化过。**

## 论文 ①：Liu et al. 2009 —— FDIA 开山之作

| 项目 | 内容 |
|---|---|
| **标题** | False Data Injection Attacks against State Estimation in Electric Power Grids |
| **出处** | ACM CCS 2009（安全领域顶会） |
| **链接** | [ACM](https://dl.acm.org/doi/10.1145/1653662.1653666) |
| **一句话** | 证明攻击者只要构造 `a = H·c`，就能在**残差完全不变**的情况下任意篡改状态估计结果。 |

### 为什么它是必读

这篇文章定义了整个研究方向。你后面读的所有 FDI 检测论文，
**威胁模型都源自这里**。不读它，你连"攻击者能做什么"都说不清。

### 核心构造（必须理解）

```
系统模型：      z = H·x + e
传统 BDD：      计算残差 r = z - H·x̂，若 ||r|| > τ 则报警
                其中 x̂ = (HᵀH)⁻¹Hᵀz

攻击者构造：    a = H·c        （c 是任意向量，代表想要的状态偏移）
注入后：        z_bad = z + a

攻击后的估计：
  x̂_bad = (HᵀH)⁻¹Hᵀ(z + Hc) = x̂ + c        ← 状态被精确偏移 c

攻击后的残差：
  r_bad = z_bad - H·x̂_bad = (z + Hc) - H(x̂ + c) = r   ← 严格不变
```

**结论**：BDD 从数学上**不可能**检测出这种攻击。

### 这篇文章的局限（你的机会）

| 局限 | 说明 | 你的机会 |
|---|---|---|
| 假设攻击者知道**完整** H | 现实中断层信息很难拿到 | 研究"部分信息"下的攻击与检测 |
| 只考虑**单快照** | 没有利用时序信息 | 引入时序约束 |
| 假设量测**无噪声**（部分推导） | 噪声会影响攻击精度 | 研究噪声下的攻击可行性 |

### 读的时候注意

- 重点看**威胁模型的表述方式**（Day 50 你要写自己的威胁模型，这是范本）
- 数学推导要自己推一遍（`code/fdia_minimal.py` 就是这个推导的可运行版）

## 论文 ②：Sridhar et al. 2012 —— 电力 CPS 安全总纲

| 项目 | 内容 |
|---|---|
| **标题** | Cyber–Physical System Security for the Electric Power Grid |
| **出处** | Proceedings of the IEEE, 2012 |
| **链接** | [IEEE](https://ieeexplore.ieee.org/abstract/document/6032699) |
| **一句话** | 用一篇文章把"电力 CPS 安全"的完整框架讲清楚：攻击面、防御层次、开放问题。 |

### 为什么它重要

**这是建立全局认知最快的一篇。** 它不深，但广 ——
读完你会知道整个领域有哪些子问题、它们之间什么关系。

### 关键框架

文章把电力 CPS 分成三层，每层都有对应攻击面：

| 层次 | 组成 | 典型攻击 |
|---|---|---|
| **物理层** | 发电机、变压器、线路 | 物理破坏 |
| **通信层** | SCADA、通信网络、协议 | 窃听、篡改、DoS |
| **应用层** | 状态估计、调度决策、市场 | **FDIA**、负荷重分配 |

> **注意**：FDIA 属于**应用层攻击** —— 它不破坏物理设备，也不阻断通信，
> 而是**欺骗决策算法**。这类攻击最隐蔽，也最难防。

### 局限

2012 年的文章，**深度学习方法还没有成为主流**（那是 AlexNet 同一年）。
所以它列出的"开放问题"里，很多现在已经有部分答案了 ——
**这恰好是你可以对照的地方**：它提的问题，哪些被解决了？怎么解决的？

## 论文 ③：Buldyrev et al. 2010 —— 相依网络级联失效

| 项目 | 内容 |
|---|---|
| **标题** | Catastrophic cascade of failures in interdependent networks |
| **出处** | *Nature* 正刊, 2010 |
| **链接** | [Nature](https://www.nature.com/articles/nature08932) |
| **一句话** | 两个相互依赖的网络（如电力网 + 通信网），一个的局部故障会引发另一个的连锁崩溃。 |

### 为什么它值得读

这是**跨域耦合**的经典理论工作，也是理解"为什么电网安全这么难"的关键。

**核心洞见**：电力网依赖通信网做调度，通信网依赖电力网供电 ——
这个**双向依赖**结构使得系统的脆弱性**远超**单个网络脆弱性的简单相加。

### 和你的研究的关系

| 视角 | 启示 |
|---|---|
| 攻击者视角 | 攻击通信网的**关键节点**，可能引发电力网的连锁失效 |
| 防御者视角 | 单纯的"电力网加固"不够，必须考虑**跨域依赖** |
| 建模视角 | 可以用**多层网络**建模，这是 GNN 方法的理论基础 |

> **提示**：这篇是复杂网络领域的，不是安全领域的。
> 读它是为了获得**跨域视角**，不用抠数学细节。

## 论文 ④：arXiv 2505.03120（2025）—— 对抗样本攻击 ICS 异常检测器

| 项目 | 内容 |
|---|---|
| **标题** | Adversarial Sample Generation for Anomaly Detection in Industrial Control Systems |
| **出处** | arXiv 2505.03120, 2025 |
| **链接** | [arXiv HTML](https://arxiv.org/html/2505.03120v1) ｜ [PDF](https://arxiv.org/pdf/2505.03120) |
| **一句话** | 研究 ML 检测器（IDS）如何被对抗样本攻击，以及如何生成有效的攻击样本。 |

### 为什么它是这四篇里最该精读的

| 理由 | 说明 |
|---|---|
| **方向完全对口** | 工业控制系统 + 异常检测 + 对抗攻击 = 你的选题区域 |
| **免费全文** | arXiv，无障碍阅读 |
| **新（2025）** | 代表了当前前沿，不是十年前的老工作 |
| **有攻防闭环** | 既做攻击也讨论防御，结构完整 |

### 核心思路（读的时候重点看）

```
1. 目标：让异常检测器把"异常"判成"正常"（漏报攻击）
2. 方法：沿"降低异常分数"的方向扰动输入
         x_adv = x + ε · sign(-∇_x score(x))
3. 挑战：ICS 数据有物理约束，扰动不能任意大
4. 评估：攻击成功率 vs 扰动幅度
```

### 这篇文章给你的两个提示

1. **检测器自身也是攻击目标** —— 这是很多人忽略的盲区
2. **对抗鲁棒性是安全类论文的必答题**（Day 53 会详讲）

### 局限与你的机会

- 它的物理约束建模可能比较简化 → 你可以做得更严谨
- 它可能只考虑单一攻击类型 → 你可以研究多种攻击的对比

## 3.2 检测对比实验（三场景）

```bash
python code/fdia_detection_demo.py
```

**核心结论**：

| 攻击类型 | 谁有效 | 你的论文该怎么写 |
|---|---|---|
| 完全信息攻击 | **都不行**（AUC≈0.5） | 别碰，信息论死胡同 |
| 部分信息攻击 | 传统 BDD（0.9945） | 需论证 ML 的增量价值 |

> [!warning] 这个结论可能和你预期的不一样，但它是诚实的
> 很多初学者以为"上了深度学习就能检测 FDI"，实测会打脸。
> **搞清楚方法的边界，比盲目堆模型重要得多。**

```bash
python code/graph_basics.py
```

**你会看到**：

```
  节点数（母线）  : 14
  边数（支路）    : 20
  稀疏度          : 0.796   ← 只有约 20% 的位置非零

  第  1 层后  未归一化最大幅值 =    2.571e+00   归一化后最大幅值 =      0.645
  第 10 层后  未归一化最大幅值 =    8.699e+05   归一化后最大幅值 =      0.319

**为什么这个脚本值得跑**：它把两件事连起来了 ——

```
  · 邻接矩阵 A   ←→  状态估计里的 H
    H 的稀疏结构完全由拓扑决定，所以 "H = 图在物理定律下的具体化"
  · 攻击者要构造 Δz = H·Δx，就必须知道 H 的结构 = 必须知道拓扑
    ⇒ 这就是【选题 B】把"知道 k 行 H"参数化的物理基础
```

> ⚠️ 脚本里也写了诚实的边界：**拓扑固定不变时，GNN 未必打得过 MLP**。
> GNN 的额外结构先验只在"拓扑会变"（N-1、检修、拓扑攻击）或"量测缺失导致部分不可观测"时才有价值。

# 第四部分：三个可行选题

> **选题四道关**（Day 49 详讲）：痛点真实 → gap 明确 → 方法合理 → 实验能做完。

## 选题 A · 物理约束引导的 FDIA 检测

**一句话**：把潮流方程和时序平滑性作为**硬约束**建模进检测器，检测"物理不可信"的状态。

| 维度 | 内容 |
|---|---|
| **痛点** | 纯数据驱动的方法学不到物理规律，在训练分布外容易失效 |
| **Gap** | 现有方法大多只用数据，把"物理知识"这个免费先验浪费了 |
| **方法** | 在损失函数中加入物理约束项；或用物理规律做数据增强 |
| **数据** | pandapower 生成 IEEE 14/118 的时序量测（Day 41 已上手） |
| **基线** | 传统 BDD + LSTM-AE + 纯数据驱动 MLP |
| **风险** | 物理约束可能过于理想化，仿真数据看不出优势 |
| **难度** | ★★★☆☆ |

**为什么推荐**：这是"AI + 领域知识"的经典范式，审稿人喜欢，也容易讲清贡献。

---

## 选题 B · 攻击者信息边界的系统性研究（★ 最稳）

**一句话**：研究"攻击者知道 k 行 H"时，各类检测方法的性能退化规律。

| 维度 | 内容 |
|---|---|
| **痛点** | 现有工作要么假设攻击者全知（不现实），要么假设一无所知（太弱） |
| **Gap** | **中间的连续谱没有被系统研究过** —— 这是明确的空白 |
| **方法** | 构造参数化的攻击强度；对比 5+ 种检测方法的退化曲线 |
| **数据** | pandapower 仿真 + 公开数据集 |
| **基线** | BDD / SVM / RF / LSTM / GNN（覆盖三条技术路线） |
| **风险** | 可能被质疑"只是实验对比，没有新方法" |
| **难度** | ★★☆☆☆ |

**为什么推荐**：**这是三个里最容易做完的。**
不需要提出新算法，只需要严谨的实验设计 + 清晰的结论。
对第一篇论文来说，"扎实的实证研究"是完全可接受的贡献类型。

**关键产出**：一条"攻击者知识 vs 检测难度"的曲线 —— 这就是论文的核心图。

## 选题 C · 时序一致性异常检测

**一句话**：用状态跳变 + 多步预测残差做检测，捕获单快照方法看不到的异常。

| 维度 | 内容 |
|---|---|
| **痛点** | 单快照方法对隐蔽 FDI 完全失效（实验已证实） |
| **Gap** | 现有方法对"时序一致性"的利用不够充分 |
| **方法** | 多步预测 + 预测残差；或状态转移的物理约束 |
| **数据** | 负荷时序（UCI）+ 仿真量测 |
| **基线** | 快照 BDD + 单步预测 + LSTM-AE |
| **风险** | 时序模型训练成本高，1 小时/天的节奏可能吃紧 |
| **难度** | ★★★★☆ |

**为什么推荐**：**理论上最有空间**（实测 AUC 从 0.4890 提升到 0.9987）。
但对算力和时间要求高，适合作为第二篇论文。

### 选题 B · 攻击者信息边界（★ 第一篇推荐）

```
必需工具：
  W12 对抗攻防      → 攻击者视角、威胁模型、评估协议

  W14 / W15 / W16   → 全部不需要

关键风险：可能被质疑"只是实验对比，没有新方法"
```

**从工具视角看 B 的升级路径**（重要）：

> **B 的天然短板是"没有方法贡献"。用 W14 的博弈建模思路，可以把它补上。**
>
> ```
> 纯 B：扫描 k → 画退化曲线 → "攻击者知道得越多，检测越难"
>        （审稿人：这不明摆着吗）
>
> B+ ：再加一个【信息隐藏策略】的探索
>        → 防御者主动限制拓扑信息的可见性，能换多少鲁棒性？
>        → 这就从"测量退化"升级为"防御策略设计"
>        → 贡献类型从【纯实证】变成【实证 + 策略】
> ```
>
> **这一步不需要真的用强化学习**，只需要借用"攻防双方各自优化"的建模框架。**W14 第 92 天（攻防博弈建模）的价值就在这里** —— 即使你不做强化学习，那一节的思维方式也用得上。

### 选题 A · 物理约束引导的检测

```
必需工具：
  W13 物理约束      → 核心（PINN、潮流残差、损失权重）
  W10 图神经网络    → 用拓扑构造输入图
  W12 对抗攻防      → 证明鲁棒性提升（不做这个，审稿人会问）

不需要：
  W11 / W14 / W15 / W16

预计工作量：中等
关键风险：★ 仿真数据里"物理不一致"根本不存在，方法可能没有增量
```

> **⚠️ 做 A 之前必须解决的一个根本问题**（Week17 Day 110 已详述）：
>
> ```
> 你想证明的："物理约束能提升检测效果"
> 你手上的数据："pandapower 生成的、严格满足潮流方程的仿真数据"
>
> ⇒ 你想检出的"物理不一致"，在数据的生成过程里就被抹掉了
> ⇒ 结果很可能是：加不加物理约束，F1 差不多
> ```
>
> **三条出路**（按推荐度排序）：
> 1. **在生成数据时人为引入物理不一致** —— 量测噪声调大、模拟坏数据/丢包/时间不同步
> 2. **把物理约束用在训练集之外的场景** —— 训练在正常工况，测试在拓扑变化/极端负荷
> 3. **把物理约束做成"可解释性"而非"性能提升"** —— 承认性能增益有限，论证检测结果可审计
>
> **选第 3 条的话，贡献类型就从"方法"变成了"分析"** —— 这是更诚实的定位，但投稿目标要相应调整。

### 选题 C · 时序一致性异常检测

```
必需工具：
  W11 生成模型      → 生成不同隐蔽程度的攻击样本
  W12 对抗攻防      → 攻击者会针对你的时序假设调整，必须做
  W10 图神经网络    → （可选）时空联合建模

不需要：
  W13 / W14 / W15 / W16

预计工作量：高
关键风险：★ 本质是攻防博弈，第一篇很难收口
```

> **C 的核心陷阱**（Week17 Day 110 的原话）：**"无限递归"**。
>
> ```
> 你证明："时序方法能检出单快照攻击"
> 审稿人："那攻击者连续篡改呢？"
> 你补做 → 发现检不出 → 加"连续性检测"
> 审稿人："那攻击者慢速漂移呢？"
> ……（没有终点）
> ```
>
> **C 的正确位置是第二篇**。当你在 B 的过程中积累了完整的攻击构造与评估代码后，做 C 的成本会大幅下降。
