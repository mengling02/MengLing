## 二、实验一：最小验证脚本（5 秒）

### 2.1 运行

```bash
python code/fdia_minimal.py
```

### 2.2 实测输出（本机真实结果）

```
[1] 量测矩阵 H: (12, 5), 秩 = 5 (需等于状态数 5)
[2] 真实状态 x_true = [-0.0753  0.2704  0.1392  0.0592 -0.2064]
    正常量测 z (前 4 个) = [-0.0739  0.2755  0.1363  0.0566]
[3] 正常情况：
    估计状态 x_hat = [-0.0766  0.27    0.1434  0.0585 -0.2102]
    ||x_hat - x_true|| = 0.005904
    ||r|| = 0.014437  (阈值 τ = 0.039686)
    BDD 判定：✓ 通过（无坏数据）

[4] FDI 攻击：
    目标状态偏移 Δx = [ 0.05 -0.03  0.02 -0.04  0.01]
    构造注入量 Δz = H·Δx = [ 0.05 -0.03  0.02 -0.04] ... (共 12 维)
    篡改幅度 ||Δz|| = 0.151987
    单点最大篡改 = 0.080000  (占量测幅度 22.8%)

[5] 攻击后的状态估计与检测：
    估计状态 x_hat_bad = [-0.0266  0.24    0.1634  0.0185 -0.2002]
    估计值偏移 ||x_hat_bad - x_hat_normal|| = 0.074162
    ||r_bad|| = 0.014437  (阈值 τ = 0.039686)
    BDD 判定：✓ 通过（无坏数据）

==============================================================
★ 核心结论 ★
==============================================================
  状态被偏移了        : 0.074162   ← 攻击成功
  残差范数变化        : 1.56e-17   ← BDD 完全看不见
  BDD 能否检出        : 不能（漏报！）
==============================================================
```

### 2.3 怎么读这个结果

**最关键的两个数字**：

| 数字 | 含义 |
|---|---|
| 状态偏移 `0.074162` | 攻击**成功**了 —— 状态估计被拉偏了 0.074 |
| 残差变化 `1.56e-17` | BDD **完全看不见** —— 残差范数一模一样 |

`1.56e-17` 是浮点误差量级（机器精度约 `2.2e-16`），也就是说残差**在数学上严格不变**。

**为什么？** 数学推导（务必自己写一遍）：

```
攻击者构造：  Δz = H · Δx        （Δx 是任意想要的状态偏移）

攻击后的估计：
  x̂_bad = (HᵀH)⁻¹Hᵀ(z + HΔx)
        = (HᵀH)⁻¹Hᵀz + (HᵀH)⁻¹(HᵀH)Δx
        = x̂ + Δx                 ← 状态被精确偏移 Δx

攻击后的残差：
  r_bad = z_bad - H·x̂_bad
        = (z + HΔx) - H(x̂ + Δx)
        = z - H·x̂
        = r                      ← 残差严格不变
```

> [!danger] 这里有个必须想明白的点
> 这种攻击之所以检测不出，**不是因为检测算法不够好**，
> 而是因为被篡改的量测在统计上**就是"另一个合法状态"的合法量测**。
>
> 也就是说：**单快照下它是信息论层面不可检测的，堆任何深度学习模型都没用。**
>
> 所以"用深度学习检测 FDI"这个说法太粗 —— 会被审稿人一句话问倒。

### 2.4 脚本第 [6] 部分的发现

```
[6] 补充实验：攻击者只掌握部分 H 时会怎样？
    部分信息攻击：||r|| = 0.040748  (对比正常 0.014437)
    BDD 判定：⚠ 报警（被检出）
```

**结论**：攻击者掌握的信息越少，越容易被检出。
这就是论文里**威胁模型必须写清"攻击者知道什么"**的原因（Day 50 详讲）。

## 三、实验二：检测对比实验（三个场景）

### 3.1 运行

```bash
python code/fdia_detection_demo.py
```

### 3.2 实测输出（本机真实结果）

```
======================================================================
场景 A · 完全信息攻击（攻击者掌握完整 H）
======================================================================
  检测器                                  ROC-AUC    PR-AUC      最佳F1
  --------------------------------------------------------------
  传统 BDD（残差范数阈值）                        0.4963    0.4984    0.6669  ← 失效
  ML（残差向量 + 范数）                         0.4980    0.4923    0.6667  ← 失效

======================================================================
场景 B · 部分信息攻击（攻击者只掌握 6/12 行 H）
======================================================================
  检测器                                  ROC-AUC    PR-AUC      最佳F1
  --------------------------------------------------------------
  传统 BDD（残差范数阈值）                        0.9945    0.9961    0.9832
  ML（仅残差向量，无特征工程）                       0.5006    0.6031    0.6667  ← 失效
  ML（残差向量 + 范数）                         0.9944    0.9960    0.9831

======================================================================
场景 C · 时序攻击（状态在某一时刻发生突变）
======================================================================
  检测器                                  ROC-AUC    PR-AUC      最佳F1
  --------------------------------------------------------------
  快照 BDD（序列最大残差范数）                      0.4890    0.5021    0.6669  ← 失效
  ML 时序特征（状态跳变统计）                       0.9987    0.9991    0.9944
```

### 3.3 三个场景的教训（这是本实验最值钱的部分）

> [!important] 这张表建议抄在笔记本上
> | 攻击类型 | 谁有效 | 你的论文该怎么写 |
> |---|---|---|
> | **完全信息攻击** | 都不行 | 别碰，这是信息论死胡同 |
> | **部分信息攻击** | 传统 BDD | 需论证"ML 相对 BDD 的增量价值" |
> | **时序攻击** | **ML + 时序先验** | ★ 最有空间，重点做这里 |

**逐条解读**：

**场景 A：BDD 0.4963，ML 0.4980 —— 全部失效**

两者都在 0.5 附近（= 随机猜测）。这不是方法不够好，是**信息论层面的不可能**。

> ★ 任何声称"用深度学习检测完全信息 FDI"的论文，都值得怀疑。

**场景 B：BDD 0.9945 反而最好，ML 只喂残差向量时 0.5006（失效）**

这个结果可能出乎意料，但完全合理：
- 判别信息就在**残差范数**里，而 BDD 天然用了这个统计量
- 线性模型**算不出"范数"这种二次型统计量**，所以只喂残差向量时它学不到东西
- 一旦把范数也作为特征喂进去，ML 立刻达到 0.9944（和 BDD 持平）

> ★ 教训：**不是"深度模型一定比传统方法好"。** 在信息已经充分暴露的场景里，
> 传统方法可能又准又便宜。论文里必须解释"为什么非要用深度学习"。

**场景 C：快照 BDD 0.4890（失效），时序 ML 0.9987（有效）**

单快照完全看不出问题（残差不变），但状态在物理上应该**平滑变化** ——
攻击造成的"状态跳变"是可捕获的。时序特征（跳变幅度）一抓一个准。

> ★ 教训：**这才是 ML 真正有优势的地方。** 它能把物理规律编码成特征，
> 捕获单快照方法根本看不到的异常。**时序一致性是免费的先验。**

## 四、常见报错与处理

| 报错 | 原因 | 解决 |
|---|---|---|
| `ModuleNotFoundError: No module named 'numpy'` | 没装依赖 | `pip install numpy` |
| `ModuleNotFoundError: No module named 'numpy._utils'` | **numpy 安装不完整**（下载中断） | `pip install --force-reinstall numpy` |
| `AssertionError: 系统不可观测！` | H 矩阵秩不足 | 检查量测是否冗余；加入 PMU 直接量测 |
| `LinAlgError: Singular matrix` | `HᵀH` 不可逆（秩不足） | 同上，确保 `rank(H) == n_states` |
| 结果每次都不一样 | 没固定随机种子 | 加 `np.random.seed(0)` |
| `RuntimeWarning: invalid value encountered` | 出现 NaN/Inf | 检查是否除零，加 `+1e-9` |

> [!tip] 报错要"三抄"
> **抄报错原文、抄解决命令、抄一句话原因。**
> 攒够 20 条，你就有了自己的《踩坑手册》—— 这东西比论文本身值钱（Day 43 详讲）。

## 六、这个实验给你的论文启示

> [!important] 论文立论建议（不要写"我用深度学习检测 FDI"，太泛会被拒）
>
> 1. **明确攻击者的信息边界**（威胁模型），选"部分信息"而非"完全信息"
> 2. **把物理约束显式建模进方法** —— 时序平滑性 / 潮流方程 / 状态范围
> 3. **和强 BDD 基线对比**，并解释为什么你的方法有增量价值
> 4. **在"完全信息攻击"上诚实承认不可检测** —— 反而增加论文可信度
>
> 第 4 条尤其反直觉：**承认局限不会让论文变弱，只会让它更可信。**
> 审稿人最反感的是"什么都好"的论文。

### 三个可行的选题方向

| 方向 | 核心 idea | 难度 | 对应课程 |
|---|---|---|---|
| **A. 物理约束引导的检测** | 把潮流方程作为硬约束，检测"物理不可信"的状态 | 中 | Day 38 / Day 48 |
| **B. 攻击者知识边界的鲁棒检测** | 研究不同信息假设下检测方法的表现退化 | 低-中 | Day 50 |
| **C. 时序一致性异常检测** | 用状态跳变 + 多步预测残差做检测 | 中 | Day 24 / Day 27 |
