> **一句话**：选题不是"选最有价值的"，是**选最可能做完的** —— 做不完的题目，价值等于零。

| **1 小时/天可行性**（分高=可行） | 4 | 5 | 2 |
| **加权总分**（权重见下） | **3.9** | **4.15** | **3.0** |

**权重设置**（说明理由，你可以按自己情况调整）：

| 维度 | 权重 | 为什么这个权重 |
|---|---|---|
| 数据获取难度 | 0.25 | 拿不到数据，一切归零 |

### 三、逐个说清真实风险（**这一节最该认真读**）

#### 候选 A · 物理约束引导的 FDIA 检测

**它好在哪**：

```
① 数据与工具全部现成：pandapower 生成时序量测，潮流方程现成（Day 84 已学）
② 故事好讲：物理知识是"免费先验"，审稿人喜欢"AI + 领域知识"的范式
③ 与实验室方向对口：AI 与数据安全
```

**真实风险（必须知道）**：

| 风险 | 具体表现 | 严重程度 |
|---|---|---|
| **方向拥挤** | "物理约束 + 异常检测"已有大量工作，PINN 类方法在电力上的应用也不新 | **高** |
| **仿真数据看不出优势** | 你的数据是 pandapower 生成的，**它本身就严格满足潮流方程**。在这种情况下，"加入物理约束"的增益可能极小 —— 因为数据里没有"物理不一致"的噪声 | **高** |
| **无法证明实用性** | 真实电网的数据受量测噪声、通信误差影响，物理约束才真正有用。但你没有真实数据 | 中高 |
| **审稿人会问"增量在哪"** | "你把物理约束加到损失里"——这在 2026 年不算新想法 | 中高 |

> **最关键的一条是第 2 条**。**这是"仿真数据"这个约束带来的根本性困难**：
>
> ```
> 你想证明的："物理约束能提升检测效果"
> 你手上的数据："严格满足物理约束的仿真数据"
>
> ⇒ 你的实验里，"物理不一致"这个信号根本不存在
> ⇒ 你的方法要检出的东西，在数据里被生成过程抹掉了
> ⇒ 结果可能是：加不加物理约束，F1 差不多
> ```
>
> **如果你要做 A，必须解决这个问题**。可能的出路：
>
> ```
> 出路 1：在生成数据时【人为引入】物理不一致
>   · 量测噪声调大（让潮流方程在噪声下不再严格成立）
>   · 模拟量测坏数据、通信丢包、时间不同步
>   ⇒ 这样"物理约束"才有用武之地
>   ⇒ 但审稿人会问："这个不一致程度是怎么设定的？现实吗？"
>
> 出路 2：把物理约束用在【训练集之外】的场景
>   · 训练在正常工况，测试在拓扑变化 / 负荷极端工况
>   ⇒ 物理约束帮助模型外推
>
> 出路 3：把物理约束做成【可解释性】而非【性能提升】
>   · 承认性能提升有限，但论证"检测结果可解释、可审计"
>   ⇒ 这是更诚实的定位，但贡献类型从"方法"变成了"分析"
> ```

**结论**：A **看起来最容易，实际上最容易做成"没有增量"**。**不推荐作为第一篇。**

#### 候选 B · 攻击者信息边界的系统性研究

**它好在哪**：

```
① 数据、算力、时间全部可控（这是最硬的优点）
② Gap 是明确的：现有工作集中在"全知"与"一无所知"两个极端，
   中间的连续谱缺少系统研究（精读笔记缺口 1）
③ 贡献类型清晰：这是【实证研究】（empirical study），
   在安全领域是【完全被认可】的贡献类型
④ 关键产出明确：一条"攻击者知识 vs 检测难度"的曲线 —— 这就是核心图
⑤ 实验过程中会自然发现 A 和 C 的机会（第二篇的来源）
```

**真实风险（必须知道）**：

| 风险 | 具体表现 | 严重程度 | 应对 |
|---|---|---|---|
| **"只是实验对比，没有新方法"** | 这是最可能被拒的理由 | **高** | 见下面的应对方案 |
| **k 的定义可能被质疑** | "知道 k 行 H"如何操作化？按行随机抽？按节点连通性抽？ | 中 | **定义清楚，并做多组定义下的对比** |
| **"退化曲线"是否平凡** | 如果曲线就是单调下降，那"结论太显然" | 中高 | 需要找出**非平凡的现象**（见下） |
| **评估对象的选择** | 选哪些检测器？选少了没说服力，选多了做不完 | 中 | 覆盖三条技术路线，各选 1-2 个 |

**如何把 B 做成"有非平凡发现"的研究 —— 这是 B 能否成立的关键**：

```
如果结论只是"攻击者知道得越多，检测越难" → 审稿人：这不明摆着吗？

⇒ 你需要找的是【非单调】或【非平凡】的现象，例如：

  · 是否存在某个临界点 k*，检测性能在这里【断崖式下降】？
    → 这个临界点与什么有关？（节点度分布？量测冗余度？）

  · 不同的检测方法，退化曲线的【形状】是否不同？
    → 有没有方法在低 k 下表现差、高 k 下反而相对好？
    → 如果有，说明"知识利用方式"比"知识量"更重要

  · 攻击者的"知识"是否等价于"攻击成功"？
    → 知道 k 行 ≠ 能构造出有效的 k 行攻击（有优化难度）
    → 【区分"信息边界"与"能力边界"】—— 这是一个真正有深度的点

  · 防御者能否【利用攻击者的信息边界】？
    → 比如：故意隐藏一部分拓扑信息，让攻击者只能做部分攻击
    → 这就从"测量退化"升级成"防御策略设计"【这是方法贡献】
```

> **最后一条是 B 的升级路径**：如果时间允许，在 B 的框架上再加一个"**信息隐藏策略**"的探索 —— 即"防御者主动限制拓扑信息的可见性，能带来多少鲁棒性收益"。**这样 B 就从纯实证研究，升级为"实证 + 策略"的复合贡献，被拒风险显著下降。**

**结论**：B **仍然是最推荐的第一篇**，但**不要只做"扫描 k 画曲线"**，必须至少包含一个非平凡发现。

#### 候选 C · 时序一致性异常检测

**它好在哪**：

```
① 理论上最有空间：实测 AUC 从 0.4890（快照方法）提升到 0.9987（时序方法）
② 方法贡献清晰，容易讲成"新方法"
③ 与实验室"入侵检测"方向最对口
```

**真实风险（必须知道）**：

| 风险 | 具体表现 | 严重程度 |
|---|---|---|
| **算力与时间** | 多步预测模型训练成本高；你每天只有 1 小时 | **高** |
| **本质上是"攻防博弈"** | 你的方法假设攻击者"保持时序平滑"或"不保持"—— 攻击者会针对你的假设调整。**这是一场没有终点的博弈**，第一篇论文很难收口 | **高** |
| **与已有工作重叠** | 时序异常检测在电力上已有大量工作，"多步预测残差"不是新思路 | 中高 |
| **实验矩阵庞大** | 要覆盖多种攻击模式 × 多种时序窗口 × 多种模型，工作量翻倍 | 中高 |

> **第 2 条是最容易被忽略的坑**：**C 的结论天然依赖"攻击者模型"**。你证明了"时序方法能检出单快照攻击"，审稿人会问："那攻击者连续篡改呢？"你补做，发现检不出，于是再加"连续性检测"，审稿人再问……**这是一个无限递归，第一篇论文很难收敛。**
>
> **C 的正确位置是第二篇** —— 当你在 B 的过程中积累了攻击构造与评估的完整代码后，做 C 的成本会大幅下降。

### 四、和电网安全的关系

**上面那张打分表是通用的。但"电网安全"这个具体方向，给选题加了四条通用方向没有的约束 —— 你必须把这四条叠加上去再评估一次。**

| 约束 | 通用 AI 方向 | 电网安全方向 | 对选题的影响 |
|---|---|---|---|
| **数据** | 公开数据集多，可直接下载 | **真实数据基本拿不到**（涉密 + 商业机密） | 只能靠仿真，所有选题的"外部效度"都被削弱 |
| **物理** | 无需物理约束 | **必须满足物理规律**，否则结论无意义 | 任何方法都要过物理合理性这一关 |
| **审稿人** | 单一圈子 | **两个圈子**（电力 + AI/安全） | 选题必须在两边都讲得通 |
| **后果** | 错误代价是"模型不准" | **错误代价可能是物理损失** | 不能做"看起来很酷但不可解释"的方法 |

**逐条说清这四条约束怎么作用到你的三个候选上**：

```
【约束 1 · 数据】
  A / B / C 三者都依赖 pandapower 仿真。
  ⇒ 这不是某一个候选的问题，是【整个方向】的问题。
  ⇒ 含义：你的论文必须在"局限"里诚实声明这一点，
     并且要做一些【补偿性设计】来提升可信度：
       · 引入时间相关噪声（AR(1)），让仿真更接近真实量测特性
       · 在两个不同规模（IEEE 14 / 118）上验证结论一致性
       · 报告对噪声水平、量测冗余度的敏感性
  ⇒ 【如果导师能提供真实数据，整个打分表要重做】——
     因为"数据获取难度"这一列会全部变成 5 分，
     而"仿真-真实域偏移"这个真正的空白（精读笔记缺口 4）就打开了。

【约束 2 · 物理】
  · 候选 A：物理约束就是它的核心，天然满足
  · 候选 B：攻击样本必须做【物理可行性过滤】（否则攻击不现实）
  · 候选 C：时序平滑性本身是一种物理先验
  ⇒ 三个候选都要过这一关，但 B 和 C 需要额外做过滤/约束的工程

【约束 3 · 审稿人】
  这是【最容易被低估】的一条：
    · 电力审稿人会问："你的攻击符合电力系统的物理规律吗？
      量测配置合理吗？指标是运维关心的吗？"
    · AI/安全审稿人会问："你的威胁模型严格吗？
      对比充分吗？和最新的对抗鲁棒性工作什么关系？"
  ⇒ 选题必须在【两边都讲得通】：
    A → 电力圈讲得通（物理建模），AI 圈会觉得方法不新
    B → 两边都讲得通（威胁模型是安全圈的语言，仿真设置是电力圈的语言）
    C → AI 圈讲得通，电力圈会问"这不就是负荷预测的残差吗"
  ⇒ 【B 在"两圈通吃"这一条上得分最高】—— 这也是它推荐度最高的原因之一。

【约束 4 · 后果】
  电网场景不接受"检测不出来也没关系"。
  ⇒ 你的选题必须回答："如果检测失败，会怎样？"
    A：物理约束让结果可解释，但检不出就是检不出
    B：能给出"在什么知识水平下检测不再可靠"的量化边界 ← 【最有价值】
    C：时序方法能提高检出率，但攻击者会适应
  ⇒ 【B 能给出"检测能力的边界"，这在安全上是比"更高 F1"更有用的结论】
```

**一个直接的判断**：

> **在"只能用仿真数据"这个硬约束下，选一个"结论依赖精确数值"的选题是危险的，选一个"结论依赖趋势与规律"的选题是稳健的。**
>
> ```
> ❌ 危险型选题："我的方法把 F1 从 0.92 提升到 0.95"
>    → 仿真数据上的 3 个百分点，在真实场景下可能完全消失
>    → 审稿人会问："这个提升是真实的还是仿真特有的？"
>
> ✅ 稳健型选题："检测性能在 k* 处出现断崖，且 k* 与量测冗余度相关"
>    → 这是一个【规律】，规律比数值更容易跨数据源成立
>    → 即使真实数据的绝对性能不同，"存在临界点"这个结论仍可能成立
> ```
>
> **你的候选 B 属于稳健型，A 和 C 的"性能提升"部分属于危险型。** 这是打分表之外、但对电网安全方向特别重要的一条判断标准。

### 五、决策：怎么选

**推荐路线（给出理由，你自己判断）**：

```
第一篇 → 选 B（信息边界研究），但必须满足三个条件：
  条件 1：至少包含一个非平凡发现（临界点 / 曲线形状差异 / 信息边界≠能力边界）
  条件 2：覆盖三条技术路线的检测器（物理统计 / 传统 ML / 深度学习）
  条件 3：把"防御者利用信息边界"作为一个探索性章节（哪怕结论是否定的）

第二篇 → 从 B 的过程中自然产生，大概率是 A 或 C 的变体
  因为你在做 B 时会积累：
    · 攻击样本生成代码（→ 直接用于 C）
    · 多方法评估框架（→ 直接用于 A）
    · 对"什么有用什么没用"的一手认知（→ 这是选题最好的依据）
```

**如果导师明确要求"必须有方法创新"怎么办**：

| 情况 | 建议 |
|---|---|
| 导师要求方法创新，但没说必须第一篇就创新 | 先做 B，把"信息隐藏策略"做成方法贡献；第二篇再做 A 或 C |
| 导师要求第一篇就必须有新方法 | 选 A，但**必须先解决"仿真数据里物理不一致不存在"这个问题**（见上面的三条出路） |
| 导师有明确的工程需求（如某企业的实际场景） | **听导师的** —— 有真实数据的课题，比任何打分表都重要 |

**一个必须接受的现实**：

```
无论选哪个，你的第一篇论文都【大概率不会是高水平创新】。

理由很直接：
  · 120 小时的总投入，扣除学习时间，真正做研究的时间不到 40 小时
  · 你没有真实数据、没有 GPU 集群、没有导师手把手带
  · 这是全世界绝大多数研究生的第一篇论文的真实状况

⇒ 第一篇的目标是：【走完完整流程 + 得到一个可发表的扎实结果】
  不是：【提出一个改变领域的方法】
```

## Day 111 —— 问题定义与威胁模型：写清边界

> **一句话**：威胁模型是安全论文的**地基**，它决定了你的结论"在什么范围内成立" —— **地基没打，后面写得再漂亮也是空中楼阁。**

### 一、威胁模型的六要素

**这六个要素必须全部写清楚，缺一个都会被审稿人追问。**

| 要素 | 要回答的问题 | 常见缺失 |
|---|---|---|
| **① 攻击者目标** | 他想达成什么？（篡改状态估计？掩盖越限？制造误报？） | 只说"攻击电网"，太模糊 |
| **② 攻击者知识** | 他知道什么？（完整 `H`？k 行 `H`？只知道量测？知道检测器结构？） | **最常被糊弄的一项** |
| **③ 攻击者能力** | 他能操作什么？（篡改几个量测？能否持续？能否读写？） | 只说"注入虚假数据" |
| **④ 攻击者约束** | 他不能做什么？（不能违反物理规律？不能被发现？预算上限？） | **几乎没有论文写这一项** |
| **⑤ 时间特性** | 单快照还是持续？是否有时间窗限制？ | 常被忽略 |
| **⑥ 防御者可观测性** | 防御者能看到什么？（量测？残差？历史数据？拓扑？） | 常被忽略 |

> **第 ② 项和第 ④ 项是本周的重点** —— 你的候选 B 的全部价值就在第 ② 项的**连续谱**上；而第 ④ 项决定了攻击的"可行性"，很多论文忽略了它，导致攻击在现实中根本不可实施。

### 二、威胁模型模板（**直接抄去改**）

```
================================================================
威胁模型（Threat Model）
================================================================

【系统模型】
  电网拓扑：IEEE 14 节点系统（公开算例，N 个节点，M 条支路）
  状态估计：加权最小二乘（WLS）
      z = H·x + e,   x̂ = (HᵀW H)⁻¹ Hᵀ W z
  量测配置：全部节点电压幅值 + 全部注入功率（或按标准配置说明）
  坏数据检测（BDD）：残差范数检验，阈值 τ 由显著性水平 α = 0.05 确定

【① 攻击者目标】
  在【不被 BDD 检出】的前提下，使状态估计结果偏离真值至少 δ：
      ||x̂_bad − x̂||₂ ≥ δ
  攻击者不追求特定物理后果（如制造越限），只追求"状态偏移"
  —— 这个设定更一般，也更容易量化。

【② 攻击者知识】★ 本文的核心变量
  攻击者掌握 H 矩阵的 k 行（1 ≤ k ≤ M），其余 M − k 行未知。
  · k = M  ：完全信息攻击（文献中的标准假设）
  · k = 0  ：无信息攻击（随机注入）
  · 0 < k < M ：部分信息攻击 ← 【本文研究的连续谱】

  【k 行的选取方式】本文考虑三种（并做对比）：
     方式 1：随机选取 k 行（平均情况）
     方式 2：选取度最大的 k 个节点对应的行（最坏情况）
     方式 3：选取与目标节点直接相连的行（局部信息，最现实）
  ⇒ 三种方式的差异本身就是本文的一个发现。

  攻击者【不】掌握：
      · 检测器的参数与阈值（黑盒假设）
      · 历史量测数据
      · 防御者的随机种子

【③ 攻击者能力】
  · 可以篡改任意数量（但不超过 r 个）的量测值
  · 可以精确控制篡改量（无执行误差）
  · 可以重复攻击多次（每次独立）

【④ 攻击者约束】★ 常被忽略，本文必须写
  · 物理可行性：篡改后的量测必须满足线路容量与电压幅值范围约束
      V_min ≤ |V_i| ≤ V_max,  |P_ij| ≤ P_ij^max
  · 幅度约束：||a||₂ ≤ ε（注入向量的范数上界）
  · 隐蔽性要求：||r_bad − r||₂ ≤ γ（残差变化必须小于 γ）
  ⇒ 这三条约束共同定义了"可行攻击集 A_feasible"

【⑤ 时间特性】
  本文考虑两种：
     · 单快照攻击：只篡改一个时刻的量测
     · 多快照攻击：连续篡改 T_win 个时刻，且保持时序平滑
  ⇒ 多快照是本文的扩展实验，用于说明"时序一致性先验的边界"

【⑥ 防御者可观测性】
  防御者可以获取：
     · 实时量测 z（含攻击）
     · 拓扑与线路参数（即 H）
     · 历史量测窗口（长度 T_hist）
  防御者【不能】获取：
     · 攻击者的真实注入向量 a
     · 攻击者的 k 值与选取方式
  ⇒ 这保证了评估的公平性。

【防御者方法（被评估对象）】
  覆盖三条技术路线的五种检测器：
     ① BDD（物理/统计基线）
     ② SVM（传统 ML）
     ③ 随机森林（传统 ML）
     ④ LSTM-AE（深度学习，重建式）
     ⑤ 时空 GNN（深度学习，图 + 时序，Day 66）
  ⇒ 每个检测器在同一数据划分、同一阈值策略下评估。

【不在本文范围内（明确声明）】
  · 不研究攻击的【物理后果】（不涉及实际切负荷或设备损坏）
  · 不研究【攻击检测的实时部署】（不讨论工程实现与硬件）
  · 不研究【防御策略的博弈优化】（Day 92 的 Stackelberg 不在范围内）
  · 不使用任何真实电网数据（全部为 pandapower 仿真）
  · 不假设攻击者能访问 SCADA 通信链路（只考虑量测篡改）
================================================================
```

### 三、写威胁模型的三个关键动作

**动作 1：把"知识"操作化。**

```
❌ 模糊写法：
   "攻击者知道部分拓扑信息。"
   → 审稿人：部分是多少？怎么量化的？怎么选的？

✅ 可操作写法：
   "攻击者掌握 H 的 k 行，k ∈ {1, 2, 4, 8, M/2, M}，
    选取方式为随机（方式 1），每个 k 下重复 20 次取均值与标准差。"
   → 审稿人：清楚，可复现，可质疑但不可否认
```

**动作 2：把"约束"写进去 —— 这是提升论文质量最快的一招。**

```
❌ 大多数论文的写法：
   "攻击者可以篡改任意量测值。"
   → 问题：这在现实中不可行（会被物理校验发现，也可能超出设备量程）

✅ 加上约束：
   "攻击者的注入向量 a 需满足 ||a||₂ ≤ ε 且篡改后量测满足
    线路容量约束。ε 的取值参考量测噪声的 3σ 水平（ε = 3σ）。"
   → 问题变难了，但结论变可信了
   → 【而且】这给了你一个额外的实验维度：ε 变化下的检测性能
```

**动作 3：明确写出"不做什么"。**

```
为什么必须写？
  ① 审稿人不会要求你做范围外的事（因为你先声明了）
  ② 你自己不会被无限扩大的范围拖死
  ③ 显示你清楚这个工作的边界 —— 这是成熟研究者的标志

写法：
  "本文不研究 X / Y / Z。这些问题的讨论见 [相关工作]，"
  "它们与本文的威胁模型假设不兼容，因此不在本文范围内。"
```

### 四、和电网安全的关系

**电网场景下威胁模型的三个特殊性**：

| 特殊性 | 含义 | 对你论文的影响 |
|---|---|---|
| **物理约束是硬约束** | 篡改后的量测必须能通过物理校验，否则攻击者自己就暴露了 | 必须在威胁模型里写清楚（动作 2） |
| **拓扑信息本身就是攻击资产** | `H` 矩阵就是拓扑与线路参数（回顾 Day 96） | **"攻击者知道 k 行 H"这个假设，等价于"攻击者掌握了部分拓扑信息"** —— 这让你的研究有了现实意义：拓扑信息保护策略 |
| **检测失败代价不对称** | 漏报一次真实攻击 vs 误报一百次 | 评估指标必须报告 PR-AUC 与固定 FPR 下的 TPR，不能只报准确率 |

**一个可以写进 Introduction 的动机链（这是你论文的第一段）**：

```
① 状态估计是电网调度决策的基础，FDIA 可绕过 BDD（Liu 2009）
② 已有大量检测方法，但它们的评估几乎都建立在两个极端假设上：
     · 攻击者完全知道 H（不现实：拓扑是保密信息）
     · 攻击者完全不知道 H（太弱：攻击成功率极低）
③ 现实中攻击者掌握的是【部分拓扑信息】—— 通过泄露、推断、历史数据积累
④ 那么：检测方法在"部分信息"下的表现如何？退化规律是什么？
   防御者能否利用这一点？
⑤ 本文给出：一条"攻击者知识 vs 检测难度"的量化曲线，
   并识别出三个非平凡现象（临界点 / 曲线形状差异 / 信息≠能力）
```

> **这五句话就是你的 Introduction 骨架。** 写完威胁模型之后，立刻把它写下来 —— 因为威胁模型决定了动机链能怎么写。

## Day 112 —— 方法设计与创新点提炼：一句话说清

> **一句话**：如果你不能用**一句话**说清创新点，说明你还没想清楚 —— 而审稿人只用一句话就会决定"这篇值不值得看"。

### 一、三种合法的贡献类型

**先破除一个误解**：论文贡献不只有"提出新算法"。

| 贡献类型 | 典型表述 | 难度 | 你适用吗 |
|---|---|---|---|
| **① 新方法** | "提出 X 方法，在 Y 任务上超过 SOTA" | 高 | ⚠️ 部分（你的 B 可以有小方法贡献） |
| **② 新发现** | "首次系统研究了 X 现象，发现 Y 规律" | 中 | ✅ **最适用**（候选 B 正是这一类） |
| **③ 新数据集 / 新评估** | "构建了 X 数据集 / 提出 Y 评估协议" | 中 | ✅ 部分（"公平对比协议"也算） |

**为什么"新发现"在安全领域是完全被认可的贡献**：

```
安全领域的顶会（CCS / USENIX Security / S&P / NDSS）每年都有大量
"测量类论文"（measurement paper）—— 它们不提出新算法，
只做一件事：把一个别人没系统测过的东西测清楚。

例：系统测量 X 类漏洞在真实系统中的分布
    → 没有新算法，但是高影响力的工作

⇒ 你的候选 B 属于这一类。
⇒ 关键不是"你提了新方法"，而是"你发现的东西别人不知道"。
```

### 二、"一句话说清"的公式

**用这个模板压缩你的创新点**：

```
在【什么场景/什么约束】下，
用【什么手段】，
解决【什么具体问题】，
相对【最强基线】在【什么指标】上提升/改变了【多少】，
并且【什么额外的价值】（可解释 / 更低成本 / 更鲁棒）。

或者（实证研究版）：
本文系统研究了【X】在【Y 范围】内的变化规律，
发现【三个非平凡现象】，
并据此提出【一个策略/一个设计原则】。
```

**套用到你的三个候选上**：

```
候选 A：
  "在【仿真量测含噪】的场景下，用【潮流方程作为硬约束的投影层】，
   解决【纯数据驱动方法在训练分布外失效】的问题，
   相对【LSTM-AE 基线】在【跨工况泛化的 F1】上提升【X 个百分点】，
   并且【检测结果可被物理量解释】。"

候选 B：
  "本文系统研究了【攻击者的拓扑信息量 k】在【0 到 M 全部范围】内
   对【三条技术路线的五种检测器】性能的影响，
   发现【① 存在性能断崖的临界 k*；② 不同方法的退化曲线形状不同；
   ③ 信息边界不等于能力边界】，
   并据此提出【一种拓扑信息最小可见性策略】，在【检测性能】上
   相对【完全公开拓扑】提升【X 个百分点】。"

候选 C：
  "在【攻击者保持时序平滑】的场景下，用【多步预测残差 + 状态跳变检测】，
   解决【单快照方法对隐蔽 FDI 完全失效】的问题，
   相对【快照 BDD】在【AUC】上从【0.4890】提升到【0.9987】，
   并且【给出该方法的失效边界（攻击者连续篡改时的性能上界）】。"
```

> **注意每个版本的最后一句都是"并且……"**。**这一句是你的"差异化"** —— 它回答了"那又怎样"。没有这一句，你的贡献就只是"我做了个实验/我加了个模块"。

### 三、创新点的自我拷问（**五连问，逐个过**）

**这五问是审稿人的思维路径。你必须自己先问一遍。**

| # | 拷问 | 你的回答要求 | 如果答不上 |
|---|---|---|---|
| 1 | **这不是早就有了吗？** | 指出至少 3 篇最接近的工作，并说清你和它们的**具体差异** | 回去读文献，或换角度 |
| 2 | **差异重要吗？** | 说清这个差异**导致什么实际后果**（不只是"指标高了 0.5%"） | 说明差异太小，需要重新设计 |
| 3 | **换一个方法能不能达到同样效果？** | 说明你的手段的**必要性**（不是"也能用别的"） | 说明手段不是关键，贡献不在方法 |
| 4 | **这个结论在什么条件下不成立？** | 明确指出失效边界 | **答不上来 = 你对方法理解不够** |
| 5 | **如果我是审稿人，我最想攻击哪一点？** | 提前准备回应 | 答不上来 = 你会被问倒 |

**第 4 问是最容易被忽略、也最能体现水平的**：

```
❌ 弱的表述：
   "本方法在 IEEE 14 和 118 节点系统上均取得最优性能。"
   → 审稿人：那别的场景呢？

✅ 强的表述：
   "本方法在【量测冗余度 ≥ 1.5、攻击者知识 k ≤ M/2】的条件下
     显著优于基线。当 k 接近 M 时，所有方法的性能均退化至
     随机水平 —— 这与信息论下界一致，说明该条件下问题不可解。
     我们的方法不声称能突破这个下界。"
   → 审稿人：作者清楚方法的边界，可信度高
```

> **主动声明失效边界，会显著提升论文的可信度。** 这是"诚实"在学术写作里的直接收益。

### 四、和电网安全的关系

**电网安全方向的方法设计有三个额外要求**：

| 要求 | 含义 | 具体做法 |
|---|---|---|
| **物理可解释** | 检测结果要能对应到具体的物理量 | 报告"哪些节点/量测贡献了异常分数" |
| **计算可接受** | 现场装置资源受限 | 报告推理延迟、参数量、显存 |
| **失效可说明** | 必须说清在什么攻击下会失效 | 给出"性能 vs 攻击强度"曲线 |

**一个具体的差异化设计（针对候选 B）**：

```
大多数检测方法论文的 Method 节结构：
   输入 → 特征 → 模型 → 输出异常分数

你的 Method 节可以多一节：
   【信息边界感知的阈值策略】
   
   观察：当攻击者知识 k 增大时，攻击的"物理不一致性"下降，
         固定阈值必然导致性能断崖。
   做法：让阈值随"可检测性指标"自适应调整
         τ_adaptive = τ_0 · f(κ)
         其中 κ 是一个不需要知道 k 就能估计的"可检测性代理量"
   贡献：这不是新模型，而是【一个新设计原则】——
         "检测器的阈值应当与攻击者的信息能力耦合"
   ⇒ 这个贡献【很小但真实】，且与你的主线（信息边界）直接相关
   ⇒ 比硬造一个"新网络结构"诚实得多，也更容易辩护
```

> **上面这个思路值得你认真考虑**。它的好处是：**不需要发明新网络、不需要大量算力、与你的核心发现直接挂钩、且结论即使是负面的也能写。** 这符合 Day 110 里"选题必须稳健"的要求。

## Day 113 —— 实验矩阵设计：主实验 + 消融 + 鲁棒性

> **一句话**：实验不是"跑几个看结果"，是**先写一张空表格，再往格子里填数** —— 表格写不出来，说明你还没想清要证明什么。

### 一、五类实验及其各自要回答的问题

| 类别 | 回答什么问题 | 最少配置 | 你的工作量 |
|---|---|---|---|
| **主实验** | 我的方法在标准设置下表现如何？ | 1 个主表 + 1 张核心图 | 大 |
| **消融** | 我的每个设计选择是否必要？ | 每个创新组件去掉一次 | 中 |
| **鲁棒性** | 在攻击/扰动下是否稳定？ | 3-5 个扰动强度 × 多种子 | 大 |
| **敏感性** | 关键超参如何影响结果？ | 2-3 个超参 × 4-6 个取值 | 中 |
| **效率** | 计算成本是否可接受？ | 延迟 + 参数量 + 显存 | 小（但常被漏做） |

> **最后一行"效率"是最容易漏做、又最容易做的**：跑一次前向传播记时间就行。**但它对电网场景特别重要**（现场是边缘装置），**审稿人一定会问。**

### 二、主实验表：先写空表

**候选 B 的主实验表（这是你的核心产出）**：

```
表 1：不同攻击者知识水平下的检测性能
       （IEEE 14 节点，攻击强度 ε = 3σ，20 次重复的均值 ± 标准差）

| 攻击者知识 k | BDD (AUC) | SVM (AUC) | RF (AUC) | LSTM-AE (AUC) | ST-GNN (AUC) |
|---|---|---|---|---|---|
| k = 0（无信息）   |           |           |          |               |              |
| k = 1             |           |           |          |               |              |
| k = 2             |           |           |          |               |              |
| k = 4             |           |           |          |               |              |
| k = 8             |           |           |          |               |              |
| k = M/2           |           |           |          |               |              |
| k = M（完全信息） |           |           |          |               |              |

【预期】k 增大时性能下降；完全信息下所有方法接近 0.5（信息论下界）
【核心看点】下降的形状：是线性？是断崖？不同方法形状是否不同？
```

**为什么"先写空表"这个动作重要**：

```
① 强迫你想清楚【对比哪些方法】→ 发现漏了某条技术路线
② 强迫你想清楚【控制哪些变量】→ 发现某个变量没控制住
③ 强迫你想清楚【重复几次】→ 意识到需要多种子
④ 空表能拿给导师看 → 半小时的反馈省下两周的返工
```

### 三、消融实验：每个设计选择都要被验证

**原则：论文里出现的每一个"我们设计了……"，都要有一条消融记录。**

| 消融项 | 做法 | 要证明什么 |
|---|---|---|
| **去掉自适应阈值** | 用固定阈值替代 `τ_adaptive` | 阈值策略是否必要 |
| **换 k 的选取方式** | 随机 / 最大度 / 局部 | 结论是否对 k 的定义敏感 |
| **换检测器骨干** | LSTM-AE → MLP-AE | 结论是否依赖特定骨干 |
| **去掉某个特征** | 移除图结构特征 / 时序特征 | 每个特征来源的贡献 |
| **换数据划分** | 随机划分 vs 按时间划分 | 是否存在数据泄漏导致的高估 |

> **最后一项特别重要**：**如果你用随机划分做时序任务，会有严重的数据泄漏**（训练集里有测试时刻的相邻样本）。**按时间划分的结果通常明显更差** —— 但它是诚实的。审稿人一定会问划分方式。

### 四、和电网安全的关系

**电网场景实验设计的三条特殊要求**：

| 要求 | 原因 | 做法 |
|---|---|---|
| **必须报告固定 FPR 下的 TPR** | 运维实际关心"每天最多误报 N 次" | 报告 TPR@FPR=0.1% / 1% |
| **必须做时间划分而非随机划分** | 随机划分有数据泄漏，且不符合部署场景 | 前 70% 时间训练，后 30% 测试 |
| **必须报告"物理可行性"过滤的效果** | 攻击样本是否满足物理约束，直接影响难度 | 报告"过滤前后"的攻击成功率 |

**一个具体的实验设计（把"物理可行性"变成实验变量）**：

```
设置两组攻击生成方式：
  组 1：无约束攻击（任意注入向量）
  组 2：物理可行攻击（满足线路容量 + 电压范围 + 幅度约束）

对比：检测器在两组攻击下的性能差异
⇒ 如果组 2 明显更难检测（预期如此），这就说明：
   "不加物理约束的攻击评估会高估检测器性能"
⇒ 这是一个【评估方法学】层面的贡献，成本很低，价值不小
```

### 五、鲁棒性实验：对抗与扰动

**候选 B 的鲁棒性实验设计**：

| 扰动类型 | 强度设置 | 目的 |
|---|---|---|
| **攻击强度 ε** | 1σ, 2σ, 3σ, 5σ, 10σ | 检测性能随攻击幅度如何变化 |
| **量测噪声** | σ 的 0.5×, 1×, 2×, 4× | 噪声增大时方法是否崩 |
| **攻击者数量** | 单攻击者 vs 多攻击者协同 | 多攻击者是否更难检测 |
| **时序一致性** | 单快照 vs 连续 T_win 个快照 | 时序先验的边界（**这是候选 C 的种子**） |
| **拓扑扰动** | 线路断开 / 负荷突变 | 分布漂移下的稳定性 |

**一个必须注意的陷阱**：

```
❌ 常见错误：
   只报告"我的方法在最强攻击下 F1 下降最少"
   → 但没报告"在最强攻击下所有方法都不可用"
   → 审稿人：那你的方法在绝对意义上还有用吗？

✅ 正确做法：
   同时报告【相对排名】与【绝对性能】
   并明确指出："当 ε > 5σ 时，所有方法的 AUC 均低于 0.7，
   此时该场景下的检测问题实际上不可解，需要其他防御手段。"
```

### 六、机时核算：**1 小时/天能不能做完**

**这一步不做，你的实验计划就是空谈。**

```
【逐项估算】（以候选 B 为例，IEEE 14 节点）

单次训练（LSTM-AE，50k 参数，5000 条样本，50 epoch）：
   CPU 上约 8 分钟

单次训练（ST-GNN，300k 参数，同样数据）：
   CPU 上约 25 分钟；若有 GPU 约 3 分钟

【实验总量】
  主实验：5 个检测器 × 7 个 k 值 × 5 个种子 = 175 次
          其中 BDD / SVM / RF 很快（秒级），可忽略
          深度学习 2 个模型 × 7 × 5 = 70 次
             LSTM-AE：70 × 8 min = 560 min ≈ 9.3 小时
             ST-GNN ：70 × 25 min = 1750 min ≈ 29 小时  ← 【瓶颈】
  消融：5 项 × 5 种子 × 2 模型 = 50 次 ≈ 15 小时
  鲁棒性：5 类扰动 × 4 强度 × 5 种子 × 2 模型 = 200 次 ≈ 60 小时 ← 【超预算】
  敏感性：3 超参 × 5 取值 × 3 种子 = 45 次 ≈ 12 小时
  效率：10 次 ≈ 1 小时

【合计】约 126 小时（CPU）
【你的预算】每天 1 小时，其中约 40 分钟可用于跑实验 → 8 周约 37 小时

⇒ 结论：【严重超预算，必须削减】

【削减方案】（按优先级）
  ① ST-GNN 换成更轻的模型，或用 GPU（若实验室有）→ 省 25 小时
  ② 鲁棒性实验只保留最关键的 2 类扰动（攻击强度 + 时序一致性）
     且强度档位从 4 减到 3 → 省 40 小时
  ③ 种子数从 5 减到 3（但要报告这一点，并说明理由）
     → 省约 25 小时
  ④ 消融只做最核心的 3 项 → 省 6 小时

【削减后】约 32 小时 ⇒ 【可行】
```

> **上面这段核算你应该真的动手做一遍。** 数字可以变，**但"先算再动手"这个习惯是必须的** —— 我见过太多人做到一半发现机时不够，被迫砍实验，砍到最后主结论都不成立了。

**一个重要的心态**：

```
如果你的核算结果是"做不完"，这不是坏事 ——
这是你在【动手前】发现问题，而不是在【截止日期前】发现。

两种应对：
  ① 砍实验（减种子、减档位、减扰动类型）→ 但必须报告你砍了什么、为什么
  ② 换选题（回顾 Day 110 的打分表，把"可行性"权重调高）
```

## Day 114 —— 结果分析与可视化：让图说话

> **一句话**：图不是"把数据画出来"，是**把结论画出来** —— 一张好图让审稿人在 5 秒内看懂你的核心发现。

### 一、图的类型与用途

| 图的类型 | 适合表达 | 你的场景 |
|---|---|---|
| **折线图** | 一个量随另一个量变化（**你的核心图**） | k vs 检测性能的退化曲线 |
| **柱状图 + 误差棒** | 多个离散类别对比 | 五种检测器在固定 k 下的对比 |
| **箱线图** | 分布与离群（多种子结果） | 20 次重复的性能分布 |
| **热力图** | 两个变量的联合影响 | k × ε 的二维性能图 |
| **散点图** | 两个量的相关性 | "可检测性代理量" vs 实际性能 |
| **雷达图** | 多维综合对比 | ⚠️ **慎用**：面积误导性强，审稿人反感 |
| **小提琴图** | 分布形状 + 密度 | 替代箱线图，信息更多但更复杂 |

> **雷达图慎用的原因**：它的面积与实际数值不成比例，**容易造成视觉误导**。如果你的多维对比确实需要，用"平行坐标图"或"分组柱状图"。

### 二、核心图的三个层次

**同一份数据，可以画成三个层次的图。你要画到第 3 层。**

```
【第 1 层：描述】（不够）
   标题："不同 k 值下各检测器的 AUC"
   图：5 条线，随 k 上升而下降
   读者得到：一个下降趋势
   → 问题：审稿人会问"所以呢？"

【第 2 层：对比】（合格）
   标题："不同检测器的性能随攻击者知识量的退化速率存在显著差异"
   图：5 条线 + 标注每条线的下降斜率
   读者得到：ST-GNN 退化最快，RF 退化最慢
   → 有了对比，但还没有机制

【第 3 层：机制】（好）
   标题："检测性能在 k* = 4 处出现断崖，该临界点与量测冗余度一致"
   图：5 条线 + 【标注 k* 位置】+ 【叠加量测冗余度的参考线】+ 【标注理论下界】
   读者得到：一个可解释的现象 + 一个可验证的规律
   → 这才叫"让图说话"
```

**具体怎么画第 3 层的图**：

```python
import numpy as np
import matplotlib.pyplot as plt

# 假设数据：k 值、五种检测器的 AUC（含标准差）
k_vals = np.array([0, 1, 2, 4, 8, 10, 14])
methods = {
    "BDD":     np.array([0.52, 0.61, 0.71, 0.68, 0.55, 0.51, 0.50]),
    "SVM":     np.array([0.61, 0.74, 0.83, 0.79, 0.66, 0.58, 0.51]),
    "RF":      np.array([0.64, 0.78, 0.86, 0.83, 0.72, 0.64, 0.52]),
    "LSTM-AE": np.array([0.70, 0.86, 0.93, 0.90, 0.79, 0.70, 0.53]),
    "ST-GNN":  np.array([0.73, 0.89, 0.95, 0.94, 0.88, 0.81, 0.55]),
}
std = {m: 0.02 * np.ones_like(v) for m, v in methods.items()}   # 示意

fig, ax = plt.subplots(figsize=(6.5, 4.2), dpi=300)
markers = {"BDD": "o", "SVM": "s", "RF": "^", "LSTM-AE": "D", "ST-GNN": "*"}
colors  = {"BDD": "#888888", "SVM": "#4C72B0", "RF": "#55A868",
           "LSTM-AE": "#C44E52", "ST-GNN": "#8172B2"}

for m, v in methods.items():
    ax.errorbar(k_vals, v, yerr=std[m], marker=markers[m], color=colors[m],
                capsize=3, linewidth=1.6, markersize=6, label=m)

# 【第 3 层的三个关键标注】
ax.axvline(4, color="black", linestyle="--", linewidth=1.0, alpha=0.6)
ax.annotate(r"临界点 $k^*=4$" + "\n性能断崖",
            xy=(4, 0.93), xytext=(5.6, 0.99),
            arrowprops=dict(arrowstyle="->", color="black", lw=1.0),
            fontsize=9, ha="left", va="center")

ax.axhline(0.5, color="red", linestyle=":", linewidth=1.2)
ax.text(0.2, 0.515, "随机水平（AUC = 0.5，信息论下界）",
        color="red", fontsize=8.5, va="bottom")

ax.axhspan(0.5, 0.6, color="red", alpha=0.06)   # 不可用区
ax.text(13.6, 0.545, "不可用区", color="red", fontsize=8, ha="right")

ax.set_xlabel("攻击者掌握的 $H$ 行数 $k$", fontsize=10)
ax.set_ylabel("检测 AUC", fontsize=10)
ax.set_title("检测性能随攻击者知识量的退化规律", fontsize=11)
ax.set_ylim(0.45, 1.02)
ax.set_xticks(k_vals)
ax.legend(frameon=False, fontsize=8.5, loc="lower left", ncol=2)
ax.grid(alpha=0.25, linewidth=0.6)
ax.spines[["top", "right"]].set_visible(False)

fig.tight_layout()
fig.savefig("fig_degradation.pdf")     # 【矢量格式，投稿首选】
fig.savefig("fig_degradation.png", dpi=300)
```

**这张图为什么合格**：

| 元素 | 作用 |
|---|---|
| 误差棒 | 显示多种子的波动，不是只给均值 |
| 垂直虚线 + 标注 | 指出临界点 `k*`，把"趋势"变成"现象" |
| 水平红点线 | 给出"随机水平"参照，说明"退化到底意味着什么" |
| 阴影区 | 标出"不可用区"，诚实说明方法的边界 |
| 无边框 + 淡网格 | 视觉干净，符合期刊风格 |
| 矢量导出 | 放大不失真 |

### 三、五个常见错误（**逐个避开**）

| 错误 | 为什么错 | 正确做法 |
|---|---|---|
| **截断 y 轴** | 从 0.9 开始画，让 0.5% 的差异看起来像翻倍 | 关键对比必须从 0 或从有意义的基准开始，并在图注说明 |
| **只画均值不画方差** | 掩盖了随机性，读者无法判断差异是否显著 | **必须画误差棒 / 箱线图**（回顾 Day 52） |
| **颜色过多或过近** | 5 条以上的线用相近颜色，读者分不清 | ≤ 6 条线；用色盲友好配色（如 viridis / ColorBrewer） |
| **一图塞太多信息** | 想在一张图里说三件事，结果一件都没说清 | 一图一结论；拆成多张或放附录 |
| **图中文字与正文不一致** | 图里叫 "Method A"，正文叫 "Our approach" | 建立术语表，全文统一（回顾 Day 57） |

**"截断 y 轴"的补充说明**：

```
确实有需要放大差异的场景（如 0.95 vs 0.96 的对比）。
这时正确的做法是：
  ① 主图从 0（或 0.5）开始，展示完整尺度
  ② 局部放大图放在【插图】里，并明确标注"zoom-in"
  ③ 在图注里说明"局部放大显示"
⇒ 关键是【让读者知道你在放大】，而不是偷偷放大
```

### 四、和电网安全的关系

**电网安全方向的图有三条额外要求**：

| 要求 | 原因 | 做法 |
|---|---|---|
| **必须标注物理意义** | 电力审稿人关心"这个数字对应什么物理量" | 轴标签写 `电压幅值 (p.u.)` 而不是 `feature_3` |
| **必须标注攻击条件** | 同一张图在不同攻击下含义不同 | 图注写明 `ε = 3σ, k = 4, 随机选取` |
| **必须包含基线参照** | 没有参照的曲线无法判断好坏 | 至少画一条 BDD 基线 + 随机水平线 |

## Day 115 —— 论文成稿：六章节逐节写

> **一句话**：写论文的顺序**不是从摘要开始**，而是**从图表开始** —— 图表是骨架，文字是长在骨架上的肉。

### 一、写作顺序（**先改掉"从 Abstract 开始写"的习惯**）

```
正确的写作顺序：

  第 1 步：定图表（半天）
    · 核心图（Day 114 已画）
    · 主实验表（Day 113 已定空表）
    · 方法总图（Day 112 已画）
    ⇒ 这三样定下来，论文的骨架就定了

  第 2 步：写 Method（1-2 天）
    · 因为有图，写起来最快
    · 而且这部分最不容易被推翻（方法是你自己设计的）

  第 3 步：写 Experiment（1-2 天）
    · 表格和图的说明 + 分析
    · 每张表下面必须有一段"所以呢"

  第 4 步：写 Introduction（1 天）
    · 此时你已经知道结论了，倒推着写动机最准

  第 5 步：写 Related Work（半天）
    · 前面读文献的笔记直接用

  第 6 步：写 Conclusion（半天）
    · 最轻松，但要留出"局限与未来工作"

  第 7 步：最后写 Abstract（半天）
    · 全文写完再写摘要，四句话套路
    · 摘要里出现的每个数字，正文里必须能找到
```

**为什么这个顺序**：

| 顺序 | 理由 |
|---|---|
| 图表先定 | 图表决定"要证明什么"，文字只是解释图表 |
| Method 早写 | 它是唯一不依赖结果的部分；而且写的过程中常会发现方法描述不清的地方，能及时回去补实验 |
| Intro 后写 | 你只有知道结论，才知道动机该往哪个方向讲 |
| Abstract 最后写 | 摘要是全文的压缩，必须在全文成型后写 |

### 二、六章节的段落骨架

#### Abstract（150-250 词，四句话）

```
第 1 句：背景 + 问题
  "电力系统状态估计面临虚假数据注入攻击（FDIA）的威胁，
   现有检测方法普遍假设攻击者完全掌握网络拓扑信息。"

第 2 句：gap（别人没做什么）
  "然而现实中攻击者通常只掌握部分拓扑信息，
   其知识量对检测性能的影响尚无系统研究。"

第 3 句：本文做了什么 + 主要发现（**必须带数字**）
  "本文系统评估了五种检测方法在攻击者知识量 k 从 0 到 M 变化时的
   性能退化规律，发现：(i) 性能在 k* = 4 处出现断崖式下降；
   (ii) 基于时序的方法退化最快但绝对性能最高；
   (iii) 完全信息攻击下所有方法的 AUC 均降至 0.5 附近。"

第 4 句：意义
  "该结果为拓扑信息保护策略提供了量化依据：
   将可见拓扑信息限制在 k < 4 可使现有检测器保持可用。"
```

> **第 3 句是摘要的心脏**。**没有数字的摘要 = 没有结论的摘要。** 审稿人扫摘要时，找的就是这句话。

#### Introduction（4-5 段）

```
第 1 段：领域背景（3-4 句）
   状态估计 → BDD → FDIA 的威胁

第 2 段：已有工作与局限（4-5 句）
   三条技术路线的代表工作 + 它们的共同假设（完全信息 / 无信息）

第 3 段：本文的 gap 与动机（3-4 句）
   现实中攻击者的知识是【连续谱】，缺少系统研究

第 4 段：本文贡献（**列表形式，3 条**）
   · 首次系统量化了攻击者知识量与检测性能的关系
   · 发现三个非平凡现象（临界点 / 曲线形状差异 / 信息≠能力）
   · 提出一种拓扑信息最小可见性策略

第 5 段：论文组织（2-3 句）
   "本文其余部分组织如下：第 2 节……"
```

**贡献列表的写法规范**：

```
❌ 弱：
   "本文提出了一个新方法，并在实验中取得了良好效果。"

✅ 强：
   "本文的主要贡献如下：
    (1) 据我们所知，这是首个系统研究攻击者部分拓扑信息
        对 FDIA 检测性能影响的工作，覆盖 k ∈ [0, M] 的完整范围；
    (2) 我们发现检测性能在 k* = 4 处出现断崖，且该临界点与
        量测冗余度相关（Spearman ρ = 0.83, p < 0.01）；
    (3) 基于该发现，我们提出一种拓扑信息最小可见性策略，
        在保持检测性能的同时将攻击成功率降低 34%。"
   → 每条贡献都有可验证的量化描述
```

#### Related Work（按"技术线"分节，不是按"论文"罗列）

```
建议结构：
  2.1 FDIA 攻击模型（电力安全线）
  2.2 检测方法（按三条技术路线分三小段）
  2.3 对抗鲁棒性与信息边界（AI 安全线）
  2.4 小结：现有工作的共同局限

每段的结构（**这个模板非常有用**）：
  ① 这一类方法的共同思路（1 句）
  ② 代表工作（2-3 句，引用 [x-y]）
  ③ 它们的局限（1-2 句）—— 【必须写】
  ④ 与本文的关系（1 句）
```

> **"只罗列不评价"是最常见的 Related Work 病**（回顾 Day 57）。**每段结尾必须有一句局限。** 而且这个局限要指向你的 gap —— 否则审稿人会问"你列这些和我有什么关系"。

#### Method（3-4 小节）

```
3.1 问题形式化
   · 系统模型：z = Hx + e
   · 攻击模型：z_bad = z + a
   · 威胁模型（**Day 111 写的那份直接搬过来**）
   · 符号表（如果符号超过 15 个，做一个表）

3.2 攻击生成方法
   · k 行信息的利用方式
   · 优化目标与约束
   · 求解过程（伪代码）

3.3 检测方法（被评估的五个）
   · 每个一小段，说清输入输出与关键设计
   · 不重复别人的方法细节，引用即可

3.4 信息边界感知的阈值策略（**你的方法贡献**）
   · 动机（从 3.2 的发现自然引出）
   · 形式化
   · 与固定阈值的区别

3.5 复杂度分析
   · 时间 / 空间复杂度
   · 推理延迟的实测值
```

#### Experiment（4-5 小节）

```
4.1 实验设置
   · 数据生成（pandapower 版本 + 算例 + 生成参数）
   · 实现细节（框架版本、超参、随机种子）
   · 评估指标（AUC / F1 / TPR@FPR）
   · 基线说明（**为什么选这五个**）

4.2 主实验（表 1 + 图 1）
   · 先陈述事实（"表 1 显示……"）
   · 再给解释（"这一现象的原因是……"）
   · 最后给含义（"这意味着……"）

4.3 消融实验（表 2）
4.4 鲁棒性与敏感性（图 2 + 图 3）
4.5 效率分析（表 3）
4.6 讨论：失效边界（**主动写**）
```

> **每个表/图下面的三段式（事实 → 解释 → 含义）是本节的写作公式。** 只写"表 1 显示我们的方法最好"是远远不够的。

#### Conclusion（1-2 段）

```
第 1 段：回顾做了什么 + 主要结论（不带新信息）
第 2 段：局限与未来工作（**必须写，而且要诚实**）

局限的规范写法：
  "本文的评估基于 pandapower 仿真数据。真实电网的量测噪声分布、
   通信延迟与设备老化效应可能与仿真存在系统性差异，
   因此本文的结论在真实部署场景下的适用性有待验证。
   未来工作包括：在公开的真实电网数据集上验证，
   以及研究攻击者具备推断能力（而非直接获取拓扑）时的性能退化规律。"
```

### 三、写作中的四个硬规范

| 规范 | 要求 | 检查方法 |
|---|---|---|
| **术语一致** | 全文一个概念一个叫法 | 建术语表，投稿前核对（回顾 Day 57） |
| **符号一致** | 同一符号全文含义不变 | 建符号表；改符号时全局搜索替换 |
| **时态** | 方法用现在时，实验用过去时 | 逐段检查 |
| **数字精度** | 统一小数位（如 AUC 保留 3 位） | 表格里数字位数不统一最显业余 |

**"符号一致"的具体陷阱**：

```
常见问题：
  · 第 3 节用 M 表示量测数，第 4 节用 M 表示节点数
  · 第 3 节用 τ 表示阈值，第 4 节用 τ 表示时间窗口长度
  · H 有时写 H，有时写 H（加粗），有时写 𝐇

⇒ 做法：在 Method 节开头放一张【符号表】，全文严格按它写
⇒ 改符号时用编辑器的全局替换，不要手工改
```

### 四、和电网安全的关系

**电网安全论文的四个额外写作要求**：

| 要求 | 具体做法 | 为什么 |
|---|---|---|
| **威胁模型要独立成节或独立小节** | 放在 Method 开头，标号清晰 | 这是安全论文的地基，审稿人第一眼找它 |
| **物理量必须给单位与量纲** | `P = 5.2 MW`，不写 `P = 5.2` | 电力审稿人对此极敏感 |
| **必须写"不在范围内"** | 在 Introduction 或 Discussion 里 | 防止审稿人要求你做范围外的事 |
| **必须披露数据来源与仿真设置** | pandapower 版本 + 算例来源 + 生成参数 | 可复现性的最低要求 |

**一个具体的"讨论节"写法（诚实版本）**：

```
✅ 诚实且有分量的讨论节写法：

  "本文的结论有三条边界，我们明确声明：

   ① 【数据边界】所有实验基于 pandapower 仿真。仿真数据的量测噪声
      服从独立高斯分布，而真实系统的量测误差存在时间相关性。
      这可能使本文报告的检测性能被高估。

   ② 【攻击者边界】我们假设攻击者不掌握检测器参数（黑盒）。
      若检测器为公开方法，该假设不成立，攻击者可能构造更强的攻击。

   ③ 【规模边界】我们在 IEEE 14 与 118 节点系统上验证。
      对于数千节点的大规模系统，量测冗余度与图结构的统计特性不同，
      结论是否成立需要进一步验证。

   我们不声称本方法能突破完全信息攻击下的信息论下界。"
```

> **这段文字的作用**：它让审稿人觉得"作者清楚自己在做什么"。**主动写出边界，比被审稿人指出边界，结果是完全不同的** —— 前者是严谨，后者是漏洞。

## Day 116 —— 复盘 + 内部预答辩

> **一句话**：预答辩不是为了"讲得好看"，是为了**在被审稿人问倒之前，先被自己人问倒** —— 你在这里被问住的每一个问题，都是一次免费的审稿意见。

### 一、预答辩 PPT 结构（10-12 页，15 分钟）

| 页 | 内容 | 时间 | 关键要求 |
|---|---|---|---|
| 1 | 标题 + 作者 + 单位 | 10 s | — |
| 2 | 一句话概括（研究问题 + 核心发现） | 40 s | **这页最重要**，听众凭它决定要不要认真听 |
| 3 | 背景：为什么这个问题重要 | 1.5 min | 用真实事件或数据说明痛点 |
| 4 | 已有工作的局限（gap） | 1.5 min | 一张对比表，一眼看出空白 |
| 5 | 本文贡献（3 条） | 1 min | 与贡献列表一致 |
| 6 | 威胁模型（六要素） | 1.5 min | 一张图 + 六行说明 |
| 7 | 方法总图 | 2 min | 用 Day 112 画的那张 |
| 8 | 主实验结果（核心图） | 2.5 min | **这里要讲得最慢最清楚** |
| 9 | 消融 + 鲁棒性 | 1.5 min | 表格 + 一句结论 |
| 10 | 效率与部署考虑 | 1 min | 延迟 + 参数量 |
| 11 | 局限与未来工作 | 1 min | **主动讲，不要等被问** |
| 12 | 结论 + 致谢 | 30 s | — |

> **第 2 页和第 8 页是全部的重点。** 如果听众只能记住两件事，就是这两页。

### 二、15 分钟讲述脚本（**逐字稿骨架**）

```
【0:00-0:40】开场（第 1-2 页）
  "各位老师好，我汇报的题目是《攻击者拓扑信息量对 FDIA 检测性能的影响研究》。
   用一句话概括：我们系统测量了攻击者掌握部分拓扑信息时，
   五种检测方法的性能退化规律，发现性能在 k*=4 处出现断崖，
   并据此提出了一种拓扑信息最小可见性策略。
   下面我分四个部分汇报。"

【0:40-4:00】背景与 gap（第 3-5 页）
  "状态估计是电网调度的基础……（背景 3 句）
   现有的检测方法有一个共同假设……（gap 2 句）
   但现实中……（动机 2 句）
   本文的贡献有三条：……（贡献列表）"

【4:00-7:30】威胁模型与方法（第 6-7 页）
  "我们的威胁模型是……（六要素逐个说，每个一句）
   方法上，我们评估了覆盖三条技术路线的五种检测器……
   此外我们提出一个信息边界感知的阈值策略……"

【7:30-12:00】实验（第 8-10 页）★ 重点
  "这是我们的核心结果。（指着核心图）
   横轴是攻击者知识量 k，纵轴是检测 AUC……
   有三点值得注意：
     第一，性能在 k*=4 处出现断崖，这与量测冗余度一致；
     第二，不同方法的退化速率不同，RF 最慢；
     第三，k 接近 M 时所有方法都降到随机水平，
           这与信息论下界一致，我们不声称能突破它。
   消融实验显示……效率方面……"

【12:00-14:00】局限与未来（第 11 页）
  "本文有三条边界：数据边界、攻击者边界、规模边界……
   未来工作包括……"

【14:00-15:00】结论（第 12 页）
  "总结：我们量化了……发现了……提出了……谢谢各位老师。"
```

**讲述的三个技巧**：

| 技巧 | 做法 | 反例 |
|---|---|---|
| **先说结论再说过程** | "结论是 X，下面说为什么" | 从头按时间顺序讲 |
| **讲图不讲字** | 指着图说"这条线"，不要念 PPT 上的字 | 把 PPT 当提词器 |
| **主动说边界** | 在"局限"页主动讲，不等被问 | 被问到时才承认 |

### 四、和电网安全的关系

**电网安全方向预答辩的三个特殊问题**：

| 问题 | 背后关切 | 回答要点 |
|---|---|---|
| **"你用的数据是真实的吗？"** | 涉密与合规 | 明确说"全部为公开算例仿真"，并说明为什么（合规 + 可复现） |
| **"你的方法能部署到现场吗？"** | 工程可行性 | 报告延迟与参数量；诚实说明边缘装置的约束 |
| **"你的攻击脚本会不会被滥用？"** | 伦理与安全 | 说明脚本仅针对仿真环境，且论文中的攻击构造是已有公开方法的应用 |

**第三点值得单独说**：

```
在安全方向发表攻击方法，是一个需要谨慎处理的问题。

处理原则（建议写进论文的伦理声明）：
  ① 攻击构造基于已公开发表的理论（如 Liu 2009），本文未提出新的攻击能力
  ② 所有实验在仿真环境进行，不涉及任何真实系统
  ③ 论文的主要目的是【提升检测能力】，攻击分析服务于防御
  ④ 代码开源时会移除任何可能被直接滥用的部分（如需，可申请获取）
```

### 五、模拟质疑：红队演练

**做法：找 2-3 个同学，让他们扮演"最刻薄的审稿人"。**

```
演练规则：
  ① 你讲 15 分钟，他们打断提问（模拟真实答辩）
  ② 他们必须提出至少 3 个"致命质疑"（不是礼貌性提问）
  ③ 全程录音，回去听自己哪里卡壳了

三个必被问的方向（提前给"红队"提示）：
  · "你这个方法在真实数据上能 work 吗？"
  · "你的提升是不是调参调出来的？"
  · "这个现象我早就知道了，你的新意在哪？"

演练后的动作：
  · 把卡壳的问题记下来 → 逐个补答案 → 补实验或补论证
  · 如果某个问题补不了 → 【考虑修改论文的表述范围】
    （把过强的声称改弱，而不是硬撑）
```

**"改声称"比"补实验"更常见也更明智**：

```
❌ 硬撑：
   被问"你的方法在大规模系统上有效吗"
   → 回答"应该有效"
   → 审稿人：你没有证据

✅ 改声称：
   把"本方法在电力系统中有效"
   改为"本方法在 IEEE 14 与 118 节点系统上有效，
        大规模系统的适用性有待验证"
   → 声称与证据匹配，无懈可击
```
