## Day 89 —— 从检测到决策：防御者到底要做什么

> **一句话**：检测器的输出是一个**判断**（代价为零，错了可以改），决策器的输出是一个**动作**（代价可能不可逆）—— 这是两类完全不同的问题。

### 一、检测 ≠ 决策：三个维度的差异

| 维度 | 检测 | 决策 |
|---|---|---|
| **输出** | 标签 / 分数（0/1、`p(attack)`） | 动作（切 3 号母线 20% 负荷） |
| **错的代价** | 误报 → 多一次人工核查；漏报 → 攻击得逞 | 误动 → **可能直接造成停电** |
| **可逆性** | ✅ 完全可逆（重新判定即可） | ❌ 切负荷 / 断线**不可逆**（或代价极高） |
| **时间尺度** | 秒级~分钟级（一个检测周期） | 毫秒级（保护）到分钟级（调度） |
| **评价指标** | PR-AUC、误报率 @ 召回率 | 失负荷量、越限次数、动作次数、约束违反率 |
| **数据需求** | 大量带标签样本 | **大量交互样本**（比标签贵得多） |

> **最关键的一行是"可逆性"。**
>
> 检测模型错了，你改一下阈值就完事。决策模型错了，可能是一条 220 kV 线路被拉停。
>
> **这决定了：决策类方法的评估标准必须比检测类严格得多**，而且必须包含"最坏情况"分析。

### 二、电网防御者的动作空间

**先看清楚防御者能做什么，再决定用不用 RL。** 很多"用 RL 做防御"的论文，动作空间设计得根本不像真实电网能执行的操作。

| 动作 | 具体形式 | 时间尺度 | 可逆性 | 代价 | 真实执行者 |
|---|---|---|---|---|---|
| **切负荷（UFLS）** | 按馈线/节点切除一定比例 | 100 ms ~ 秒 | ❌ 不可逆 | **高**（直接经济损失 + 用户投诉） | 低频减载装置 / 调度 |
| **拓扑重构** | 开合开关改变网络结构 | 秒 ~ 分钟 | ⚠️ 可逆但开关有寿命 | 中 | 调度员 |
| **调整发电出力** | 增/减机组出力 | 分钟 ~ 十几分钟 | ✅ 可逆 | 低 | AGC / 调度 |
| **调整电压设定值** | 改发电机 `V_set`、投切电容器 | 分钟 | ✅ 可逆 | 低 | 调度 / AVC |
| **隔离设备** | 断开被攻陷的 RTU / 通道 | 秒 | ⚠️ 需人工确认 | 中（失去量测） | 运维 |
| **限流 / 转供** | 限制断面潮流、负荷转供 | 分钟 | ✅ 可逆 | 中 | 调度 |
| **提高告警等级 / 人工介入** | 通知调度员复核 | 秒 | ✅ 可逆 | **极低** | 系统 |

**这张表最重要的一列是"代价"和"可逆性"：**

```
代价低 + 可逆       → 可以放心交给自动化（调压、AGC）
代价高 + 不可逆     → 必须人工确认（切负荷、断线）

⇒ 一个诚实的设计结论：
   在电网里，RL 最合理的落点是"代价低 + 可逆"的那一档，
   或者作为"代价高 + 不可逆"动作的【建议生成器】，由人来按下按钮。
```

**❌ / ✅ 对照**：

```
❌ 差的设计：
   动作空间 = {切 1~14 号母线的 0~100% 负荷}，共 15 个连续动作维度，
   让 RL 直接输出并自动执行。
   → 审稿人：谁给你权限自动切负荷？误动作谁负责？

✅ 好的设计：
   动作空间 = {维持现状, 调压, 拓扑重构(从候选集中选), 建议切负荷(需人工确认)}，
   且切负荷动作有硬性上界（单次 ≤ 全网负荷的 5%，且不切医院/关键负荷）。
   → 明确说明了动作的可行域、执行主体与安全兜底。
```

### 三、为什么决策比检测难：四个结构性原因

| # | 原因 | 具体表现 |
|---|---|---|
| **1** | **延迟反馈** | 现在切了负荷，后果在几秒到几分钟后才显现；信用分配（credit assignment）极难 |
| **2** | **代价不对称** | "少切一点"可能引发连锁跳闸；"多切一点"是确定的经济损失。两边的代价差几个数量级 |
| **3** | **动作不可逆** | 检测错了可以重判，切掉的负荷无法"重接" |
| **4** | **约束密集** | 每个动作后都要满足潮流可行、电压不越限、线路不过载 —— 且必须**在动作之前**就知道 |

**第 4 条的技术含义**：

```
决策问题的标准形式不是
    max E[return]
而是
    max E[return]   s.t.  P(约束违反) ≤ δ

这叫 Constrained MDP（CMDP）。Day 94 会展开。
```

**决策方法的四个档次（先想清楚该用哪个，再动手）**：

| 方法 | 适用 | 优点 | 缺点 |
|---|---|---|---|
| **规则 / 查表** | 保护动作（低频减载表） | 可验证、可审计、毫秒级 | 无法适应未预见工况 |
| **优化（OPF / 鲁棒优化）** | 有明确目标函数与约束 | 有最优性保证、约束严格满足 | 需要精确模型；不确定性处理保守 |
| **强化学习** | 规则难写、优化算不动、有仿真器 | 无需精确模型、可在线决策 | 样本效率低、无保证、难验证 |
| **博弈论** | **有自适应对手** | 显式建模对手 | 求解困难、假设强 |

> **一个必须记住的判断**：**如果这个问题能用优化方法解，就不要用 RL。**
>
> RL 的价值在"模型不准 / 算不动 / 规则写不出来"的地方。**电网的 OPF、UFLS 都有成熟的优化解法** —— 所以你要说清"为什么优化方法在这里不够用"，否则审稿人一定会问。

### 四、和电网安全的关系

**把 FDI 检测和防御决策串起来看，真实的链路是这样的：**

```
量测 z（可能被篡改）
   ↓
状态估计 → 残差 → 【检测器】→ 告警
   ↓
【决策层】→ 动作建议
   ↓
【调度员确认】→ 执行
```

**关键问题：检测器的输出，如何影响决策？**

| 情况 | 决策层的处境 | 后果 |
|---|---|---|
| **正确告警** | 知道有攻击，决策可以保守化（不信任量测） | ✅ 安全 |
| **漏报** | 以为一切正常，基于**被污染的状态**做决策 | ❌ **最危险**：决策本身成了攻击的一部分 |
| **误报** | 频繁进入保守模式 | ⚠️ 经济代价 + 运维麻木 |

> **"漏报 → 基于污染状态做决策"这一条是本章最重要的动机。**
>
> 它说明：**FDI 攻击的最终危害不是"检测器没报警"，而是"调度员按错误的状态做了错误的动作"**（回顾 Day 38 的危害链）。
>
> **所以"检测-决策联合建模"是一个真实且有意义的研究方向**：决策层不能假设检测结果一定正确，而应该把"检测结果可能错"这个不确定性纳入决策（这叫 **robust POMDP** 或 **risk-aware decision making**）。

**诚实边界（必须写进论文）**：

| 说法 | 诚实版本 |
|---|---|
| "我们用 RL 实现了电网自动防御" | "我们在仿真环境中训练 RL 策略生成动作建议，**执行需人工确认**。真实电网不允许未经审核的自动切负荷" |
| "RL 策略优于传统方法" | "在 [仿真环境 / 特定故障场景集] 上，RL 策略的失负荷量比低频减载表低 X%，代价是动作次数增加 Y 次" |
| "策略可以处理任意攻击" | "训练分布内有效。分布外的攻击（如多阶段协同攻击）未验证" |

### 🔍 延伸思考

1. 如果检测器漏报，决策层基于污染状态动作 —— 这时"决策层的损失函数"应该怎么设计才能减轻危害？（提示：想想保守性 / 鲁棒性）
2. 动作空间里"提高告警等级 / 人工介入"代价极低且完全可逆。为什么很多 RL 论文不把它放进动作空间？
3. 如果一个决策问题的动作全是可逆的、低代价的，还需要 RL 吗？还是用优化就够了？

## Day 90 —— MDP 五元组：把电网防御写成强化学习问题

> **一句话**：把电网防御写成 MDP 最难的不是算法，是**奖励函数** —— 奖励写错，RL 会学出一个在数学上最优、在物理上灾难的策略。

### 一、五元组逐项对应

```
MDP = (S, A, P, R, γ)

  S : 状态空间        A : 动作空间
  P : 状态转移概率     R : 奖励函数
  γ : 折扣因子（0 < γ < 1）
```

| 元素 | 抽象含义 | 电网防御里的具体对应 | 难点 |
|---|---|---|---|
| **S** | 决策所需的信息 | 节点电压、线路负载率、发电机出力、开关状态、**告警历史** | 维度高；部分可观 |
| **A** | 可执行的动作 | 见 Day 89 的六类动作 | 混合离散 / 连续；有硬约束 |
| **P** | 动作后的状态变化 | 潮流方程 + 负荷变化 + **攻击者行为** | **未知**；只能靠仿真器采样 |
| **R** | 即时奖励 | 失负荷量、越限惩罚、动作代价 | **最容易写错** |
| **γ** | 未来重要性 | 电力场景通常取 0.95 ~ 0.99 | 太小 → 短视；太大 → 方差爆炸 |

**`P` 为什么"未知"**：你不知道真实电网的转移概率。**RL 的价值恰恰在于不需要知道 `P`** —— 只需要一个能交互的环境（仿真器）。但这也意味着**你学到的东西只在仿真器的分布内有效**（Day 94 展开）。

**目标**：

```
最大化期望折扣回报：  J(π) = E_π[ Σ_{t=0}^{T} γ^t · r_t ]
```

### 二、状态设计与部分可观测（POMDP）

**先区分两件事**：

| 概念 | 定义 | 电网里 |
|---|---|---|
| **状态 `s`** | 决定未来演化的完整信息 | 全网真实运行状态（**永远拿不到**） |
| **观测 `o`** | 智能体实际能看到的东西 | 量测 + 告警 + 开关遥信 |

**因为 `o ≠ s`，电网决策本质是 POMDP（部分可观测马尔可夫决策过程）。**

```
POMDP 的两条常见处理路线：

① 把历史拼进观测：  o_t = [z_t, a_{t-1}, z_{t-1}, ...]
   → 简单，但维度随窗口线性增长
   → 用 RNN / Transformer 编码历史（回顾 Day 22、Day 31）

② 维护信念状态：    b_t = P(s_t | 历史)
   → 理论干净，但计算昂贵，电网规模上不实用
```

**电网状态表示的实用建议**：

| 特征组 | 具体内容 | 为什么需要 |
|---|---|---|
| **物理量测** | 节点电压幅值、支路有功/无功 | 基础 |
| **派生量** | 线路负载率、电压偏差、备用容量 | 归一化后更好学 |
| **拓扑** | 开关状态、线路投退 | **拓扑变了，最优动作完全不同** |
| **时序** | 最近 N 步的量测变化率 | 判断趋势（负荷爬升 / 攻击突变） |
| **安全层输出** | 残差范数、检测器分数 | **让决策知道"数据可能不可信"** |

> **最后一行是安全场景特有的，也是关键。** 普通 RL 论文的状态里没有"数据可信度"这一项 —— 但在电网攻防场景里，**决策层必须知道当前量测是否可信**，否则就会出现 Day 89 说的"基于污染状态决策"。

### 三、奖励设计：最大的坑

**这是本周最容易翻车的地方。** 奖励函数是"你想要什么"的形式化，而 RL 会**精确地**优化你写下来的东西 —— 包括你没想清楚的部分。

**三个典型错误**：

| 错误 | 写法 | RL 会学出什么 |
|---|---|---|
| **目标错位** | `r = −(线路负载率最大值)` | 学出"把线路全断开，负载率就是 0" |
| **缺少动作代价** | 只奖励"电压不越限" | 学出"每步都疯狂调压"，动作抖动 |
| **惩罚太弱** | `r = −0.01 × 越限程度` | 学出"轻微越限也没事"，因为越限的收益更大 |

**奖励设计的四条原则**：

```
① 主目标只写一个：电网里就是"最小化失负荷量"（或"最小化停电用户数"）
② 约束用【硬约束】而不是惩罚项（回顾 Day 85）
   → 惩罚项可以被"用更大的收益抵消"，硬约束不能
③ 动作代价要显式写进去（切负荷次数、开关操作次数）
④ 不要在奖励里写"中间指标"（如电压偏差），除非你确实要优化它
   → 写进去的东西 RL 一定会去优化，可能以你不想要的方式
```

**一个具体的奖励函数骨架**：

```python
def compute_reward(info, action, cfg):
    """
    info 里包含仿真器返回的：失负荷量、越限情况、动作类型
    注意：所有项都要归一化到同一量级（回顾 Day 84 的归一化教训）
    """
    # ① 主目标：失负荷量（越小越好），按基准容量归一化
    r_shed = -info["load_shed_mw"] / cfg["base_load_mw"]

    # ② 动作代价：切负荷次数、开关操作次数
    r_action = -cfg["w_shed"] * action["n_shed_actions"] \
               - cfg["w_switch"] * action["n_switch_ops"]

    # ③ 越限只给很小的惩罚作为"提示"，真正的约束靠 action masking（Day 94）
    r_violate = -cfg["w_violate"] * info["n_violations"]

    return r_shed + r_action + r_violate
```

**"奖励黑客"（reward hacking）的电网版本**：

| 你写的奖励 | RL 找到的捷径 | 后果 |
|---|---|---|
| 最小化线路负载率 | 断开重载线路 | 用户停电 |
| 最大化电压合格率 | 把电压全设到 1.0 | 无功设备疯狂动作、损耗上升 |
| 最小化动作次数 | 什么都不做 | 故障时不响应 |
| 最大化"检测到的攻击数" | 把正常样本也判成攻击 | 误报爆炸（回顾 Day 40 的"制造误报"攻击） |

> **检查方法**：训练完之后，**把 RL 学到的策略跑一遍，逐条看它做了什么动作**。
>
> 如果你看到一个"数学上回报很高但工程上荒谬"的动作序列 —— 奖励写错了。**这个人工检查不能省。**

### 四、和电网安全的关系

**把"攻击者"放进 MDP，问题就从单智能体变成双人博弈：**

```
单智能体 MDP：   P(s' | s, a)              ← 转移只由环境决定
双人博弈：       P(s' | s, a_def, a_att)   ← 转移由双方共同决定
```

**这意味着三件事**：

| 变化 | 后果 |
|---|---|
| **环境不再是平稳的** | 防御者的最优策略依赖攻击者的策略；攻击者会适应 |
| **单智能体 RL 会失效** | 训练时攻击者策略在变 → 非平稳环境 → 收敛性无保证 |
| **需要博弈论工具** | 极小极大 / Stackelberg / 纳什均衡（Day 92 展开） |

**攻击者建模的三种方式**：

| 方式 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **固定攻击脚本** | 训练时用固定的攻击样本 | 简单、可复现 | 学到的策略只对这类攻击好 |
| **对抗训练** | 训练中交替优化攻防双方 | 更鲁棒 | 可能循环不收敛；算力翻倍 |
| **最坏情况优化** | `max_π min_{a_att} E[return]` | 有鲁棒性保证（在攻击集内） | 极保守；求解困难 |

**诚实边界（必须写进论文）**：

| 说法 | 诚实版本 |
|---|---|
| "我们的 RL 策略能对抗任意攻击" | "我们假设攻击者从 [固定攻击集] 中选择，未考虑自适应攻击者" |
| "奖励函数反映了电网的真实目标" | "我们把失负荷量作为主目标，用硬约束保证物理可行。**奖励函数是工程选择，不是电网真实效用的完整刻画**" |
| "策略在真实电网上有效" | "全部实验在 pandapower 仿真环境中进行，未在真实系统验证" |

## Day 91 —— 从 Q-Learning 到 PPO：值函数与策略梯度

> **一句话**：值函数方法学"每个动作值多少分"（只能处理离散动作），策略梯度方法直接学"该做什么"（能处理连续动作）—— **电网里两种都要用，因为动作既有离散的（开关）也有连续的（出力）**。

### 一、值函数方法：Q-Learning → DQN

**核心思想**：学一个"动作价值函数" `Q(s, a)`，然后**选 Q 最大的动作**。

```
Q-Learning 的更新（表格版）：

  Q(s, a) ← Q(s, a) + α · [ r + γ · max_{a'} Q(s', a') − Q(s, a) ]
                              └──────── TD 目标 ────────┘

DQN 的三项关键改造：
  ① 用神经网络参数化 Q(s, a; θ)          ← 处理高维状态
  ② 经验回放（replay buffer）             ← 打破样本相关性
  ③ 目标网络（target network）            ← 稳定 TD 目标
```

**DQN 的两个硬限制**：

| 限制 | 含义 | 电网里的后果 |
|---|---|---|
| **只能处理离散动作** | 输出维度 = 动作个数 | "切 3 号母线 17.3% 负荷"表达不出来 |
| **需要 `max_{a'} Q(s', a')`** | 连续动作下求最大值本身是个优化问题 | 需要额外近似，误差累积 |

**离散化能救吗**？可以，但会爆炸：

```
14 个节点 × 每个节点 11 档切负荷比例（0%, 10%, ..., 100%）
⇒ 动作数 = 11^14 ≈ 3.8 × 10^14

组合爆炸。所以连续动作必须用策略梯度方法。
```

### 二、策略梯度：REINFORCE → Actor-Critic → PPO

**策略梯度直接参数化策略 `π_θ(a|s)`，用梯度上升最大化回报。**

```
策略梯度定理：

  ∇_θ J(θ) = E_{π_θ}[ ∇_θ log π_θ(a|s) · A(s, a) ]

其中 A(s,a) 是优势函数（这个动作比平均好多少）
```

| 方法 | 关键改进 | 遗留问题 |
|---|---|---|
| **REINFORCE** | 用整条轨迹的回报当权重 | 方差极大 |
| **Actor-Critic** | 用一个 Critic 估计 `A(s,a)`，降方差 | 有偏；两个网络难协调 |
| **A2C / GAE** | 用广义优势估计（GAE）平衡偏差与方差 | 仍是 on-policy，样本效率低 |
| **TRPO** | 限制策略更新的 KL 距离 | 二阶优化，实现复杂 |
| **PPO** | 用 clip 近似 TRPO 的约束 | **实践中最常用** |

**PPO 的 clip 目标（唯一需要记住的公式）**：

```
记  r_t(θ) = π_θ(a_t|s_t) / π_{θ_old}(a_t|s_t)     ← 新旧策略的概率比

  L^CLIP(θ) = E[ min( r_t(θ)·A_t ,  clip(r_t(θ), 1−ε, 1+ε)·A_t ) ]

直觉：如果新策略相对旧策略变化太大（比值超出 [1−ε, 1+ε]），
      就把梯度截断 —— 不让策略一步走太远。
```

```python
import torch

def ppo_loss(logp_new, logp_old, advantages, clip_eps=0.2):
    """PPO 的 clip 损失（骨架）"""
    ratio = torch.exp(logp_new - logp_old)              # r_t(θ)
    unclipped = ratio * advantages
    clipped = torch.clamp(ratio, 1 - clip_eps, 1 + clip_eps) * advantages
    # 取 min：悲观下界，保证更新不会因"运气好"而过猛
    return -torch.min(unclipped, clipped).mean()
```

**为什么是 `min`**：

| 情况 | `unclipped` | `clipped` | `min` 的效果 |
|---|---|---|---|
| 优势 `A > 0`（好动作） | 比值越大越好 | 上限 1+ε | **限制"变好时"的步子** |
| 优势 `A < 0`（坏动作） | 比值越小越好 | 下限 1−ε | **限制"变坏时"的步子** |

> **`min` 让更新始终取悲观的一侧** —— 这是 PPO 比原始策略梯度稳定得多的根本原因。

### 三、方法选型对照

| 维度 | DQN（值函数） | PPO（策略梯度） | SAC（离策略策略梯度） |
|---|---|---|---|
| **动作空间** | 只能离散 | 离散 + 连续 | 只能连续 |
| **样本效率** | 较高（用回放） | **低**（on-policy） | 高（离策略） |
| **稳定性** | 中（需要目标网络） | **高** | 中（需要调温度参数） |
| **超参敏感度** | 中 | **低** | 高 |
| **实现复杂度** | 低 | 低 | 中 |
| **电网里适用** | 开关组合（小规模） | **通用首选** | 连续出力调节 |

**给电网场景的选型建议**：

```
① 动作是"从候选开关组合里选一个"（动作数 ≤ 几十）
   → DQN，简单有效

② 动作是"各节点切负荷比例"（连续、有界）
   → PPO 或 SAC。算力有限选 PPO（更稳，好调）
   → 有硬界约束时，输出层用 sigmoid 参数化（回顾 Day 85）

③ 动作是"混合的"（既选线路又定出力）
   → 拆成两级：高层选拓扑（离散），低层定出力（连续）
   → 这叫分层 RL（hierarchical RL），实现复杂度显著上升
```

### 四、和电网安全的关系

**样本效率：一个必须算清楚的账。**

```
PPO 的经验值：一个中等难度任务通常需要 10^6 ~ 10^8 个环境步

电网环境的"一步"意味着什么？
  = 一次潮流计算（pandapower 在 IEEE 118 上约 10~50 ms）
  + 一次状态更新

⇒ 10^6 步 × 20 ms ≈ 5.5 小时（单线程）
⇒ 10^7 步 ≈ 55 小时
⇒ 10^8 步 ≈ 23 天

这还只是训练一个策略，不算超参搜索。
```

| 加速手段 | 效果 | 代价 |
|---|---|---|
| **并行环境**（多进程跑仿真） | 近似线性加速 | 需要多核 CPU；pandapower 不是线程安全的 |
| **model-based RL**（先学一个动力学模型，在模型里训练） | 样本效率提升 10~100 倍 | **模型误差会传播**，学出的策略可能不适用于真实仿真器 |
| **模仿学习预热**（先用规则法生成数据） | 大幅减少探索 | 上限受规则法限制 |
| **简化仿真器**（用 DC 潮流代替 AC） | 快 10~100 倍 | 物理保真度下降，sim-to-real gap 变大 |

> **这里有一个绕不开的权衡**：**仿真越快 → 训练越容易 → 但和真实电网差得越远。**
>
> 用 DC 潮流训出来的策略，迁移到 AC 环境后可能连潮流都不收敛。**这个 gap 必须量化，而不是假设它不存在。**

**混合动作空间是电网决策的真实形态**：

| 动作类型 | 例子 | 数学性质 |
|---|---|---|
| 离散 | 开关开合、投切电容器 | 组合优化 |
| 连续有界 | 切负荷比例 ∈ [0, 1]、机组出力 ∈ [P_min, P_max] | 连续控制 |
| 整数 | 切几条馈线 | 整数规划 |

**诚实边界（必须写进论文）**：

| 说法 | 诚实版本 |
|---|---|
| "我们训练了 RL 策略用于电网防御" | "我们在 [仿真器 + 算例 + 步数] 下训练了 PPO 策略，训练耗时 X 小时（Y 次潮流计算）" |
| "策略在测试场景上表现良好" | "在 [N] 个测试场景上，平均失负荷量比基线低 X%；**最坏场景下比基线差 Y%**" |
| "方法可以扩展到更大规模" | "我们在 IEEE 14 / 118 上验证。更大规模（如 300 节点以上）的**训练成本与收敛性未验证**" |

1. PPO 是 on-policy 的，意味着数据用完就丢。如果每次环境交互都要跑一次潮流计算，你愿意用 on-policy 吗？有没有折中方案？

## Day 92 —— 电网攻防博弈建模：Stackelberg 与零和博弈

> **一句话**：只要对手会**适应**你的策略，单智能体 RL 就不再适用 —— 你要找的不是"最优策略"，而是"**在最坏对手下也不至于崩的策略**"。

### 一、为什么需要博弈论：非平稳性

**单智能体 RL 的收敛性依赖于环境平稳（`P` 固定）。** 一旦有自适应对手：

```
训练第 1 轮：防御者学"识别攻击模式 A"  →  攻击者看到后改用模式 B
训练第 2 轮：防御者学"识别攻击模式 B"  →  攻击者改用模式 A
...
⇒ 策略在 A / B 之间来回震荡，永远不收敛
```

**这不是实现问题，是问题结构本身决定的。** 解决办法是换目标：

```
单智能体 RL：   max_π  E_{P}[return]                ← 假设环境固定
博弈论：        max_π  min_{σ} E_{P,σ}[return]      ← 假设对手会针对你
                （极小极大 / 鲁棒最优）
```

### 二、Stackelberg 博弈：领导者与跟随者

**定义**：一方先行动（领导者），另一方观察到领导者的策略后再最优响应（跟随者）。

```
Stackelberg 双层优化：

  上层（领导者）：  min_x  f( x, y*(x) )
  下层（跟随者）：  y*(x) ∈ argmin_y  g( x, y )

关键：上层的目标里包含了"下层会怎么响应"。
```

**FDI 攻防的时序天然是 Stackelberg 结构：**

```
第 1 步【防御者先动】：部署检测器（阈值、模型、监控点位）
                              ↓
第 2 步【攻击者观察】：推断检测器（架构 / 阈值 / 特征）
                              ↓
第 3 步【攻击者后动】：构造攻击 Δz 以最大化"绕过 + 造成危害"

⇒ 防御者是领导者，攻击者是跟随者。
⇒ 防御者的最优策略不是"对固定攻击最好"，而是"对攻击者的最优响应最好"。
```

| 角色 | 决策变量 | 目标 | 信息 |
|---|---|---|---|
| **防御者（领导者）** | 检测器配置、监控点位、阈值 | 最小化期望损失（在攻击者最优响应下） | 不知道攻击者的具体动作 |
| **攻击者（跟随者）** | 篡改哪些量测、改多少 | 最大化损失 − 被发现概率×代价 | 可能知道检测器（白盒）或不知道（黑盒） |

**一个具体的双层优化形式**：

```
上层（防御者选阈值 τ 与监控点位集合 M）：
    min_{τ, M}   L_detect(τ, M; Δz*)  +  λ · Cost_FP(τ)
    s.t.         Δz* = argmax_{Δz ∈ 𝒜}  [ Damage(Δz) − P_detect(Δz; τ, M) · Penalty ]

下层（攻击者选攻击向量 Δz）：
    max_{Δz ∈ 𝒜}  Damage(Δz) − P_detect(Δz; τ, M) · Penalty
    s.t.          Δz ∈ range(H)            ← 物理可行（回顾 Day 84）
                  ‖Δz‖_∞ ≤ ε                ← 篡改幅度上界
                  ‖Δz‖_0 ≤ k                ← 只能改 k 个量测
```

> **注意：下层的约束集 `𝒜` 就是 Day 84 讨论的"攻击者可行域"。** 物理约束在这里的作用是**限定博弈的边界** —— 这也回答了"物理约束在安全里到底有什么用"（Day 88 的价值排序第 ① 条）。

### 三、零和 vs 一般和；纳什均衡 vs 极小极大

**先搞清楚"博弈是什么类型"，这决定了你能用什么工具。**

| 类型 | 定义 | 电网攻防里成立吗 |
|---|---|---|
| **零和** | 一方所得 = 另一方所失 | ⚠️ **近似成立**：攻击者得逞 ≈ 电网受损。但攻击者的动机可能不是"让电网受损"（可能是勒索、示威、测试），代价函数也不同 |
| **一般和** | 双方收益独立 | ✅ 更真实，但求解更难 |
| **完全信息** | 双方都知道对方收益 | ❌ 真实场景信息不对称 |
| **重复博弈** | 多次交互，可建立声誉 | ✅ 攻防是长期的（但"声誉"在匿名攻击下不成立） |

**两个核心解概念**：

| 概念 | 含义 | 适用 |
|---|---|---|
| **纳什均衡** | 任何一方单方面改变策略都不会更好 | 一般和博弈 |
| **极小极大（鞍点）** | `max_π min_σ`，保证最坏情况下最好 | 零和博弈 |
| **Stackelberg 均衡** | 领导者先动，跟随者最优响应 | 有时序的博弈（**攻防场景**） |

**安全博弈（Security Games）与随机化防御**：

**这是博弈论在安全领域最成功的应用**，核心思想是：

```
如果防御策略是确定的，攻击者总能找到绕过它的方法。
⇒ 防御者应该【随机化】自己的策略（混合策略）

经典模型：
  防御者把有限的监控资源分配到 N 个目标上（min_ 覆盖 / max_ 覆盖）
  攻击者选一个目标攻击
  ⇒ 求解混合策略，使攻击者在任何目标上的期望收益都 ≤ 某个值
  ⇒ 这可以写成一个线性规划（LP），规模上是可解的
```

**随机化防御在电网里怎么用**：

| 应用 | 做法 |
|---|---|
| **检测阈值随机化** | 每次判定的阈值在 `[τ_lo, τ_hi]` 内随机取 —— 攻击者无法精确卡阈值 |
| **监控点位轮换** | 在预算内轮换被监控的 RTU 子集 —— 攻击者不知道当前监控哪些 |
| **状态估计的量测子集随机采样** | 每次估计随机丢弃一部分量测 —— 攻击者难以构造对所有子集都有效的攻击 |

> **随机化的代价**：可预测性下降 → 运维人员更难理解告警、更难审计。**在电网这种强监管场景里，随机化本身需要论证。**

### 四、和电网安全的关系

**为什么"FDI 攻防 = Stackelberg 博弈"这个框架对你有用：**

| 价值 | 说明 |
|---|---|
| **它解释了"为什么完全信息攻击这么强"** | 攻击者（跟随者）能看到你的检测器，可以针对性构造 |
| **它给出了正确的评估标准** | 不能只测"对固定攻击集的检测率"，要测"**对最优响应攻击的检测率**" |
| **它指向了随机化防御这个方向** | 让防御策略不可预测，是提高攻击成本的经典手段 |
| **它提醒你"自适应攻击"的必要性** | 不做自适应攻击的评估是无效的（回顾 Day 80、Day 81） |

**但必须说清四个诚实的边界**：

```
① 真实博弈通常不是零和的。
   攻击者可能只想"证明能攻破"（那他的收益里没有"电网损失"这一项）。
   非零和 ⇒ 极小极大不是正确目标 ⇒ 需要一般和博弈工具（更难）。

② 可能有多个攻击者，且他们之间也会博弈。
   多个攻击者同时攻击时，"攻击者的最优响应"本身没有良定义。

③ Stackelberg 双层优化的求解在电网规模上通常不可行。
   下层是"攻击者最优响应"（一个优化问题），上层又要优化。
   精确求解的复杂度极高 ⇒ 实践中只能近似（比如：离散化、局部搜索、用 RL 近似下层）。

④ 攻击者的收益函数是【你假设的】，不是【你知道的】。
   这是所有博弈论建模的根本软肋：
   如果攻击者的实际目标与你的假设不符，求出的均衡没有意义。
```

**❌ / ✅ 对照**：

```
❌ 夸大："我们建立了电网攻防的 Stackelberg 博弈模型并求出了均衡。"
   → 审稿人：你怎么知道攻击者的收益函数？求解规模多大？均衡唯一吗？

✅ 诚实："我们把 FDI 攻防建模为 Stackelberg 博弈：防御者先确定检测器配置，
         攻击者在观察到配置后最大化 (危害 − 被发现概率 × 惩罚)。
         我们假设攻击者的惩罚系数为 λ_att ∈ [1, 10] 并做了敏感性分析。
         由于双层优化在 IEEE 118 上不可精确求解，我们用局部搜索近似下层，
         并报告了近似误差。我们未声称求出了全局 Stackelberg 均衡。"
```

### 🔍 延伸思考

1. 如果防御策略随机化了，运维人员看到的告警阈值每次都不一样 —— 这在真实调度场景里可接受吗？如果不接受，有没有折中？
2. 上面的双层优化里，下层是"攻击者最优响应"。如果攻击者不是最优的（真实攻击者常常不是），你的防御策略是不是过度保守了？这个代价有多大？

## Day 93 —— 强化学习实战：切负荷与拓扑重构决策

> **一句话**：切负荷和拓扑重构是电网决策的两个经典问题，也是**唯一两个"RL 可能真的比规则法好"的场景** —— 因为它们的动作空间规则法写不全。

### 一、切负荷（UFLS）：把问题写成 MDP

**背景**：功率缺额导致频率下降，必须在几百毫秒内切除足够负荷，否则频率崩溃。

**传统做法（低频减载表）**：`if f < 49.0 Hz: 切第 1 轮（全网 5%）` / `if f < 48.6 Hz: 切第 2 轮` / ……

| 传统做法的优点 | 传统做法的缺点 |
|---|---|
| 毫秒级响应，可靠 | 固定轮次，不考虑**负荷的重要程度分布** |
| 可离线验证、可审计 | 不考虑**当前拓扑**（切哪个节点效果不同） |
| 不依赖通信 | 不考虑**攻击导致的量测污染** |

**MDP 建模**：

| 元素 | 设计 |
|---|---|
| **状态 `s`** | `[f, df/dt, 各节点负荷量, 各节点电压, 拓扑编码, 备用容量]` |
| **动作 `a`** | 各节点的切负荷比例 `∈ [0, 1]^n`（连续有界，用 sigmoid 参数化） |
| **奖励 `r`** | `−（失负荷量） − w·（动作次数） − w_v·（频率越限时长）` |
| **转移 `P`** | 由仿真器决定：执行切负荷 → 更新负荷 → 跑潮流 + 频率动态 |
| **终止** | 频率恢复到安全范围 / 触发更严重保护 / 超过步数上限 |

```python
import torch
import torch.nn as nn


class LoadSheddingPolicy(nn.Module):
    """切负荷策略网络：输出各节点切负荷比例 ∈ (0,1)（硬约束，见 Day 85）"""

    def __init__(self, state_dim, n_bus, hidden=256):
        super().__init__()
        self.backbone = nn.Sequential(
            nn.Linear(state_dim, hidden), nn.Tanh(),
            nn.Linear(hidden, hidden), nn.Tanh(),
        )
        self.mu = nn.Linear(hidden, n_bus)                 # 均值
        self.log_std = nn.Parameter(torch.zeros(n_bus))    # 可学习的对数标准差

    def forward(self, s):
        h = self.backbone(s)
        mu = torch.sigmoid(self.mu(h))                     # 硬约束：比例 ∈ (0,1)
        return torch.distributions.Normal(mu, self.log_std.exp().clamp(1e-3, 1.0))

    def act(self, s):
        dist = self.forward(s)
        a = dist.sample().clamp(0.0, 1.0)
        return a, dist.log_prob(a).sum(-1)
```

> **注意 `sigmoid` 的作用**：它保证输出落在 `(0, 1)`，**切负荷比例不可能为负或超过 100%** —— 这是 Day 85 讲的"硬约束（输出参数化）"的直接应用。**副作用**：`sigmoid` 在 0 和 1 附近梯度极小（饱和区），如果最优策略是"完全不切"（比例 = 0），梯度会很小、学得慢。缓解办法：不直接输出比例，而是输出"相对基准的增量"，或改用 `clamp` 兜底。

### 二、拓扑重构：组合爆炸与两级设计

**问题**：通过开合开关改变网络结构，使潮流分布更合理（消除过载、降低网损）。

**为什么难**：

```
n 个开关，每个有开/合两种状态 ⇒ 状态空间 = 2^n

IEEE 14 有 15 个开关 ⇒ 32768 种组合（还能穷举）
IEEE 118 有 177 条支路 ⇒ 2^177 ≈ 10^53（不可能穷举）
```

**实用做法：两级设计（不要指望 RL 直接搜索组合空间）**：

```
第 1 级：用启发式 / 灵敏度分析生成【候选拓扑集合】
        （比如只考虑断开过载线路所在断面的相邻开关组合），规模控制在几十 ~ 几百
第 2 级：用 RL 在候选集上选择（离散动作问题）
        → 动作数 = 候选集大小 → DQN 或 PPO（离散）都能用
```

| 设计 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **端到端 RL** | RL 直接输出开关组合 | 理论上最优 | 组合爆炸，**不可行** |
| **两级（候选集 + RL）** | 启发式生成候选，RL 选择 | 可行、可解释 | 上限受候选集限制 |
| **纯优化** | 用 MIP / 启发式搜索 | 有最优性保证（小规模） | 大规模算不动 |

> **一个务实的判断**：**拓扑重构这类"离散组合 + 有明确约束"的问题，优化方法（MIP / 启发式）往往比 RL 更合适。** 只有当"目标函数难以显式写出"或"需要在线毫秒级决策"时，RL 才有优势 —— **如果你要用 RL 做拓扑重构，论文里必须论证这两点中的至少一点。**

### 三、实验设计：环境、基线、指标

**环境**：

```python
import pandapower as pp
import pandapower.networks as pn
import numpy as np


class GridDefenseEnv:
    """电网防御决策环境骨架（Gym 风格）。实际实现需处理潮流不收敛、开关操作合法性等边界。"""

    def __init__(self, case="case14", max_steps=20):
        self.case, self.max_steps, self.t = case, max_steps, 0
        self.net = getattr(pn, case)()

    def reset(self):
        self.net, self.t = getattr(pn, self.case)(), 0
        return self._get_state()

    def _get_state(self):
        """状态：电压幅值 + 线路负载率"""
        v = self.net.res_bus["vm_pu"].values
        loading = self.net.res_line["loading_percent"].values / 100.0
        return np.concatenate([v, loading]).astype(np.float32)

    def step(self, action):
        """action: 各节点切负荷比例 ∈ [0,1]；返回 (state, reward, done, info)"""
        base_p = self.net.load["p_mw"].values.copy()
        self.net.load["p_mw"] = base_p * (1.0 - action)

        try:
            pp.runpp(self.net)
        except Exception:
            # 潮流不收敛 = 动作把系统推入不可行区域，给大惩罚并终止
            return self._get_state(), -10.0, True, {"converged": False}

        load_shed = float((base_p * action).sum())                  # MW
        n_violations = int(((self.net.res_bus["vm_pu"] > 1.10)
                            | (self.net.res_bus["vm_pu"] < 0.90)).sum())
        reward = -load_shed / 100.0 - 0.1 * n_violations

        self.t += 1
        done = (self.t >= self.max_steps) or (n_violations == 0 and load_shed < 1e-6)
        return self._get_state(), reward, done, {"load_shed_mw": load_shed,
                                                 "n_violations": n_violations}
```

> **上面这段代码里最重要的一行是 `try / except`。** **潮流不收敛是电网仿真里的常态**（负荷过重、拓扑不合理、切负荷过多）。如果你的 RL 环境不处理这个，训练会直接崩。而且"不收敛"本身就是一种强信号 —— 它意味着当前动作让系统进入了不可行区域，**给一个大的负奖励并终止是合理的建模**。

**基线（必须有，而且要公平）**：

| 基线 | 做法 | 为什么必须比 |
|---|---|---|
| **低频减载表** | 固定轮次、固定比例 | 这是**真实电网在用的方法**，不比它就没有说服力 |
| **按负荷优先级切** | 按重要程度排序，从最不重要开始切 | 比低频减载表聪明，是最强的规则基线 |
| **优化方法（如需要）** | 用 MIP 求当前场景下的最优切负荷 | 给出**性能上界**（如果 RL 比它还差，说明 RL 没用） |
| **随机切负荷** | 随机选节点切 | 下界，用来确认 RL 至少比瞎猜好 |

**指标（不能只看"失负荷量"）**：

| 指标 | 含义 | 为什么要报 |
|---|---|---|
| **失负荷量（MW）** | 主目标 | 核心指标 |
| **失负荷用户数** | 更贴近真实损失 | MW 相同但影响人数可能差很多 |
| **动作次数** | 切负荷操作次数 | 频繁操作本身是风险 |
| **约束违反次数** | 电压/线路越限 | **安全类方法必须报** |
| **最坏场景表现** | 所有测试场景里最差的那个 | 平均好不代表安全 |
| **决策延迟** | 从状态到动作的时间 | 保护场景要求毫秒级 |

### 四、和电网安全的关系

**把 FDI 攻击接进决策环节 —— 这是本章最有价值的研究点。**

```
攻击者篡改量测 → 状态估计给出偏移的状态（如"线路 5 过载了"）
      → 【决策层看到的是错误的状态】→ RL 基于错误状态动作
      → 切了不该切的负荷 / 没切该切的
⇒ 攻击者不需要自己造成物理破坏，让防御者自己动手就够了
```

**这个场景的三种研究设定**：

| 设定 | 防御者的假设 | 难度 | 真实性 |
|---|---|---|---|
| **A. 完美检测** | 假设攻击被完全检测出来，决策时忽略被污染量测 | 低 | ❌ 不真实 |
| **B. 检测有误** | 检测器有漏报/误报，决策需处理不确定性 | 中 | ✅ 较真实 |
| **C. 对抗自适应决策** | 攻击者知道决策策略，针对性构造 | 高 | ✅ 最真实 |

> **设定 A 是很多论文的做法，也是最容易被审稿人质疑的**：如果检测器真的完美，那"决策"这个问题本身就简单了。**设定 B 和 C 才是真正有价值的方向**，而且它们和 Day 92 的博弈框架天然衔接。

**sim-to-real gap 在决策场景里的具体表现**：

| 差异来源 | 仿真里 | 真实电网 | 后果 |
|---|---|---|---|
| **潮流模型** | 精确参数、无误差 | 参数有误差、有未建模元件 | 策略在真实系统上可能越限 |
| **负荷动态** | 静态或简单模型 | 电动机负荷的动态特性复杂 | 频率响应不同 |
| **通信延迟** | 通常假设 0 | 几十毫秒 ~ 秒级 | 毫秒级保护场景完全不适用 |
| **保护动作** | 通常未建模 | 保护会**先于** RL 动作 | RL 的动作可能根本轮不到执行 |
| **人的干预** | 无 | 调度员会介入 | 策略假设与实际不符 |

**诚实边界（必须写进论文）**：

| 说法 | 诚实版本 |
|---|---|
| "RL 策略实现了自适应切负荷" | "我们在 pandapower 仿真中训练并评估策略，**未考虑保护装置的自动动作与调度员干预**" |
| "策略优于低频减载表" | "在 [N] 个仿真故障场景上，平均失负荷量降低 X%，但**最坏场景下高 Y%**；动作次数增加 Z 次" |
| "可用于实际电网" | "本方法是**决策建议生成器**，实际执行需调度员确认。真实部署需要（1）更精确的仿真校准（2）与现有保护体系的协调设计（3）现场验证" |

### 🔍 延伸思考

1. 切负荷环境里，"潮流不收敛"应该给多大惩罚？给太小 → 策略敢乱切；给太大 → 策略学到"什么都不做"。怎么定？

## Day 94 —— 样本效率与安全约束：RL 落地电网的硬伤

> **一句话**：在真实电网上跑 RL 试错是**不可接受的**（一次错误动作可能就是一次停电）—— 所以 RL 在电网里的唯一诚实路径是"**仿真训练 + 安全层过滤 + 人工确认**"。

### 一、样本效率：数据从哪来

**先算清账**（回顾 Day 91）：`10^6` 步 × `20 ms` ≈ `5.5 小时`（单线程，IEEE 118）。

| 手段 | 做法 | 加速比 | 代价 |
|---|---|---|---|
| **并行环境** | 多个进程各跑一个仿真器实例 | ≈ 核数 | pandapower 非线程安全，要用多进程；内存占用线性增长 |
| **向量化仿真** | 用 numpy 批量跑多个工况 | 10~50× | 需要自己实现潮流求解器（或改用 DC 潮流） |
| **DC 潮流近似** | 用线性化模型代替 AC | 10~100× | 物理保真度下降，**sim-to-real gap 变大** |
| **model-based RL** | 先学一个动力学模型 `P̂(s'\|s,a)`，在模型里训练 | 10~100× | **模型误差会传播**；策略可能过拟合到模型误差上 |
| **模仿学习预热** | 先用规则法/优化法生成数据做行为克隆 | 大幅减少探索步数 | 策略上限受示范者限制 |
| **降低状态维度** | 只保留关键节点 | 2~5× | 可能丢掉关键信息 |

**model-based RL 的诚实评估**：

```
好处：样本效率高（在学到的模型里可以"免费"采样）
风险：策略可能学会利用模型误差，而不是真的解决问题

一个必须做的检查：
  在【学到的模型】里评估策略性能  →  得到 P̂
  在【真实仿真器】里评估同一策略  →  得到 P
  如果 P̂ ≫ P，说明策略过拟合到模型误差上了。
  这个差值必须报告。
```

### 二、安全约束：从"惩罚"到"保证"

**CMDP 的标准形式**：

```
max_π  E_π[ Σ γ^t r_t ]          ← 最大化回报
s.t.   E_π[ Σ γ^t c_t ] ≤ d      ← 期望累积代价不超过阈值 d
```

| 方法 | 做法 | 保证 | 代价 |
|---|---|---|---|
| **拉格朗日法** | 把约束做成惩罚项，动态调 `λ` | ❌ 无保证（只软性满足） | 简单；`λ` 难调 |
| **CPO** | 在信任域内解带约束的优化 | ⚠️ 有理论保证（近似） | 实现复杂、计算贵 |
| **安全层（Shield）** | 动作先过一层"安全过滤器"，不合法的动作被替换 | ✅ **硬保证**（在过滤器正确的前提下） | 过滤器本身要正确 |
| **动作掩蔽（Action Masking）** | 把非法动作的 logits 设为 `−∞` | ✅ **硬保证** | 只适用于离散动作 |
| **约束投影** | 动作投影到可行集 | ✅ 硬保证（投影正确时） | 需要能高效求解投影 |

**动作掩蔽的实现（最实用的一种）**：

```python
def masked_logits(logits, valid_mask):
    """
    valid_mask: (batch, n_actions) 的布尔张量，True 表示该动作合法
    把非法动作的 logit 设为 −inf ⇒ softmax 后概率为 0 ⇒ 永远不会被采样
    """
    return logits.masked_fill(~valid_mask, float("-inf"))


def get_valid_actions(net, min_vm=0.90, max_vm=1.10):
    """
    判断哪些动作是合法的。
    注意：严格来说，"动作后是否越限"需要跑一次潮流才知道 —— 这就是难点所在。
    实用做法：用灵敏度分析快速估计，或用保守的启发式规则。
    """
    # 简化示例：只允许操作那些不会导致孤岛、且当前未检修的开关
    valid = []
    for sw in net.switch.itertuples():
        if not sw.closed and sw.et == "l":
            valid.append(sw.Index)
    return valid
```

> **动作掩蔽的一个隐藏难点**：**判断"动作是否合法"本身可能需要跑一次仿真**（因为要检查动作后的电压是否越限）。
>
> 如果每个候选动作都要跑一次潮流，那掩蔽的成本可能比训练本身还高。**实用做法是用灵敏度分析或代理模型快速估计**，但要接受"估计可能不准"这个代价。

**"安全层"架构（推荐的设计）**：

```
        策略网络 π_θ(a|s)
              ↓ 提议动作 a
    ┌─────────────────────────┐
    │  安全层 (Safety Shield) │
    │  ① 硬约束检查（越限？孤岛？）│
    │  ② 动作幅度限制（≤ 5% 负荷）│
    │  ③ 兜底规则（超出则执行减载表）│
    └─────────────────────────┘
              ↓ 安全动作 a'
          仿真器执行
```

> **这个架构的最大好处是"可解释、可审计"**：即使 RL 策略失效，安全层也能兜住。**在电网这种强监管场景里，这一层的存在往往比 RL 策略本身更能说服审稿人。**

### 三、sim-to-real gap 的四个来源

| # | 来源 | 具体表现 | 缓解手段 |
|---|---|---|---|
| **1** | **模型误差** | 线路参数不准、未建模元件、负荷模型简化 | 参数辨识；域随机化（训练时随机扰动参数） |
| **2** | **延迟** | 通信延迟、计算延迟、执行机构延迟 | 训练时注入随机延迟 |
| **3** | **未建模动态** | 保护动作、电动机负荷动态、人工干预 | 把保护动作写进仿真器；设置"保护优先"规则 |
| **4** | **对手行为差异** | 真实攻击者不按你的假设行动 | 多类型攻击者训练；保守化（极小极大） |

**域随机化（Domain Randomization）的做法**：

```
训练时，每个 episode 随机采样一套环境参数：
  线路阻抗  ←  标称值 × U(0.9, 1.1)
  负荷水平  ←  标称值 × U(0.7, 1.3)
  通信延迟  ←  U(0, 50) ms
  攻击强度  ←  U(0, ε_max)

⇒ 策略学到的是"对这一族环境都还行"的策略，而不是"对精确标称环境最优"的策略
⇒ 鲁棒性提升，但标称环境下的性能会下降
```

> **这是一个明确的权衡**：**域随机化范围越宽 → 鲁棒性越好 → 标称性能越差。**
>
> 论文里要报告这条曲线（随机化范围 vs 标称性能 vs 最坏性能）。

### 四、和电网安全的关系

**一张"RL 落地电网"的分级表（这是本周最该记住的东西）**：

| 级别 | 形态 | 可行性 | 需要的额外工作 |
|---|---|---|---|
| **L0 离线分析** | 用 RL 分析"哪些场景下规则法不够好" | ✅ **完全可行** | 无 |
| **L1 建议生成** | RL 给出动作建议，调度员决策 | ✅ **可行** | 建议必须带"为什么"（可解释性） |
| **L2 仿真验证** | 建议在仿真环境中自动验证后再呈现 | ✅ 可行 | 需要一个能快速仿真的数字孪生 |
| **L3 人在回路自动化** | RL 自动执行 + 调度员可随时接管 | ⚠️ 研究阶段 | 需要安全层 + 紧急停止机制 + 完整的失效分析 |
| **L4 完全自动** | RL 直接控制 | ❌ **当前不可接受** | 需要形式化验证、认证、监管批准 |

> **这张表的用法**：**在论文里明确声明你的工作处在哪一级。**
>
> 如果你做的是 L1，就老老实实写"我们生成建议供调度员参考"，**不要暗示可以自动执行**。审稿人（尤其是电力背景的）对这一点极其敏感 —— 一篇声称"RL 实现电网自动防御"的论文，在电力期刊基本会被直接质疑。

**诚实边界（必须写进论文）**：

```
1. 本方法在 pandapower 仿真环境中训练与评估，未在真实 SCADA 数据或实际电网上验证。
2. 仿真器未建模继电保护装置的自动动作。真实系统中，保护可能先于本策略动作。
3. 我们通过安全层（硬约束检查 + 兜底规则）保证动作不违反电压与拓扑约束，
   但安全层本身依赖于潮流计算的正确性，而潮流计算依赖量测 —— 量测可被攻击。
4. 样本效率方面：训练需要 X 次潮流计算，耗时 Y 小时。
   真实部署需要数字孪生级别的仿真能力。
5. 我们把本方法定位为【决策建议生成器】（L1），
   实际执行需调度员确认。我们未验证自动执行（L3/L4）的安全性。
```

### 🔍 延伸思考

1. 安全层依赖潮流计算，而潮流计算依赖量测 —— 量测被攻击时安全层也会失效。这个"循环依赖"有解吗？（提示：可以引入不依赖量测的保护，比如本地的频率/电压继电器）
2. 域随机化范围越宽鲁棒性越好但标称性能越差。你会怎么定这个范围？（提示：看真实系统的参数误差范围有多大）
3. 如果 RL 策略和安全层给出的动作冲突，该听谁的？这个仲裁逻辑应该怎么写才既安全又不会让 RL 白学？

## Day 95 —— 复盘 + 决策类方法的适用场景

> **一句话**：决策类方法的选型不该由"哪个更酷"决定，而该由"**约束能不能显式写出、模型准不准、算不算得动**"这三个问题决定。

### 一、决策方法选型表

| 方法 | 需要精确模型 | 约束满足 | 在线速度 | 可解释 | 适用条件 |
|---|---|---|---|---|---|
| **规则 / 查表** | ❌ 不需要 | ✅ 硬保证 | 极快（μs~ms） | ✅ 最好 | 场景有限、可穷举 |
| **确定性优化（OPF 等）** | ✅ 需要 | ✅ 硬保证 | 慢（秒~分钟） | ✅ 好 | 模型准、目标明确 |
| **鲁棒优化 / 随机优化** | ✅ 需要 + 不确定集 | ✅ 硬保证 | 很慢 | ✅ 好 | 不确定性可刻画 |
| **强化学习** | ❌ 不需要（只需仿真器） | ⚠️ 靠安全层 | 快（ms） | ❌ 差 | 规则难写、优化算不动 |
| **博弈论** | ✅ 需要收益函数 | ⚠️ 视模型 | 慢（求解均衡） | ✅ 好 | 有自适应对手 |

**选型流程**：

```
问题 1：约束能显式写成数学形式吗？
  ├─ 能 → 问题 2
  └─ 不能（如"运维可接受度"这类软目标）→ 强化学习 / 规则法

问题 2：模型（潮流参数、负荷特性）足够准吗？
  ├─ 准 → 优化方法（有最优性保证，别用 RL）
  └─ 不准 / 有强不确定性 → 问题 3

问题 3：需要在毫秒级在线决策吗？
  ├─ 需要 → 强化学习（离线训练，在线推理快）
  └─ 不需要（秒级可接受）→ 鲁棒优化

问题 4：对手会适应我的策略吗？
  ├─ 会 → 博弈论框架（Stackelberg / 极小极大）
  └─ 不会 → 单智能体 RL
```

### 二、RL 真正优于传统方法的三个条件

> **三个条件必须同时满足，缺一个 RL 就不划算。**

| # | 条件 | 为什么 |
|---|---|---|
| **1** | **规则写不出来** | 如果规则能覆盖大部分场景，规则法的可审计性远胜 RL |
| **2** | **优化算不动** | 如果 MIP / OPF 能在可用时间内求解，用 RL 是自找麻烦 |
| **3** | **有高保真仿真器** | 没有仿真器，RL 无法训练（真实系统不允许试错） |

**逐条对照电网的常见任务**：

| 任务 | 规则能写？ | 优化算得动？ | 有仿真器？ | 结论 |
|---|---|---|---|---|
| **切负荷（UFLS）** | 部分能（减载表） | 能（但需要毫秒级） | ✅ 有 | ⚠️ **边缘**：RL 的优势在"考虑节点差异"，但要论证毫秒级约束 |
| **拓扑重构** | 难 | 小规模能 | ✅ 有 | ⚠️ **边缘**：优化法在小规模更强 |
| **机组组合 / 经济调度** | 能（规则 + OPF） | 能 | ✅ 有 | ❌ **不要用 RL** |
| **FDI 检测** | 难 | 不适用 | ✅ 有 | ✅ 用深度学习（分类，不是 RL） |
| **攻防对抗策略** | 难 | 难（双层优化） | ✅ 有 | ✅ **RL / 博弈论最有空间** |
| **电压无功控制** | 能 | 能 | ✅ 有 | ❌ 不要用 RL |

> **看这张表**：**RL 在电网里真正的空间不在"控制"，而在"对抗"。**
>
> 控制类问题（切负荷、调压、调度）都有几十年积累的优化方法和规则体系，RL 很难全面超越。
>
> **但"面对一个自适应攻击者该怎么做"是一个优化方法没有好答案的问题** —— 这才是 RL + 博弈论的优势区，也是你作为安全背景研究者的差异化方向。

### 三、论文里怎么写决策类工作

**四个必须做到的点**：

| # | 要求 | 做不到会怎样 |
|---|---|---|
| **1** | **基线必须包含规则法和优化法** | 只跟其他 RL 方法比，审稿人会说"没跟传统方法比" |
| **2** | **指标必须含约束违反次数** | 只报奖励，无法判断策略是否安全 |
| **3** | **必须报最坏场景** | 平均值好但最坏情况灾难的策略在电网里不可接受 |
| **4** | **必须声明落地级别（L0~L4）** | 暗示自动执行会被电力背景审稿人直接否掉 |

**一个推荐的实验设计模板**：

```
【环境】pandapower + IEEE 14 / 118，故障场景集 N 个（含正常 / 故障 / 攻击）

【基线】
  ① 低频减载表（真实电网在用）
  ② 按负荷优先级切（最强规则基线）
  ③ 优化方法（性能上界，如果算得动）
  ④ 随机策略（下界）

【指标】
  主指标：失负荷量（均值 ± 标准差，5 个随机种子）
  安全指标：约束违反次数、潮流不收敛次数
  效率指标：动作次数、决策延迟
  鲁棒指标：**最坏 10% 场景的表现**（不只是平均值）

【消融】
  ① 去掉安全层 → 看约束违反次数怎么变
  ② 去掉攻击者建模 → 看对抗场景下性能掉多少
  ③ 不同域随机化范围 → 标称性能 vs 最坏性能曲线

【诚实声明】
  本方法定位为 L1（建议生成），未验证自动执行的安全性。
  仿真未建模继电保护动作。
```

### 四、和电网安全的关系

**本周的诚实总结：RL 在电网安全里的真实位置。**

| 说法 | 诚实版本 |
|---|---|
| "用 RL 实现电网智能防御" | "用 RL 生成防御动作建议，在仿真环境中评估，**执行需人工确认**" |
| "RL 可以处理未知攻击" | "RL 对训练分布内的攻击类型有效；分布外攻击的泛化能力未验证" |
| "RL 不需要物理模型" | "RL 不需要显式的优化模型，但**需要一个能交互的仿真器**，而仿真器的物理保真度直接决定策略的可迁移性" |
| "样本效率问题可以用并行解决" | "并行能加速，但**真实电网无法提供训练环境**这个根本约束没有改变" |
