## Day 117 —— 投稿材料准备：cover letter 与格式检查

> **一句话**：cover letter 是**唯一一次你能直接对编辑说话的机会** —— 编辑每天看几十份投稿，你的信只需要让他回答一个问题："这篇值不值得送审？"

### 一、cover letter 的六段结构

**长度控制在一页以内（300-400 词）。** 编辑不会读长信。

| 段 | 内容 | 长度 |
|---|---|---|
| 1 | 投稿声明：论文题目 + 投稿到哪个刊 + 稿件类型 | 2 句 |
| 2 | 问题与 gap：这篇解决什么问题，现有工作的不足 | 3-4 句 |
| 3 | 贡献：3 条，与论文的贡献列表一致 | 3 句 |
| 4 | 为什么投这个刊：**匹配度说明** | 2-3 句 |
| 5 | 声明：原创性、未一稿多投、无利益冲突、LLM 使用披露 | 3-4 句 |
| 6 | 推荐审稿人（如期刊要求）+ 联系方式 + 致谢 | 3-4 句 |

**英文 cover letter 模板（可直接改用）**：

```
Dear Editor-in-Chief,

We are pleased to submit our manuscript entitled
"Quantifying the Impact of Attacker Topology Knowledge on
 False Data Injection Detection in Power Systems"
for consideration for publication in [Journal Name] as a [Research Article].

State estimation is the foundation of power system dispatch, and false data
injection attacks (FDIA) can bypass conventional bad data detection.
While numerous detection methods have been proposed, their evaluation
almost universally assumes that the attacker either possesses complete
knowledge of the grid topology or none at all. In practice, an attacker
typically holds only partial topology information. To the best of our
knowledge, the effect of this partial knowledge on detection performance
has not been systematically studied.

In this work, we make three contributions:
(i)  we systematically evaluate five detectors spanning three methodological
     families across the full range of attacker knowledge k ∈ [0, M];
(ii) we identify three non-trivial phenomena, including a sharp performance
     cliff at a critical point k* that correlates with measurement redundancy;
(iii) we propose a topology-visibility-minimizing strategy that reduces the
     attack success rate by 34% while preserving detection performance.

We believe this work is well suited to [Journal Name] because of the journal's
focus on [specific scope, e.g., cyber-physical security of power systems],
and because recent articles in the journal (e.g., [ref]) have addressed
closely related problems from complementary angles.

We confirm that this manuscript is original, has not been published previously,
and is not under consideration elsewhere. All authors have approved the
submission and declare no competing interests. Portions of the code
implementation and language editing were assisted by a general-purpose large
language model; all experimental design, method selection, result analysis,
and conclusions were independently performed and verified by the authors.

Suggested reviewers: [Name, Affiliation, Email] (if required by the journal).
We look forward to your consideration.

Sincerely,
[Name], on behalf of all authors
[Affiliation, Email]
```

**中文期刊的 cover letter 更简短（200-300 字）**：

```
尊敬的编辑老师：

您好！现向贵刊投稿论文《攻击者拓扑信息量对电力系统虚假数据注入
检测性能的影响研究》，申请作为研究论文发表。

状态估计是电网调度决策的基础，虚假数据注入攻击可绕过传统坏数据
检测。现有检测方法的研究普遍假设攻击者掌握完整拓扑信息或不掌握
任何信息，而现实中攻击者通常只掌握部分拓扑信息。据我们所知，
该知识量对检测性能的影响尚无系统研究。

本文的主要工作包括：(1) 系统评估了覆盖三条技术路线的五种检测方法
在攻击者知识量 k 从 0 到 M 全范围内的性能；(2) 发现性能在临界点
k* 处出现断崖式下降，且该临界点与量测冗余度相关；(3) 提出一种
拓扑信息最小可见性策略，在保持检测性能的同时将攻击成功率降低 34%。

本文与贵刊近期关注的电力信息物理系统安全方向高度契合，恳请审阅。
本文为原创成果，未一稿多投，全体作者均同意投稿且无利益冲突。
部分代码实现与语言润色使用了通用大语言模型辅助，实验设计、方法选择、
结果分析与全部结论均由作者独立完成并验证。

顺祝工作顺利！
[姓名]
[单位、邮箱、日期]
```

> **注意两个细节**：
> ① **"为什么投这个刊"这一段不能省，也不能写成"贵刊影响力大"。** 要具体到"贵刊近期发表过 X 方向的论文"，**这说明你真的读过这个刊**。
> ② **LLM 使用披露要主动写。** 各期刊政策不同（有的要求在 cover letter，有的要求在方法节），**投稿前必须去官网查该刊的具体规定** —— 这条我不能替你确认。

### 二、投稿前 30 条格式检查清单

**逐项打勾。这一节建议打印出来，投稿前一天过一遍。**

**A. 稿件结构（8 条）**

- [ ] 1. 使用目标期刊的**官方模板**（从官网下载，不用第三方站）
- [ ] 2. 页数在期刊限制内（超页可能被直接退回）
- [ ] 3. 标题页含：题目、全部作者、单位、通讯作者邮箱、基金信息
- [ ] 4. 摘要字数符合限制（常见 150-250 词）
- [ ] 5. 关键词 3-6 个（用期刊要求的格式）
- [ ] 6. 章节编号与模板一致
- [ ] 7. 图表数量在限制内（部分期刊限制图数）
- [ ] 8. 补充材料（附录 / 代码）按期刊要求单独提交

**B. 图表（7 条）**

- [ ] 9. 所有图分辨率 ≥ 300 dpi，或为矢量格式
- [ ] 10. 图内文字在印刷尺寸下可读（字号 ≥ 8 pt）
- [ ] 11. 图中无中文（投英文刊时）
- [ ] 12. 每个图/表都有编号与标题，且正文引用过（无"孤图"）
- [ ] 13. 表格用三线表（或期刊要求的样式）
- [ ] 14. 表格数字小数位统一
- [ ] 15. 图注包含必要的实验条件（攻击强度 / 随机种子 / 样本数）

**C. 公式与符号（4 条）**

- [ ] 16. 所有独立公式有编号，且正文引用过
- [ ] 17. 变量斜体、单位正体、矩阵加粗（全文统一）
- [ ] 18. 符号表齐全（符号超过 15 个时必须做表）
- [ ] 19. 无符号冲突（同一符号全文含义唯一）

**D. 参考文献（4 条）**

- [ ] 20. 格式完全符合期刊要求（GB/T 7714 或 IEEE 或期刊自有格式）
- [ ] 21. 无重复条目（同一篇被引两次、编号不同）
- [ ] 22. 每条引用都能追溯到原文（**逐条点开链接验证过**）
- [ ] 23. 包含近两年的相关工作（Related Work 时效性）

**E. 声明与合规（7 条）**

- [ ] 24. 作者贡献声明（CRediT 或期刊要求的格式）
- [ ] 25. 利益冲突声明
- [ ] 26. 数据可用性声明（数据是否公开、如何获取）
- [ ] 27. 伦理声明（如涉及）
- [ ] 28. **LLM 使用披露**（按目标期刊政策）
- [ ] 29. **涉密审查**：无真实电网拓扑 / 内网地址 / 设备指纹 / 未脱敏数据
- [ ] 30. 全体作者已确认最终版本

> **第 22 条和第 29 条是两条最容易被跳过、后果最严重的。**
>
> **第 22 条**：如果你的参考文献里有一条是 LLM 编造的（回顾 Day 108），**这是学术不端风险**，不是"小错误"。逐条点开验证，花 1 小时，避免大事故。
>
> **第 29 条**：电网方向的论文有额外的涉密红线（回顾 Day 59）。**投稿前的最后一次检查，重点看拓扑、IP、设备型号、真实量测这四类内容。**

### 三、作者信息与推荐审稿人

**作者顺序的确定原则**（各实验室惯例不同，**必须先问导师**）：

| 位置 | 一般贡献 |
|---|---|
| 第一作者 | 主要执行者：方法设计 + 实验 + 写作 |
| 通讯作者 | 通常是导师，负责整体方向与投稿 |
| 中间作者 | 按贡献排序（数据集、代码、讨论） |

**推荐审稿人怎么写**：

```
选择标准（三条，按重要性）：
  ① 在相关方向发表过论文（能看懂你的工作）
  ② 与你无利益冲突（非同单位、非近期合作者、非师生关系）
  ③ 分布在不同的技术圈（一个电力背景 + 一个 AI 背景）

❌ 不要推荐：
   · 你的导师的合作者（利益冲突）
   · 同一单位的同事
   · 只有一面之缘、明显不会认真看的人

✅ 建议写法（附一句话理由）：
   Prof. X, [University] — expert on state estimation and FDIA detection,
   author of [specific paper].
```

> **推荐审稿人不是"找人说好话"**，而是帮编辑找到"能读懂这篇论文的人"。**如果你的论文横跨电力和 AI，推荐一个纯 AI 审稿人可能反而更糟** —— 他会问"为什么不和最新的 SOTA 比"。

### 四、和电网安全的关系

**电网安全方向的投稿，有三个额外的准备动作**：

| 动作 | 具体内容 | 为什么 |
|---|---|---|
| **① 涉密审查** | 逐项检查拓扑、内网地址、设备指纹、真实量测（回顾 Day 59） | 电网信息属于关键基础设施信息，泄漏是合规问题 |
| **② 代码仓库的脱敏** | 攻击脚本只针对仿真环境；README 里明确声明用途 | 避免被质疑"提供可滥用的攻击工具" |
| **③ 伦理声明** | 说明攻击构造基于公开理论、实验在仿真环境、目的是提升防御 | 安全方向发表攻击方法需要谨慎处理 |

**一段可以直接用的伦理声明**：

```
"本文使用的攻击构造方法基于已公开发表的理论框架 [Liu et al., 2009]，
本文未提出新的攻击能力。所有实验均在 pandapower 仿真环境中进行，
不涉及任何真实电力系统或生产数据。本文的核心目的是提升攻击检测
能力，攻击分析服务于防御方法的设计与评估。"
```

**选择投稿目标的三个务实建议**（回顾 Day 58 的选刊逻辑）：

```
建议 1：先看"你的核心创新点落在哪一边"
  创新点在物理约束建模 → 投电力类
  创新点在检测算法本身 → 投计算机/安全类
  两边都有 → 投交叉类

建议 2：核对门槛，不要只看影响因子
  如果目标期刊的论文都做了 5 个数据集 + 10 个基线，
  而你只有 2 个数据集 + 5 个基线 → 大概率被拒（门槛问题，不是质量问题）

建议 3：核实三件事（必须自己去官网）
  · 期刊全称与刊号
  · 是否在中科院《国际期刊预警名单》上（**投了不算成果**）
  · 格式模板的官方下载地址
```

## Day 118 —— 应对审稿意见：rebuttal 的写法

> **一句话**：rebuttal 不是辩论，是**在有限篇幅里，让编辑相信"这些意见要么已被解决、要么不影响主结论"**。

### 一、审稿意见的四种类型

**不同类型的意见，回应策略完全不同。先分类，再动笔。**

| 类型 | 特征 | 回应策略 | 篇幅占比 |
|---|---|---|---|
| **① 误解型** | 审稿人读错了 / 你没写清 | **先澄清事实，再补写清楚**（不要指责审稿人） | 20% |
| **② 真问题型** | 确实是你的不足 | **承认 + 补实验 / 改声称** | 50% |
| **③ 无法完成型** | 要求超出你条件（如真实数据） | **说明客观限制 + 给出替代证据 + 弱化声称** | 20% |
| **④ 编辑倾向型** | 编辑的元意见（如"需与 X 对比"） | **最高优先级**，必须明确回应 | 10% |

**逐类举例说明**：

```
【① 误解型】
  审稿意见："作者声称其方法在完全信息攻击下仍有效，这与已知结论矛盾。"
  实际情况：你在 4.3 节明确说了完全信息下性能降至随机水平

  ❌ 差的回应：
     "审稿人没有仔细阅读第 4.3 节。"
     → 语气指责，编辑反感

  ✅ 好的回应：
     "我们感谢审稿人指出这一点。需要澄清的是，本文从未声称方法在
       完全信息攻击下有效 —— 相反，我们在第 4.3 节明确指出，
       当 k → M 时所有方法的 AUC 均降至 0.5 附近（图 1 与表 1）。
       这说明我们的结论与已有理论一致。为避免误读，
       我们已在摘要与引言中显式加入这一边界的说明（见修改稿第 1 页、
       第 2 页高亮部分）。"
     → 澄清事实 + 承认"我们写得不够清楚" + 给出修改位置

【② 真问题型】
  审稿意见："缺少与 2024 年 X 方法的对比。"
  实际情况：确实没做

  ✅ 好的回应：
     "审稿人指出的对比确实缺失。我们已补充 X 方法作为基线，
       并在相同的威胁模型与数据划分下评估。结果显示
       （修改稿表 2 新增行）：在 k ≤ 4 时 X 方法与本文方法性能接近
       （AUC 差 < 0.01），但在 k ≥ 8 时本文方法保持优势
       （AUC 0.88 vs 0.79）。这一补充进一步支持了本文的结论。"

【③ 无法完成型】
  审稿意见："应在真实电网数据上验证。"
  实际情况：拿不到真实数据

  ✅ 好的回应：
     "我们完全同意真实数据验证的价值。由于电力系统量测数据涉及
       关键基础设施信息，公开可用的真实数据在撰写时无法获取。
       为部分弥补这一局限，我们做了三件事：
       (a) 在数据生成中引入了时间相关噪声（AR(1) 模型），
           使仿真数据更接近真实量测的误差特性（修改稿 4.1 节）；
       (b) 在 IEEE 14 与 118 两个规模上验证结论的一致性；
       (c) 在"局限与未来工作"中明确声明这一边界（修改稿第 X 页）。
       我们已将结论的适用范围明确限定为仿真条件。"
     → 承认局限 + 给出替代证据 + 【弱化声称】

【④ 编辑倾向型】
  编辑意见："请在修改稿中明确说明与 [某篇论文] 的区别。"
  → 这是编辑给的"送审通过的条件"，**必须正面回应，且要放在 rebuttal 最前面**
```

> **第 ③ 类的关键是最后一步"弱化声称"。** 不要为了保住原结论而硬撑 —— **把"本方法在电力系统中有效"改成"本方法在 IEEE 14 与 118 节点仿真系统上有效"，审稿人就没有理由再追**。

### 二、rebuttal 的结构模板

```
================================================================
Response to Reviewers
Manuscript ID: [XXX]
Title: [论文题目]
================================================================

我们感谢各位审稿人的认真评审。以下逐条回应所有意见。
修改稿中的改动均已高亮标出。

【改动摘要】（放在最前面，让编辑 30 秒内看到你做了什么）
  · 新增 1 个基线（X 方法），主表与消融表已更新
  · 新增 2 组鲁棒性实验（时间相关噪声、多攻击者协同）
  · 重写了 4.3 节，明确声明完全信息攻击下的性能下界
  · 补充了威胁模型中的攻击者物理约束（第 3.1 节）
  · 全文弱化了超出实验证据的声称（共 6 处）

----------------------------------------------------------------
Reviewer 1
----------------------------------------------------------------

【意见 1.1】审稿人原文（**必须逐字引用，不要转述**）
   "..."

【回应 1.1】
   （① 分类：真问题 / 误解 / 无法完成）
   （② 直接回应：同意 / 澄清 / 说明限制）
   （③ 具体动作：改了哪里、加了什么实验、给了什么数据）
   （④ 修改位置：第 X 页第 Y 段 / 表 Z / 图 W）

【意见 1.2】
   ...

----------------------------------------------------------------
Reviewer 2
----------------------------------------------------------------
   ...

----------------------------------------------------------------
Reviewer 3
----------------------------------------------------------------
   ...
================================================================
```

**四个必须遵守的格式要求**：

| 要求 | 原因 |
|---|---|
| **逐字引用审稿意见** | 转述会失真，且显得你在回避原文 |
| **逐条编号对应** | 编辑要能一眼看出"每条都回应了" |
| **标明修改位置** | 编辑不会去找，你必须告诉他改在哪 |
| **改动摘要放最前** | 编辑可能只看开头 |

### 三、语气规范：六个 ❌ 与六个 ✅

| ❌ 差的写法 | ✅ 好的写法 | 为什么 |
|---|---|---|
| "审稿人误解了我们的方法" | "我们意识到原文表述不够清晰，现澄清如下" | 把"审稿人错了"转成"我们没写清" |
| "这个问题不重要" | "该问题在本场景下的影响有限，原因如下……" | 直接否定会激怒审稿人 |
| "由于时间限制未能补充" | "受限于 [具体客观条件]，我们采用了替代方案……" | 时间不是理由，客观限制才是 |
| "我们完全同意，但……" | "我们同意这一点，并已补充实验验证（见下）" | "但"字后接否定，读起来像敷衍 |
| "如所周知……" | "已有工作 [x] 表明……" | 不要用"显然"来回避论证 |
| "感谢审稿人的宝贵意见"（每条都写） | 只在开头总致谢一次 | 重复的客套话浪费篇幅 |

**"六个不要"（**任何一条都会显著降低接收概率**）**：

```
① 不要情绪化 —— 即使审稿人明显没读懂
② 不要回避 —— 没回应的意见，编辑会数出来的
③ 不要撒谎 —— 说"已补充实验"但实际没做，等于学术不端
④ 不要只辩解不修改 —— 必须有实际的修改动作
⑤ 不要超篇幅 —— 很多会议 rebuttal 有字数限制，超了会被截断
⑥ 不要忽略最不利的那条意见 —— 编辑往往最关注它
```

### 四、和电网安全的关系

**电网安全方向最可能被问到的四个质疑，及回应要点**：

| 质疑 | 背后关切 | 回应要点 |
|---|---|---|
| **"为什么不用真实数据？"** | 结论的外部效度 | 承认限制 + 说明数据不可得的客观原因 + 引入更真实的噪声模型 + 弱化声称到"仿真条件下" |
| **"你的电力系统背景不足"** | 物理合理性 | 展示物理约束的建模（潮流方程 / 容量约束 / 电压范围）+ 引用电力领域的标准文献 |
| **"为什么不用 XXX 电力专用方法做基线？"** | 对比的完备性 | 补充该基线；如果做不完，说明筛选标准并把它列入未来工作 |
| **"攻击脚本会不会被滥用？"** | 伦理 | 说明基于公开理论、仅仿真环境、目的是防御（回顾 Day 117 的伦理声明） |

**回应"电力背景不足"的具体做法**：

```
❌ 弱回应：
   "作者团队具备电力系统相关知识。"
   → 空话，没有证据

✅ 强回应：
   "我们感谢审稿人的提醒。为确保障碍模型与评估设置的物理合理性，
    本文在以下三处引入了电力系统领域的标准建模：
    (a) 攻击注入向量受线路容量与电压幅值范围约束（式 5-6，
        依据 [电力系统标准文献]）；
    (b) 量测配置采用 [标准配置说明]，与状态估计的可观测性要求一致；
    (c) 数据生成使用 pandapower [引用]，其潮流模型已被广泛使用。
    此外，我们在修改稿中补充了对量测冗余度与可观测性的讨论（4.1 节），
    以说明实验设置的物理合理性。"
   → 用【具体的建模动作】证明你懂物理，而不是声明你懂
```

### 五、时间管理与优先级

**会议 rebuttal（时间极短）**：

```
典型时间窗：3-7 天
篇幅：常限制 500-1000 词

优先级排序：
  ① 编辑的元意见（如果有）
  ② 所有审稿人都提到的同一条问题 ← 【最高优先】
  ③ 涉及主结论正确性的质疑
  ④ 容易回应、能快速补的（占位、笔误、引用缺失）
  ⑤ 单条审稿人的细节意见

时间分配建议（以 5 天为例）：
  第 1 天：分类 + 排序 + 列出所有需要补的实验
  第 2-3 天：跑补充实验（**这是最耗时的，必须先启动**）
  第 4 天：写 rebuttal
  第 5 天：找人读一遍，改语气，检查是否逐条回应
```

**期刊大修（Major Revision，时间较充裕）**：

```
典型时间窗：1-3 个月
篇幅：通常无严格限制（有的期刊要求"response letter"）

与会议的区别：
  · 期刊可以【真的改论文】而不只是回应
  · 期刊的"大修"通常意味着"改好了就能接收"
  · 但需要提交【修改后的论文 + 逐条回应 + 带修订标记的版本】

必须提交的三份文件：
  ① 修改稿（clean version）
  ② 逐条回应（response to reviewers）
  ③ 带修订标记的版本（marked-up / tracked-changes version）
```

> **"所有审稿人都提到的同一条问题"要放在最前面回应。** 这条往往决定了论文的生死 —— 如果三个审稿人都说"缺少与 X 的对比"，那这条不解决，接收无望。

### 🔍 延伸思考

1. 如果你的三个审稿人给出了互相矛盾的意见（一个说"实验太多"、一个说"实验太少"），你会怎么处理？
2. 有一类审稿意见你确实无法回应（比如要求你换一个完全不同的方法），这时候的正确做法是什么？（提示：编辑在做什么决策？）
3. "弱化声称"和"坚持结论"之间的边界在哪里？什么情况下应该弱化，什么情况下应该据理力争？

## Day 119 —— 被拒之后：改投策略与心态

> **一句话**：被拒不是对你工作的判决，是**一次免费的专业评审** —— 关键是你有没有把这份评审变成下一篇论文的资产。

### 一、三种被拒情形

**情形不同，应对完全不同。先判断你属于哪一种。**

| 情形 | 特征 | 时间成本 | 应对 |
|---|---|---|---|
| **① 编辑直接拒（desk reject）** | 1-2 周内收到，无审稿意见 | 低 | 换刊，**不修改内容**（除非是格式问题） |
| **② 送审后被拒** | 1-4 个月后收到，有 2-4 份审稿意见 | 高 | **先改再投**，审稿意见是资产 |
| **③ 大修后被拒** | 3-6 个月后收到 | 最高 | 仔细读编辑的最终意见，判断是"改得不够"还是"方向不合" |

**① desk reject 的常见原因（**多数与质量无关**）**：

```
· 方向不匹配（Aims & Scope 不符）← 最常见
· 格式不符合要求（超页、模板不对）
· 未引用该刊近期论文（有些刊在意）
· 创新性被认为不足（编辑的第一印象）
· 语言问题严重到无法评审

⇒ 结论：desk reject 通常说明"投错刊了"，不说明"工作不行"。
   最快的应对是【换一个更匹配的刊】，而不是重做实验。
```

**② 送审后被拒，怎么判断原因**：

| 审稿意见的模式 | 说明 | 应对 |
|---|---|---|
| 都认可价值，但都说"实验不充分" | **工作有价值，实验要补** | 补实验后投同级或稍高 |
| 都质疑"新意不足" | **gap 不成立或太弱** | 需要重新定位角度，不是补实验能解决 |
| 意见互相矛盾 | **方向本身有争议** | 换一个更匹配的圈子投 |
| 一份正面两份负面，编辑按负面判 | **常见，运气成分** | 补上负面意见提到的点，换刊再投 |

> **"都质疑新意不足"是最需要认真对待的一种。** 它说明你的 gap 陈述没站住 —— **这时候补实验是没用的，必须回到 Day 110 重新审视选题的定位。**

### 二、改投决策树

```
问题 1：审稿意见里有没有"可执行的修改建议"？
  ├─ 有，且是"补实验 / 补对比 / 补说明"类
  │    → 【先改再投】。修改周期估算：
  │        · 补 1-2 个基线：1-2 周
  │        · 补一组鲁棒性实验：1 周
  │        · 改写表述与声称：2-3 天
  │    → 改完后，投【同级或稍高一级】的刊
  │
  └─ 没有，都是"新意不足 / 方向不感兴趣"类
       → 继续问题 2

问题 2：同一个方向还有别的刊吗？
  ├─ 有（交叉方向通常有多个候选）
  │    → 【换刊直投】。注意：
  │        · 换到审稿人圈子不同的刊（电力 ↔ 计算机）
  │        · 针对新刊的读者，重写 Introduction 的动机部分
  │        · 保留审稿意见中"确实成立"的修改
  │
  └─ 没有，或都被拒过
       → 继续问题 3

问题 3：降低目标是否可接受？
  ├─ 可接受（第一篇论文，先拿到成果）
  │    → 【降级投】：CCF-C / 中文核心 / 交叉类开放获取刊
  │        · 这不是失败。第一篇论文的目标是【走完流程 + 拿到成果】
  │        · 有了一篇，第二篇的起点完全不同
  │
  └─ 不可接受
       → 【补强后重投同级】：需要 2-3 个月的工作量
           风险：可能再次被同一批审稿人拒
```

**决策树之外的三条经验**：

```
经验 1：不要在同一批审稿人手里连投两次
  → 换刊时注意审稿人库的重叠度（同领域的刊重叠度可能很高）
  → 换一个"圈子"（电力 → 计算机）比换一个"同圈子的刊"更有效

经验 2：被拒后的第一件事是【整理审稿意见清单】
  → 把所有人的意见合并去重，做成一张表：
     | 意见 | 提出者 | 类型 | 是否成立 | 应对 | 状态 |
  → 这张表是你改稿的依据，也是下一篇论文的检查清单

经验 3：给"改投"设一个明确的时间盒
  → 例：2 周内改完，1 周内投出去
  → 不要陷入"再改改看"的无限循环（很多人的第一篇就死在这里）
```

### 三、把审稿意见变成资产

**审稿意见是"免费的同行评审"。** 把它系统化地利用起来：

| 动作 | 具体做法 | 长期价值 |
|---|---|---|
| **建一个"审稿意见库"** | 按类别归档（实验设计 / 表述 / 相关工作 / 方法） | 下次写论文前先看一遍，避免重犯 |
| **提取"通用问题"** | 如"缺少与 X 的对比""划分方式没说清" | 变成你的**投稿前自检清单** |
| **提取"领域关注点"** | 审稿人反复问什么，说明这个领域在意什么 | 指导下一篇的选题与实验设计 |
| **保留原文** | 不要删掉审稿意见 | 修改稿的 response letter 需要引用原文 |

**一个具体的做法**：

```
建一个文件：审稿意见库.md

结构：
  ## 2026-XX 投稿 [期刊名] —— 被拒
  ### 审稿人 1
    · 【实验设计】缺少与 X 方法的对比 → 已补 → 结论未变
    · 【表述】摘要中"显著提升"未给数字 → 已改
  ### 审稿人 2
    · 【相关工作】未引用 Y 的 2024 工作 → 已补
    · 【方法】未说明 k 的选取方式 → 已补（3 种方式对比）
  ### 审稿人 3
    · 【新意】认为与 Z 工作重叠 → 需在 Introduction 中明确区别

  ## 汇总：通用问题（下次投稿前必查）
    - [ ] 基线是否覆盖三条技术路线
    - [ ] 数据划分方式是否说明
    - [ ] 所有"提升"类表述是否都有数字
    - [ ] 最接近的 3 篇工作是否明确区分
```

> **这个文件的长期价值极高**：**写到第三篇论文时，你会有一份"这个领域审稿人真正在意什么"的一手清单** —— 这是任何综述都给不了你的东西。

### 四、和电网安全的关系

**电网安全方向改投的三个具体考虑**：

| 考虑 | 说明 |
|---|---|
| **圈子跨度大，改投空间也大** | 电力类（TSG / TPS / 电力系统自动化 / 电网技术）与计算机安全类（CCF 会议）的审稿人圈子几乎不重叠 → **换圈子投是有效策略** |
| **注意预警名单** | 改投前重新核对目标刊是否在预警名单上（**投了不算成果**，回顾 Day 58） |
| **涉密审查要重做** | 每次改投都要重做一遍涉密检查（回顾 Day 117），尤其是改投到不同国家/地区的期刊时 |

**"换圈子投"的具体做法**：

```
电力圈被拒 → 投计算机/安全圈，需要改什么：
  ① Introduction 的背景要写得更"通用"（不要假设审稿人懂电力）
  ② 威胁模型要解释得更细（为什么这个攻击重要）
  ③ 物理约束要给出公式与依据（不要只说"符合潮流方程"）
  ④ Related Work 要补 AI 安全线的文献（回顾 Day 57 的"两条线"）

计算机圈被拒 → 投电力圈，需要改什么：
  ① 强调物理合理性（审稿人最在意这个）
  ② 补充电力领域的标准引用
  ③ 评估指标要加"固定 FPR 下的 TPR"（运维关心的指标）
  ④ 增加对"N-1 安全"等相关概念的辨析（避免术语歧义）
```

> **这个"换圈子改写清单"值得你保存。** 它本质上是**针对两类审稿人的差异化沟通策略** —— 同一份工作，对不同读者要用不同的语言。

### 五、心态：拒稿的统计现实

**先把几个事实摆出来**：

| 事实 | 含义 |
|---|---|
| 顶会的接收率通常在 15-25% | **大多数投稿会被拒**，这是常态 |
| 顶刊的接收率通常更低 | 且周期长 |
| 一篇论文从投稿到接收，平均经历 2-3 次投稿 | **"一次就中"是少数情况** |
| 审稿意见的质量参差不齐 | 有认真的，也有 10 分钟写出来的 |
| 被拒的原因中，有相当比例与质量无关 | 方向不匹配、审稿人偏好、运气 |

**几条务实的心态建议**：

```
① 把"投稿"和"论文质量"解耦
   投稿是一个【匹配过程】，不是【质量判决】。
   同一篇论文，投 A 刊被拒、投 B 刊被接收，非常常见。

② 设定"过程指标"而不是"结果指标"
   ❌ "这个月要投中一篇"  → 你无法控制
   ✅ "这个月要投出去一份" → 你能控制
   ✅ "被拒后 2 周内改完再投" → 你能控制

③ 给自己设一个"难过时限"
   收到拒信可以难过，但设一个时限（比如 1 天）。
   过了时限，开始执行改投决策树。

④ 不要一个人扛
   把审稿意见拿给导师和同门看 —— 他们往往能判断
   "哪些意见要听、哪些可以不理"，这个判断力是经验带来的。

⑤ 记住你的目标是"长期产出"，不是"这篇必须中"
   第一篇被拒的代价是 3 个月。
   因为被拒而停摆一年的代价，是 12 个月 + 心态损伤。
```

**一段必须说清楚的话**：

> **你在 120 天里做的工作，不会因为一次拒稿而消失。** 你有的东西是：一个跑通的实验框架、一份完整的论文、一份可复现的代码、一份对领域的一手认知、一份审稿意见清单。**这些在任何一次改投里都继续有效。**
>
> 拒稿带走的是"这一次的机会"，不是"你的能力"。

### 三、长期科研节奏建议

**120 天结束后，真正的挑战才开始：没有课表了，怎么保持产出？**

**核心节奏：三个周期嵌套。**

| 周期 | 时长 | 做什么 | 产出 |
|---|---|---|---|
| **周节奏** | 每周 | 精读 1 篇论文 + 记录 1 条想法 | 52 篇/年 + 52 条想法 |
| **月节奏** | 每月 | 复盘：读完的论文里哪些相关？想法里哪个值得做？ | 一份月度复盘 |
| **季节奏** | 每季度 | 定一个可交付目标（投一篇 / 跑完一组实验 / 写一节论文） | 4 个交付/年 |

**周节奏的具体安排（每天 1 小时的话）**：

```
周一-周二：精读 1 篇论文（三遍读法，分两天）
周三：把论文的要点写进你的文献库（模板化，10 分钟）
周四：动手 —— 跑代码 / 做实验 / 改论文
周五：继续动手
周六：写一段论文（哪怕 200 字）
周日：休息或补做

关键点：
  · "每周精读 1 篇"是最低门槛，不是最高目标
  · 精读的产出必须是【笔记】，不是"我读过了"
  · 笔记要能回答三个问题：它解决什么？怎么解决的？它没解决什么？
```

**月复盘的四问**：

```
① 这个月读的论文里，哪 3 篇和我的方向最相关？
   → 归档到"核心文献"，其余归到"泛读"

② 这个月产生的想法里，哪一个最值得动手试？
   → 写成一个 3 行的实验计划（做什么 / 看什么指标 / 需要多久）

③ 我的实验/论文进展如何？卡在哪？
   → 卡点要具体到"哪一步做不了"，不要写"进展缓慢"

④ 下个月要交付什么？
   → 必须是一个可交付的东西（一个表 / 一节论文 / 一组实验）
```

**季度的目标模板**：

```
第 1 季度：把第一篇投出去 → 被拒 → 改完再投
第 2 季度：第一篇接收（或投第三个刊）+ 开始第二篇的实验
第 3 季度：第二篇成稿 + 把方法迁移到第二个场景
第 4 季度：第二篇投稿 + 整理一篇综述或开源工具

⇒ 注意：每个季度只有一个【可交付】目标。
   不要同时开三个坑 —— 研究生的时间经不起并行。
```

**三条长期建议**：

```
① 保持"写"的习惯，不要只在投稿前写
   每周写 200-500 字（论文片段、笔记、实验记录都算）
   → 写作是肌肉，停两周就生锈

② 维护一个"想法池"，不要让它只留在脑子里
   想到什么立刻记一行（问题 / 想法 / 可能的方法 / 可行性）
   → 选题的灵感来自积累，不来自灵光一现

③ 每年至少精读 3 篇"和方向不直接相关"的论文
   → 跨方向的输入是产生原创想法的主要来源
     （你实验室的"程序逆向 / 图像识别 / 多模态"都是潜在的输入源）
```

### 四、和电网安全的关系

**你的网安背景在电网安全方向的三个真实优势**（这是你的差异化，不是劣势）：

```
① 攻击者视角

② 对"安全"的严格定义

   → 这在写威胁模型时是决定性的（回顾 Day 111）。

③ 攻防闭环的思维
   你不满足于"我的方法效果好"，你会问"如果我攻击它呢"。
```
